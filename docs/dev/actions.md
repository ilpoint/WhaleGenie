# 动作修改与表单约定

所属：[WhaleGenie 开发说明](../dev.md)。

## 修改动作的流程

1. **检索现有契约。** 在动作目录、`MacroRunner`、`MacroCheck`、手册和测试中检查动作键、字段名、
   记录字段及同义概念，优先复用现有名称。
2. **修改语义目录。** 在 `WhaleGenie.Core/Execution/ActionSemantics.json` 声明动作分类、参数、
   值形态、控件形状、单位、空值、范围、默认值、必填与选项失败键、拾取器、副作用、等待、子列表和返回值。
3. **实现引擎分派。** 动作族各自成类：`WhaleGenie.Core/Execution/<Family>Actions.cs` 里的静态 `Map`
   把动作键交给只收 `IRunContext` 的处理器；族不持有运行器，也不读它的私有字段，共享能力经
   `IRunContext`、`StepArguments`、`StepResults`、`WindowFacts` 等取得。控制流（分支、循环、调用、
   尝试、变量写入）仍由解释器实现，这类动作加在 `MacroRunner.Dispatch.cs` 的表里。读值与范围检查
   使用目录，记录字段使用 `FieldNames`，不得按 `type` 前缀推断行为。
4. **更新展示与文案。** `ActionDisplay.json` 只写形状决定不了的事：编辑器种类（默认由值形态与
   拾取器推导，例外才写）、选项文案、启用条件、路径意图、页面归属与预览。文字写进
   `ActionEnglish`（英文）与 `ActionStrings`（中文），键是 `<动作>.name`、`<动作>.desc`、
   `<动作>.<字段>.label` / `.hint`、`<动作>.return.<结果>.label` / `.hint`；缺英文会被
   `LocalizationTests` 挡住，中文可以后补并回落到英文。图标映射位于 `ViewModels/AppIcons.cs`，
   菜单图标键位于 `ViewModels/MenuIconCatalog.cs`。
5. **补齐失败键。** 新失败键同时进入 `RunKeys` 和手册失败键表；日志键使用独立的 `Log.*` 词表。
6. **补齐页面与返回值。** 参数只归属于一个页面；返回值页、目录声明、引擎写入键和记录字段保持一致。
7. **增加自动化用例。** 至少一条引擎用例执行新动作，并补充值形态、控件形状、范围、副作用、返回形状、
   失败键、页面、文案及结果清空等契约断言。
8. **删除被取代的形状。** 同版移除旧参数、开关、文案、测试和文档，不保留别名或双读；不兼容的
   文件形状变化须升级包格式版本。仅删除可安全忽略的字段时可以保持版本，但不得增加迁移逻辑。
9. **完成手动验收。** 涉及真实桌面行为时，按[手动验收清单](validation.md#手动验收清单)记录环境、步骤和
   观察结果。
10. **收尾验证。** 更新手册、依赖与许可说明；完成路线图对应事项后删除该事项；运行构建、全部测试和
    格式检查。

新增一个动作要改的地方，按上面的顺序数下来共八处：语义目录、展示目录、族文件（或控制表）、
`ActionEnglish.cs`、`ActionStrings.cs`、手册对应篇、族用例，以及——只有在出现新失败键或新图标时——
`RunVocabulary.cs` 与 `AppIcons.cs`。改动面超过这八处说明这个动作被放错了族，或目录里缺了能表达
它的形状；展示目录里只写这个动作与通用默认不同的地方，写得越多越可能是在补形状该说的话。

## 动作表单与编辑器约定

动作表单按用户需要回答的问题分块，而不是按字段类型堆砌：

- 每块使用统一图标与标题，同块字段必须相邻，目录加载时检查；图标由 `AppIcons.Block` 提供。
- 同一个问题跨页时保留同一块标题与序号，不按页面重新编号。只有一项简单设置时不增加多余块头。
- 必填项新建后即有可用值；空值只表示未提供，不默认等同于 0。坐标、区域、颜色、窗口和元素等已有
  拾取能力的字段复用对应拾取器。说明先解释字段含义，再说明修改时机；数值须给出范围、单位和默认值。
- 一行一项的数据使用统一行表；返回值使用“留下 / 结果 / 结构 / 变量名”四列，结构列给出可读示例。
- 执行与容错页统一承载超时、延迟、重试和失败策略；危险动作提供确认或可撤销路径。
- 每页至多三块。界面文案不用破折号，同一概念在字段、提示和手册中使用同一个词；动作名称须说清所属族，
  两个动作不得同名。

各族按以下顺序组织问题，新动作不另起一套顺序：

| 族 | 块顺序 |
| --- | --- |
| 视觉 / 识别 | 范围 → 找什么 → 按内容挑 → 怎样算成功 → 怎么点 → 识别调参 |
| 输入（键鼠、手柄） | 发给谁 → 按什么 / 点哪儿 → 怎么点 → 节奏 |
| 界面 / 浏览器 | 在哪个窗口 → 找哪个元素 → 元素限定 → 改成什么样 / 读哪一部分 → 第几个 |
| 数据 / 文件 / 剪贴板 | 哪个变量 → 从哪儿读 → 存到哪儿 → 挑哪些 → 怎么读 / 怎么写 → 怎么排 |
| 脚本 | 跑什么 → 交给谁跑 → 传什么给它 |
| 窗口 / 程序 | 哪个窗口 → 挪到哪儿 / 等它 → 交给它什么 |
| 流程 | 问什么 / 比什么 / 跑几轮 → 每轮叫什么 → 节奏 → 各分支跑什么 |

步骤树、条件读回和取值窗口的结构约束见[架构文档](../architecture.md)，本文不重复其设计理由。
