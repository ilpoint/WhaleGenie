# 手动验收与截图评审

所属：[WhaleGenie 开发说明](../dev.md)。

## 手动验收清单

按受影响范围选择项目，并在提交信息中记录 Windows 版本、DPI、显示器数量、相关外部程序版本、
操作步骤和观察结果。环境变化后重新验收受影响项目。

- **输入与取色**：在记事本等现有程序中验证点击、输入、拖选和滚轮；在已知颜色位置验证抓屏取色。
- **两种启动方式**（改了 `src/WhaleGenie/Web` 后）：`WhaleGenie.exe`（VS Code 的 `launch.json`
  用的就是它）与 `dotnet WhaleGenie.dll` 各启动一次，菜单、轮盘与界面面板都要照常画出来——浮层的
  WebView2 环境与壳共用，换宿主不应退回旧引擎而只剩空白窗口。托盘的图标应是鲸鱼；窗口规则列表里
  不应出现鲸灵自己的窗口，也不应少掉别的 dotnet 程序（自己人按进程号认）。
- **网页壳**（改了 `webui/` 或 `src/WhaleGenie/Web|Bridge` 后）：默认启动——壳渲染、
  标题栏拖动、双击最大化、置顶、最小化/最大化/关闭（关闭=藏进托盘，托盘菜单才真正退出）、
  托盘唤回、单实例唤回与退出链路全部可用；切语言即时生效（词表整包推送）；深浅色与自定义
  强调色生效、焦点环在两种主题下可见；100% 与 150% DPI 下标题栏、宏列表与侧栏系统开关键无裁字；
  自动保存项目的开关与默认项目路径按「设置与宏包」核对；DevTools 仅在
  DEBUG 可用；发布形状里 `webui/index.html` 存在且壳能从它启动。浏览器开发模式
  （`npm run dev`）下壳可独立打开、mock 宿主可推进同一组交互。
- **网页壳的焦点、声音与系统开关**（改了 `WebShellWindow`、`WindowBridge`、`SystemState`、
  `ProjectBridge` 或 `webui/src/shared/focus` 后）：把光标放进宏列表搜索框，按系统热键与一个宏的
  启停键，两者都不应切换；把焦点移出输入框或切走窗口后再按，应恢复。用热键翻转系统开关，页面
  的开关与文字应立即跟着变。在页面启停宏只听一声，关掉设置里的宏声音后应完全静音。关掉窗口再
  打开，尺寸应是上次的普通尺寸；最大化后关闭不应把最大化尺寸记成选择。
- **界面宏**：给一个宏加界面触发并选目标窗口，把目标窗口切到前台，按钮组应出现在目标客户区内；
  再点别的程序让目标失焦，按钮组应仍留在原窗口内、位置不跳；**再切回目标窗口**，按钮组应直接
  压在目标窗口上方，不消失，也不需要拖动窗口才回来；关闭或最小化目标后按钮组消失，恢复后再出现。
  不选窗口的规则跟随前台窗口移动。把另一个窗口拖到目标窗口上方，按钮组应被一起盖住，不能透过
  焦点窗口显示。点把手上的折叠按钮，按钮收起、只剩顶部约 20 像素的窄条；在窄条下面点一下，应直接
  点到下面的窗口（不是点到面板）。再点窄条上的展开按钮恢复；点排列按钮，按钮在竖排与横排之间切换，
  横排变宽后仍应落在目标客户区内。**切到横排后再折叠，标题栏的两个按钮仍应留在 86 宽的窄条内，
  展开按钮能点开**；折叠条和面板四角应是圆角，卡片右边、下边不裁成直角。拖动一次按钮组，位置按
  目标客户区保存；**把它拖到客户区外再松开，落点应夹回客户区内**，下一次刷新不跳。**给同一组按一次
  显示/隐藏快捷键，面板应能切走再切回**；打开宏设置，界面的启停键应与实际生效的一致。**同时开两个都符合
  同一规则的窗口（如两份未命名 Notepad），切到哪个，按钮组应跟到哪个；再按显示/隐藏键，应在当前前台
  窗口上消失/出现**，不能只切后面那扇窗的按钮组。在界面宏设置里分别用主键盘减号和小键盘减号捕获一次，
  字段应分别显示 `-` 与 `NumPadSubtract`，两种键各按一次都应生效；小键盘的数字/加减乘除/回车不再被
  存成主键盘字符。
- **五类拾取器**：框选、取色、点、元素和窗口规则分别进入与退出，检查焦点、Esc、回车、右键、
  鲸灵窗口隐藏与恢复；在添加动作窗口中至少验证一次。
- **识别画面上的拾取**（`LookPickWindow`）：点击图片 / 点击文字 / 点击检测到的物体的「拾取点位…」，
  以及多点找色的「拾取偏移与颜色…」。要验的是偏移以命中中心为原点、点在框外仍然有效、
  颜色取自打开那一刻的识别画面（不是此刻的屏幕），以及这一步没找到东西时给出说明而不是空窗。
  多点找色还要验：表单上不再有「周围要对的颜色」一格；「对比色（N 处）」一节（标题、序号/偏移/
  颜色/色块那一列与拾取按钮）在**容差之后**，拾完后这一列随即更新；拾取器打开时带出已有
  那几处，确定后整张表写回、取消不改；圆点与列表上的序号对得上；拖圆点改一条、右键圆点出菜单、
  空白右键不多条、滚轮键单击新增；左上的「+」与每行「编辑…」都开得出一行三框、框末带表达式的窗口。
- **定格与框选**：取色后移动背景窗口或播放视频，确认读数仍来自打开时的画面；框选图不得包含鲸灵窗口。
- **FluentAvalonia 窗口**：在深色和浅色主题下检查标题栏、窗口控制按钮、扩展标题栏拖动、文本对比度和
  关键控件布局。
- **设置页**：深色与浅色各走一遍常规、主题、热键、菜单呼出/窗口规则、轮盘菜单、轮盘动作、声音、
  屏幕读取、画面、输入、驱动与存储；确认改动立即写回并在重开页面后保留，语言与主题立即生效，
  自定义强调色作用到所有窗口，热键可捕获与清除，存储位置能打开对应目录。菜单呼出键可用键盘、
  中键与 4/5 侧键各捕获一次；窗口规则表单能列出打开的窗口、到桌面取一扇窗口并保存。**把一条旧规则
  （比较方式曾写成 `TitleContains`）在菜单规则和轮盘场景里各打开一次，比较方式应有选中项，保存后
  存成 `titleContains`；界面的同一组规则保存后组键不变，面板位置与启停键仍在原处。**
- **轮盘设置与动作**：场景列表可新增/编辑/删除/上下移动，轮盘位置可点开编辑宏、备注与图标，
  程序场景继承全局动作并写出覆盖；轮盘预览在页面里按全局动作显示版面。轮盘与窗口规则的实际桌面
  行为按「轮盘菜单」「窗口规则」条目验收。设置页本身的改动不应让触发器计划停在旧值。

- **轮盘菜单**：先启用系统总开关（`Home`）。中键按下应照旧弹出菜单宏；**短按右键**应照旧
  弹出系统右键菜单，鲸灵不出任何界面；**按住右键并移动**才弹出轮盘，且以按下点为中心。移向内圈、
  外圈时扇区高亮并有一根从中心到指针的实线；划到圆盘之外，线变成虚线并伸出可见圆盘、末端跟着
  指针，中心只显示该方向动作的**宏名字或备注**（没有「划一下」之类的提示词）。快速移动指针时
  线的末端应始终贴着指针，不能落后一截。中心圆显示「关闭」，在中心松开、`Esc`、
  左键都取消；**取消之后立刻点几下左键，确认没有被吞掉**（这是曾经因为只拦截松开而出现的回归）。
  悬停按 `F1` 重复触发；超时自动取消。在屏幕边缘触发确认可见轮盘仍在屏幕内。设置页的预览按
  当前全局动作画版面，不经过全局钩子，也不代替实时轮盘。把触发键改成中键 / 4 侧键各验一次，再
  关掉「启用轮盘菜单」确认右键完全不受影响。第三圈容量切到 8/16/24 各看一次版面与命中；只给内圈
  填动作时确认空外圈被隐藏。在轮盘动作管理里点一个扇区，确认能改宏、备注与图标，选一个图标后
  文字上方出现它；「清除该位置」把整格清空。
  新增一个按进程名匹配的程序场景、覆盖一个位置，确认其余位置显示「（全局）」；轮盘弹出后滚动滚轮三次，确认
  来源按叠加／全局／当前程序／叠加变化。把重复键从 `F1` 改成 `F8` 验一次，再关掉光泽、
  悬浮边框、弹出动效与主题跟随，确认浅色固定盘面仍可读。
- **浮层置顶与定位**（改了 `WebOverlayWindow`、`WheelOverlayHost`、`MenuOverlayHost` 或
  `PanelOverlayHost` 后）：先让一个**置顶**程序（或用标题栏钉子把壳置顶）在前，再呼出菜单、轮盘与
  面板——三者都要压在它上面，不能只在普通窗口上正确。菜单置顶时点窗口外不收起、切程序收起；
  菜单搜索框点开后能输入、`Esc` 关闭并把前台还给原程序；**不用鼠标点菜单外，改用 `Alt+Tab`
  或热键切走，未固定的菜单也要收起**，固定的菜单留下并重建当前程序的分页。**三块浮层都要再关掉、再呼出一次**：
  第二次打开必须照样画出来，不能只剩一扇空白窗口（页面只在窗口上屏后加载，首开与重开各验一次）。
  轮盘在 100%/150%/200% DPI 与副屏（含负坐标）下中心落在按下点、可见圆不被裁掉；指针移入中心
  再呼出时，指针先被移到实际圆心。面板跟随目标客户区移动、目标最小化即消失、折叠后只剩顶部窄条
  且窄条下方点击能落到目标窗口；用系统开关来回切两次，任务管理器里的窗口数不应增加。
- **屏幕捕获设置**：把「跟随屏幕刷新率」关掉，确认数字框可改、上限等于设置页显示的赫兹数；填一个
  比刷新率大的值，确认保存后回到上限。打开「缓存捕获的画面」，确认「缓存有效期」那一格跟着可用；
  跑一个连续识别同一窗口的宏，比较开关前后的运行耗时。
- **存储位置打不开**：把某一行的目录设为只读后点「打开」，确认界面只出现一句「文件夹打不开，
  详情见日志」，`runtime.log` 里有这一次的异常，窗口里不出现 .NET 原文。
- **驱动级输入**：安装 usbip-win2，分别验证启动时加载与否、键鼠动作和手柄；退出后确认虚拟设备已移除。
- **识别与录制**：验证 YOLO 检测、等待与点击落点；验证录制热键、动作翻译和停止流程。
- **脚本与依赖**：验证批处理、PowerShell、Python、C#、AutoHotkey、包安装及断网失败路径。
- **宏工作台（网页）**：从「宏」页新建、编辑或运行打开独立工作台窗口；确认标题栏只有编辑器/运行调试两页签、主壳活动栏没有编辑器和运行调试；运行页签图标是 `bug-play`。确认动作库位于编辑器第一列（基础动作/流程控制/子宏/公共宏）、
  中间文档页签与步骤树、右侧变量中心 + 宏设置上下双面板都在；单击动作选中、双击/「添加步骤」/拖入接缝先打开动作编辑器，确认后才加入；
  块的分节能用「添加」放子步骤，多分支能用「添加分支」加一支；Ctrl/Shift 多选、右键菜单、
  Ctrl+C/X/V/G/E、拖放换位与「提取为新宏」可用；公共宏卡片会复制子宏并留下调用；双击步骤/点铅笔打开动作编辑器，在
  里面改参数、条件、行表、备注/超时/失败处理；变量中心的五档过滤、局部/全局变量对话框能新建与改名；
  宏设置两页（常规/专属）能改名称、触发入口、输入限制、启停键与形参/返回值；键位捕获、图片浏览、
  动作编辑器的四页页签、返回值表、必填校验与取消/确认可用；框内「取值」按钮与 Token 取值窗口可用；标签行不出现导出按钮，文件菜单的导出与导入共用同一个勾选向导；录制开始/停止能写回步骤；
  脏页签关闭先问保存，保存失败保留页签；Ctrl+S/Ctrl+W 与「运行调试」可用；切语言后动作库与
  分节标题跟着变；深/浅主题、100% 与 150% DPI、1280×840 与 960×640 下不裁字、焦点环可见，
  窄窗收起右侧栏后内容区可横向滚动。
- **触发入口的窗口规则（网页编辑器）**：选中一条「窗口内接口」或「窗口出现 / 消失」入口，点「选择窗口」，
  确认打开的是动作字段用的同一个窗口规则对话框（左边此刻开着的窗口、右边匹配方式与内容、两个比较开关），
  列表里没有鲸灵自己的窗口；从列表取一扇按「使用这个窗口」写回，卡片摘要与规则行换成刚取的那扇；把匹配方式
  改成「进程名」再保存、重开工程，匹配方式与进程名都在；「窗口句柄（当前实例）」不在窗口内接口的备选里
  （只在窗口触发器的备选里）。
- **子宏与工作台关闭（网页编辑器）**：在「子宏」页点“新建”，确认出现未保存草稿页签而父宏列表不立即增加；
  保存后列表才多一项，连续新建默认名不重复；从“导入”分别选公共宏库、当前工程宏与一个宏包文件，
  确认子宏加入并打开页签；子宏页签上父宏列表仍然可见。主壳标题栏项目名后显示“项目自动保存已开启”，
  主壳没有编辑器状态条；关闭自动保存项目后项目名后的括号消失。关闭工作台、Alt+F4 与托盘退出时，
  未保存的宏在工作台里列出来；隐藏主壳不询问工作台文档。
- **保存与文档身份（网页编辑器）**：打开一个宏改名并保存，再从宏列表打开新名字，确认仍是同一个
  页签；新建宏保存后同样不出现第二个同名页签；子宏改名/加步骤保存后父宏页签出现未保存，保存父宏
  后关闭并重开包能看到子宏改动；把工程「另存为」到新路径，确认标题/列表/后续自动保存都跟着新
  文件，旧文件不再变化；关掉自动保存项目后保存宏，确认页脚显示工程包尚未写入，退出时仍询问工程；
  用 MCP 或另一窗口改过目标宏后保存，确认提示冲突、页签保持未保存而不是显示成功；脏文档时分别
  点关闭、Alt+F4、关闭工作台和托盘退出，确认各出现一次询问，保存失败留在对话框。
- **包内容预览与内嵌公共宏**：新建工程并导入一条公共宏作为子宏，保存后检查包里有
  `library/entries.json`；再从文件菜单打开同一个包，确认预览同时列出工程宏、变量、触发入口和库条目，
  点“打开宏项目”后编辑器能看到“本工程”来源的条目。只留 `triggers.json` 或只留
  `library/entries.json`，确认预览只显示对应区段，工程与库不会互相误读。
- **公共宏来源与版本**：在设置里切换“编辑器来源”为两者/本工程/本机，确认编辑器列表按来源变化；
  同 id 不同版本两行都在且显示版本号，点哪一行插入哪一行，`Origin` 与所选版本一致。
- **包存储边界**：工程打开/保存/导出/导入与子宏“从文件导入”都经同一包存储；用一个被改坏的
  `.wgmacro` 和一个只读目录，确认计划阶段报包错误、现有工程/旧包不被破坏；打开一个较大的包时
  界面不卡住；公共库在编辑器里读写的文件是
  `%APPDATA%\WhaleGenie\library\public-macros.wgmacro`；从公共库页导入一个库包时确认先看到预览，
  再由 id/版本合并。
- **公共宏设置**：切换导入落点为本工程/本机，导入带内嵌库的包，确认条目只进入所选位置；关闭
  “导出时带上本工程公共宏”，导出包不应出现 `library/entries.json`。
- **诊断日志与文件选择**：连续点「打开宏项目 / 导入」再取消几次，确认原生选择器与进程都还在；
  把 `runtime.log` 写大，确认当前文件与 `.1`、`.2` 各不超过 512 KB，旧版本留下的超大备份在下次
  写入时被清掉。
- **Token 取值窗口**：从文本/名字/颜色/多行/条件格/行表值格分别点框内「取值」，确认窗口进入
  对应模式；结构带里插入/摘除/换运算符/括号/列表/函数/变量/常量；拖动一块换位置，撤销/重做/清空；
  点「确定」把形状写回字段，点「取消」不改原值；空值确认应清空该格；必填空洞或读不通时「确定」不可用；
  条件格左右值与行表单元格的取值钮也要分别打开并写回对应格子；
  变量片显示名与实际名要区分；数字框可直接输入，数字框里写公式后应变成只读公式显示；
  旧宏里带 `$` 的文字仍能读入，但新建值不再要求 `$` 语法。
- **变量名字与格式 32**：打开一个 31 及更早的 `.wgmacro`，确认被拒绝并给出可读的版本提示；新建一个宏，
  加全局变量、局部变量和一个「设置变量」步骤，保存后重新打开，确认引用仍读到同一个值；把全局变量改名，
  确认同名局部变量没有被跟着改；从取值窗口选一个名字写进条件行，保存再打开，确认仍按名字读取，且文件里没有 `$` 前缀。
- **两个工程各一张表**：打开 `A`，在变量中心加一个全局变量并让一次运行写入值；不关程序直接打开 `B`，
  确认变量中心里没有 `A` 的声明，`B` 里声明同名变量也读不到 `A` 的值；回到 `A` 那份包重新打开，确认值
  只按持久化规则恢复。
- **变量约束与生命周期**：声明一个数字局部变量，用「设置变量」写一段文字，确认那一步失败并报
  `Run.VariableTypeMismatch`；声明一个叫 `i` 的局部变量再加一个 `for i` 循环，确认检查器标红且不能运行；
  用「清除变量」清掉一个只在步骤里写过的局部变量，确认之后再读它报未定义；清掉声明过的局部变量，确认它回到
  该类型的空值；清掉一个全局变量，确认回到声明初值；跑一个
  每轮写新名字的循环，确认日志只提醒一次变量表变大，值没有丢。
- **日期类型**：把一个全局变量声明为 `date`，默认值写 `2026-11-13`，保存后确认预览不带时间；在条件里用取值窗口搭出 `日期 < today()`，确认按时间比较而不是按字面；把 `sort([today(), parseDate("2020-01-01", "yyyy-MM-dd")])`
  放进一个值格里，确认第一项是 2020-01-01；勾上持久化，重启后确认它仍是日期（预览不变成一长串文本）。
- **类型词汇与包 31**：保存一个带整数、文本、布尔、日期、图片结果的宏，用文本编辑器打开 `.wgmacro`，确认
  `type` 写成 `Number` / `Text` / `Bool` / `Date` / `Image`；打开一个 30 的包，确认被拒并给出 31 的提示；
  在变量中心的下拉里确认没有「颜色」，日期与图片可选。
- **声明默认值形状化**：在宏接口里给一个参数用取值窗口写入 `数量 + 1`（引用 + 算式），保存再打开，确认
  仍是同一形状、文件里 `default` 是带 `op` 的对象而不是一行带 `$` 的字；在局部变量管理器里用取值窗口给
  初值写入一段夹着变量名的文字，保存往返后确认名字仍是名字、文字仍是文字；两个输入框都只读，唯一入口是
  「取值」按钮；`whalegenie_get_macro_signature` 的 `defaultShape` 与文件里的形状一致。
- **等号与文本**：在条件里写 `1 == "1.0"`、`today() == 今天`（用日期字面量），确认都成立；写
  `"1" == "1.0"`，确认不成立；把 `unique([1, "1", "1.0"])` 放进值格里，确认只剩一项。

  写 `2026-11-12.csv`，确认不被当成日期。
- **循环绑定**：声明一个局部 `i` 初值 7，再写一个计数器为 `i` 的循环体，运行后确认 `i` 回到 7；在循环内
  读 `sys.loopIndex` 正常，在循环外读它，确认那一步报 `Run.BadExpression`。
- **压缩包的两个层次**：打一个含文件的 `photos` 目录，两种设置各打一次并解压：不带上得到里面的文件，
  带上得到 `photos/` 目录；对同一个目标再打第二次，确认替换而不是失败。
- **透明色与不同底色**：同一张小图标分别放在两种底色上截两次图，用其中一张当参考图，确认「自动识别
  透明色」开着时在另一张上仍找得到；把这一档关掉、再把那张图的底色写进「透明色」，确认同样找得到；

  容差、另一行留空，确认那一行按自己的容差认、留空那行按「容差 %」认。

  写一个用户变量后新开一个 `cmd` 读到它，并确认已经开着的 `cmd` 读不到。

## 自动化能验到哪一步（2026-11 实测边界）

清单里的一部分可以脚本化，不必每次交给人工；剩下的必须由使用者在目标机器上过一遍。这个边界已按
本机实测确认过一次，方法留在这里，日期性结果写在对应提交信息里。

**可脚本验证**（在 Debug 构建上，WebView2 暴露 CDP 端口 9223）：

- **壳的生命周期**：启动后的窗口尺寸/位置、`WM_CLOSE` 后隐藏而进程仍在、第二次启动时第一个进程的
  窗口被唤回且第二个进程退出。
- **浮层的窗口状态与相对顺序**：先让一个置顶程序（或用 `SetWindowPos` 把记事本置顶）在前，再启动
  `--wheel-overlay`/`--menu-overlay`；枚举窗口读 `GWL_EXSTYLE`（topmost 0x8、hit-transparent 0x20、
  no-activate 0x08000000、tool-window 0x80）与 Z 序，确认浮层压在置顶程序之上。
- **拾取器与浮层的进入/退出**：从页面发桥命令（`editor.actionWindowPick`、`editor.actionPick` 的
  point/region/drag/color/element 模式、`editor.session`/`editor.actionOpen` 打开表单）→ 枚举出新的
  置顶覆盖窗口 → 发 `WM_KEYDOWN Esc` 与 `WM_CLOSE` → 读桥回复确认取消。桥调用走页面里的
  `window.invokeCSharpAction`，应答从 `window.__whale.onMessage` 回来（C# 传的是对象，不是字符串）。

**只能人工验证**（脚本不能替代判断）：

- DPI 125/150/200% 与多屏（含负坐标）：需要改系统缩放或接显示器；单屏 100% 只能验到“能用”。
- 像素级读数与命中：取色/取点的颜色是否真取自屏幕、框选是否对齐、UIA 描边是否框准——脚本只能验
  窗口进出，不能验读数对不对。
- 偏差点选（`LookPickWindow`）：要有一次真实运行留下的取景图才能进入。
- 界面面板：需要一个配好界面宏的项目与目标程序。
- 独占全屏游戏、UAC 提权、屏幕锁定、托盘菜单退出与真实手势：注入的事件被设计性忽略（`e.Injected`），
  脚本不能触发轮盘手势，只能用真实鼠标键盘。
