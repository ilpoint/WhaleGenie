# 用 MCP 写宏

所属：[WhaleGenie 使用说明](../manual.md)。

## 用 MCP 让 AI 帮助写宏

主界面「运行调试」按钮左边有一枚 **MCP** 按钮，点开是一个浮层：上面两个权限开关，下面一段**客户端配置**。
鲸灵开着的时候，AI 改的就是你**屏幕上这份**项目——没保存的改动它也看得见，它存盘就是存你手上这个文件；
鲸灵没开时它才会另起一份，读的是你上次打开的那个包。
MCP 由客户端启动鲸灵、用标准输入输出与它对话，所以没有端口、没有地址可填——把那段配置粘进客户端的
`mcpServers` 里，由客户端来启动这个程序。配置里只有 `--mcp` 一个参数，粘一次就够；权限在开关上，不在配置里。启动后，外部 AI 客户端（Claude Desktop、Copilot 等）可以读动作目录、读当前项目、写宏、
检查、apply 和保存。动作目录会给出参数名、记录内部字段名、数字单位和
取值范围，也会标出隐藏动作和每个子步骤列表接受的 `childKeys`，所以 Case 该放在哪个分支、哪些动作不能放在
顶层都由目录说明，不必靠猜；动作列表会一并说明一共多少个、这一页之后还有没有，所以 AI 不会只看到前十来个
就以为目录只有这些。哪些字段只是「某个模式下才必填」（例如后台点击才需要窗口规则）也写在目录里。
目录还会标出**做下去无法撤回**的动作（删文件、删文件夹），以及哪一格里的哪个取值让它变成这样（关机的
睡眠、重启、关机），所以 AI 在放入这类步骤时就能先说明白，而不是等运行时报 `Run.NotConfirmed`。
**AI 可以自己跑一条宏**，但要在浮层里授权（下面说）：它跑的是草稿里的那份（`apply` 之前就能试），
跑完把每一步算出了什么交回来，所以它能先试再交给你。一次只跑一条，第二条会被拒；有时间上限，也能停。
跑得久的宏可以让它"先开跑、不等结果"（`wait=false`）：立刻拿到运行编号，之后用 `run_status` 看进度、
`stop_macro` 停，不用把一次调用挂在那里等。

客户端连着的时候，AI 还能**看**这台机器：截图（整块桌面或指定窗口）、某个像素的颜色、指针位置、打开的
窗口列表（带程序名与窗口类）、某一个窗口的详情、某个位置上是什么控件（连同它此刻的值、能不能用，以及可复用的
selector）、按 selector 找到的一组控件、正在运行的程序。调试不再靠你把截图和日志来回传。

要 AI 也能**动手**——移动鼠标、点击、滚轮、拖拽、按键或组合键、打字、激活 / 移动 / 关闭窗口、读与写剪贴板，
以及把草稿写进项目、存盘、存一张图片——打开 **允许直接控制**。读剪贴板也在这档里：那上面是刚复制的东西，
可能是密码。改完不用重开客户端，也不用重新复制配置：
服务每次调用前都会重读这个开关，下一次调用就按新的来。按键、点击和窗口操作一次只发一件，两个客户端也不会
把一次组合键交错成别人没想发送的输入。

要 AI 也能**运行宏**（自己试行、读回每一步的结果），打开 **允许 AI 运行宏**。它和「允许直接控制」是两件事：
点一下和跑一条会写文件、起进程的宏，不是同一个请求；两个都不开就是只读。

- 程序**不监听任何端口**：它只在客户端给的那条管道上说话，别的程序连不上，也没有令牌要管。
- **授权存在设置里，随时改、随时生效**：开关一翻就写进 `settings.json`，服务端每次调用前读一遍，所以
  不用重启鲸灵，也不用让客户端重连。关掉开关，下一次调用就会被拒。看屏幕、窗口和控件不需要授权；发键鼠与
  写项目要开第一档，跑宏要开第二档。
- 跑一条宏时一次只跑一条，有总时长上限，也能让 AI 停。跑出来的结果和你在调试窗口里看到的是同一份，进运行日志。
- 让 AI 写「调用另一个宏」的步骤时，形参名与结果名来自**被调用宏的声明**，动作目录里查不到；客户端用
  `whalegenie_get_macro_signature` 就能读到它收什么、交回什么，还能拿到一段可直接用的调用骨架
  （`arguments` 行列表里一行一个形参，列是 `name` / `value` / `given`；`returns` 行列表的列是 `key` / `name`）。
- 草稿是**内存里的一张副本**：`apply` 之前什么都不写进项目。一次会话最多留 8 张：满了会先丢掉已经
  `apply` 过的最旧一张（回答里会说明丢了哪张），一张都没 `apply` 时会直接拒绝新的，让你先丢一张。AI 能列出还没落地的草稿
  （`whalegenie_list_drafts`，也就是「草稿箱」），也能在动手之前先问一句「这一改会动什么」
  （`whalegenie_preview_apply`）：哪些宏会新增、删除、修改，修改的那几个是哪一步、哪个参数变了，
  哪些全局变量会跟着动。看过再 `apply`，比事后再回滚便宜。
- 参数形状写错时（例如把宏当成一段字符串发过来），回答里给的是 `BadJson` 与那句话该怎么说，而不是
  「调用失败」——目录里声明的 `"type": "object"` 不变，所以客户端读到的约定仍然是严格的。
- 目录、项目与宏都能作为 MCP **资源**读：`whalegenie://actions`（全部动作）、`whalegenie://actions/{key}`
  （一个动作）、`whalegenie://project`（打开的项目：版本号、每个宏的步数与参数、全局变量、触发器）、
  `whalegenie://macros/{name}`（一个宏的每一步：标识、动作、位置）。能缓存资源的客户端读一次就留着，不必
  每一轮重新问。项目页带着**版本号**：同一个号下内容不变，号变了才需要重读。宏页不含每一步的参数——那是
  `get_step` 与 `get_macro` 的事，把参数放上去等于把整条宏搬上去，缓存就白省了。
- AI 对这台机器做过什么可以查：浮层里的「查看调用记录」打开当天的 `logs/mcp-<日期>.log`，一行一次调用——
  改了什么、向机器发过什么、看了哪块屏幕、结果如何。打字只记字数，不记内容。只有改了东西、动了机器、或者
  拿走一整张图的调用才记，翻目录这类只读调用不记。
- `window_activate` 的回答分两个字段：`requested` 是"请求发出去没有"，`activated` 是"窗口真的到前面了没有"——
  Windows 可以拒绝把窗口提到前台却仍然报告调用成功，只看前者会让下一步点到别人的窗口里。按键发给当前焦点
  窗口，所以打字之前要先把目标窗口提到前面，而不是假设它就在那儿。
- 窗口移动不必带尺寸：`window_move` 只给位置就保持原来的大小，给宽高才是改大小。
- 子宏可以直接按名字调用：同一个宏里的子宏用它的名字（`control.runMacro` 的「宏」），重名时用
  `父宏/子宏` 这种写法，两种都认。
- 用浮层里的「复制客户端配置」得到一段 JSON，粘进客户端的 `mcpServers`，再重开一次客户端；之后改开关
  都不必再动这段配置。
- 这是标准的 **stdio** 传输：客户端支持 MCP 就能接，不需要它支持 HTTP 或 SSE。
- 客户端如果支持 MCP prompts，会看到两条默认提示词：`whalegenie_write_macro`（怎么写宏）与
  `whalegenie_debug_macro`（怎么读日志 Debug）。客户端不显示 prompts 时，可以调用
  `whalegenie_instructions`（`topic` 写 `write` 或 `debug`）取同一份提示；也可以用服务说明。
- **最小化或关闭主窗口只是静默收进通知区域**，不弹提示，程序仍在后台保持触发器；要真正结束程序，用
  「文件 → 退出鲸灵」或通知区域图标菜单里的「退出」。MCP 那个进程是客户端起的，客户端退出或关掉管道，
  它就自己结束，不会留下来。

**没有包路径的空项目**：第一次打开开关时，鲸灵会先问要不要给项目一个 `.wgmacro` 路径：

- 「选择保存位置」：先走「另存为」，保存成功后才启动 MCP；以后 `save_project` 直接写这个包。
- 「先打开」：MCP 先启动，AI 可以写草稿、校验、`apply`；但 `save_project` 会提示项目还没有路径。你在鲸灵里
  保存一次之后，不重启 MCP 也能继续让 AI 保存。
- 取消：MCP 保持关闭。

典型流程：

1. 打开 MCP 开关；空项目按上面的提示选保存位置，或先打开稍后保存。
2. 复制配置，让客户端连接；客户端里可以用默认提示词起头。
3. 让 AI 读动作、打开项目、读一个宏；修改后的宏先放在草稿里，`apply` 后才出现在主界面，`save_project` 才写包。
   写完后先调 `whalegenie_validate`；它会按 `hidden` / `childKeys` 检查嵌套位置，例如 Case 不能离开多分支，
   每条问题都指明是哪个宏、哪一步（步骤标识），所以 AI 能直接改那一行。
4. 改已有的宏时，AI 不必把整段宏重发：它可以只改某一步的一个参数、改一张表里的一行、插入或删掉一步。
   表指的是「这一步的实参」「要带回的结果」「要找的几块区域」这类一行一项的参数，改一行只发那一行。
   子宏里的步骤也能改：补丁上带 `macro: "sub:<名字>"` 就作用在那个子宏里，`outline` 的每一行会说是哪个
   宏里的步骤。
   同一条补丁还能改**步骤自己的设置**（注释、跳过、超时、重试与退避、前后延时、失败后怎么办）、**宏自己的
   设置**（描述、名字、触发方式、循环、计划、监视路径、进程名、空闲秒数、延时倍率、窗口目标）和**宏的形参与
   结果声明**（增、改、删、调顺序）。这些以前只能整宏重发，一重发就会把没提到的设置冲回默认值。
   这类改动是整批生效或整批不生效——有一条放错位置就一步都不写，不会留下改了一半的宏。AI 写进来的步骤也会带
   四字符标识，和你在编辑器里加的步骤一样，运行调试里对得上号。要改之前它可以用 `whalegenie_get_step`（草稿、
   宏名、步骤标识）只读这一步的完整参数与它自己的校验问题，不必把整段宏读回来；`list_macros` 与
   `get_actions` 一样带 `offset` / `limit` / `hasMore`，宏多的项目分页读。
5. 校验说「阻断」的问题会让 `apply` 拒绝写入；AI 改完再 apply，除非它明确带 `force`。校验里的「提示」不拦
   apply，只是值得看。
6. 你点运行调试或在触发器里运行；失败时让 AI 用运行日志分析：
   - `whalegenie_list_runs`：最近几次运行；
   - `whalegenie_get_run_log`：某一次运行的日志、**每一步算出了什么**（结果名、值、宏有没有留下它），
     以及失败日志路径；默认给**最后** 500 行（出错的行
     在末尾），`tail` 可以改，回答里的 `fromLine` 说从第几行开始、`truncated` 说前面还有没有；
   - `whalegenie_read_picture`：把宏自己截下的 PNG 读回来（只认项目目录与日志目录里的文件），
     让 AI 能看着图判断，而不是只凭坐标猜。
   - `whalegenie_get_last_failure_log`：最近一份失败日志。只认失败运行写下的 `failure-*.log`，不会把服务器
     自己的调用记录当成失败；也可以把上一次回答里的 `failureLogPath` 传进去读那一份。
7. AI 根据日志改草稿，再 `apply`、`save_project`。保存前鲸灵会把旧包复制一份，放在
   `%APPDATA%\WhaleGenie\projects\<宏包名>-<路径哈希>\last.wgmacro.bak`。
8. 打开「允许 AI 运行宏」之后，AI 可以自己跑一遍：`whalegenie_run_macro`（带草稿 id 就跑草稿那份）会交回
   每一步的状态与它算出的值，`whalegenie_run_status` 说现在在跑什么，`whalegenie_stop_macro` 让它停。
   这样它在交给你之前就能对着答案改，而不是把没试过的宏交上来。

注意：

- AI 收到的失败是一段带**代号**的说明（英文，例如 `UnknownAction`、`RevisionConflict`、`DirectControlOff`），
  后面跟着一句「下一步该做什么」。那是给它自己改的，不是给你看的报错。
- 草稿基于打开时的项目版本；期间你在界面里改了项目，`apply` 会被拒绝，要求重新打开，避免覆盖你的修改。
- 全局变量也能先读后写：`whalegenie_get_globals` 交回的声明形状与 `set_globals` 收的一样，AI 不必在没看过
  原表的情况下整表替换。
- MCP 只读写当前项目与当前包，不读任意文件、不执行命令。它能跑宏（要开第二档开关），但跑的是项目里或草稿里
  已有的宏，不是它临时拼的一段代码；脚本步骤只有在你或它跑那条宏时才被执行。读图片只认项目目录与日志目录。
- 已有图片的宏可以读写，但第一版不通过 MCP 新增图片；不要把宏里的图片路径改掉。
- 运行日志可能包含窗口标题、路径等；只在 MCP 打开时通过工具返回。
