# 运行与调试

所属：[WhaleGenie 使用说明](../manual.md)。

## 运行与调试

宏卡片右上角有一枚**「运行调试」**（右键菜单里也有同一项）：它打开运行与调试窗口，把那个宏的步骤装进
去、**停在第一步之前**——什么时候跑由窗口里的「运行」/「单步」说。窗口一次只开一个，再对另一个宏点它
（或右键另一个宏）就是停下正在跑的那个、换成它的步骤重新装载；上一个为什么停了写在这次运行日志的第一
行。编辑器右下「宏设置」底部有一枚**「运行调试」**：把当前文档页手里的步骤装进窗口并停在那儿，不用先保存；
还没有写步骤时它按不动；再按一次只换成一扇装着当前步骤的窗口，不会越按越多。主窗口标题栏的「运行调试」
按钮打开的是同一个窗口，只是不带步骤：没有装宏的时候运行控制不画，页面上给一个**「装哪个宏」**下拉和
**「载入这个宏」**，选一个按下去就把它装上、停着——与卡片走的是同一条路。

运行与调试窗口与主窗口是两扇独立的窗口：主窗口最小化或关闭只是收进通知区域，这一扇留在屏幕上，正在跑的那次
照旧看得见。它自己最小化到任务栏以后，再按主窗口标题栏的「运行调试」或卡片上的同一项，还原回来的是同一扇窗口，
不会另开一扇，也不会因为找不到窗口而按不动。

装进来的宏如果声明了形参，调试页上方会多一段**「形参」**：一行一个，写清类型、必填还是默认值，可以填值，也可以
勾「传空值」传一个空串。必填的格子没有值也没有勾空值时，「运行」和「单步」按不动；可选形参留空就用声明的默认值。
这一段只在运行调试窗口里有；由卡片开关或触发器直接跑一个宏时没有地方填，默认值照用，必填缺失会在第一步之前失败，
失败原因写进运行日志与失败日志文件。

**放不回原样的一步会先问一句**：删除文件或文件夹、注销、睡眠、重启、关机这类步骤，运行到它之前会停下来问一次；锁屏、关显示器、取消关机不算。答「取消」就是这一步按自己的「失败时」处理，失败键是 `Run.NotConfirmed`。一次运行里同一步只问一次，循环里重复二十遍也一样问一次。由触发器跑起来、或者通过 MCP 调用时没有人在场，这类步骤直接按「没有确认」失败，不会自己往下做。

窗口分「调试」与「变量」两页。**调试**：步骤列表、每一步最后看到的画面缩略图（点开就是识别结果窗口；读剪贴板图片那一步的缩略图
就是它取到的那张图，点开是整图）、
每一步跑出来的东西（见下），以及日志。**变量**：本宏 / 全局 / 系统三个页签；全局页只读显示定义、当前值、
默认值、说明和持久化状态，定义的新建与修改回到宏编辑器的变量中心。系统变量的当前值实时读出来且只读，
"在用"那一页列出整个宏列表用到了哪些变量。运行与「试找一下」还会把正在读的那个窗口在屏幕上框出来，
读到哪一步框就落在哪个窗口上。

**看得见的都能带走**：每一步算出的结果、日志、变量值都写在可以选中的控件里，选中就能复制；日志那一栏
与每一条变量旁边另各有一枚**「复制」**——日志那一枚放走的是整份日志（时刻带文字一行一条），变量那几枚
放走的是它自己那一行的值，按了哪一行带走的就哪一行。

**运行失败会自己留下一份日志**：一次运行以失败收场时，这一整段运行日志会写成一份文字文件，放在程序所在
目录的 `logs` 里，文件名形如 `failure-订单导出-20251016-210311.log`：开头一行写着这是哪个宏、什么时候失
败的，往下是这一整段日志的每一行——每行先是时刻、再是文字，行首的空格表示它落在第几层块里，文字与运行调
试窗口里看到的一样（触发器起的运行没有那一扇窗口，这一份就是它唯一的记录）。编码是 UTF-8 带 BOM，双击就
能打开；运行调试窗口里的日志最后会多一条「已把运行日志存到 …」，把文件的全路径写在那里。宏顺利跑完、或者
是你自己按下的「停止」，都不写文件。

全局钩子、触发器计时器和进程级未处理异常另写 `logs/runtime.log`。同一种后台故障在 10 秒内只留一条，文件超过
2 MB 时把上一条改名为 `runtime.log.1`。它记录线程、阶段和完整异常栈，用来排查没有运行调试窗口的崩溃。

系统变量（`sys.` 开头）**每次读到的是当时的值**，不是运行开始时记下的那一份：循环里读两次
`$sys.mouseX` 是两个位置，等一分钟再读 `$sys.time` 是新的时间，`$sys.clipboard` 读的是这一刻的剪贴板。
其中 `sys.macroName` 是正在跑的宏的名字（调用了别的宏，那个宏里读到的是它自己的名字），
`sys.macroFolder` 是写相对路径时算起的那个文件夹，`sys.activeWindow` 与 `sys.activeProcess` 是此刻在最
前面的窗口的标题与程序名。上面那个变量页显示的也是同一个值：它读的就是宏会读到的东西。

**循环的轮次与结束原因**：`sys.loopIndex` 只表示当前最内层循环跑到第几轮（从 0 数起）；离开内层循环后
恢复成外层的轮次，离开所有循环后读到空。设计期在循环体外引用它时，编辑器会在那一步上标出来。
「遍历」的「每一项放进」与「轮数放进」、「计数循环」的计数器也一样只属于最内层循环：内层用了同一个名字时，
离开内层会把外层的值放回去；设计期对同名嵌套循环标一条。循环结束后这些名字留着最后一项 / 最后一个数，
读得到。「重复」「遍历」「计数循环」「当…时循环」的「基础设置」末尾都可勾「结束原因」（`ended`）：正常走完
分别得到 `count` / `items` / `range`（「当…时循环」是 `condition`），到达「最大轮数」时得到 `limit`，
这时运行日志另有一行警告；用 `break` 提前离开时一律得到 `break`。「重复」「遍历」「计数循环」「当…时循环」
的「基础设置」里各有一块「节奏」：间隔的单位是毫秒，默认 0，表示两轮之间不等；「遍历」的倒序也在
「基础设置」里，与它要过的那串东西同一块。「等待直到」的查看间隔同样在基础设置里。

**多分支里的 break**：case（与 otherwise）里写 `break` 离开的是这个多分支，接着执行多分支后面的步骤，
不会跳出外面那层循环；`continue` 不属于多分支，仍交给最近的循环。多分支外面既没有循环也没有多分支时，
`break` 才是错的（`Run.BreakOutsideLoop`）。
**条件里的比较**：`if`、当…时循环、等待直到、断点条件用的是同一张词表，一行就是一句比较。数字族是
等于 / 不等于 / 大于 / 小于 / 不小于 / 不大于；文本族是包含 / 不包含 / 开头是 / 结尾是 / 匹配正则 /
为空 / 不为空；列表族另有条目数为；真假族是成立 / 不成立。每个词对应一种写法：包含写成
`contains($a, x)`，为空写成 `length($a) == 0`，条目数为写成 `count($list) == 3`，所以宏文件里仍是
普通表达式，手写、多分支、`compare()` 看到的都是同一件事。文本与列表共用「包含」：`contains()` 本来
就同时认一段文字和列表里的一项。多分支的比对方式取自同一张表，少的是「为空」与「条目数为」——分支值
本身就是右值，空值那件事由「其他情况」回答。行表顶上那一格决定几行怎么合起来：**全部成立 / 任一成立 /
全都不成立**，第三档写成 `not (a or b)`；`not (a and b)` 是另一个意思，因此只认前一种写法。

**断点与暂停**：点步骤左边的圆点就是下断点，再点一下取消，点完那一点立刻变红。**断点的三件事都在那一步
的右键菜单里**：下断点 / 取消断点（标题跟着当前状态变）、设置断点条件…、清除条件（有条件的行才有）；右键
圆点与右键那一行是同一份菜单——圆点只有 16 像素宽，菜单挂在它上面大多数人找不到。跑到带断点的步骤前会
停下来等「继续」；断点还可以带一个**条件**（「设置断点条件…」，条件写在弹出的表单里，和 `if`、`waitUntil`
用的是同一套条件）：条件成立才停，不成立就直接跑过去——循环里的某一步只有跑到第几轮才会停下来时用它。
条件算不出结果时（例如它读的变量那一刻还没有值）会照停，并在日志里写清是为什么。「清除条件」只去掉条件，
断点还留着，回到每次到这儿都停。停在断点上时，工具栏上那枚**「跳过这一步（这一次）」**按下去就是：这一步
不执行、也来不及有副作用，运行直接接着下一步走，行上写的是"未执行"；没停住时它按不动。
条件那一行没有圆点：条件是被它所属的那一步问的，不是自己跑的一步，要停在问之前，把断点下在那一步上。

**窗口里的按键与按钮**：工具栏上是「运行 / 单步 / 继续 / 停止」四枚；停在断点上时旁边多一枚**「跳过这一
步（这一次）」**，它只在停住时按得动。键盘上 **F5** 管运行与继续（停着就是接着跑，没跑就
从头跑）、**F10** 是单步、**Shift+F5** 是停止，每枚按钮的悬浮提示里写着它对应哪个键。单步说的是"做下一
步、做完再停住"：第一次按下停在第一步之前，之后每按一次做一步。

**每一步跑出来什么**：运行调试里每一步的行会把这一次的结果写出来 —— 怎么结束的（完成 / 失败 / 未执行）、
花了多少毫秒、失败的话为什么失败，以及**这一步真正算出的每一个结果**：勾了结果的行用宏里的变量名，没勾的
行用鲸灵自己的名字（例如 `encoded`、`match`），两者都读得到值，所以想看一眼某个返回值不必先回去勾上再跑
一遍。勾选只决定"要不要成为变量"，不决定"看不看得见"。

**宏自己问人**：「询问使用者」与「询问文字」这两步会让宏停下来等人：前者问一句话、交回真假，后者要一行
文字、交回文本。编辑器里跑的时候，问题出现在步骤列表下面那一条上；触发器发起的运行没有运行调试窗口，问题
由主窗口弹出来问。答到一半被「停止」按下，按"没有回答"收场——「询问使用者」交回假、「询问文字」交回空，
这一步仍然算完成，宏自己按交回来的东西决定下一步。问多久会一直等下去：宏停在那里，屏幕上就是那个问题。
交给引擎但不接界面的运行（例如自动化测试直接调引擎）也按"没有回答"走，不会挂住。

**这一步自己判失败**：「判为失败」（`control.fail`）把这一步记成失败，交给这一步设置里的重试与失败
策略，和你按下「停止整个宏」是两回事——判失败说的是"这一步没做成"，宏里写着的失败策略照常起作用。
失败键可以留空，此时仍报 `Run.StepFailedByMacro`；填写时必须写成 `User.` 加一个能读回来的变量名，
例如 `User.NoScreen`，捕获条件就可以按 `caught.key` 分别处理。原因可以不填；填了会写进日志，并作为
失败详情交给上层（`control.try` 的 `detail`）。反过来，
「说明」（`control.note`）只是写在宏中间给人看的一行字：运行时不做事、不写日志，里面的名字片
也不替换，宏长起来以后靠它分段。

**两条宏一起跑**：两个宏同时发键鼠时，按键会写进对方中间——收到输入的那个窗口看到的是两条宏的按键交错在
一起。默认就是这样：键鼠互斥不是程序的开关，**只有写进「独占输入」（`control.holdInput`）块的那一段**
才会占着门，别的宏的键鼠步骤在门口等它，一次放一步、发完就让出。要让两步之间也不被打断，把它们写进同一个
块；块与块之间没有人在排队，另一条宏仍能插进来。哪些步骤算发键鼠由动作目录声明：键鼠动作、点图 / 点字 /
点检测、UIA 点击、后台输入，以及设了「脚本会发键鼠」的脚本步骤，沿「执行子宏」调到的步骤也看进去；子宏
跟着这一次运行走。读屏幕、识别与等窗口不参与排队，两个宏可以同时看同一个窗口。有人在门里时，运行调试里
看得见现在是谁在发输入。

**每宏限速**：编辑器「专属设置」里的**输入限制**只属于这个宏的**一次运行**：它按那个速率拉开自己发出的事件，
程序设置里的限制对它不再叠加。被「执行子宏」调到的宏沿用调用方的限制；子宏自己那一格，只在它被单独运行时
生效。这跟运行速度（倍率）是同一条规则：运行带的是启动它的那个宏的答案。

**共享变量、浏览器与脚本**：全局变量由所有宏共用，值在鲸灵运行期间一直保留，关掉程序才回到声明里的默认值，
不写进项目文件。两条宏先后写同一个名字时，以最后写的那一次为准：普通两步「读出来、加一、写回去」在同一
时刻跑两次可能丢掉一次；要累计就写「增加全局变量」，它把读取与写回合成一步，加完的数从返回值里交出来，后续条件与步骤
直接用，不必再读一次。两条宏同时往同一个全局列表里追加、插入、改写或移除时，每一次操作都是整步做完的，
谁也不丢项。子宏与调用它的宏看到同一份全局值，局部变量仍各自独立。

浏览器整个程序只有一份，当前标签页也只有一份：每个浏览器步骤都排一条自己的队，另一条宏正在读页面或切页
时这一步会等，等到了再整步做完。**输入门与浏览器门是两道门**：谁占着输入门不影响浏览器步骤，反过来也一样，
两条宏可以一条在打字、另一条在读页面。运行调试里除了「正在发输入」，也会写出现在是谁在用浏览器。

脚本在别的进程里跑，可以直接发键鼠，鲸灵看不见这些输入，也拦不住它们；脚本动作里的「脚本会发键鼠」只是
声明，编辑器据此在写宏时提醒。「独占输入」块管得住块里的步骤，管不住脚本在别的进程里自己发出的按键：两条
都会发输入的宏同时跑时，让它们不要同时跑，或把发输入的部分写成普通步骤放进块里。

**按键触发可以是组合键**：触发页里点「设置按键」以后，按一个键就是那个键；按住 Ctrl、Shift、Alt、Win 中的一个
或几个，再按最后一个键，绑定的就是一个组合键（例如 `Ctrl+Shift+S`）。运行时前面的修饰键都按着、最后那个键
按下的那一刻才算数；组合里的 Ctrl 左右不分，单独一个修饰键仍然分左右（`左Ctrl` 与 `右Ctrl` 是两个绑定）。
鼠标按键与滚轮各自是一个绑定，不跟修饰键配成组合。

**等人按一个键**：「等待按键」（`input.waitKey`）停在原地，直到有人按下或松开一个键；键名留空就等下一个
按下的键。等多久由这一步的「超时」说，默认 10 分钟；超时报 `Run.Timeout`。「拦下这个键」为真时，结束等待的
那个键不交给前面的程序（其余按键照常），适合“按 F8 继续”又不让 F8 打进正在写的文档。它交回结束等待的键名，
以及这个键是不是程序发的（`injected`）；它在钩子线程上收键，不参与输入互斥的排队。

**手柄按键也能当绑定**：触发页点「设置按键」以后，按一下手柄上的键就是那个绑定，名字写成 `Pad A`、
`Pad LB` 这样（与鼠标按键写成 `Mouse Left` 是同一个做法，动作参数里仍旧写 `a`、`lb`）。手柄不像键盘那样
会主动说按了什么，鲸灵是每隔 30 毫秒读一次：按下的那一刻起一次，松开算松开，所以「按住才跑」「再按一次
停」「松开才跑」这三档与绑键盘时一样。左扳机与右扳机是量出来的，越过三成行程就算按下；手柄上的 Guide
键 Windows 留给自己，绑不了。手柄按键各自是一个绑定，不跟修饰键配成组合（和鼠标按键一样）。

**手柄没插上会怎样**：读不到手柄就是「什么都没按着」——绑着手柄的宏永远不会被它触发，而正按着的时候拔掉
等于松手，用它启动的「按住才跑」的宏随之停下。手柄插回来按一下，照旧起一次。

**开着的宏在等什么**：运行调试里有一段「等触发的宏」，凡是用定时去看的那几种触发器（颜色、程序、窗口、
计时）各占一行：等的是什么、现在成不成立、上次判定是什么时候、下次什么时候去看它。宏没有在该跑的时候跑起
来，答案几乎都在这一段里，不必靠猜。窗口这一类另有一句「窗口有变化时机器会先说一声」：机器听见窗口出现、
消失或改名就立刻看一遍，所以只亮一下就关掉的窗口也认得到；那 500 毫秒一轮是机器不肯说时的退路。
窗口触发器认窗口用的是和别处同一对「匹配内容」与「匹配方式」，标题会变就用进程名或正则认；宏的触发页里
「匹配内容」下面同样列着这一步现在会认到的窗口，改一格就重读一遍。
