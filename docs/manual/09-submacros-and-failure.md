# 子宏、失败接住与独占输入

所属：[WhaleGenie 使用说明](../manual.md)。

## 子宏：一段流程用第二次

一个宏可以说明自己**收什么、交回什么**，别的宏就能像调用一段现成的流程那样用它；这段流程在文件里只
有一份，改一处两处都跟着变。**宏接口**在「宏设置 → 专属设置」页底部编辑：形参与结果各一行，名字、类型、默认值、必填与说明都在这里；调用别的宏时，表单按这里的声明生成。

形参或结果的类型选「记录」时，那一行下面会展开一张**字段表**，一行一个字段的名字与类型。写下来以后：

- 变量墙说得出这条记录里有什么，而不是只说「这是一条记录」；
- 写 `field(记录, "名字")` 时，名字写错**当场**在步骤上标出来，并列出它声明过哪些字段，不用等运行到那一步才失败。

字段表可以不填：不填就是「没说」，与「记录里什么都没有」不是一回事——没说的时候程序不去猜，也就不查。

形参与结果的**顺序**就是调用表单里格子出现的顺序，也是运行调试「形参」段的顺序。每行右上角的 ↑ ↓ 用来调顺序；
第一行没有 ↑、最后一行没有 ↓。新建的形参默认是**必填**：一个可选形参在调用处留空时是静默的空值，而必填会当场
说缺了什么。要可选就取消那一行的「必填」。

名字必须是宏语言读得回来的变量名：首字符是字母、数字或下划线，其余是字母、数字、下划线和点。带空格或连字符的
名字写不进取值窗口，保存时会被拦住；数字开头的名字可以直接挑用。写这个宏的步骤时，形参与结果
还会作为局部变量出现在变量墙和 `$` 建议里；结果是记录时，位置和矩形字段
也会把它当成一条记录来收。

每个形参的**默认值**一行是一格输入框，框里贴着一枚「取值」小片，点它打开取值窗口，变量与函数在同一页上；
挑中的名字插在光标处，写好的公式整段替换这一格。默认值在**调用方**读取，所以取值窗口列的是每个调用方都有的全局变量与系统变量；调用方自己的局部变量在这里枚举不到，但仍可按名字引用。变量墙没有本宏局部变量时会先显示「全部」，不会停在空的「局部变量」页；要只看全局
变量，点「全局变量」那一栏。

**必填和默认值只能留一个**：必填是“调用必须给”，默认值是“调用可以不给、留空就用它”，两个同时填就没有唯一答案。
给可选形参填了默认值以后，调用表单里那一行仍然是空的，行下面会写“默认值 …：留空就用它”；调用处留空就是这一行
不写进宏，运行时才去声明里取默认值，所以以后改默认值，所有没有单独填过这个形参的调用都会跟着变。要传一个
真正的空串（而不是用默认值），勾上那一行右边的「传空值」，这时空格子就是那个空值；必填形参也可以这样显式传空。
默认值按调用处能读到的一个值来读，在取值窗口里挑名字或搭表达式。

「执行子宏」（`control.runMacro`）的表单**按被调用子宏的声明生成**：先选子宏，「基础设置」里就
出现它声明的每一个**形参**，一行一个，值按其他字段的读法读（`n + 1` 传的是数字，一枚列表名字传的是列表
本身）。这一步要取回哪些**结果**在「基础设置」末尾的「返回值」里勾，勾上的每一项在本宏里各自成为一个变量，名字由那一行决定。
实参和要取回的结果写法相同——都是一行一个名字——所以从「这一步给出去什么」到「这一步拿回来什么」，读的是同一种表。

被调用的宏改了名、或者删掉了某个形参时，那一行**不会被删掉**：它留在原位并标出“被调用的宏已经没有这个形参了”，
值也还在。要改的事需要你决定，程序不替你把填过的值丢掉。

填错的名字不会被放过去：传了一个被调用宏没有声明的形参、同一个形参填了两行、要取回一个它没声明交回的名字、
必填形参没有填、或者「传空值」旁边还留着一个值，写宏时就在步骤上标出来；被调用的宏改了声明时，编辑区还会说项目里有多少个调用
已经和它不一致，打开那些宏就能逐个修正。这样的步骤如果还是进了宏文件（手写进去，或者被调用的宏后来改了声明），
运行到它会当场停下并说清是哪一个名字。

被调用的宏用自己的一套变量：它读得到传进去的形参、共享变量与系统变量，读不到调用者的本宏变量；
它留下的东西只有声明过、并且这一步勾了的结果才回得来。调用开始时，声明过的结果先写成空值，所以宏里读一个还没写的
结果是空，而不是“这个变量不存在”；形参和结果可以同名，那表示先收一个值、结束时再把同一个名字交回（in-out），
同名时调用开始时保留传进来的形参值；两处必须声明成同一种类型，否则这个宏在运行前就被
拒绝（`Run.BadDeclaration`）。写在里面的 `break` / `continue` 只作用于它自己
的循环，调用者的循环不受影响。

调用处勾选的结果变量在每一次尝试开始时也会先清空，所以要把一个值既传进去又取回同一个名字，调用处应把实参写成
另一个变量（形参 `n` 那一行填 `source`，结果取回到 `n`），不要用正被清空的 `n` 当实参。

被调用的宏里可以放「结束当前宏」（`control.return`）：它立刻结束这个宏，调用它的那一步照常完成，调用者
接着执行后面的步骤；已经赋过、并且声明为要交回的结果照常交回。写在最外层宏里时，这一次结束等于正常跑完，
后面的步骤不再执行。写在循环、条件或尝试块里也一样结束整个宏，不会只结束当前这一轮；`break` /
`continue` 仍然只作用于本宏的循环，不会跨过调用边界。

要调用一个子宏有两条路：在「子宏」Dock 里把它拖到步骤列表（落下就是一条「执行子宏」，已经指向它），
或者先加一条「执行子宏」，在「子宏」那一格里从下拉里选——那一列列着本项目别的宏与这个宏自己的子宏。
子宏用**它自己的名字**被调用；两个子宏重名时，下拉里给的是「父宏/子宏」这种写法，两种写法运行都认。

公共宏库里的条目是**没有触发方式的可调用宏**，不是项目里的子宏。要调用它，先在动作库的「公共宏」
页把它插入当前文档：它会成为这个宏的子宏，并在根列表留下一条 `执行子宏` 的调用；之后照上面的
方式使用即可。库页只负责管理条目，不直接运行或调用公共宏。

声明由「提为子宏」一次做出来：在动作列表里选中同一层里的若干步骤，按面板上的**提为子宏**，编辑器就建
一个以当前宏的名字命名的新宏（重名自动编号）、把这段步骤搬进去、在原来的位置留下一条指向它的
「执行子宏」。这段步骤**读到的**本宏变量成为新宏的形参，调用处已经按原名填好；这段步骤**写下的**
变量成为新宏的结果，调用处把它们逐个取回同名的变量，所以宏剩下的部分照旧读到原来的名字，什么都不用改。
新宏跟着这个宏一起进项目：保存之后它才出现在列表里，也才成为别的宏调用得到的宏。共享变量与系统变量的
变量两边都读得到，因此不会变成形参。

「执行子宏」（`control.runMacro`）是同步的那一个：它等被调用的子宏跑完再往下走，结果写完就能读；
等多久由这一步的「超时」决定（默认 10 分钟），超时报 `Run.Timeout`。子宏里有慢活时，这个默认值比
“一分钟”更接近实际；要更短或更长，在「其它设置」里改。

同一层里两个调用不要都把结果写进同一个名字：后一个会盖掉前一个，写宏时就标出来。

## 接住失败与重新抛出

「尝试 / 捕获 / 收尾」（`control.try`）先执行「尝试步骤」；尝试失败时执行「捕获步骤」，无论结果如何最后
执行「收尾步骤」。捕获只在尝试失败时发生，收尾总会执行：**从外面停下来时也执行一次**，好让锁、文件与
按住不放的键按宏作者写的那样放回去。整次停止的收尾共用一个五秒的预算，超过预算就结束；收尾没做完时只写
日志（`Log.CleanupFailed`），这次运行仍然是「被停止」、失败原因仍为空——停止不会被一次没收完的收尾改掉。
收尾自己失败、停止、结束宏或跳出循环时，以收尾的结果为准（外部停止时的收尾除外，那里失败只记日志）。

「只在满足条件时捕获」（`catchWhen`）决定这一次失败接不接：进入捕获前，失败键写在 `caught.key`、
详情写在 `caught.detail`，条件就按这两个名字比较（例如 `caught.key == "Run.ElementNotFound"`）。
留空接住所有失败；条件不成立时不接，原来的失败键与详情原样交给上层，收尾步骤照常执行。这两个名字只在
捕获块里有效，离开后恢复成进入前的值；宏原本没有这两个名字时，离开后它们就不存在。

「重新抛出失败」（`control.rethrow`）把当前捕获块接住的失败交给上层，失败键与详情保持不变。它只认当前
这一层捕获块：在捕获块外使用，或者在捕获块里调用一个自己使用 `control.rethrow` 的子宏，都会报
`Run.NothingToRethrow`，不会借用调用者刚接住的失败。需要把失败换成新的原因时，用「判为失败」
（`control.fail`）另写一条。

## 连续发完一段：独占输入

「独占输入」（`control.holdInput`）与「独占浏览器」（`control.holdBrowser`）在一整段里持续占着各自那道门，直到最后一个
子步骤。**键鼠互斥只有这一个来源**：普通发键鼠的步骤不再自己排队，两条宏同时跑时它们会交替发出；把组合键，
或者「点开 → 等页面 → 读表」这样的流程写进这两个块，这一段就是一个回合，别的宏的同类步骤要等它结束。
`browser.dialog` 本来就会独占浏览器，和「独占浏览器」嵌套只记层数，不会自己等自己。同步调用的子宏用同一份
互斥，照常进出；后台运行是另一条运行，不继承这一块，要独占就把它自己那一段也包起来。排队等待的时间算这一步的「超时」。
