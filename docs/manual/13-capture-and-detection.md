# 画面获取与物体检测

所属：[WhaleGenie 使用说明](../manual.md)。

## 画面从哪来、怎么取

看屏幕的步骤（截图 / 截取窗口 / 找图 / 等待图片 / 点击图片 / 取色 / 比色 / 等待颜色 / 找色 /
多点找色 / 点击颜色 / 等画面静止 / 检测物体 / 等待检测到物体 / 点击检测到的物体 / 文字识别 / 找文字 / 点击文字，
以及它们的查询动作）都能说清画面**从哪来、怎么取**，
也能说清它**多久读一次屏幕**。还有一件不属于某一步：**从哪来、怎么取**由程序设置里那两行说了算——

| 设置里的「窗口画面」 | 取到什么 |
| --- | --- |
| 自动（默认） | 先走 Graphics Capture，不行再让窗口自己画，最后退回屏幕像素 |
| 窗口（PrintWindow） | 让窗口自己画一遍，多数窗口都行；取到整窗，含标题栏与边框 |
| Graphics Capture | 取窗口自己显示的内容，被别的窗口压住也取得到；只有内容区、不含标题栏，需要 Windows 10 2004 或更高版本 |

| 设置里的「桌面画面」 | 取到什么 |
| --- | --- |
| 自动（默认） | 先问显卡要它正在往显示器送的那张画面（桌面复制，整屏约 2 毫秒），做不到时按 GDI 复制 |
| 桌面复制（DXGI） | 显卡交出的整块画面，独占全屏的游戏只有它取得到；显示器开着 HDR 或转着用时不行 |
| 桌面（GDI） | 从屏幕里复制，不要求显卡，抓一小块最省，总能取到点什么 |
| Graphics Capture | 按窗口画面那一档的机器读显示器，需要 Windows 10 2004 或更高版本 |

**来源由识别方式决定**：识别方式选屏幕就是桌面，桌面画面那一档；选窗口就是那个窗口（截取窗口用
它自己认出的那个），窗口画面那一档。点了哪一档就只走那一档，这一档失败就报出来
（`Run.NoGraphicsCapture` / `Run.CaptureFailed` / `Run.EmptyRegion`），不换别的路——只有"自动"会
一路退下去。用得上这几条的前提是游戏**没被最小化**：最小化之后窗口自己不再画，窗口那两档都报
`Run.EmptyRegion`。改完设置从下一步看画面起生效。

**「整屏」指的是整块桌面**，不是主显示器：所有显示器合起来的那一块矩形就是宏坐标所在的那个范围，把显示器
摆在主屏左边或上边，它的左上角就是负数。区域那四个数留空量到的边缘、截图不带矩形时的整屏、系统变量
`sys.screenWidth` / `sys.screenHeight`，量的都是这块矩形；三块拾取器（取色、元素、区域）的覆盖层也盖住
整块桌面，副屏上的坐标同样拾得到。**每块显示器在哪**用「列出显示器」（`screen.list`，系统分类）读：交回
一条记录列表 `displays`，一块显示器一条，键是 `left` / `top` / `width` / `height` / `right` / `bottom` /
`primary` / `box`，另有 `x` / `y` 是这块显示器的中心；取其中一块的一项写
`field(get(显示器, 0), "left")`，全部走一遍用 `forEach`。

**Graphics Capture 的会话按窗口、按屏幕各留一份**，不在每次读的时候重新开关。开一个会话要建显示设备与
帧池（第一次 0.4 秒上下），读一次就开关一次比留着慢三倍；而且 Windows 会在正被读的窗口或屏幕
四周画一圈捕获提示边框，会话开着就在、关掉就没——**每次读都开关会话，那圈边框就会一闪一闪**。
读不动（库认不出这个窗口）的窗口记下来，后面不再每次去试。窗口高亮框跟随目标窗口层级，
不把普通目标压到所有窗口之上；目标本身置顶时，高亮框只留在置顶组内。
系统停用时这些会话一并关掉；重新启用后，下一次读屏幕再开一份，停用期间不必占着显卡设备。系统总开关默认是
`Home`，可以在设置里换成别的键或组合键。

Windows 11 上那圈系统边框会被代码关掉（`IsBorderRequired`）；**Windows 10 19045 及更早没有这个接口，
关不掉**——会话一开，那圈黄框就一直在（本机 Windows 10 上实测：屏幕最上面两行是 199,174,7 的黄，没有
会话时一个黄像素都没有）。系统那圈框只说"有东西在读"，说不了"读的是哪一个"：读的是哪个窗口，看我们自己
画的蓝框——添加动作窗口列出来的窗口、运行调试读到哪个窗口，框就落在哪里；**鲸灵自己的窗口不画框**（在那里
写字的那个窗口就在眼前，框上去只是压在它自己的边上），名单照旧把它们列出来。

会话与文字识别模型都来自**程序持有的那一份设备层**：窗口、触发器的运行、试找与调试运行共用它，谁都不在
半路释放，程序退出时才一起放掉——所以同一个窗口第二次读不再重开会话，第二步读文字不再加载一遍模型。设置里
的**「启动时预加载文字识别」**（默认关）就是把模型加载提到启动时做，免得第一步读文字的步骤替它等；
关着时模型在第一次读文字时加载，之后一直留在内存里。

另外两个答案不在步骤里，而在**设置 → 屏幕捕获**里：它们是这台机器的事，同一次运行的每一步共用同一个答案。

- **取帧上限**（范围 1 到显示器刷新率，默认跟随）：这台机器每秒最多取几次画面，所有宏共用，
  同时跑着两个宏时它们轮流取帧，而不是各自按上限取一张。等待类步骤（等待图片、等画面静止、
  点击图片、等待颜色、点击文字、等待检测到物体、点击检测到的物体）就按这个节拍看屏幕。
  调到刷新率以上没有意义：画面没有重新画过，读到的一定还是同一张；调小则等待更晚才发现变化。
- **复用上次的画面**（默认关，保留时长 0–1000 毫秒，默认 100）：打开后，同一个来源（同一个窗口，
  或桌面）刚取过的画面整幅留下，后面的识别直接在这张上裁剪，不再重新取帧——这个“后面”既是同一个
  宏的下一步，也可以是另一个同时跑着的宏。省下的是重复取帧。连续对同一个画面识别好几样东西时最值得
  打开；要看到画面真的变了（例如等某个东西消失）时保持关闭，因为复用的画面最旧可以到保留时长那么旧。

「等待直到」与「等待界面元素」的检查间隔仍叫 `intervalMs`，写在步骤里，默认 200 毫秒；留空同样按屏幕
刷新一次的时间看。这两步等的是条件与界面，不是屏幕上的像素，所以它们的节拍留在步骤里。

「等待界面元素」等到之后，把等到的那个元素按「读取界面元素」同一种记录交回来（勾上它的「元素」结果即可）：
等着一个输入框出现、再看它里面写着什么，是一条步骤而不是两条，读到的也就是让等待结束的那一个。

等待类步骤（等待图片 / 点击图片 / 等待颜色 / 点击颜色 / 等画面静止 / 点击文字 / 等待检测到物体 /
点击检测到的物体 / 等待窗口 / 等待程序 / 等待程序结束 / 等待界面元素 / 点击界面元素 / 按下界面元素 /
等待剪贴板 / 复制 / 等待直到）等多久只写在步骤设置里的**「超时」**一处。计时从第一次尝试开始，
所有尝试**共用**这一份预算，重试之间的等待也算在里面；新建这些动作的步骤时默认 5000 毫秒
（等待直到、等待程序、等待窗口与等待元素是 10000，等待程序结束是 60000，等待剪贴板与复制是 1500），
清空即不限时，等到运行被停为止。到了这个时长，这一步被取消并判失败，交给重试与失败策略；剩余时间
不够再等一次时不再重试。这一步等的是什么就说什么（没等到哪张图 / 哪个颜色 / 哪行字 / 哪个条件），
不只是一句"超时"。查找颜色与找文字只看一次，没有等待，等某个画面条件成立用 `control.waitUntil`，
等一个像素变色用「等待颜色」。

「等画面静止」另有一个**「静止多久」**（`quietMs`，默认 500 毫秒）：它是这个等待的判定条件，不是超时——
画面要连续这么久没有变化才算静止。它成立之前，这一步仍然受自己的「超时」管；两者说的是不同的事。

已经开始、无法中途取消的设备调用（UIA、浏览器、命令与脚本）不会被硬生生打断：它们返回后才判定，
返回时已超过这一步的预算就判失败，运行调试把这次尝试记作“返回时已超限”。

**重试与整块**：每个可执行步骤的“重试次数”在「其它设置」里，一次重试就是同一个步骤再做一遍。
块的重试是**整块重来**：从块的第一条步骤重新开始，已经成功过的子步骤也会再做一遍。运行调试在
每一步下面列出每次尝试的耗时与当时剩余的预算。

一次"查看"是一次取景加一次比对。在 2560×1440 的开发机上实测：整屏走桌面复制约 2 毫秒（每秒约 500 次），
同样整屏走 GDI 约 25 毫秒（每秒约 40 次）、100×100 的小区域约 4 毫秒（每秒约 240 次）、窗口 Graphics Capture 约
10 毫秒（每秒约 100 次）；参考图越大、区域越大，比对那一段越贵。

「试找一下」和运行调试回看的那个窗口，顶部会写上画面取自哪里、用哪种方式取的（桌面 / 窗口，
GDI / PrintWindow / Graphics Capture / 桌面复制（DXGI）），找不着时先看这一行就知道是不是读错了窗口。

桌面复制是整屏最快的一条路（整屏约 2 毫秒，画面没有重新画过时几乎不要钱），代价是每个进程第一次用它要
先建一次显卡设备，约 0.25 秒，一次运行只付一次；它取到的画面里没有鼠标指针，与 GDI 复制屏幕一致。

**读到什么**　读文字的三步（文字识别 / 找文字 / 点击文字）共用一格**「读取内容」**（在「基础设置」
里），说读到的每一段留下什么：**全部文字**照原样留下；**只读数字**、**只留字母**、**只留中文**、
**只留字母与中文**这几档只留下要的那类字符——首尾的空格去掉、中间连续的空格并成一个，一个要的字符
也不剩下的段落就当没读到，全角字母与全角数字按半角算；**按正则提取**时旁边多一格**「提取的正则」**
（在「高级设置」里），把这段正则套在每一段上：匹配不上的段落不算，匹配上的段落只留下括号里的第一组
（正则里没有括号时留下整个匹配），例如 `单号：(\d+)` 会把「单号：88231」只留下 88231，留空表示不
做提取、读到的文字原样留下。这几档让同一步既能把一屏标签读成金额、也能读成货号，还能只留下中文；
随包那一份模型本来就中英文都读，所以「只留中文」是在读出来的结果里挑中文，不是换一份模型。表格模式
读到的同样是这几档过滤之后的段落。

## 用模型找物体（YOLO 检测）

检测物体 / 等待检测到物体 / 点击检测到的物体这三步（`vision.detect` / `vision.waitDetect` /
`vision.clickDetect`）用**你自己带来的 YOLO 模型**在屏幕的一块区域里找它认识的物体。鲸灵不提供、不打包、
也不下载任何模型：模型是一个文件，由这一步的「模型文件」指明。

| 字段 | 是什么 | 什么时候改 |
| --- | --- | --- |
| 模型文件（`model`） | 这一步要跑的 ONNX 模型，必填 | 换一个模型认别的东西，或者换成在自己数据上训出来的模型 |
| 标签文件（`labelFile`） | 一类一行的类名表，第一行是第 0 类 | 要用类名挑类（而不是写类序号）时填上 |
| 要认的类（`labels`） | 一行一个，写类名或类序号 | 只想认其中几类时填上，留空是每一类都算 |
| 检测范围（`region`） | 在哪块画面上找，一行一块 | 只想看屏幕的一部分时填上，留空是整个屏幕 |
| 置信度 %（`confidence`） | 模型的把握要到的线，0–100，默认 25 | 有把握的东西认不出来就调低，老认到不存在的东西就调高 |
| 模型输入尺寸（`inputSize`） | 画面缩放并补边成的正方形边长，默认 640 | 模型是按别的尺寸（320、480、1280）导出的时候改成那个数 |
| 允许重叠 %（`iou`） | 同一类的两个框重叠多少就不留较不把握的那个，0–100，默认 45 | 挤在一起的东西调高，同一个东西被认出两次就调低 |

**模型要哪种导出**：输出得是 `(1, 4+类数, 猜测数)` 这一种，也就是 YOLOv8 / YOLO11 的默认导出。
导出时带目标置信度的旧版（v5 / v7 会答出 `1x25200x85` 这样的形状）与已经做完 NMS 的端到端导出都读不了：
运行时报 `Run.BadModelShape` 并把实际形状写出来。模型第一次跑到这一步时读一次，之后一直留在内存里
（最多同时留 3 个），所以同一个模型用第二次不再付加载的钱。**模型文件不会进宏包**：路径相对时从宏文件夹
算起，所以把模型放在宏旁边、连宏带模型一起搬走也照旧找得到。

标签文件的编码按文件字节判（有 BOM 按 BOM，没有先当 UTF-8 试，试不通按本机代码页），中文类名照写。
「要认的类」里写了标签文件没有的名字时报 `Run.UnknownLabel`，并把标签文件开头几个类名一起报出来，
省得对着文件猜是哪个字写错了。

**三步各做一件事**：检测物体只看一次，没认出来就交一个空值、不判失败；等待检测到物体一直看到认出为止，
等多久由步骤设置里的「超时」说了算（默认 5000 毫秒），到点报 `Run.DetectNotFound`；点击检测到的物体
认出后点在**框中心加上「横向偏移」「纵向偏移」**的位置，还要更稳可以填「落手前再确认」多看一次。

**交出的记录**与找图那几步是同一条：`x`、`y` 是框中心（点击落的就是这里加上偏移），`left`、`top`、
`width`、`height` 与 `box` 是框，`score` 是模型的把握。另外多两项：`class` 是模型给的类序号（从 0 算），
`label` 是标签文件给它的名字（标签文件里没有这一类时为空）。取一项用 `field(变量, "label")`。勾上
「全部命中」时每一处都是一样的记录，顺序由「命中排序」说（阅读顺序 / 分数最高 / 面积最大 / 随机），
「第几个命中」数的就是这一列。

模型一次答出全部框，所以这一步不管自己只取第几个，都先把它们全收下来：「识别结果」窗口里画的是
**模型认出的每一处**（取走的那个单独标出来），不勾「全部命中」也全都画出来；「第几个命中」按这一列数，
与「命中排序」一起决定取走哪一处。

**一次检测要多少时间**取决于模型与机器：本机用 yolov8n（ONNX，640）实测一次 35 毫秒上下（机器上还有
别的活在跑时会飘到 50 毫秒），第一次还要加上加载模型，约 0.14 秒；换成更大的模型（yolo11x 这类）会
明显更久。「查看间隔」留空时等待类步骤每轮都会跑一次模型，所以等待检测的节奏实际上由模型自己的速度快
慢决定，不必再填一个等待时间。
