# 返回值与结果变量

所属：[WhaleGenie 使用说明](../manual.md)。

## 返回值：这一步的结果交给谁

「基础设置」页的末尾是**「返回值」**（不再是单独一个页签：上面少一个页签，读的时候少一个要翻的地方），列的是**这一步运行时能算出来的东西**：找图给的是命中的
位置、大小、相似度，读文件给的是文本或行，截图给的是图片和它盖住的矩形，启动程序给的是程序记录。
**勾上的结果各自成为一个变量**，名字按 `备注_返回值名` 拼（备注框里改一个词，名字跟着改；自己
在名字框里写过的名字就不再跟着动），能在「变量」墙里找到、能在「插入变量」里选到；这个名字已经
被别的步骤用了时，末尾自动补上这一步的步骤标识；手工把名字写成别人的会显示出来，旁边一个「换个
名字」加个编号避开。**没勾的结果不写**，既不出现在变量墙里，也不占内存 —— 读它会被设计期检查
标成"没定义"。一个都不勾是允许的：这一步不留结果，只留下 `step.<步骤标识>.outcome` 这个状态
变量。**要看这一步算出了什么，不必先勾上**：运行调试里每一步的行上会把这**一次真正算出的所有
结果**（勾没勾都在）连同耗时写出来，「没勾的结果」在那里读得到，也标出哪些是宏自己留着的。

**列出来的是用得上的那些**：一步能算出的东西里，「取画面方式」（`method`）与「来源窗口」（`window`）
只说明它怎么拿到画面，宏拿着做不了什么，因此不列在返回值里（引擎照旧算，老宏里勾过的照旧交、
在编辑器里保存也不会丢）。剩下的结果排成一张四列的表：**留下 / 结果 / 结构 / 变量名**，一行一项，列对齐；
勾上的那几行右边写上变量名（没勾的行那一格是灰的）。**「结构」这一列写出它长什么样**：
一个开关是 `true | false`，一段文字是 `"文字"`，一张图是「图片」，一条记录是它的字段骨架
`{x, y, left, top, …}`，一列记录是 `[{x, y, …}, …]`，一张表是 `[{列名: "文字"}, …]`（表的样子是运行时
读出来的：键就是表头那一行，没有表头时是 `A`、`B`、`C`）；骨架只放前四个字段，**悬停看全部字段与类型**
（每个字段就是 `field(变量, "x")` 里要写的那个词）。结构用与字段同级的字号写在单独一列，
不缩成名字下面的小字：缩了就没人看得清，宁可旁边空一点。每一项的完整说明仍是悬停在结果名上；
名字重了的时候，这一行下面才多出一条警告和「换个名字」。

**两种读法各占一项**：读文件（`file.readText`）交「文本」与「行」，文本是整份原文，行是按行切开的列表，
`limit`、去掉空行与去掉两端空格只作用于行；取色（`vision.getPixel`）交「颜色」（`#RRGGBB` 文本）与
「颜色数值」（同一个颜色的整数）；读剪贴板图片交图片、宽度与高度；复制与移动文件交实际落点；截屏与截取
窗口在填了「存到文件」时交保存到的路径；等待窗口交「窗口」记录；启动程序交「程序」记录（`id`、`process`、
`title`、`handle`、`how`；窗口还没出现时 `title` 为空、`handle` 为 0，`how` 说明它是按程序名认的）；
识别文字切到表格时交「表格」。一项一项勾，不再靠一个开关改变另一个结果的形状。

**读剪贴板图片不用先猜有没有**：打开「读剪贴板图片」（`clipboard.readImage`）这一步时，表单里直接摆着
此刻剪贴板上的那张图与它的尺寸；复制了别的就按「刷新」。剪贴板上没有图时写的是一句「剪贴板上还没有
图片」，被别的程序占着时写的是另一句，等一会儿再刷新。这一步没有要填的字段，因为它的全部答案就是
剪贴板上当时是什么。

**一行一条的列表有固定的列**：返回值行是 `key` / `name`，图片行是 `image`，按键序列行是 `keys` /
`holdMs` / `gapMs`，页面限定行是 `how` / `value`，区域行是 `text`，或者 `x` / `y` / `width` / `height`。

按键序列的每一次按键占两行：第一行是这一次的组合；第二行是这一次的「按住」与「间隔」，留空就跟随
整个序列（默认 50 / 120 毫秒），只有某一次的节拍和别处不同才填。点某一行的「设置组合键」后，依次按下
这一拍的每一个键，每按一次就加进**同一格**（例如 `3+4+5`，要同时按住的键就一起按）；按钮变成
「停止捕获」，再点一次这个按钮或者按 Esc 结束。序列里的组合字段本身就是虚拟键盘按钮，仍然可以一键一键拼出组合。
写错列名、漏掉或留空这一步要的 `key` / `name` / `image` / `keys` / `how`，运行前报 `Run.BadRowColumn`；区域行不能同时写名字和四个数，
设计期也在这条步骤上标出；手写文件里多出来的列不会再被悄悄跳过。

每一步跑完还留下**一条**系统变量：`step.<步骤标识>.outcome`，值是 `ok` / `failed` / `skipped`。
它只回答"成没成"，不装失败原因——一步一条已经够长了，每条再带一个原因会让变量中心里翻不到头。

标识在同一个宏（连同它的子宏）里是唯一的。手写文件或从别处搬进来的一整块步骤，可能带着同一个标识：
这时后出现的那一步会换成新标识，指向它的条件与表达式一起改，步骤列表上方会写明改了哪几个。所以"改了名"
不会让宏在运行时突然读不到那一步。

要知道**为什么**失败、或者按原因分支，把那一步包进「尝试 / 捕获 / 收尾」：进到捕获段时
`caught.key` 就是失败键（例如 `Run.NoDevice`），`caught.detail` 是详情，捕获条件里比一比就能只接某一种
失败，也可以原样重抛。运行调试的步骤行同样把键与说明写出来，事后查也看得到。

**结果只属于这一次尝试**：每一次跑这一步（重试的每一次、循环的每一轮）开始时，它勾选的结果变量先清空；
这一步这一次没写某一项，那一项就是空的，不是上一次尝试或上一轮留下的值。调用别的宏也一样：同步调用失败、
或后台运行在「等待」时报失败时，调用处勾的结果一个都不写回，读它是空；后台运行的结果只有等成功之后才
有值（见「调用别的宏」）。所以"上一步没给结果"和"上一步给的是空"读起来一样，要区分就看这一步的
`step.<步骤标识>.outcome`。循环的每一轮开始时，循环体里各步骤的状态先回到 `skipped`：这一轮没跑到的
步骤，状态就是 `skipped`，不是上一轮的答案。

调用另一个宏时，交给形参的值与它声明的类型不符，调用在开始前报 `Run.BadArgumentType`；等到结果时，子宏交回的值与
声明不符报 `Run.VariableTypeMismatch`；被调用的宏声明了空名、读不出来的名字、重名、运行保留的名字，或者某个形参既是必填又
有默认值，调用前报 `Run.BadDeclaration`，设计期在调用步上标出。

动作的返回值行必须写这一步真正能交出的结果键和一个可读的变量名。漏写或留空 `key` / `name` 报
`Run.BadRowColumn`；未知结果键、同一结果键或变量名在一行列表里重复，以及读不出来的目标变量名，都在动作执行前
报 `Run.BadResult`；动作实际交出的值与目录声明的类型或记录字段不符，报 `Run.VariableTypeMismatch`。

找图、等图、点图、找色、点色、找颜色组合、找文字、点文字、认元素这些**找**的动作，交出的「命中」
（`match`）是一个**记录**：一条命中是"一件事的几项答案"，它们一起走，不用为每一项各勾一个变量。
**每一条记录都说清自己有哪些字段**，字段名就是下面这些，一个不多一个不少；找的动作里没读到的东西
（图片没读字、找图没认出类别）对应的字段是空的，不是没有这一项：

找图、找色、找多点颜色、物体检测、找文字和 `uia.find` 另有布尔结果 `found`，没找到时正常结束并交回
`false`，不会触发失败策略。`browser.exists` 与查找颜色都只查询一次；查找颜色的 `found` 同时表示颜色是否找到，指定点位时也表示该像素是否符合颜色。
