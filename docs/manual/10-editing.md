# 添加步骤与设计期检查

所属：[WhaleGenie 使用说明](../manual.md)。

## 添加步骤

编辑器分三列：左边是动作库，中间是步骤列表，右边上半是当前文档的变量中心、下半是宏设置，中间的分隔条可以上下拖动；右栏最窄为 360 像素，宏设置最低保留到能看见「保存」和「运行调试」，两枚按钮固定在右下。「保存」更新项目并留在编辑器中，下一次编辑前显示“已保存”；离开编辑器使用标题栏的「关闭」，有未保存修改时会先询问。窗口标题栏从右到左依次是关闭、最大化 / 还原、最小化和置顶；置顶后再按一次取消，按钮高亮表示正在置顶。
动作库顶部有四个等宽 Dock，整行不超出左栏：「基础动作」列普通内置动作；「流程控制」列未隐藏的 `control.*` 动作；
「子宏」列这个宏自己的全部子宏（存下来就出现，不必先被调用）；「公共宏」列本机公共宏库。搜索会过滤当前 Dock。

「基础动作」页内部左侧还有分类竖栏：全部、按键、视觉、界面、浏览器、脚本、程序与窗口、数据、文件、剪贴板、
系统。分类使用图标、短标签和固定颜色；OCR 归入视觉，窗口动作归入程序与窗口。选择分类后搜索只过滤该分类，
切回「全部」恢复所有基础动作。动作沿用紧凑的彩色描边按钮，按行自动换行；动作名直接写在按钮上，完整说明
在悬停提示气泡里。

把动作卡拖到步骤列表的行间，或在单列表块的中部、块首与块尾，高亮插入带和文字会说明保存后的落点；空列表高亮整块区域。展开块的块尾线上半属于块内末尾，下半和列表末尾空白属于块后顶层位置。松手后打开一个
可拖动、可缩放的动作窗口；窗口开着时动作库、步骤列表和宏设置暂时锁定，变量中心仍可操作，变量卡可以直接拖进
窗口里的字段。落点不接受该动作时，插入带改用拒绝样式并写明原因；松手不会打开动作窗口，也不会改动宏。
只有按「添加步骤」才在锁定落点插入，关闭或取消不改宏。窗口底部另有「运行」：把这一步按现在写的样子跑一次，
要看屏幕的动作只找不点，找到什么直接显示出来；**运行期间鲸灵自己的窗口全部收起来**，跑完按原状回来，所以这一步
看见的是它要看的那块画面，而不是问话的这个窗口。双击步骤、按 `F2`
或右键选「编辑」也打开同一个窗口，保存后原位替换。动作窗口只编辑已经选定的动作，不再在左侧重复一列
「选择动作」，也不再常驻显示 `control.*` 技术键；技术键仍可从「其它设置」的 JSON 预览中查看。容器先以空块
插入并自动展开，子步骤再从左侧拖进主列表；空容器也有块首、块尾和折叠箭头。动作窗口只说明“子步骤在主列表
编辑”一次，不再为每个子列表重复同一句话，也不为块内步骤另开第二个窗口。

**双击左侧的动作卡片**也能插入：它和拖到步骤列表是同一条路，保存后放到当前落点（选着某一步就放在它后面，空列表就是末尾），不必按住拖过去。除了拖放，每个块首还有带 `+` 图标和文字的「添加子步骤」或「添加分支」按钮。点击后左侧动作库临时切到
当前落点允许的动作并聚焦搜索框；随后照常把动作卡拖到目标段。`switch` 的分支列表只接受 Case，因此
「添加分支」直接打开 Case 表单。`Insert` 同样把焦点送回动作库。新增、拖动、粘贴、组合与提取使用同一条
规则：普通列表不收隐藏的 Case，Case 也不能离开多分支的分支列表。被拒绝的操作不改变宏并留在列表上方说明
原因；文件里原有的非法结构会在对应步骤上标错，但仍可作为草稿保存下来再修正。

中间步骤列表上方有文档页：「当前宏」是父宏，其余页是父宏拥有的子宏。切换页面只切换正在看的步骤与设置；
子宏页签旁有关闭按钮，关闭只收起这页，不删除子宏定义或调用，需要时从「子宏」Dock 再点开；删除定义仍走
子宏页右侧的「删除子宏」。按「保存」会同时保存父宏和全部已收起、仍保留的子宏，编辑器保持打开；点标题栏的「关闭」才离开。子宏页的右侧只显示名称、说明、形参、返回值、公共宏来源版本，
不显示触发、菜单、界面组或录制设置。「运行调试」运行当前页。

变量中心可按名称、显示名、类型、说明和来源搜索，并按五个筛选组查看。变量卡在鼠标停留时显示当前可读取的值；
全局变量卡带“持久化”标记，系统变量读取当前值，声明的局部变量显示它的初始值，其余局部与步骤状态变量在运行前
显示“运行后才有值”。
记录变量还会列出字段名和类型。刷新不会丢掉当前筛选、滚动位置或正在查看的变量。

「子宏」页的「添加子宏」可以从零新建，也可以复制一个现有项目宏。复制只取可调用内容，原项目宏及其触发器、
菜单保持不变；新建或复制只增加定义与文档页，不会自动调用。子宏改名会同步更新父宏树中的调用；仍有调用时
不能删除。最后一个调用移除后定义不会自动消失。

「公共宏」页的「管理公共宏」打开本机公共宏库。公共宏只保存可调用内容，并在每次内容变化后增加版本号。
把公共宏拖入当前宏时，会复制成当前父宏的子宏并记录来源 ID、名称和版本；同一来源与版本再次拖入只增加调用，
公共宏以后的新版本不会改动已有副本。公共宏删除后，项目里的副本照常运行。

`if`、`while`、`waitUntil` 和 `try` 的捕获过滤都用一个整值布尔表达式字段。表达式可以只用 `$found` 这样的
变量，也可以写 `$count > 3 and contains($name, "ok")`；变量卡能直接拖进去，框里的「取值」小片打开取值窗口。

全局变量可以从「设置变量」的动作窗口直接新建和编辑，也可以从变量中心的「全局变量」集中管理。两边编辑的是
同一份定义：名称、类型、默认值、说明和「持久化保存」。动作窗口取消时连同新变量一起放弃；
管理中心点保存才提交整个窗口的修改。默认值可以写普通值或表达式，在宏开始时按全局声明顺序计算，持久化保存的
实际值优先。表达式使用动作整值字段的语法，例如 `$count + 1` 或 `list(1, 2)`；要以 `$` 开头的普通文本写
`$$`。变量名可以用汉字、字母、数字或下划线开头，后面只能再用这些字符和点，所以 `2金币` 与 `$123` 都合法；
写变量名的格子仍只填裸名字，值里的变量仍写 `$名字`。变量改名只改声明，引用按身份跟随，所以同名局部变量不会再被
顺手改掉；条件行、断点、声明默认值这类仍以文本编辑的通道，保存时按唯一名字重绑，同名遮蔽的极端情况不保证，
脚本里的动态名称仍需按提示手工检查。持久化默认关闭；勾选后当前值保存在当前 Windows 用户的
`%LOCALAPPDATA%\WhaleGenie\persistent-variables.json`，重启鲸灵后按这个声明恢复。文件按身份而不是名字
保存，两个工程各有一个同名的 `count` 也不会互相串值；值的类型一起存下来（写作 `Number`、`Text` 这样的
类型名），列表和长小数不会在保存再读回之后变形。勾选或取消只在你点保存时落盘，运行中写进去的值由引擎
在后台补写。
「当前值」只显示、不能改：它是运行中的程序此刻装着什么（没有运行时显示默认值或保存下来的持久值），
设计期算不出运行期的值，提供输入框只会让人以为改了就生效。想改起始值就改默认值，想给持久变量播种就勾上持久化。
新建后名称框直接取得焦点；编辑时当前行不会因为搜索词不再匹配而消失。存在错误时仍可点保存，窗口会清除筛选并
定位到第一个错误。删除先确认，但只从编辑草稿移除；关闭、Esc 或取消时若有尚未保存的修改，会先问保存、放弃还是
继续编辑。

局部变量声明在变量中心的「局部变量」窗口里新建和编辑：左栏列这个宏自己的全部名字，右栏填名称、类型、初始值和
说明，点保存才写回宏。它和全局变量不同，配的是初始值而不是默认值——每次运行开始时按声明顺序把它写进这个宏自己
的变量表，所以第二次运行不会沿用上次改过的值；留空就从该类型的空值开始（数字 0、布尔假、空列表、空文本）。
初始值也可以写表达式，在那一刻求值，因此可以读形参、系统变量和全局变量，但不能读同一个宏里排在它后面的声明。
类型决定这份初始值怎么读，也是运行期的约束：往声明为数字的名字里写一段文字，那一步会失败并指出是哪个变量
（`Run.VariableTypeMismatch`），而不是等到几十步之后读数字时才炸。空值始终允许——「结果还没写」不是类型错误；
文本变量收任何值，它就是用来装还没定形的值的。`date` 是真正的日期值：比较按时间先后，排序按时间，日期函数直接处理它，也可以直接写成 `2026-11-12`；
`image` 是运行期图片的句柄；`color` 不再是一种变量类型——颜色是文本加取色器，写法由取色器负责。窗口里还有一类行是步骤写出来的名字（步骤交回的结果、「设置变量」
写下的名字）：装着什么由那一步决定，这里只能改名，不能删——要停掉它得改那一步。

要释放一个名字，用「清除变量」：局部变量会从本宏的表里删掉，之后读它和从没写过一样；全局变量属于项目、
不能从宏里删掉，所以清除是把它的声明初值写回去。

循环自己用的名字（`item`、计数器、`sys.loopIndex`）只在这个循环体里有绑定：循环结束时，它遮蔽的名字回到
循环前的值；它自己新起的名字留在表里，所以循环结束后还能读到最后一轮的计数器。`sys.loopIndex` 在循环外
根本没有绑定，读到它会报 `Run.BadExpression`，这和读任何没写过的名字是同一种失败。

运行期拼出来的名字（例如 `row_${i}`）会一直留到这次运行结束：超过五万个名字时日志提醒一次，超过二十万个
名字时那一步以 `Run.VariableTableFull` 失败，而不是一直涨到机器撑不住。

变量中心里双击全局变量会打开全局变量管理中心，双击局部变量（含步骤返回名）会打开局部变量窗口并选中它；
宏形参和结果双击后转到宏接口，系统变量与 `step.<标识>.outcome` 只读。鼠标停在变量卡上会说明双击做什么，
变量卡也可以直接拖进参数框。

变量的三种保存范围不要混用：局部变量只属于本次宏运行（声明的初始值每次运行都会重写一遍）；全局变量在鲸灵运行
期间由所有宏共享，默认值只在第一次用到时兜底；勾选持久化的全局变量重启后按名称恢复。文件动作「保存变量快照」
与「恢复变量快照」另做一份显式 JSON 快照，可以选择局部或全局名称、写到指定路径，用来备份、转移或按流程恢复
状态，不能替代上述任何一种作用域。

步骤行可以右键：编辑、复制、剪切、粘贴、删除、上移、下移、组合、提取为宏、启用 / 停用都在菜单里，不必记快捷键；双击仍然直接编辑。
## 写宏时就会标出来的问题

编辑器只标出步骤自己就能确定的问题，把标记落在对应的步骤行上；宏自己的形参 / 结果名没有步骤行可落，单独列在步骤列表上方，不调用它的宏也看得到；运行到才会知道的事（屏幕、文件、变量的值）
不猜。会标出的包括：`if` / `while` / `waitUntil` 没选条件；`break` 不在循环或多分支里、`continue` 不在循环里；循环轮次
写在循环外；调用的宏或形参 / 结果名不存在；必填形参没有填，或者「传空值」旁边还留着一个值；调用时交给形参的常量值与它声明的形状明显不符；读了一个没人定义的名字；
位置记录与旁边的数字都没填（读屏幕的截图与识别除外），**位置记录和数字都填了**（只留一种写法）；
**记录填进了数字格、文本填进了记录格、记录写进了只收文本的格子**；嵌套循环用了外层循环的变量名（内层结束会覆盖外层的值）；多分支既没有 case 也没有 otherwise；本宏变量用了 `sys.` 开头或 `step.<标识>.outcome` /
`step.<标识>.outcome` 这种运行自己保留的名字；**动作或字段已经不在目录里**（被删掉或改过名）；**行列表写了没有的列或缺了要的列**；**必填字段空着**；**宏自己的声明或调用到的宏声明了空名、读不出来的名字、重名、运行保留的名字，或者既是必填又有默认值**；**声明了结果却没有任何步骤写这个名字**（脚本或计算出来的名字写入时只是提醒）；**默认值明显不是声明的类型**；**默认值以 `$` 开头却读不成表达式**；**叫这个名字的调用已经没有对应形参 / 结果**；**选项不是目录里的词**；**同一个结果名勾了两行**；
**整值格里以 `$` 开头、或文本花括号里、却读不成的表达式**；以及不在 `if`、多分支或循环里的自递归调用。

等待类步骤的空超时默认是「一直等」，本身不算错。只有这一步还设置了重试，或者外层块另有一个有限超时时，
编辑器才会提醒：这时重试或外层预算都不会让这一步更早结束，要依赖它们就应给这一步填一个超时。
