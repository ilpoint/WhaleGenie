# 设置与宏包

所属：[WhaleGenie 使用说明](../manual.md)。

## 设置

设置主页在网页壳的「设置」里，不再打开单独的系统设置窗口。页面是 VS Code 式两栏：左侧分类
（常用、主题、输入、菜单/轮盘、存储），右侧顶部搜索框按文字过滤卡片；页面按卡片分区：

- **常规**：语言与启动选择。**启动时打开上次的项目**关闭后每次从空列表开始；
  **启动时启用触发**关闭时启动后按快捷键启用；**已启用的宏排在前面**关闭时按项目里的原顺序。
- **主题**：深色、浅色或自定义。自定义选一个强调色和控件底子，下面三块预览分别显示主按钮、
  选中行与强调文字；颜色推导不到 4.5:1 时明确提示并保留内置强调色。改动立即作用到全部窗口。
- **热键**：系统总开关快捷键与录制开始/停止快捷键；点「设置快捷键」后直接按键，点「清除」留空。
  系统总开关留空则停用，主界面按钮仍然有效；录制键默认 `Ctrl+F10`。
- **菜单呼出键**：点「设置快捷键」后按一个键盘组合，或按鼠标中键/4/5 侧键；也可以直接点
  「鼠标中键（默认）」。下方是本项目的一套窗口规则：默认规则放通用菜单，程序规则按前台窗口
  覆盖下方区域；规则可增删、加页、上下移动，也可拖动排序。
- **窗口规则**：添加或编辑规则时在页面里选窗口；规则表单可切换按标题、进程名或窗口类匹配，
  也可取窗口句柄。需要到桌面上临时点一扇窗口时，按「取窗口」，鲸灵窗口会让开，按提示点目标窗口。
- **轮盘菜单**：触发按键、是否只在指定程序里弹出、尺寸、文字大小、第三圈容量、超时、重复触发键，
  以及版面、操作与外观开关。卡片的预览按当前全局动作画版面。
- **轮盘动作管理**：先选全局场景或一个程序场景，再点轮盘上的位置编辑宏、备注与图标。程序场景只
  覆盖填过的位置，其余显示为「（全局）」；「清除该位置」只清本场景的这一格。
- **声音**：切换系统与切换宏各一声，默认都开。
- **屏幕读取**：启动时预加载文字识别与取画方式。
- **画面**：每秒最多取几次画面、是否复用已取到的画面与缓存有效期。
- **输入行为**：输入限制、忽略程序自己的输入与日志保留数。
- **驱动级输入**：显示驱动是否就绪，可设启动时预装虚拟键鼠与启动时请求管理员权限。
- **存储位置**：列出四类文件各自放在哪儿，每行带一个「打开」直接到那个文件夹。

菜单呼出键与窗口规则属于本机设置，轮盘位置和菜单页面跟着项目走；其余都是这台机器的行为。
改动立即生效并保存。

**存储位置**的四类文件：

| 行 | 位置 | 放的是什么 |
| --- | --- | --- |
| 设置、日志与未保存的工作 | `%LOCALAPPDATA%\WhaleGenie\` | `settings.json`（各窗口的选择）、`logs\`（失败日志）、`recovery.json`（未保存的工作） |
| 项目图片与上次保存的包 | `%APPDATA%\WhaleGenie\projects\<宏包名>-<路径哈希>\` | `assets\`（包里解出来的图，步骤里的图片引用指的就是它）与 `last.wgmacro.bak`（上一次保存替换掉的包） |
| 项目尚未保存时的截图 | 系统「图片」文件夹下的 `WhaleGenie\` | 项目还没有文件时，宏截下来的图 |
| 公共宏库 | 程序目录的 `library\` | 所有项目共用的宏 |

前两类在用户目录里，升级、重装或换一个安装位置都不会带走它们；最后一行跟着程序目录走，因为那是要
拷给别人的成品。**日志保留**最多留几份失败与 MCP 日志，范围 1–999，默认 100。


### 设置项背后的细节

设置页只写「这一项是什么、什么时候改」，其余留在这一节。

- **快捷键**：支持字母、数字、`F1`–`F24`、方向键、编辑键、小键盘键与修饰键组合；例如小键盘减号显示并
  保存为 `NumPadSubtract`。界面组与全局快捷键按同一套名称识别，读不出来的键当场提示、不会保存。
- **取画方式**：自动的顺序是窗口走 Graphics Capture、PrintWindow、屏幕像素，桌面走桌面复制、GDI；
  点名哪一档就只走那一档。PrintWindow 取整窗含标题栏，Graphics Capture 取窗口自己画的那部分、
  被别的窗口压住也取得到；桌面复制是唯一能取到独占全屏游戏的档，代价是不支持高动态范围与转屏。
  Windows 10 使用 Graphics Capture 时会显示系统捕获边框，Windows 11 可以关掉。
- **捕获节拍为什么以刷新率为界**：画面没有重新画过，再取只能拿到同一张，所以上限就是显示器刷新率；
  等待类步骤也按这个节拍看屏幕。`control.waitUntil` 与 `uia.waitElement` 等的是条件与界面元素，
  它们的间隔仍写在步骤里。复测见[这里](../dev/delivery.md#性能测量)。
- **缓存画面的代价**：缓存的画面最旧可以到「缓存有效期」那么旧；超过一秒就不再是省开销，而是读一张旧截图。
- **usbip-win2**：安装需要管理员权限，过程中 USB 设备会短暂断开，可能要求重启；只有驱动这一样要手动装，
  虚拟键鼠、虚拟手柄与它们的服务端随程序带。
- **为什么高权限窗口读不到快捷键**：快捷键靠系统钩子读，前台窗口属于更高权限的程序（任务管理器，
  或以管理员权限启动的程序）时，Windows 不让鲸灵看到那里的按键，普通输入也送不进去。送输入不是问题，
  驱动级输入能进那些窗口；不能的是在那里用快捷键启动宏。
- **日志保留的边界**：失败日志一次运行一个文件、MCP 日志一天一个文件；启动时按修改时间删掉最旧的，
  只留这个数。`runtime.log` 由自己的滚动机制管着、不参与计数，`logs\` 里的别的文件也不会被删。
- **菜单版面**：80×80 格子、4 列，上下各 3 行；通用区与命中的规则区各自分页，标题固定显示鲸鱼图标与鲸灵。
- **存储目录打不开时**：界面只说一句「文件夹打不开，详情见日志」，异常原文写进 `runtime.log`。

## 关于与第三方组件

标题栏「帮助 → 关于」打开网页关于页：版本、项目说明、项目主页入口与支持开发者的两枚付款码都在
这一页。「第三方组件」展开后显示随包嵌入的 `THIRD-PARTY-NOTICES.md`，列出图标素材、界面、引擎、
运行环境、只在编译时用到的组件和用户自装组件；它与发行包旁边那份文件同源。

## 宏包（.wgmacro）

`.wgmacro` 是一个 zip 容器：

| 内容 | 说明 |
| --- | --- |
| `manifest.json` | 版本、宏的列表、全局变量（文件名小写） |
| `README.md` | 打开包时能看到的一份说明，列出里面的宏 |
| `triggers.json` | 项目级触发入口、悬浮组位置、菜单页面、格子图标和禁止呼出程序 |
| `assets/` | 宏与菜单格子用到的图片，引用写作 `assets/<文件名>` |
| `nodes/<编号>-<slug>.json` | 每个宏的步骤树（slug 由宏名生成） |

全局变量声明与步骤里的引用都只写名字：名字就是键，文件里没有第二套身份。
26 及更早的包打不开：旧工程要用旧版本把内容导出成文字后重建，本版不提供迁移工具。

读写都在 `Storage/MacroPackage.cs` 一处：打开时把 `assets/` 解到磁盘并在步骤里改写成绝对路径，
保存时再把用到的图片收进包里。**解出来的图片和上一次保存留下的 `.bak` 都不放在包旁边**，而是在
`%APPDATA%\WhaleGenie\projects\<宏包名>-<路径哈希>\` 里（图片在该目录的 `assets/`，备份是
`last.wgmacro.bak`）：项目文件夹里因此只有 `.wgmacro`，从只读位置打开包也有地方解图。设置页的「存储位置」卡片把这一处与另外三处一并列出，
并可以一键打开。

### 导入与导出

文件只有一种：`.wgmacro` 宏包。一个包可以装整个项目，也可以只装一两条宏——**导出时勾什么，包里就有什么**；
包里是什么、要变成什么，则由导入时勾什么决定。

**导出**有两处：

- 宏卡片的**导出宏**按钮：打开网页向导，先勾上这一条，再挑别的。
- 编辑器文档页签右侧的**导出**：直接导出当前这一页，不经过向导。

向导按树列出宏和它里面的子宏：

- 勾一个宏，它自己的子宏一并带上（那几行跟着勾上并锁住）；
- 只勾子宏，那个子宏就被单独拿出来，像一条宏一样写进包里。

底部实时写着已经勾了几个宏。文件里仍可能留下指向没一起带走的宏的调用，那样的宏运行到那一步会停；
勾选时最好把被调用的一起带上。

装进包里的是：选中的宏（连同它自己的子宏）、它们**实际读到的**全局变量、它们的触发入口（热键、菜单位置、
界面组位置）以及要用到的图片。

**导入**是文件菜单的**导入…**：先在系统对话框里选包，网页向导随后列出包里能带进来的内容，底部写着会落到哪里：

- 勾了顶层宏 → 进当前项目。项目里已有同名宏时，后进来的那个加上日期，导入结束会说明改成了什么。
- **只勾子宏 → 进公共宏库**。能被调用的一段就该待在库里，项目要用的时候从库里取一份，库里的条目带着版本。
- 全局变量：文件里声明、选中的宏又真的读到的那些，如果项目里已经有同名，会**逐条问一次**——重命名（只改随
  文件带进来的宏，本项目的宏一个都不动）、用本项目的、覆盖本项目的。
- 导入完给一张清单：新增了哪些宏、哪些因为重名改了名字、变量各自怎么处理的，以及**现在撞上的触发入口**——
  那些不自动改，留给你换一个键或换一个菜单位置。

图片落在当前项目的 `assets/` 里。导入时同名文件的**内容**会先比一比：一样就共用，不一样就另存一份
（`按钮-2.png`），所以一个包不会悄悄替掉另一个宏要用的那张图。
