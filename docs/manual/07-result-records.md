# 命中记录与位置

所属：[WhaleGenie 使用说明](../manual.md)。

## 命中记录与位置

| 记录 | 字段 |
| --- | --- |
| 命中（`match`，以及 `every` 里的每一条） | `x`、`y`（中心）、`left`、`top`（左上角）、`width`、`height`、`score`（把握）、`box`（整块矩形）、`text`（读到的字）、`class`（检测模型给的类号）、`label`（类名） |
| 截图（`place`） | `x`、`y`、`left`、`top`、`width`、`height`、`box` |
| 窗口（`window.info` 的 `window`、`window.list` 的 `windows`） | `title`、`process`、`class`、`handle`、`minimized`、`maximized`、`x`、`y`、`left`、`top`、`width`、`height`、`box`、`clientBox`（内容区，列表里留空）、`how`、`caseSensitive`、`trim`、`multiline`（这四项可直接作为下一条步骤的窗口规则） |
| 点（`screenPoint`、`windowPoint`、`screenStartPoint`、`screenEndPoint`、`windowStartPoint`、`windowEndPoint`） | `x`、`y`、`basis`（值为 screen 或 window） |
| 显示器（`screen.list` 的 `displays`） | `x`、`y`、`left`、`top`、`width`、`height`、`right`、`bottom`、`primary`、`box` |
| 程序（`process.info` 的 `program`） | `info`（程序文件）、`id`、`name`、`memoryMb`、`cpuSeconds` |
| 元素（`uia.read` 的 `element`） | `enabled`、`visible`、`value`、`name`、`automationId`、`controlType`、`x`、`y`、`left`、`top`、`width`、`height`、`box` |

`x`、`y` 是那块矩形的中心，单位是屏幕像素：点图、点文字落的就是这里，也是"下一步移过去"的意思；
`left`、`top` 与「搜索区域」里那四个数同一个口径；`box` 是 `左,上,宽,高`，填进搜索区域那一行的
变量格，下一步就在同一处找；`score` 是这一次的把握（找图找色是相似度 0–1，找文字是识别模型给的
读数分）。

看画面的找动作（找图、找色、找文字、物体检测）还各有一项**来源窗口**（`window`）与**取画面方式**
（`method`）：前者说画面取自哪个窗口，直接从屏幕读取时为空；后者是 `graphicsCapture`、`gdi`、
`printWindow` 之一。认元素（`uia.find`）不取画面，只交来源窗口（`window`），没有 `method`。没找到时
这些项也一并清空，所以上一步的结果不会留在这一步里。

**取记录里的一项用 `field(变量, "字段名")`**，写错字段名不只是取不到值：这一步会报错，并把这条
记录**有哪些字段**列在错误里。整个记录写进文本时会写成一个 JSON 对象（`{"x":30,"y":40,...}`），
所以 `toJson` 与读 JSON 的那几个函数照样能用；`count(变量)` 给出这条记录有几个字段。

**中心点与左上角在同一个记录里各占一个字段，因为这两件事本来就不一样**：`x`、`y` 是动作要点的
那个点，`left`、`top` 是矩形的左上角。要让下一步在刚找到的地方再看一次，把 `box` 填进搜索区域
那一行的变量格，或者**直接把整个记录交给那一行**：区域里在取值窗口选一个记录变量时，「left」「top」「width」
「height」四个字段就是那块矩形。找图、找色、找文字与认元素（`uia.find`）的命中、`window.info` 交的
窗口、`window.list` 里的每一条、截图交的 `place` 都走这条路：整条记录填进那一行就行，取其中一格用
`field(记录, "left")`。这些记录里凡是有矩形的，都同时带着 `x`、`y`：取的就是这块矩形的中心
（奇数宽高时按整数除法取整），所以"把鼠标移到窗口正中"写 `field(窗口, "x")`、
`field(窗口, "y")` 就够，不必自己拿 `left` 与 `width` 算一半。
**写成数字的位置与矩形另外各有一格收一条记录，这一步的位置从哪儿来只由这两者之一说**：鼠标动作
（移动、点击、双击、按下、松开、滚动）与看一个像素的动作（`vision.getPixel`、`vision.waitColor`，
以及可选的查找颜色点位）的「位置」一格收一条记录，落在这条记录说的那一点上——记录带着 `x`、`y`，取的是那块矩形的中心，
"把刚找到的东西点一下"就是这么写的。拖拽的起点与终点各有一格（`startPlace` / `endPlace`），两端可以
一头取记录、一头写数字。**要读、要截的那一块与「移动或调整窗口大小」四格同理**：「矩形」一格收一条带 `left`、
`top`、`width`、`height` 的记录，"把刚找到的那一块截下来""读一读它上面的字""把这个窗口摆成那个窗口
那样"都是这么写的。**记录格与数字格互斥**：填了记录，旁边那几格数字就被清空；反过来动了数字，记录格
就清空——同一个问题只有一个答案，文件里不会两样都留着。记录格填了而那条记录没有 `x`、`y`（或没有
`left`、`top`、`width`、`height`）时报 `Run.BadPoint` / `Run.BadRegion`，并把读到的那条记录写出来；
记录格填的不是一条记录（一个数字、一段文字）时同样报 `Run.BadPoint` / `Run.BadRegion`。**鼠标动作的
「就在指针当前所在位置」压过记录格**：勾上它就以指针为准。**两格都空着**时设计期会标出来（读屏幕的
截图与识别除外：那里两格都空着就是整块屏幕）。
记录里的数本来就是屏幕上量出来的，所以**「识别方式」选窗口时只挪写出来的数字**：起点两格填 `10` 与 `20` 时它们
是窗口里的那一点，交给它一条命中时它是屏幕上那一点（同一条命中在哪个基准下说的都是屏幕上那一点）；搜索区域那一行
交给一条记录时看的也是记录自己那一块，与基准无关。想按基准挪，就写 `field(记录, "left")` 这样把数
取出来再填。

找图、找色、找文字这类会有多处的动作，返回值里还有一项**「全部命中」**（`every`）：勾上就有了
一列记录，顺序就是「命中排序」里的顺序，「第几个命中」数的也是这一列；`count()` 数一数、
`get()` 取出其中一条、`forEach` 逐个走一遍都能直接用。每一项的样子和上面那张表一样，所以
"这条文字写在哪儿、写的是什么"是同一项里的两个字段，不用拿两张表对号。不勾就只有选中的那一处。

**点图与点文字也把命中的位置交出来**，和找图、找文字一样：点完之后想知道"刚才点的是哪儿"、
或者要把那个位置交给下一步时，不必再写一次查找。

**窗口信息（`window.info`）交的是一条记录**，一条记录把"这个窗口在哪儿、它是什么"一起说清：`title`、
`process`（程序名，不带 `.exe`）、`class`（窗口类名）、
`handle`（句柄）、`minimized` / `maximized`、`x` / `y`（窗口矩形的中心）、`left` / `top` / `width` /
`height` 与 `box`（整块矩形，
写成 `左,上,宽,高`），再加上 `clientBox`（内容区，去掉边框与标题栏的那块）、`how`、
`caseSensitive`、`trim`、`multiline`。**等待窗口（`window.waitFor`）等到的也是同一条记录**，勾「窗口」
就能把它直接交给下一步。窗口信息的矩形是看见的矩形；窗口坐标以 `clientBox` 的左上角为原点。
**这条记录可以直接当窗口用**：任何窗口字段填 `窗口`，运行时按记录里的 `how` 和比较开关从
`title` / `process` / `class` / `handle` 取那一项重新认窗。选择句柄档时记录里的句柄必须非 0，并且只认那个
当前实例；记录里没有匹配方式要的那一项时
报 `Run.WindowRecordField`；拿一条命中当窗口用时也是这样，取其中一项用 `field(记录, "字段名")`。

**窗口的矩形说的是它被看见的那个矩形**，不是 Windows 用来拉伸它的那个：普通窗口上左右下各多出七像素
看不见的边框，最大化的窗口还比屏幕大一圈。窗口相对坐标、这里的矩形、屏幕上框出来的位置、以及窗口画面的
起点是同一件事的四个说法，所以都按看见的算；`window.move` 收的也是这个矩形，把刚读到的那组数填回去，
窗口就回到原处。`window.move` 的 X、Y、宽、高默认留空并保持原值，四个都留空时设计期提示至少填一条边；
「拾取窗口位置和尺寸」从目标窗口当前可见矩形开始，拖动会同时移动或调整目标窗口；按 F1 确认，
Esc 取消并把窗口放回原处，
结果一次填入四个数并清空矩形记录。

**列出窗口（`window.list`）给的是一列记录**，一个窗口一条，字段是 `title`（标题）、`process`
（程序名，不带 `.exe`，就是「匹配方式」选进程名时要比的那一段）、`class`（窗口类名）、`handle`
（句柄）、`minimized` / `maximized`、`x` / `y`（窗口矩形的中心）、`left` / `top` / `width` /
`height` 与 `box`（位置与大小，
写成 `左,上,宽,高`）——与 `window.info` 交的那条记录同一个形状，`clientBox` 留空：内容区要问一次系统，列表不为每条都问。标题相同的两个
窗口是两个窗口，各占一条。
「它有哪些窗口」与"这些窗口分别是什么"是同一列里的同一条，不用拿几张表对号。这一步一个结果都
不勾时不去查程序名与类名 —— 那两个要问一次系统才知道，不勾就不花这份时间；勾了之后还要勾上
「每个窗口都读程序名与类名（慢）」它们才有值（默认关，关着时这两格留空，只按标题认窗口的宏不必付
这份时间）。挑出要列哪些窗口用的也是「匹配内容」与「匹配方式」这一对，留空就是列出所有窗口。

**截屏（`vision.capture`）与截取窗口（`vision.captureWindow`）把画面在哪儿也交出来**：返回值里勾上
「位置」（`place`）就有了这块画面的记录，`x` / `y` 是它的中心，`left` / `top` 是它开始的位置，
`width` / `height` 是它的大小
（画面在屏幕边上被截短时写的就是实际拿到的那一份），`box` 是整块矩形。下一步要在这块画面上再看一次，
把整条记录填进搜索区域那一行就行。来源窗口与取画面方式不作为返回值列出：它们是这一步怎么取到
画面的，宏拿它们做不了什么；要确认这张画面从哪儿来，看运行调试里这一步的行。

**读表格（`uia.readTable`）交的就是一列记录**：返回值页的结构列写 `[{列名: "文字"}, …]`，一格一个值。
一行一条，键是表格列标题那一行写的列名，取一个单元格按名字取——`field(get(表格, 0), "金额")`——
不用数它排第几。表格没有列标题时，列名就是 `A`、`B`、`C`；列名为空、或者与前面某一列重名的列，
也用它的列号当名字——一个名字底下不能放两列。勾上「按表格读」的文字识别（`ocr.recognize`）交的
同样是每行一条记录，屏幕上读来的东西没有列标题，键一律是格子的列号 `A`、`B`、`C`。
这与读 CSV 是同一种形状（见「分隔符文件」）。

**认到的元素（`uia.read`）交的也是一条记录**：`enabled` 与 `visible`（现在能不能用、是不是显示着）、
`value`（元素自己持有的内容——输入框里的文字、按钮上的标题；本身不持有内容的元素为空）、`name`、
`automationId`、`controlType`，再加上 `x` / `y`（元素矩形的中心）与 `left` / `top` / `width` /
`height`、`box`。取其中一项用
`field(元素, "value")`：想"等这个按钮能用再点"就在循环里读它、用表达式分支，不必靠猜。
要**按下**一个控件而不动鼠标，用「按下界面元素」（`uia.invoke`）：它走控件自己的动作，鼠标停在原处、
窗口也不会被抬到前面，所以后台窗口里的按钮按得动；控件不提供这种方式时会报出来，不会退回去点鼠标
——真要挪过去点一下，用「点击界面元素」。

**两个同名元素里到底是哪一个，用「元素锚点」说**：高级设置里那一块问三件事——挨着谁（另写一个选择器，
旁边有与上面同一个元素拾取器）、在哪一边（左、右、上、下）、至少隔开多少像素（0–10000，默认 0，
贴着边也算）。十二个带选择器的界面动作都有这一块。「在哪一边」与「至少隔开」一直显示着、随时能改，只有上面填了
锚点元素它们才算数。方位只看这一条轴，所以同一行里上下差几个像素的按钮仍算「在右边」；「在`确定`右边」就是填 `Button[name='确定']`、选「右边」、间隔 0。锚点元素找不到、
或者系统说不出它在哪儿时，这一步按**没找到**处理，不会退回随便挑一个——那正是会选错的那条路。
锚点元素自己不再带锚点：它取第一个命中，说不了那么细就把它的选择器写具体。

**占比 %**（`coverage`，只有查找颜色有）问的是"这块区域里有多少是那个颜色"：0–100 保留一位小数，
找没找到都会写，所以占比不够时能读出差多少；「至少占比」拿它当判定线，低于这条线就算没找到。
指定点位时占比只有 0 或 100。查找颜色只看一次：要一直等到占比够了才往下走，在 `while` 里查找颜色，用
`found and coverage >= 50` 这样的表达式判断，满足时 `break`；只等某一个像素变成某个颜色，
用「等待颜色」。
