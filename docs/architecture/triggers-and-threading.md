# 触发器、线程与设计限制

所属：[WhaleGenie 架构](../architecture.md)。

## 10. 触发器与录制

`MacroTriggerService` 分派热键、颜色、热字串、计划、文件、进程、窗口和空闲触发；界面与菜单由各自
浮层直接发起运行。后台服务只读取 `TriggerRuntimeSnapshot` 和 `GlobalHotkeyPlan`，并通过异常隔离与
节流日志避免重复故障刷屏。

程序自己发出的输入是否算数由一处全局设置决定：`WhaleGenieInputGate` 记住刚发出去的键名，触发器与
录制器都问它同一个答案，各自不再保留副本。开关为关时两边照收，用于让本程序驱动自家快捷键。

Core 的录制层将原始输入翻译为去抖、合并后的 `RecordedAction`，阈值集中在 `RecordingOptions`。
应用层的 `RecordingStepBuilder` 将动作转换为可编辑步骤，编辑器负责保存与恢复快照。

### 轮盘触发

轮盘由 `MainWindow.AttachSystemHotkey` 额外订阅全局鼠标与键盘事件，不进入 `MacroTriggerService`。
`Runtime/WheelGesture.cs` 是不接触控件的手势状态机；命中呼出键后同时吞掉按下与松开，未形成手势的
短按通过 `WheelGestureAction.Replay` 补发普通点击，注入标记防止补发事件再次触发手势。呼出键只允许
右键、中键和 4/5 侧键，并与菜单呼出键、系统热键保持互斥。

`OnlyInPrograms` 启用时，钩子线程用项目 `WheelMenuRules` 的不可变副本匹配前台窗口；未命中场景就不
吞键。按下时命中的场景、来源和宏快照冻结到本次轮盘，滚动只切换叠加、全局与当前程序来源，不因前台
窗口变化重选内容。

超过移动阈值后才经 `Dispatcher.UIThread.Post` 打开窗口。钩子只把最新坐标写入 `WheelAim`，界面
按渲染优先级投递一次读取（同一时刻只有一个待读），读取取到的是最新坐标，因此高频移动不会堆积，
提示线也不会排在一次绘制之后才更新；代际号丢弃上一轮已投递的回答。透明轮盘窗口用
`WS_EX_TRANSPARENT` 让鼠标穿透，钩子线程不读取 Avalonia 对象。

`Models/WheelMenu.cs` 负责场景、槽位、几何与选项，`WheelCanvas` 同时服务实时轮盘和设置页编辑器。
槽位只包含一个宏、一条备注和一个图标；动作编辑以副本进出，程序场景保存为对全局槽位的覆盖。项目内容
写入 `ProjectTriggers.Wheel` 并随 `triggers.json` 保存，本机面板选项写入 `wheel-menu.json`。设置页以
`ShowAsPeer` 保持单实例，预览模式复用同一窗口但只走 Avalonia 指针事件。

## 11. 线程与退出

- **界面线程**：项目状态、ViewModel、窗口操作及需要界面上下文的 MCP 读写。
- **钩子线程**：全局输入回调与触发判定，只读取快照并派发，不访问控件。
- **线程池**：宏运行、MCP 会话、异步设备等待和模型预热。
- **图形专用线程**：Graphics Capture 与桌面复制等需要串行图形调用的路径。
- **互斥原语**：`SharedDoors.Input`、`SharedDoors.Browser` 和 MCP 单运行控制分别保护不同资源，不合并为全局大锁。

退出时不得在界面线程同步等待 MCP 停止，因为 MCP 请求可能正在等待界面线程。窗口隐藏与进程退出
必须区分；真正的退出流程统一处理未保存内容、触发器、MCP、共享设备和虚拟输入设备。

## 12. 当前设计取舍与限制

1. **界面工程与运行期应用层分开。** 文件模型在 `WhaleGenie.Domain`，触发器、运行编排与 MCP 工具在
   `WhaleGenie.App`，两者都不引用 Avalonia；界面工程只剩窗口、ViewModel 与界面适配，因此无界面启动
   不会加载界面框架。
2. **设备聚合接口较宽。** 综合运行器和编辑器需要多种设备，窄接口按实际使用点逐步采用；测试替身按
   设备拆分，不要求先重写整个设备契约。
3. **界面保留交互后置代码。** 拖放、焦点和窗口行为留在窗口中，不为形式上的完整 MVVM 引入消息总线或
   逐控件 ViewModel。
4. **文案采用手写字典。** 文案可逐条审阅并由测试对账，不引入生成器复制另一份定义。
5. **部分运行路径仍依赖手写分派。** 动作目录与 `SeeOnce`、MCP 工具发现和审计调用点需要同步维护，
   相关改动必须增加可失败的检查，不能依赖人工记忆。
6. **进程级共享状态仍然存在。** 文案、本地设置和部分设备入口采用静态共享；测试须恢复这些状态，
   新代码不得借此绕过组合根管理有状态服务。全局变量已经不在其列：声明与值都归 `VariableSession`，
   由组合根建一个并注入，窗口、触发器和 MCP 读的是同一个对象。
7. **MCP 会话不提供资源订阅。** 客户端使用修订号主动刷新；多客户端通过各自进程与草稿隔离。
