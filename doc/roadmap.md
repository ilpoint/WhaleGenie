# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 接下来做什么，给改这个仓库的人（含 agent）看。它与仓库根目录的 `AGENTS.md` 分工：
`AGENTS.md` 讲定位、开发规范与设计约定（不常动的东西），这份文件只讲下一步动什么。用程序的人看
[manual.md](manual.md)，工程细节看 [dev.md](dev.md)。

- **只写还没做的**：一个阶段做完就把那一段删掉。做过的改动在 git 里，这里不留"已完成"清单——留着的话，
  这份文件会慢慢长成一本账，谁也不知道哪一条还算数。
- **一个阶段就是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，还会让读的人以为它在排期。
- 阶段里提到的东西如果还没在代码里，都写着"（将新增）"；没写的就是已经有的。

## 排序原则与衡量标准

- **先地基，后便利**：决定别的东西怎么写的（比如返回值的形状）排在前面；只是让人少点几步的排在后面。
- **游戏向排在办公向前面**。
- **判断标准只有一条**：用户能不能把这件事表达出来。
- **一个阶段的验收必须做得出来**：写清测试在哪、手动项是什么。说不清怎么验的，就不算一个阶段。

## 工程规矩

阶段里逐条照着做：

1. 一个阶段一串提交，每个提交只做一件事。
2. 阶段收尾三项全绿：`dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`（命令与出处见
   [dev.md](dev.md)）。
3. **改完就删旧的**：被新形状取代的参数、返回值、开关、文案键、测试与文档段落，都在同一阶段里删掉；不留
   双读、不留"旧文件也还能读"的分支。
4. 新增目录字段、返回值与文案时，中文与英文两侧的键一起加；`ActionPageTests` 的 Tuning 名单、
   `ReturnsPageTests`、`LocalizationTests` 跟着补。
5. 新增依赖必须是官方库、只 Windows，并写进 [dev.md](dev.md) 的依赖表与 `THIRD-PARTY-NOTICES.md`。
6. 真实桌面的项（移动鼠标、抓屏取色、注入按键、UIA 与页面拾取、录制、窗口布局）按 `AGENTS.md` 规范 5
   手动过一遍，结论写进提交信息。
7. 这一阶段动到的动作，说明文字按书面语顺手改（见 `AGENTS.md` 规范 2）。
8. 阶段做完，把这一段从这份文件里删掉。

## 阶段表

顺序就是"先地基、后便利"：读懂一个阶段的现状与改动，不需要先读后面的。

### 阶段 1 · 一条命中就是一个记录

**为什么**：命中的每一部分都要单独勾一次；而「全部命中」只留中心点，一条命中的宽高与相似度拿不到——想读
"第 3 个命中的分数"，只能再写一次查找。

**现状**：一次命中被拆成十一个变量（`MacroRunner.GiveMatch` 写 `match` / `x` / `y` / `left` / `top` /
`width` / `height` / `score` / `box`，文字识别另有 `text`）；「全部命中」每项只有中心点 `"x,y"`（`GiveEvery`）；
`window.list` 用五张并列的表（标题 / 程序名 / 类名 / 句柄 / 矩形）说一串窗口；「记录全部命中」在高级设置，
要靠它交出的那两项在返回值页，一件事两个开关。

**改成**：

- `Value` 多一种数据种类**记录**（将新增）：按键有序，`AsText()` 写成一个 JSON 对象，写进文件与读回来
  往返一致。
- 表达式新增 `field(记录, 名字)`（将新增）：取记录里的一个字段；字段不存在时报错，并把这条记录有哪些字段
  列在错误里。
- 命中类动作交出一个记录（将新增）：键按动作给 `x` / `y` / `left` / `top` / `width` / `height` / `score` /
  `box` / `text`。原来那十一个标量返回值与「记录全部命中」参数一并删掉，引擎改判「全部命中」那一项有没有勾。
- `window.list` 的 `windows` 改成记录列表（将新增；键 `title` / `process` / `class` / `handle` / `box`），
  四张并列表删掉。
- 区域与搜索区域字段除文本外也认记录（将新增）：读它的 `left` / `top` / `width` / `height`，于是"把刚读到
  的那块矩形交给下一步"不用自己拼文本；`box` 作为记录里的一个字段留着，写给手写文件与变量字段用。
- 默认变量名从 `<备注>_<动作>_<返回值名>_<标识>` 收到 `<备注>_<返回值名>`，重名时在末尾补步骤标识
  （落点是 `VariableNames.ForStep`）。

**收尾**：`allMatches` 参数与它的文案键、`GiveEvery` 的中心点列表、四张并列表、旧命中的十一个返回项与它们
的文案键，全在这一阶段里删掉。

**验收**：引擎的替身设备层用例——一次命中交出一个记录、全部命中是记录列表、没勾的返回值不写变量，各一条；
`field` 取值、缺字段报错、记录的 JSON 往返，各一条；`ReturnsPageTests` / `ReturnNameTests` /
`ActionPageTests` / `MacroCheckTests` / `VariableWallTests` 与 `SampleFiles.cs` 里的样例宏跟着改；
[manual.md](manual.md) 的「返回值」整节改写。

### 阶段 2 · 参数说的话要对得上

**为什么**：同一个样子、同一个位置的框，一个会算算式、一个不会；"留空"在一张表单上有两种意思；"等不到怎么
办"写在两处。这些只能靠记住，记不住就写错，而且错了不报错。

**现状**：只有整段以 `$` 开头的值才是算式，其余是文本加就地替换（`AcceptsFormula` 与 `AcceptsVariables`
是两件事），两种框外观一样；区域那四个数留空是"从这条边量到屏幕边缘"，别的数字字段留空是"没说"，区别只在
文档里；`control.waitUntil` 自带 `timeoutMs` 与 `onTimeout`，与步骤超时加失败策略说的是同一件事；坐标基准
与"窗口矩形按看见的算"只是文档里的约定，表单上不提示。

**改成**：

- 表单按 `ActionParameter.AcceptsFormula` 给算式字段一个看得见的标记（行首一个小 `ƒ`），提示行第一句写明
  "这里可以写算式"；文本字段的提示行写明"这里不计算式，`$名字` 只做替换"（将新增的用户可见文案，两侧键
  一起加）。
- 区域那四个框的占位文字写明"留空到屏幕边缘"；其余数字字段的提示行写明"留空即没填"。
- `control.waitUntil` 的 `timeoutMs` 与 `onTimeout` 删掉：等多久由这一步的「超时」说，到点判失败，交给重试
  与失败策略；`pollMs`（检查间隔）保留。
- 区域参数旁常驻一行小字，说明当前的坐标基准（屏幕 / 窗口 / 客户区 / 元素锚点）以及它给的是哪个矩形。

**收尾**：`waitUntil` 的两个参数与它们的文案键删掉；"哪些框能写算式"从"要记住"改成"看一眼就知道"。

**验收**：`ActionDialogTests` 卡住算式字段带标记、文本字段不带；引擎里"`waitUntil` 到点判失败并按失败策略
走"一条；文案两侧补齐；[manual.md](manual.md) 的「画面从哪来、怎么取」与「返回值」两节跟着改。

### 阶段 3 · 子宏成一次真正的调用

**为什么**：一段流程要用第二次，今天只能开新宏、手工抄、再手写 `NAME=value`；写错名字不报错，交回的名单点
不到就静默变空——"复用"这件事现在靠人不出错。

**现状**：`control.runMacro` 的 `arguments` 是自由文本（一行一个 `NAME=value`），`bringBack` 是一个用逗号
分开的名字表；两侧都不与子宏对账；没有"把选中的步骤提为子宏"这条路。

**改成**：

- 宏文件新增顶层声明（将新增）：这个宏收哪些**形参**（名字 / 默认值 / 是否必填 / 说明），以及它愿意**交回**
  哪些名字（复用返回值那一套声明）。
- `runMacro` 的参数页改成按子宏声明出的表单（将新增）：逐个形参填值，值照旧按字段的读法读；交回项改成勾选；
  不再手写 `NAME=value`。
- 设计期检查卡住两处对账（将新增）：参数名子宏没声明、交回的名字子宏没声明。
- 选中一段步骤可以「提为子宏」（将新增）：建一个新宏、把这段搬过去、原地留一条 `runMacro`，这段里用到的本
  宏变量列成待填的形参。

**收尾**：`arguments` 的自由文本写法与 `bringBack` 的自由名单退出（`.wgmacro` 未发布，不留读旧的路径）。

**验收**：引擎里"形参有默认值可以不填 / 必填没填报 `Run.MissingArgument`（将新增）/ 交回名不存在时报出来"
各一条；`MacroCheckTests` 增两条；`ActionDialogTests` 卡住表单随子宏切换；[manual.md](manual.md) 补子宏长
什么样，[dev.md](dev.md) 补文件形状。

### 阶段 4 · 运行调试用来排障

**为什么**：出了事只能看到"这一步失败了"，看不到花了多久、为什么失败；想看一眼某个返回值，还得回去勾上再
跑一遍——调试的成本高到大家干脆不调。

**现状**：每步的耗时只在超时判定里算了一次（`MacroRunner` 里那个 `elapsed`），没有交给用户；失败只有
`step.<id>.outcome`（`ok` / `failed` / `skipped`），`control.try` 里读不到原因；断点只能按步骤下；没勾的
返回值在界面上也不显示。

**改成**：

- 引擎每步执行完，把这一次**真正算出的全部结果**连同耗时与失败原因交给 `IRunLooks`（将新增一条回调，沿用
  「正在读哪个窗口」那条先例）；界面在运行调试的步骤行上给一个只读面板，与勾不勾无关。
- 失败原因写成系统变量 `step.<id>.error`（将新增）：失败时装错误键，成功与跳过时为空，宏因此能按原因分支。
  耗时只进界面与日志，不新增变量——每一步写一个耗时变量会把变量表撑爆。
- 断点可以带一个**可选条件**（将新增）：复用条件目录，不成立就不停；停在断点上时可以「跳过这一次」。

**收尾**："为了看一眼结果所以先勾上"这套绕法从文档里去掉——勾选从此只决定"要不要进变量表"，不决定"看不看
得见"。

**验收**：引擎里"面板拿得到没勾的结果 / `step.<id>.error` 只在失败时有值 / 带条件的断点不成立就不停"各
一条；`RunStepOutcomeTests`、`RunLookTests` 跟着扩；界面用例卡住面板与断点菜单；[manual.md](manual.md) 的
「运行与调试」改。

### 阶段 5 · 便利与归位

**为什么**：调一次"落手稳一点"要挨个动作翻四页；步骤行上看不出它走哪一档输入；一个变量被哪几步读了要自己
搜；CSV 的行与列名又是一对并列表。

**现状**：落手与节奏那一组参数（`variance`、`moveBack`、`settleMs`、`recheckMs`、`repeat` /
`intervalMs`、抖动）散在各动作、分在四页；步骤行不显示输入方式；变量墙只列"哪些变量被用到"，不列"哪几步
用到"；`file.readCsv` 的行是 `List<List<Text>>`，列名另交一张并列表。

**改成**：

- 用目录里已有的共用参数组写法，把这些参数抽成一组、排在同一处（基础设置里"这一步怎么做"那一段）；**键名
  与文件形状不变**，只动表单怎么摆。
- 步骤行加一个小标记，写明这一步走的是前台、后台消息还是驱动级（将新增）。
- 变量墙上点一个名字，列出用到它的步骤，点一下跳过去（设计期，靠 `Expression.ReferencedNames` 与各字段
  扫描）。
- `file.readCsv` 的行改成记录（将新增；键＝列名），`columns` 那张并列表删掉。

**收尾**：`columns` 返回值与它的文案键删掉；同一组参数不再各动作重复定义。

**验收**：`ActionPageTests` 卡住这一组的页归属，`StepTreeTests` 卡住步骤行标记，`VariableWallTests` 卡住
反查，"CSV 的行是记录、列名不再另交"各一条；[manual.md](manual.md) 的「分隔符文件」与「落点与落手」改。

### 阶段 6 · 触发可靠

**为什么**：窗口每 500 毫秒看一次、进程每次轮询读一遍快照，两次之间"启动又退出"的进程必然漏掉。用户看到的
是"我明明开了那个程序，宏没跑"。

**现状**：全是轮询（`MacroTriggerService` 的 `WindowPollInterval` 与 `PollProcesses`）；漏检率没有量过，
也没有观测手段。

**改成**，两步走：

1. **先量**：用阶段 4 的观测手段与这组手动用例，量一次真实的漏检率，把数字与结论写进这一节。用例：窗口
   出现 5 例、窗口消失 5 例、进程启动后 300 毫秒内退出 5 例。
2. **再定机制**，判据写死：能复现漏检就上事件——窗口用 `SetWinEventHook`（零新增依赖），进程用 WMI（新增
   官方包 `System.Management`，按工程规矩 5 登记）；复现不出来就只做"轮询间隔可配（最低 50 毫秒）＋去重"。

两条路都要保留"拿不到事件就回到轮询"的降级分支（将新增），并且运行调试里看得见每个触发器上次判定与下次轮询
的时间（将新增）。

**收尾**：这一节做完时把量到的数字与选了哪条路写清楚——决定不做的理由也要留下，免得下一个人再量一遍。

**验收**：触发器用例覆盖去重与降级；`TriggerKindTests` / `TriggerTests` 扩；手动按上面 5 + 5 + 5 例走一遍
并把数字写进本节。

### 阶段 7 · 多宏并行安全

**为什么**：同时跑两个宏时键鼠互相插队，界面上看不到"另一个宏正在发输入"。设计上宏内不并行、要并发就配多个
宏，那就得让并发的代价说得清。

**现状**：所有宏共用程序持有的那一份设备层（`SharedDevices`）；发输入没有互斥，也没有提示。

**改成**：

- 宏多一个开关「与别的宏互斥发输入」（将新增，默认关，写进宏文件）：开了的宏之间共享一条全局输入锁，只有
  "发键鼠"的动作取锁，读屏幕与识别不取。
- 运行调试里显示当前谁在发输入（将新增）。
- 设计期检查在这个项目里多个宏都会发键鼠时提示一次（将新增）。

**收尾**：默认行为不变（关着就是不拦），所以这一阶段不删别的东西——删掉的是"看不出别人在跑"这件事。

**验收**：引擎里"两个开了开关的运行互斥 / 默认关时不拦"各一条；界面用例卡住开关与状态显示；
[manual.md](manual.md) 与 `AGENTS.md` 的并发模型那一段跟着改。

## 零散项

这两件跟任何阶段都不冲突，谁有空谁做，做完也把这一段删掉：

- **其余动作的说明按书面语过一轮**：视觉与文字识别那一批已经改过，其余一百多个动作照 `AGENTS.md` 规范 2
  改。机械、无风险，按类别分几条提交，`LocalizationTests` 与 `ActionPageTests` 全绿即算完成。
- **删掉没人用的 `OpenCvSharp5.AvaloniaExtensions`**：[dev.md](dev.md) 记着它没被调用、只会把 Avalonia 带
  进引擎的依赖图。删引用、跑三项，再从 dev.md 的依赖表与 `THIRD-PARTY-NOTICES.md` 去掉那一行。

## 明确不做

这些是已经决定过的事，写在这里免得反复讨论；这一段永久保留：

- **防检测**：不查内存、不改包、不做驱动级隐藏。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿与 HTTP / 数据库 / 邮件 / XML 一类企业系统。
- **第二套流程机制**：用户可见的流程控制只有块，加上循环体内的 `break` / `continue` 与「停止整个宏」。
- **办公向的逐参数缺口**：暂时不追（最大一块是浏览器缺下拉选择 / 勾选 / 悬停 / 按键 / 等元素 / 上传文件）。
- **记住上次填过的值**：再填一遍用复制步骤就够了。
- **不为旧 `.wgmacro` 留兼容读法**：形状换了就换，见 `AGENTS.md` 规范 7。
- **记录只有一种说法**：不加 `$hit.score` 这类词法，也不做"记录与标量并存"；生成记录的函数（`record(...)`）
  暂时不做，等真有动作需要读用户造的记录再开。
