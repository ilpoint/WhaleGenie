# WhaleGenie 开发路线图

本文件只记录尚未完成的工作、待评估事项和产品非目标。长期规范见
[AGENTS.md](../AGENTS.md)，开发与验收命令见 [dev.md](dev.md)，当前实现见
[architecture.md](architecture.md)，已实现的用户行为见 [manual.md](manual.md)。

## 规划规则

- 阶段完成后删除对应内容，变更历史由 git 保存。
- 一个阶段只解决一类问题，并具有明确的依赖、修改范围、自动化验收和必要的手动验收。
- 不记录工期。优先级依次考虑：用户能否表达需求、文档与实现是否一致、多条宏同时运行是否正确。
- 先处理契约和静默错误，再处理行为扩展与操作便利；游戏与办公场景具有同等优先级。
- 待评估事项必须先取得测量结果，再决定是否升级为阶段。

## 阶段

阶段按顺序实施，前一个阶段的验收是后一个阶段的前提。完成一个阶段后删除其条目。
本轮的目标是让轮盘成为与键盘、菜单同等的触发入口，而不是挂在主流程之外的一块界面。

### 阶段 1 · 设置窗口的宿主与拾取器（已实现，待手动验收）

设置窗口改为独立非模态，拾取器不再把它当成“该藏起来的窗口”。

- **依赖**：无。
- **范围**：`SettingsWindow` 改由 `ShowAsPeer` 打开并保持单实例；关闭后刷新运行时状态、热键提示与
  列表排序；拾取器沿用现有的让位与回来路径，不为模态宿主另开分支。触发器仍按“设置窗口开着就暂停”
  处理，与编辑器、运行窗口一致。
- **不做**：不把轮盘编辑器搬出设置窗口，也不新增窗口。
- **验收**：自动化——设置窗口以非模态方式打开、且同一时刻只有一个；拾取器让位用例全部通过。
  手动——在设置里“新增/编辑菜单规则”“轮盘新增场景”各走一遍取消与确定，按钮都响应、加完不崩溃；
  关掉设置后主窗口的列表与热键提示是新的。

### 阶段 2 · 轮盘输入管线（已实现，待手动验收）

先测量，再让一个鼠标移动最多只换一次画面。

- **依赖**：阶段 1（同一批窗口与钩子代码）。
- **范围**：`Runtime/WheelAim.cs` 收拢指针位置，钩子只写、界面每帧读一次；呼出键的按下与松开归
  轮盘所有，没有移动就松开的按下补发一次同样的点击；开场动画按墙钟推进而不是按帧计数；轮盘关闭时
  把开合时长、写入次数与绘制次数写进日志；扇区几何按尺寸与圈数缓存，指针移动只重绘画布；关闭后
  到达的回答按代际丢弃；投递出去的回答捕获异常并关掉轮盘，而不是让界面线程带着异常结束进程。
- **验收**：自动化——连续写入只换来一次读取；关闭后写入的移动不再被读到；短按交回一次补发、划开
  的按下与松开都被吞掉。手动——右键拖动桌面的窗口时看不到它自己的选择框，松开时也不弹出它的右键
  菜单；满三圈加两百条规则，连续划十秒、开合一百次无未处理异常；`runtime.log` 的 `wheel.frames`
  一行里 `moves` 明显大于 `drawn`，`drawn` 与开合时长同量级（约每秒 60 次）。

### 阶段 3 · 触发视图与分组（已实现，待手动验收）

`MacroView` 取代了五个“触发器桶”，轮盘槽位随项目走，分组是视图之外的第二层。

- **已实现**：`全部 / 按键 / 界面 / 字串 / 菜单 / 轮盘 / 事件` 七个视图，默认“全部”；轮盘视图直接从
  `WheelMenuRules` 派生；宏的 `group` 随宏写进包，主界面的分组筛选与视图、搜索同时生效；导入的宏
  保留分组，轮盘槽位不随导入进入现有项目。
- **决定**：固定视图只做筛选、不做归属；`WheelMenuStore` 只留机器级选项；不保留旧
  `wheel-menu.json` 的规则读取，`triggers.json` 增加 `wheel` 节点但不升包版本。
- **验收**：自动化——同一宏在“全部”和它所属的每个视图各出现一次；只在轮盘上的宏出现在轮盘视图；
  没有触发入口的宏只在“全部”；分组筛选与“未分组”各筛出正确的宏。手动——建两个分组、把宏放进去，
  重开项目后仍在；把项目拷到另一台机器，轮盘槽位仍指向同一批宏。

### 阶段 4 · 新建流程与默认值（已实现，待手动验收）

新建的宏不带触发器，也不再默认循环。

- **已实现**：`MacroItem` 与 `TriggerEntry` 的循环默认改为 `Press`（读文件时缺字段同样按它）；
  `AddMacro` 不再补空按键条目；编辑器按入口视图准备第一条入口，菜单与轮盘视图在保存后放到空位。
- **决定**：不迁移旧宏的 `loopMode`；缺字段按新默认读取，不为兼容增加分支。
- **验收**：自动化——新建宏没有触发器且 `loopMode` 为 `Press`；七个视图各自准备正确的入口；从菜单
  与轮盘视图新建的宏落到第一个空位。手动——新宏第一次运行只执行一次，再次触发仍只执行一次。

### 阶段 5 · 轮盘编辑与键位冲突（已实现，待手动验收）

轮盘留在设置里，但要好编辑、不抢键。

- **依赖**：阶段 1、阶段 3。
- **范围**：扇区左键快速选宏、右键打开 `WheelActionWindow` 编辑宏／备注／图标，“清除该位置”
  一次清空；不再保留依赖悬停的备注框与“选图标 / 加子动作 / 清子动作”按钮（鼠标移开扇区就丢失
  目标，按了没有反应）。轮盘窗口与编辑器现在都画图标：有文字时图标在文字上方，打开“只显示图标”
  时只画图标；图片图标复制到项目目录并缓存，不再出现“选了图标却没变化”。全局热键与菜单呼出键、
  轮盘呼出键三方互相检查，冲突时拒绝保存并指出被谁占用。
- **决定**：编辑以副本进出，取消不改项目；程序场景里编辑继承自全局的位置时，保存即写成该场景的
  覆盖；清除一个位置会连备注和图标一起清空。**曾试做过宏列表拖入、填充空槽和子动作扇出，实际
  使用后都去掉了**：拖入不如左键点一下快，空槽填充放进去的动作大多还要逐个改，子动作则很难在
  扇出的小扇区上稳定选中；槽位保持“一个宏、一条备注、一个图标”。
- **验收**：自动化——`OpensFor` 在没有程序场景时拒绝、命中后只在该程序放行；继承位置保存为覆盖、
  清除后不留备注／图标；配置了内置图标的扇区在“显示文字”状态下也能找到图标控件。手动——右键
  编辑与清除各走一遍；选一个图标后确认文字上方出现图标，打开“只显示图标”后只剩图标；把全局
  热键改成某个呼出键时被指出；改键后原键位立即恢复原用途。

### 阶段 6 · 轮盘按软件启用（已实现，待手动验收）

轮盘可以默认关着，只在两三个常用软件里打开。

- **依赖**：阶段 3（程序场景已随项目保存）。
- **范围**：`WheelOptions.OnlyInPrograms` 与设置页开关；打开后 `WheelGesture` 只在程序场景命中
  前台窗口时接管呼出键，其他软件里连按下也不吞；命中不到时状态行说明“哪里都不会弹出”。
- **决定**：判断用 `MainWindow` 复制给钩子线程的 `WheelMenuRules` 快照，不读界面线程的集合；
  按下时命中的场景一直用到这次轮盘关闭，中途前台变化不换场景。
- **验收**：自动化——没有场景时拒绝、命中场景的程序放行、其他程序拒绝、没有前台窗口时拒绝。
  手动——在桌面和记事本里短按与拖动呼出键都表现成普通按键；在配置了场景的程序里轮盘正常弹出。

## 待评估

以下事项尚未承诺实施。升级为阶段前须写明测量结果、目标、范围和验收方法。

### 契约与正确性

- **试运行的执行路径对账**：`LooksAtScreen` 已由目录声明，但 `SeeOnce` 等实际查看路径仍含手写分派。
  先统计声明与实现可系统性漏配的动作，再决定采用目录驱动、按动作键对账或反向 fixture。
- **其余等待动作的行为用例**：部分等待动作只验证能够结束。参照已有的“第 N 次才满足”夹具，
  优先覆盖 `vision.waitColor`、`browser.waitFor*` 和 `clipboard.waitChange`，确认等待、满足和超时
  三种路径。
- **补丁成本**：当前局部补丁仍需读取并校验整宏。使用约两百步的宏比较 `set` 与 `get_step` 的耗时，
  确认瓶颈后再决定是否引入增量校验。

### 结构与诊断

- **审计与失败日志的读取边界**：两类日志同处 `logs/` 但文件名不同。检查一次真实运行产生的文件及
  读取路径，决定是否需要目录分离或显式路径参数。
- **无界面命令行**：只有出现 CI 批量验包、脚本生成宏等真实调用方时，才评估将 `Models/`、
  `Storage/`、`Localization/` 拆出界面工程；没有调用方则不新增入口。
- **MCP 工具发现与审计登记**：工具类型和审计调用仍有手工登记点。先通过故障注入确认漏登记能否被
  现有测试发现，再决定是否采用自动发现或统一拦截。

### 用词

- **术语统一只做到了设置页**：编辑器、动作文案与手册里仍有「热键」「抓屏」「图片」与设置页的
  「快捷键」「屏幕捕获」「画面」并存。先统计动作文案里各说法的分布，再决定是否连同 `ActionStrings`
  一起换代；换代时要同步 `doc/manual.md` 的字段表与失败键表，不能只改设置窗口。

### 动作与编辑器表达

- **表单对可选参数的陈列**：多点找色这类动作用到十几项设置，其中多数不填也能跑（`X`、`Y`、`位置`、
  `tolerance` 等），平铺下来读者分不清哪几项是这一步真正要回答的。先统计常用动作里“每次都填”
  与“很少填”的字段，再决定按必需/可选折叠、按用途分组，或把少用项并入高级页；不以删参数为目的。
- **询问与说明的重复入口**：评估 `control.ask` 与 `control.input`、`control.note` 与步骤备注的
  实际使用差异，再决定合并或保留。
- **变量写入动作数量**：评估 `setVariable`、全局累计和列表写入动作在动作库中的搜索与选择成本，
  不仅为减少动作数量而合并。
- **子宏入口**：评估子宏 Dock 的导航与插入用途；只有页面导航已有等价入口且使用数据支持时才移除。
- **程序族的命令行预览**：`process.start` / `command.run` 的程序、参数、工作目录是并列三格，编辑期
  看不到拼起来的命令。前提是先定变量在预览里显示 `$名字` 还是留空；验收是两格各自改动后预览跟着变、
  参数为空时不画这一行。
- **列表动作的行表**：`control.listAdd` / `listInsert` / `listSet` 只有一格 `value`，`control.forEach`
  的 `items` 也只有一格整值，编辑期看不见目标列表里已有什么、也不能一次给多项。前提是先弄清「看见已有
  条目」与「一次给多项」是不是同一件事；验收要有真实宏说明需要哪一种。

### 补动作与参数

对照同类软件（大漠与按键精灵的找图、UiPath 与 Playwright 的元素、AHK 与 PAD 的脚本、文件与系统）
逐项比过之后留下的缺口。逐条写明现状、前提和验收；补完一条删一条。

- **文件撞名的策略统一**：`file.copy` / `file.move` 是三选一 `ifExists`（覆盖 / 跳过 / 换个名字），
  `file.unzip` 只有一个 `overwrite` 开关且默认开，`file.writeJson` 没有任何策略——它恒定读旧文件、
  合并键、整份写回。前提是先定这三处的词是不是同一套；验收是三个动作在同一份宏里对同一个目标各跑一次。
- **文件读写失败的细分**：现在只有 `Run.FileFailed` 与 `Run.FileNotFound`，分不出被占用、没权限、
  磁盘满。前提是先定这层信息是「新的失败键族」，还是「像脚本那样多一条 `error` 结果」——结构列讲的是
  值的形状，塞不进失败键。

**已核对过、确实不是缺口的**，不要再当作待补项提出：每步超时（`StepTimeoutMs`，执行与容错页的
「最多花多久」，0 表示不限，从第一次尝试起算、所有尝试与重试等待共用，块上的超时覆盖整段，等待动作的
「等多久」也由它兜住）、重试次数与间隔（间隔可固定 / 线性 / 指数）与失败四选一、脚本交回结果（输出、
错误、退出码）、提示音放自己的 wav、显示桌面、机器事实（含空闲秒数、是否管理员、空闲与总内存、系统盘
剩余）、文件写的编码（四个选项一致，GBK 不乱码）、列文件夹的 `kind`（文件 / 文件夹 / 两样都要）、
剪贴板等待（30ms 固定轮询，由步骤超时兜住，刻意不给间隔参数）。

## 产品非目标与暂不计划

以下事项不属于当前产品方向。重新提出时须说明前提变化、真实使用场景和可验收收益。

- **防检测与隐藏**：不读取其他程序内存、不修改其程序包，不提供驱动级隐藏。VIIPER 仅作为输入通道。
- **专用验证靶场**：不在产品或测试中恢复只验证自身的靶场窗口；真实输入使用现有桌面程序验收。
- **多尺度模板匹配**：分辨率变化时使用相应参考图，不引入自动多尺度匹配。
- **`dir` 0–8 那套方向**：不照搬。找图留四向 + 面积 / 分数 / 随机；颜色族只有四向（命中是一像素，
  面积与分数没有意义），「从中心向外」在颜色族试过又删了，不做回来。
- **PNG 的 alpha 与四角同色**：找图的透明色只认「指定的一个颜色 + 容差」，不按 alpha 通道判、也不从
  四角推断。吸管取一次底色与它等价，而按 alpha 要把参考图的解码从彩色改掉，会动到所有参考图。
- **多锚点**：元素锚点只给一个。「在『确定』右边」一个够用，两个锚点会让查询结构再长一层。
- **网页的 strict 模式**：多个命中不报错，用 `matchIndex` 取第几个，默认第一个。
- **注册表的其它根**：只给当前用户与这台机器；HKCR、HKU 那几处改的是「每个程序都照它办」。
- **条件里直接问窗口与进程**：要么先加一步（`window.exists` / `process.exists`）再比它写出来的变量，
  要么给表达式开宿主函数的口子——后者要让 Core 的表达式表接设备，而 `while` / 等待直到是 30 毫秒一轮
  的，每轮跨进程查一次窗口足以拖死程序。只给左值：`$sys.activeWindow`、`$sys.activeProcess`。
- **屏幕分辨率与默认打印机**：前者改整台机器的显示方式，后者要配合「打印一份文档」才自洽。
- **办公文档与企业系统解析**：不内置 PDF、Word、工作簿或企业系统连接器；数据文件聚焦 CSV、JSON
  和纯文本。通用 HTTP、数据库和邮件动作也需有反复出现的真实流程后再评估。
- **第二套流程机制**：不引入宏内并行块、从块内失败点继续或替代块结构的流程系统；并发由多个宏表达。
- **浏览器多实例**：同一时刻保持一份浏览器，通过标签页和浏览器门管理操作。
- **额外记录访问语法**：不增加 `x(记录)`、`y(记录)`、`point(记录)` 或 UIA 运行时句柄持久化；
  使用现有 `field()`、位置/矩形字段和稳定窗口规则。
- **完整静态类型系统**：只进行目录声明支持的类型检查，不做类型推导。
- **物理单位与 DPI 换算**：坐标与尺寸统一使用屏幕像素。
- **自动记住动作表单输入**：重新打开动作时使用默认值；需要复用时复制步骤。
