# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 还没做的事，给改这个仓库的人（含 agent）看。长期定位、规范与设计约定在仓库根目录的
`AGENTS.md`；工程命令、依赖、测试分层与发布看 [dev.md](dev.md)；用户怎么用看 [manual.md](manual.md)。

- **只写还没做的**：一个阶段做完就从这里删掉。做过的改动在 git 里，不在本文件留“已完成”账。
- **一个阶段是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，也会让读的人以为它在排期。
- **阶段必须可验收**：写清依赖、测试落点、手动项与完成条件；说不清怎么验的，不算一个阶段。

## 衡量标准与排序

判断标准有三条，按这个顺序看：

1. **用户能不能把这件事表达出来**：少一层绕路、少一个手写字段、少一次猜。
2. **已经说出来的行为是否与实现一致**：字段提示、手册、运行调试与引擎说的是不是同一件事。
3. **多条宏同时跑时是否仍然正确**：共享变量、输入门、浏览器当前页不能靠“碰巧不撞”。

排序原则：

- **先契约，后行为，再便利**：决定别的东西怎么写的（目录、读法、值形状、单位、空值、失败键、返回字段）
  排在前面；只是让人少点几步的排在后面。
- **先正确，后效率**：会静默出错的地方先修；只是更快的放到结构整理或后续阶段。
- **游戏向与办公向同等**：两者都是一等公民，不按场景偏好插队；同类里先做能解除后续依赖的那一项。
- **一个阶段只解决一类问题**：机械搬运、行为改变与文档重写不混在同一个提交里。

## 分层总表

这五层解决的是同一件事的五个面：**AI 能不能把宏写对、能不能自己看见结果、能不能自己跑一遍、在哪儿跑
才安全、试出来的问题能不能回到下一次**。

| 层 | 先解决什么 | 阶段 | 这一层交出什么 |
| --- | --- | --- | --- |
| 契约 | 契约与文案已对齐、读写粒度已到单步；子宏里的步骤仍只能整宏重发 | W4 | 子宏的步骤也能按标识读、按补丁改 |
| 看与动 | 运行日志已带每一步的答案；AI 仍不能运行宏；只有坐标点击 | O2、O3 | 开关打开时 AI 能自己跑一遍，并能起进程、等窗口、读元素与剪贴板 |
| 靶场 | 没有位置与颜色都固定的目标，也没有边界 | R2、R3、R4 | `--range` 一个已知窗口；越界按稳定代号拒绝；端到端出报告 |
| 自进化 | 尺子只量 MCP 的形状，不量动作与运行 | S1 | 改、量、比、提交四步有固定入口与前后两份报告 |

**依赖顺序**：W4 → O2 → O3 → R2 → R3 → R4 → S1。

**已经做完并撤下的**：P、M、C 三个系列，以及本轮的 R1（动作矩阵）、W1（契约与文案纠偏）、
W2（读侧补齐）、W3（写侧补齐）、O1（观测闭环）。改动见 git。

## 契约基线

`ActionSemantics.json` 是动作参数、读法、形状、单位、空值、选项、拾取器、等待与返回值的唯一真源；
`ActionDisplay.json` 只放标签、提示与控件种类，两份由 `ActionContract` 对账并在载入时全部报完再抛。当前
**176 个动作、789 个参数、205 个结果，其中 91 个动作带返回值**；每个带返回值的动作都有 `returns` 行列表，
调用的形参与结果来源由目录的 `SignatureSource` 声明。

“取不到”统一按契约失败处理，不猜默认值：展示元数据缺失让启动对账失败；用户文件里的返回请求不合法在运行
前报可分支的失败键；引擎写错形状在交付该结果时报错。这样自动提取只有一条路径，没有被吞掉的回退。

## 阶段

### W4 子宏里的步骤

**解决什么**：补丁只认得主宏的步骤树。子宏（`subMacros`）里的步骤只能整宏重发才动得了，而
`outline` 也从不列它们，于是客户端既看不见也改不了——一个用了子宏的项目，AI 只能重写整个宏。

**依赖**：W1–W3（已是同一套补丁，只差寻址）。

**做什么**：

- `outline` 与 `get_step` 覆盖子宏：每行带一层来源（`main` 或 `sub:<名字>`），路径仍按位置写。
- `patch_macro` 的定位参数认这一层：`macro: "sub:<名字>"` 或缺省等于主宏；`insert` 的 `parent`
  也能落在子宏的列表里。
- 拒绝时把「在哪个宏里没找到」写清，不让客户端在两层之间瞎猜。

**验收**：一个带子宏的宏能用补丁改子宏里的一步、插一步、删一步；`outline` 每行都能被 `get_step`
读回来；`get_macro` 与补丁往返之后子宏的声明不变。

### O2 受控运行入口

**解决什么**：AI 写了宏没法自证。今天运行只有人按，`--mcp` 进程里连触发器都不启动。要让它能自测，就得有
一个由人授权、能一次只跑一个、能停、能核的入口。

**依赖**：O1。

**做什么**：

- 浮层加第二档开关「允许 AI 运行宏」（`McpControl.AllowsRun`），默认关，服务器一停就复位；关着时运行类
  工具按 `DirectControlOff` 一类稳定代号拒绝，并说清是哪一个开关。
- 新工具：`run_macro`（可按草稿或项目里的宏，带总时长上限与“失败即停”）、`stop_macro`、`run_status`。
  一次只允许一个，第二个回 `RunBusy`；超时按“被停止”收尾；每次调用写审计行。
- `AGENTS.md` 的“不运行宏”改成“运行宏由第二档开关把守，`WhaleGenie.Core` 仍不依赖 MCP”；两条 prompt 的
  工作流补上“写完自己跑一遍再交给用户”。

**验收**：`McpRunTests` 用一条不碰机器的宏（赋值 + 条件失败）验三件事：开关关着被拒、开着跑完能读到结果、
第二次并发被拒；真实桌面手跑一条打字宏并按规范 5 记录。

### O3 动手补齐

**解决什么**：AI 现在只能按坐标点。不能起进程、不能等窗口出现、读不到元素的值、拿不到剪贴板，也不知道
控制开关此刻是开是关——每一步都要人先把窗口摆好。

**依赖**：O2。

**做什么**：

- 进程：`process_start` / `process_list` / `process_kill`（起进程返回的句柄可能还是 0，要说清楚）。
- 等待：`wait_for_window`（同 `window.waitFor` 的语义，超时给稳定代号）、`wait`。
- 读：`window_info`、`list_windows` 回进程与类名、`element_at` 回 `value` / `enabled` / `visible`、
  `find_elements`（按选择器枚举）、`clipboard_read` / `clipboard_write`。
- 归位：`capture_screen` 回 DPI 与缩放，`project_status` 回两个开关的状态。
- 全部走同一个门禁与输入锁，新拒绝码进码表。

**验收**：每个新工具在 `McpControlTests` 里有注入设备的用例；拒绝码有断言；码表与手册同版更新。

### R2 靶场窗口与重置

**解决什么**：没有一个“位置与颜色都固定”的目标，AI 只能拿真实桌面试；试坏了没有复位。

**依赖**：O2。

**做什么**：

- `WhaleGenie/Range/` 加靶场窗口：固定坐标的按钮、文本框、下拉、复选、滚动列表、一块已知颜色的区域，
  外加一个“危险按钮”——它只用来验证越界策略不会误点。客户区矩形以常量暴露。
- 重置：清文本、滚动回顶、取消勾选、重绘色块；工具 `range_state` / `range_reset`。
- `whalegenie.exe --range`：起靶场窗口 + 起 MCP 服务，stdout 打 `endpoint=` 与 `range=`。

**验收**：`--range` 起得来；`list_windows` 看得见它、`element_at` 读得到控件；`range_reset` 之后状态与
初始一致；真实桌面手动看一眼窗口并按规范 5 记录。

### R3 受控策略

**解决什么**：靶场里 AI 仍然能点到窗外、能对任意窗口动手、能让宏写任意路径。靶场的“受控”必须是代码而不
是约定。

**依赖**：R2。

**做什么**：

- `RangePolicy`：包在设备层外面的一层，四条闸按序——坐标必须落在靶场客户区内；窗口句柄只认靶场进程；
  文件路径限靶场目录；动作白名单拒绝结束进程、关机、脚本与驱动级输入。再加整次运行的时长闸。
- 拒绝码统一 `Range.*`，每条都写审计。
- 两条路径都必须经过它：动手工具与 `run_macro`。

**验收**：`RangePolicyTests` 逐条拒绝且码稳定；关掉靶场策略时同样的调用能过，说明拦的是策略不是能力；
审计里能看到拒绝行。

### R4 端到端靶场

**解决什么**：靶场、运行、观测各自成立，但“写—跑—读—改—再跑”这条完整的回路没有入口，也没有一份能前后
对比的报告。

**依赖**：R3 与 O2。

**做什么**：

- `--mcp-doctor --range`：拉起 `--range`，校验工具面，写一个靶场宏（点按钮 → 读文本 → 断言），跑它，
  读值，改一个值，再跑，出 `TestResults/mcp-range.md`。
- `doc/dev.md` 写清部署：一次性虚拟机里跑 `--range`，MCP 只绑环回，外机用 SSH 端口转发接进来，回滚快照
  就是重置靶场；并说明虚拟机只解决爆炸半径，“固定目标 + 动作矩阵”仍然要做。
- CI 里靶场项默认跳过，`WHALEGENIE_RANGE=1` 才跑：没有交互式桌面的机器上不能红。

**验收**：报告里两次运行的差异能看出来（改了哪一个值、第二次读到什么）；无桌面环境下跳过而不是失败。

### S1 自检与自进化闭环

**解决什么**：尺子只量 MCP 的工具形状：不跑动手工具、不跑运行、不量靶场；选填工具缺失还记通过；坏 JSON
只证明“失败了”而不证明它是按 `BadJson` 拒的。于是“改完是不是真的更好”仍然靠人看。

**依赖**：R4。

**做什么**：

- 尺子覆盖三块新面：动手工具（注入设备层）、运行入口（开关关/开两态）、靶场策略（越界拒绝）。
- 选填工具缺失记 `Missing`；坏 JSON 必须核对代号；新增“动作契约摘要”资源 `whalegenie://action-matrix`。
- `doc/mcp-usability.md` 加“动作矩阵”一节；`AGENTS.md` 写死自进化回路：**改 → 量（矩阵 + 体检）→ 比
  （前后两份报告）→ 提交**。

**验收**：`--mcp-doctor --spawn --strict` 全绿且条目数按分类增加；两份报告（改前/改后）都能在版本库里
找到；`Missing` 会让 `--strict` 退出码非 0。

## 可与阶段并行的零散项

- **权限按调用确认**：现在是进程级两档开关（直接控制、运行宏），用户已确认这样够用；如果以后要按客户端或
  按次确认，单独立一个阶段，不要塞进已完成的阶段里。
- **审计与失败日志分目录**：现在同在 `logs/`，`get_last_failure_log` 一度会读错文件；W1 先按文件名区分，
  分目录留到下次动日志结构时一起做。

## 仍然有效的取舍

这些决定继续约束后续阶段；要推翻时按最后一列的重开条件重新评估。

| 取舍 | 现在的决定 | 理由与重开条件 |
| --- | --- | --- |
| 游戏向排在办公向前面 | 改为同等 | 两者都是一等公民；排序只看依赖与表达能力 |
| 变量名单按方向分 | 写名字的框只列这个动作真正会写的名字；有 `scope` 的列本宏与共享，没有的只列本宏；读值框列全部四组 | 写名字与读值是两件事；不能让用户选了共享名字却只得到局部影子 |
| 输入门只认 `input.` / `gamepad.` 前缀 | 改为目录声明，并沿宏调用图看可达步骤 | 点击图片、点击文字、点击检测、UIA 回退点击都发真实鼠标；子宏的输入也要算进来 |
| 比文字只有五档、永远忽略大小写 | 保留五档，加两个开关 | 校验码、口令、逐行正则需要表达；默认不变 |
| 宏内并行 | 仍不做并行块 | 一个宏仍是一条顺序流程；并发用多个宏与后台运行 |
| 浏览器多实例 | 仍不做 | 成本在档案、上下文与登录态；门与提示已经把共享当前页说清 |
| HTTP / 数据库 / 邮件 | 仍不做通用动作 | 手册给出用脚本发请求的路径；真实办公流程反复卡住时再按阶段评估 |
| `.wgmacro` 旧格式兼容 | 不做 | 开发阶段没有外部旧宏；P1–P2 改字段形状时各升过一次包格式版本并拒绝旧包 |
| 记录取值 | 仍只保留 `field()` 作为字段访问；位置/矩形字段自己收记录 | 一套词法比省几个字符重要；P2 起字段直接吃记录，`field()` 只用于取其中一项 |
| 表达式缓存 | 不做 | 实测解析与求值是看屏幕成本的零头；缓存会多一层状态 |
| 坐标与单位 | 像素坐标允许负数；时长从 0 起；空值含义由目录声明 | 多显示器与窗口相对坐标本来就有负值；46 小时是时间上限，不是坐标上限 |
| 循环变量 | 与 `sys.loopIndex` 一样只属于最内层循环 | 嵌套循环同名变量互相覆盖是静默错误；要留下值就在循环里赋给别的名字 |
| 结果变量 | 只属于这一次尝试；每次尝试开始清空 | 失败、重试、循环里读到上一次的答案是更难查的错 |
| 记录作身份 | 窗口记录按 `title` / `process` / `class` 用；UIA 运行时句柄不写成值 | 句柄不可序列化；能稳定表达的身份先做 |
| 子宏的互斥发输入 | 子宏用自己的设置，父宏不覆盖 | 宏的声明应当跟着宏走；父宏只影响它自己的步骤 |
| 公共宏更新 | 拖入时复制并固定来源版本，已有副本不跟随 | 项目必须能脱离本机宏库运行；要换新版就再拖一次建立新副本 |
| AI 运行宏 | 由浮层第二档开关把守，默认关、服务器停即复位；一次只跑一个 | 运行一条宏能写文件、起进程，风险面比点一下大；要放开按次授权时另立阶段 |
| 靶场边界 | 由设备层外面的一层策略执行，不靠约定 | 约定挡不住 AI；策略可以被用例逐条验证 |

## 明确不做

- **防检测**：不查内存、不改包、不做驱动级隐藏（VIIPER 是输入通道，不是隐藏）。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿解析，也不对接企业系统；数据文件只做 CSV、JSON 与纯文本。
- **第二套流程机制**：用户可见的流程控制只有块，加上 `break` / `continue` / `return` / `stop`；
  `try` 的过滤与重抛是既有块的能力，不是新机制。
- **记住上次填过的值**：关掉再打开或换了动作都回默认值；再填一遍用复制步骤。
- **从块内失败那一步继续**：重试就是整块重来；要断点续跑是另一项能力。
- **浏览器多实例**：同一时刻只有一份浏览器；并发靠门与提示。
- **宏内并行块**：一个宏仍是一条顺序流程；并发用多个宏与后台运行。
- **字段别名与双读**：旧名在同一版删掉，不写迁移分支。
- **默认改成区分大小写**：两个开关默认关。
- **`x(记录)` / `y(记录)` / `point(记录)`**：记录当位置用由 `Point` / `Rect` 字段解决，不再加
  第二种访问器。
- **DPI 缩放与单位换算**：屏幕像素就是像素；不做物理单位。
- **UIA 运行时句柄记录**：句柄不可序列化；需要“找到再操作”时先走窗口记录与鼠标记录，UIA 的稳定
  选择器另议。
- **完整静态类型系统**：只做目录声明得到的类型对账，不做类型推导。

## 阶段验收规则

1. 一个阶段一串提交，每个提交只做一件事；机械搬运与行为改动分开。
2. 前置阶段没完成，不开工依赖它的阶段；同一文件会被两个阶段改时，先排定顺序。
3. 改代码的阶段收尾跑 `dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`；只改文档的
   阶段跑 `git diff --check`、链接检查与对应的文档对账测试（见 [dev.md](dev.md)）。
4. 新增或改动动作时，目录、引擎、设计期检查、文案、页面归属、返回值页、失败键、测试与手册同一版改完；
   旧形状在同一版删掉。改字段形状、单位、空值或记录字段时，同版补对账用例；改文件形状时升包格式版本
   并拒绝旧包。
5. 真实桌面的项按 `AGENTS.md` 规范 5 手动过一遍，结论写进提交信息；无头能覆盖的不得留到手动。
6. 阶段完成就删掉本文件里对应的小节；范围变了就重写目标、依赖与完成条件，不把旧验收留在原地。
