# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 接下来做什么，给改这个仓库的人（含 agent）看。它与仓库根目录的 `AGENTS.md` 分工：
`AGENTS.md` 讲定位、开发规范与设计约定（不常动的东西），这份文件只讲下一步动什么。用程序的人看
[manual.md](manual.md)，工程细节看 [dev.md](dev.md)。

- **只写还没做的**：一个阶段做完就把那一段删掉。做过的改动在 git 里，这里不留"已完成"清单——留着的话，
  这份文件会慢慢长成一本账，谁也不知道哪一条还算数。
- **一个阶段就是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，还会让读的人以为它在排期。
- 阶段里提到的东西如果还没在代码里，都写着"（将新增）"；没写的就是已经有的。

## 排序原则与衡量标准

- **先地基，后便利**：决定别的东西怎么写的（比如返回值的形状）排在前面；只是让人少点几步的排在后面。
- **游戏向排在办公向前面**。
- **判断标准只有一条**：用户能不能把这件事表达出来。
- **一个阶段的验收必须做得出来**：写清测试在哪、手动项是什么。说不清怎么验的，就不算一个阶段。

## 工程规矩

阶段里逐条照着做：

1. 一个阶段一串提交，每个提交只做一件事。
2. 阶段收尾三项全绿：`dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`（命令与出处见
   [dev.md](dev.md)）。
3. **改完就删旧的**：被新形状取代的参数、返回值、开关、文案键、测试与文档段落，都在同一阶段里删掉；不留
   双读、不留"旧文件也还能读"的分支。
4. 新增目录字段、返回值与文案时，中文与英文两侧的键一起加；`ActionPageTests` 的 Tuning 名单、
   `ReturnsPageTests`、`LocalizationTests` 跟着补。
5. 新增依赖必须是官方库、只 Windows，并写进 [dev.md](dev.md) 的依赖表与 `THIRD-PARTY-NOTICES.md`。
6. 真实桌面的项（移动鼠标、抓屏取色、注入按键、UIA 与页面拾取、录制、窗口布局）按 `AGENTS.md` 规范 5
   手动过一遍，结论写进提交信息。
7. 这一阶段动到的动作，说明文字按书面语顺手改（见 `AGENTS.md` 规范 2）。
8. 阶段做完，把这一段从这份文件里删掉。

## 阶段表

顺序就是"先地基、后便利"：读懂一个阶段的现状与改动，不需要先读后面的。

### 阶段 6 · 触发可靠

**为什么**：窗口每 500 毫秒看一次、进程每次轮询读一遍快照，两次之间"启动又退出"的进程必然漏掉。用户看到的
是"我明明开了那个程序，宏没跑"。

**现状**：全是轮询（`MacroTriggerService` 的 `WindowPollInterval` 与 `PollProcesses`）；漏检率没有量过，
也没有观测手段。

**改成**，两步走：

1. **先量**：用运行调试已经交出来的每步耗时与结果（`IRunLooks.Ran`）与这组手动用例，量一次真实的漏检率，把
   数字与结论写进这一节。用例：窗口出现 5 例、窗口消失 5 例、进程启动后 300 毫秒内退出 5 例。
2. **再定机制**，判据写死：能复现漏检就上事件——窗口用 `SetWinEventHook`（零新增依赖），进程用 WMI（新增
   官方包 `System.Management`，按工程规矩 5 登记）；复现不出来就只做"轮询间隔可配（最低 50 毫秒）＋去重"。

两条路都要保留"拿不到事件就回到轮询"的降级分支（将新增），并且运行调试里看得见每个触发器上次判定与下次轮询
的时间（将新增）。

**收尾**：这一节做完时把量到的数字与选了哪条路写清楚——决定不做的理由也要留下，免得下一个人再量一遍。

**验收**：触发器用例覆盖去重与降级；`TriggerKindTests` / `TriggerTests` 扩；手动按上面 5 + 5 + 5 例走一遍
并把数字写进本节。

## 零散项

这两件跟任何阶段都不冲突，谁有空谁做，做完也把这一段删掉：

- **其余动作的说明按书面语过一轮**：视觉与文字识别那一批已经改过，其余一百多个动作照 `AGENTS.md` 规范 2
  改。机械、无风险，按类别分几条提交，`LocalizationTests` 与 `ActionPageTests` 全绿即算完成。
- **删掉没人用的 `OpenCvSharp5.AvaloniaExtensions`**：[dev.md](dev.md) 记着它没被调用、只会把 Avalonia 带
  进引擎的依赖图。删引用、跑三项，再从 dev.md 的依赖表与 `THIRD-PARTY-NOTICES.md` 去掉那一行。

## 明确不做

这些是已经决定过的事，写在这里免得反复讨论；这一段永久保留：

- **防检测**：不查内存、不改包、不做驱动级隐藏。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿与 HTTP / 数据库 / 邮件 / XML 一类企业系统。
- **第二套流程机制**：用户可见的流程控制只有块，加上循环体内的 `break` / `continue` 与「停止整个宏」。
- **办公向的逐参数缺口**：暂时不追（最大一块是浏览器缺下拉选择 / 勾选 / 悬停 / 按键 / 等元素 / 上传文件）。
- **记住上次填过的值**：再填一遍用复制步骤就够了。
- **不为旧 `.wgmacro` 留兼容读法**：形状换了就换，见 `AGENTS.md` 规范 7。
- **记录只有一种说法**：不加 `$hit.score` 这类词法，也不做"记录与标量并存"；生成记录的函数（`record(...)`）
  暂时不做，等真有动作需要读用户造的记录再开。
