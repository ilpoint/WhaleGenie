# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 接下来做什么，给改这个仓库的人（含 agent）看。它与仓库根目录的 `AGENTS.md` 分工：
`AGENTS.md` 讲定位、开发规范与设计约定（不常动的东西），这份文件只讲下一步动什么。用程序的人看
[manual.md](manual.md)，工程细节看 [dev.md](dev.md)。

- **只写还没做的**：一个阶段做完就把那一段删掉。做过的改动在 git 里，这里不留"已完成"清单——留着的话，
  这份文件会慢慢长成一本账，谁也不知道哪一条还算数。
- **一个阶段就是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，还会让读的人以为它在排期。
- 阶段里提到的东西如果还没在代码里，都写着"（将新增）"；没写的就是已经有的。

## 排序原则与衡量标准

- **先地基，后便利**：决定别的东西怎么写的（比如返回值的形状）排在前面；只是让人少点几步的排在后面。
- **游戏向排在办公向前面**。
- **判断标准只有一条**：用户能不能把这件事表达出来。
- **一个阶段的验收必须做得出来**：写清测试在哪、手动项是什么。说不清怎么验的，就不算一个阶段。

## 工程规矩

阶段里逐条照着做：

1. 一个阶段一串提交，每个提交只做一件事。
2. 阶段收尾三项全绿：`dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`（命令与出处见
   [dev.md](dev.md)）。
3. **改完就删旧的**：被新形状取代的参数、返回值、开关、文案键、测试与文档段落，都在同一阶段里删掉；不留
   双读、不留"旧文件也还能读"的分支。
4. 新增目录字段、返回值与文案时，中文与英文两侧的键一起加；`ActionPageTests` 的 Tuning 名单、
   `ReturnsPageTests`、`LocalizationTests` 跟着补。
5. 新增依赖必须是官方库、只 Windows，并写进 [dev.md](dev.md) 的依赖表与 `THIRD-PARTY-NOTICES.md`。
6. 真实桌面的项（移动鼠标、抓屏取色、注入按键、UIA 与页面拾取、录制、窗口布局）按 `AGENTS.md` 规范 5
   手动过一遍，结论写进提交信息。
7. 这一阶段动到的动作，说明文字按书面语顺手改（见 `AGENTS.md` 规范 2）。
8. 阶段做完，把这一段从这份文件里删掉。

## 阶段表

### 空手起步：看得见的手册与示例宏

**现状**　帮助菜单的「快速上手」打开的是 GitHub 上的 `doc/manual.md`：没网就什么都没有。包里的手册不存在，
主列表空着时也只有"新建"，第一次打开程序的人手上没有任何能跑起来的东西。

**改成什么**　打包时把 `doc/manual.md` 放进包（`build/package.ps1`），程序优先打开包内那一份、找不到再回落
到仓库地址；帮助菜单与空列表各加一条「插入示例宏」（将新增），示例覆盖拾取、找图与找文字、条件、子宏与运行
调试各一块，插进主列表就能跑。

**怎么验收**　界面用例两条（手册那一份在包内时以它为准；示例宏插进列表后 `MacroCheck` 不报问题）；
`build/package.ps1 -Tag vTEST` 跑一次，确认包里有 `doc/manual.md`；手动一条（断网时点「快速上手」，打开的
是包内那一份）。

### 界面不再点名具体实现

**现状**　除组合根（`WhaleGenie/Execution/SharedDevices.cs`、`App.axaml.cs`，以及 `MacroTriggerService` 与
`RunViewModel` 那两个默认参数）之外，界面还有 11 处直接点名 Windows 的实现：`WindowsScreenDevice.CursorPosition()`
8 处（取色器 3、宏编辑器 3、元素拾取 1、添加动作 1）、`new FlaUiDevice()` 2 处（元素拾取 1、添加动作 1）、
`new InputHookRecorder()` 1 处（宏编辑器）。`WhaleGenie.Core.Devices.Platform` 这个命名空间因此出现在界面里的
19 个文件里：多一个实现或多一个替身时，界面得跟着改。

**改成什么**　光标只留一个问法——`IScreenDevice` 加一个 `Cursor`（将新增），引擎里 `IInputDevice.Cursor` 改成
委托它，界面不再自己问 `WindowsScreenDevice`；取色器、元素拾取器与打开它们的窗口从组合根交来的 `IScreenDevice`
与 `IUiDevice` 取用；录制器由设备层交出（`IDeviceLayer` 多一个口，将新增）。组合根照旧由程序决定用哪一套
Windows 实现。

**怎么验收**　界面里除组合根那两个文件外不再出现 `WhaleGenie.Core.Devices.Platform`，加一条扫源码的用例卡住；
取色器、元素拾取器、录制各一条替身用例；真实桌面按 `AGENTS.md` 规范 5 过一遍三个拾取器与录制，结论写进提交
信息。

### 运行调试窗口：跑到哪一步看得见，算了什么看得清

**现状**　三处：

- 工具栏那一行只有六格（`RunWindow.axaml` 的 `ColumnDefinitions="Auto,Auto,Auto,Auto,*,Auto"`），而「现在
  是谁在发输入」那一行写在第七格（`Grid.Column="6"`）。Avalonia 把超出最后一格的列都归到最后一格——量过：
  三格的 Grid 里 `Grid.Column="2"` 与 `Grid.Column="5"` 落在同一个 x 上——所以勾了「与别的宏互斥发输入」
  的宏又调过运行速度时，那一行与右边的倍速徽标叠在一起（`Grid.Column="5"`，六格里的最后一格）。
- 步骤列表只把当前行换个底色（`RunViewModel.CurrentId` → `RunStepViewModel.IsCurrent` → `RunRow.current`），
  不跟着滚动：长宏跑到一半，"现在在哪"要自己找。日志那一栏倒是自动跟到底（`RunWindow.axaml.cs` 里给
  `LogScroll` 接的那一条），两栏行为不一致。
- 每一步算出的结果按一行文本显示：`StepRun.Results` 里的 `StepResult.Text` 是值的 `AsText()`，一条记录
  因此是一串 JSON、一串命中因此是好几个 JSON 用逗号接起来（`Value.AsText` 对列表就是这么接的），挤在
  340 宽的左栏里被 `TextTrimming="CharacterEllipsis"` 截掉，只能靠悬浮看全。想知道一个命中的 x、y 落在
  哪里，正卡在这一处。

**改成什么**　（1）工具栏那一行按「按钮 / 状态 / 倍速 / 谁在发输入」重排，写下的列号与 `ColumnDefinitions`
数出来的格数对齐。（2）当前行变化时把那一行滚进视野、上下各留一行余量；滚到哪儿由一个能单测的纯函数算
（与 `LookGeometry` 同一路：当前行的上下边界、行高、视口高度进去，滚动位置出来）。（3）结果是记录的展开
成一行一个字段，复用「其它设置」里 JSON 预览那棵树（`JsonTreeNode`）：一级缩进，键与值各占一列；列表里的
每一项是一条记录时照样分层展开，值不再截断、超长换行。

**怎么验收**　界面用例三条（工具栏那一行与倍速徽标都显示时两个矩形不相交——无头会话里能量到真实矩形；
滚动落点的纯函数喂进几种行号与视口高度，当前行整体落在可视区内；一条命中记录在步骤行上展开成 `x`、`y`、
`score` 各行）；手动一条（写一个二十步的循环宏跑起来，列表跟着当前行走），结论写进提交信息。

### 运行调试：从哪儿开始，怎么一步步走

**现状**　单步、继续、停止、断点与断点条件本来就有：工具栏上是「运行 / 单步 / 继续 / 停止」四枚
（`Run.Run`、`Run.Step`、`Run.Continue`、`Run.Stop`），断点是步骤行左边那个圆点，右键圆点还有「设置断点
条件…」「跳过我这一次」与「清除」（`RunWindow.axaml.cs` 的 `OnBreakpointMenuClicked`）。缺的是入口与发现
性，四处：

- 主窗口标题栏那枚「运行与调试」开的是不带宏的窗：`HasSteps` 为假，运行控制整条不画，只留一行「从主列表里
  右键某个宏，就能开始调试它」（`Run.DebugFromCard`）。从主界面点进去的人因此看不到任何"开始"的按钮。
- 编辑器里的「运行并调试这个宏」（`Palette.Run`，F5）只把窗口装好、不开跑（`MacroEditorWindow` 的
  `OnRunRequested` 只 `ShowOver`），而卡片右键是装好就开跑（`RunViewModel.DebugAsync` 末尾那句
  `RunCommand.Execute`）。同一个动作两处不一样，第二次点的人得猜。
- 「跳过这一步（这一次）」有命令没按钮：`SkipStepCommand` 只在圆点的右键菜单里，那还是"停在断点上"才知道
  去找的地方。
- 断点怎么下没有任何一处文字说明：圆点宽 16 像素，它的提示现在写的是步骤名字（`ToolTip.Tip="{Binding Label}"`）；
  窗口里也没有任何快捷键（编辑器里 F5 是开窗，到了这扇窗里 F5 什么都做不了）。

**改成什么**　（1）不带宏打开时，那句提示下面补一行「跑哪个宏 + 开始调试」（将新增的文案键，中英两侧）：
下拉列出项目里的宏（顺序与主列表一致，启不启用都列——那是触发器上的开关，不是能不能跑），按下去就把它装上
并开跑，与卡片右键走同一条路（`DebugAsync`）；（2）宏卡片右上角补一枚「运行调试」按钮，与编辑、删除同一
排，进的是同一扇窗、同一个宏；（3）编辑器的 F5 与卡片一致，装好就开跑：想一步步看的人按窗口里的「单步」
——它本来就是"没在跑就从第一步开始并停下"（`RunViewModel.Step` 里 `_stopAtNextStep` 那一支），不再需要
"先开窗再点运行"这一跳；（4）「跳过这一步」上工具栏，只在停住时可点（`IsPaused` 已经是它的可执行条件），
圆点右键那一份留着；（5）窗口接上快捷键：F5 运行 / 继续、F10 单步、Shift+F5 停止，三枚按钮的提示里写明；
（6）圆点的提示改成说清它能做什么（点一下下断点、右键设置条件与跳过这一次；将新增文案键，中英两侧）。

**怎么验收**　界面用例六条（不带宏时下拉与「开始调试」在、装上宏之后它们换成运行控制；选中第二个宏按下它，
装上的与在跑的都是第二个；卡片那枚按钮与右键菜单进的是同一扇窗、同一个宏；停住时「跳过这一步」可点、没停
住时不可点；F5 / F10 / Shift+F5 与三枚按钮做的是同一件事；圆点的提示里写着下断点这件事）；手动一条（从
卡片按钮开始调试，下断点、单步、跳过这一步、再继续各走一次），结论写进提交信息。

### 识别结果窗口：一打开就合适，能再看一次

**现状**　`LookWindow`（标题「这一步看到了什么」，添加动作窗口的「运行」与运行调试的步骤缩略图都打开它）
有五处不趁手：

- 打开时的「适应窗口」按猜出来的空间算：构造函数里 `Zoom(Fit(), false)`，而这时 `_scroll.Viewport` 还是
  0，`Fit()` 只好用自己那对兜底数字（640×400）。量过：一扇 1060×720 的窗口，图片区其实有 692×527，
  1920×1080 的画面却按 33% 打开（按真实空间该是 36%）；窗口大小变了也不重算——把窗口缩到 640×460，缩放
  还是 33%，要人自己按一次「适应窗口」。
- 没有「再看一次」：门槛没调对、想再识别一遍，得先 Esc 掉这扇窗、回到对话框再点一次「运行」，而它正好
  压在那个对话框上面。
- 每条标记只写分数（`MarkRow` 只显示 `Score(...)`），看不出这个候选离门槛差多少；顶部那句"最佳 0.62，
  需要 0.90"是整张画面的答案，落不到某一条候选上。
- 读到的文字带不走：整次读到的字只出现在顶部那行（`Look.Note` 接的是 `StepLook.Note`，引擎把所有 `span`
  用空格接起来），是个 `TextBlock`，选不中、复制不了；每一行字只画在图上那个框里。
- 图上的文字标签反过来盖住画面：`MarkVisual` 把 `box.Label` 画在框内左上角（带深色底），文字识别时正好压在
  刚读到的那几行字上——偏偏这段字就是要对着原图看它读得对不对的地方。

**改成什么**　（1）第一次布局之后（以及窗口尺寸变化之后）按真实可用空间重算适应缩放，打开时就铺满；
（2）加一个「再看一次」（将新增的文案键，中英两侧）：只识别、不动作，重跑的就是打开它的那一步，结果填回
这一扇窗（不另开一扇）。只有从添加动作窗口打开的那一份有它——那里的画面是刚写下的这一步；运行调试打开的
那一份不给，那幅画面属于那一次运行，重跑会得到与当时不同的东西；（3）每一行写出与门槛的差（"差 0.12"
这种，门槛是这一步自己的 `confidence` 一类字段，`StepLook.Minimum` 已经在手上），没有门槛的步骤不写；
（4）读到的字给出两条能带走的出路——右侧标记列表每一行写出这一条读到的字，窗口里另加一个只读的多行框把
这一次读到的全部文字列在一起，可选中、可 Ctrl+C（这一段不经过程序，选完就能拿走），旁边一枚「复制」
（将新增的文案键，中英两侧）走的是设备层的 `IClipboardDevice.WriteText`——打开它的窗口把手上的设备层交给
它，与别的窗口一样；无头会话里因此量的是替身剪贴板收到了什么；（5）图上的文字默认不画，只在列表里读；
要拿带字的截图给人看时用一行开关「把文字写在框上」（默认关；将新增文案键，中英两侧），打开时文字画在框的
上沿外侧，上沿放不下就落到框的下沿外侧，始终不压在框里。

**怎么验收**　界面用例六条（`LookWindow` 在 1060×720 下打开后缩放等于按真实图片区算出来的那个值；窗口
尺寸改小后缩放跟着重算；不给步骤时窗口里没有「再看一次」，给了步骤与替身设备层时按一次会让替身层多读
一次画面；文字识别那一次，只读框与每一行写出的字跟引擎交出的 `span` 逐条相符；「复制」按下去剪贴板里
（替身设备层的那个）是同一段文字；开关关着时画布上没有文字控件，打开后每一个文字控件都不落在任何一个框的
矩形里）；手动一条（真实屏幕上打开识别结果窗口：画面铺满；把相似度调低再点「再看一次」，同一扇窗里的命中
变多；读一段文字，把读到的整段复制出去，再打开开关看一遍带字的图），结论写进提交信息。

## 零散项

可与任何阶段并行：

- **手柄按键当触发器**：触发器眼下只有热键（键盘与鼠标）。手柄的按键要从共享输入层读出来接到触发上，还要说
  清手柄没连上时这一条怎么办；放这儿是免得漏掉，真做的时候照「工程规矩」写成阶段（验收：替身输入层上一次
  按键触发一次，录制里手柄按键也能配上）。
- **「怎么比文字」三种词汇**：OCR 与文字条件的 `matchMode`（包含 / 等于 / 正则）、窗口那一格的五档与表达式里
  的 `contains` / `startsWith` / `match` 说的是同一件事的三套词，看看能不能收成一套；`exact` 这类真需要的差
  别保留。
- **运行到这一行**：运行调试里右键某一步「一直跑到这里」。眼下要跑到某一步，只能先在那一步上下断点再从头跑
  一遍（验收：界面用例一条，停下的那一行就是点右键的那一行；手动一条，跑到的那一步与下断点跑到的同一步）。
- **其余"要一个位置"的字段也收一条记录**：`input.mouseMove` / `mouseClick` / `mouseDown` / `mouseUp` /
  `mouseScroll` 的 x、y 一对，以及 `vision.getPixel` 的 x、y，是否也各收一条记录（与拖拽的起点终点同一套
  读法）。先做拖拽那一版，用过之后再决定要不要铺开——一次只改一处，改完的东西才好判。

## 明确不做

这些是已经决定过的事，写在这里免得反复讨论；这一段永久保留。要重开某一条，就照「工程规矩」把它写成一个阶段
——现状与验收都摆出来，不在这里逐条讨论：

- **防检测**：不查内存、不改包、不做驱动级隐藏（VIIPER 那条虚拟键鼠是输入通道，不是隐藏，见 `AGENTS.md`
  的「驱动级输入（VIIPER）」）。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿这些文件本身的解析，也不对接企业系统（HTTP 接口 / 数据库 /
  邮件）；数据文件只做 CSV、JSON 与纯文本。窗口里或屏幕上看得见的表格照旧用「读取表格」那一步读。
- **第二套流程机制**：用户可见的流程控制只有块，加上循环体内的 `break` / `continue` 与「停止整个宏」。
- **记住上次填过的值**：填过的值只在这次打开、动作没换的时候留着，关掉再打开或换了动作都回到默认值；再填一遍
  用复制步骤就够了。
- **不为旧 `.wgmacro` 留兼容读法**：形状换了就换，见 `AGENTS.md` 规范 7。
- **记录只有一种说法**：取一个值只有一条路——`field(记录, "名字")`，不加 `$hit.score` 这类词法，也不让同一个
  值既是记录又是标量；一条记录里没读的字段留空，不另开一种取值。这一条管"值怎么取"，不管"字段收什么"：区域
  与搜索区域那四个数既收一条记录，也照旧收 `左,上,宽,高` 文本。生成记录的函数（`record(...)`）不做，等真
  有动作需要读用户造的记录再开。
- **不按字段取值的函数**：`x(记录)`、`y(记录)`、`point(记录)` 这类不做。`field()` 一条路已经够用，再加一套
  等于同一件事有两种写法；真要让"记录当位置用"，那是字段收什么的问题，由「拖拽的起点终点各收一条记录」
  那一段去解决。要加函数就得同时补 `doc/manual.md` 的「表达式函数一览」（`FunctionTableTests` 拿它跟函数表
  对账），这也是加一个函数比改一个字段贵的理由。
