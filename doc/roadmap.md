# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 还没做的事，给改这个仓库的人（含 agent）看。长期定位、规范与设计约定在仓库根目录的
`AGENTS.md`；工程命令、依赖、测试分层与发布看 [dev.md](dev.md)；用户怎么用看 [manual.md](manual.md)。

- **只写还没做的**：一个阶段做完就从这里删掉。做过的改动在 git 里，不在本文件留“已完成”账。
- **一个阶段是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，也会让读的人以为它在排期。
- **阶段必须可验收**：写清依赖、测试落点、手动项与完成条件；说不清怎么验的，不算一个阶段。

## 衡量标准与排序

判断标准有三条，按这个顺序看：

1. **用户能不能把这件事表达出来**：少一层绕路、少一个手写字段、少一次猜。
2. **已经说出来的行为是否与实现一致**：字段提示、手册、运行调试与引擎说的是不是同一件事。
3. **多条宏同时跑时是否仍然正确**：共享变量、输入门、浏览器当前页不能靠“碰巧不撞”。

排序原则：

- **先契约，后行为，再便利**：决定别的东西怎么写的（目录、读法、值形状、单位、空值、失败键、返回字段）
  排在前面；只是让人少点几步的排在后面。
- **先正确，后效率**：会静默出错的地方先修；只是更快的放到结构整理或后续阶段。
- **游戏向与办公向同等**：两者都是一等公民，不按场景偏好插队；同类里先做能解除后续依赖的那一项。
- **一个阶段只解决一类问题**：机械搬运、行为改变与文档重写不混在同一个提交里。

## 分层总表

| 层 | 先解决什么 | 阶段 | 这一层交出什么 |
| --- | --- | --- | --- |
| 验收 | 返回值测试不能靠全仓库搜到同名文字就算通过 | C3 | 每个声明结果都有可追踪的写入路径证据，新增动作漏写返回会在契约测试里定位 |
| 可观测性 | 表单生成失败时用户与开发者都能知道是哪个动作、哪个字段 | C4 | 目录与展示元数据的缺口以结构化结果报出，并在设计期窗口标到步骤 |

**阶段状态**：C3、C4 尚未完成。C3 先做，因为返回值路径稳定后，C4 才能把“目录有、界面没有”与
“回报有、页面没有”分开说明。

C 系列只整理测试证据与观测方式，不动用户可见行为；M 系列改的是契约束。两边互不依赖，可以并行。
M 系列内部按 M3 → M4 → M2 排。**M5（调用步的形状）已经做完并从这份文件撤下**：实参从散键变成行列表、
`macro` 改成必填、包格式升到 v20，改动与失败键见 [dev.md](dev.md) 与 [manual.md](manual.md)。

## 审核结论

原计划的“契约先行”方向成立，但字段字典不能再造一份独立配置。`ActionSemantics.json` 已经是动作参数、读法、
形状、单位、空值、选项、拾取器、等待与返回值的唯一真源；`ActionDisplay.json` 只放标签、提示、控件种类和
页面归属。再建一份字段字典会让“自动提取”从一处生成变成三处对账。

当前基线有 176 个动作、787 个参数、92 个带返回值的动作和 206 个结果。每个带返回值的动作都有 `returns`
行列表；调用宏的形参与结果来源由目录的 `SignatureSource` 声明，返回请求与交付值按同一张返回表校验。
这条边界继续成立：

“取不到”统一按契约失败处理，不猜默认值：展示元数据缺失让构建或启动对账失败；用户文件中的返回请求不合法
在运行前报可分支的失败键；引擎写错形状在交付该结果时报错。这样自动提取只有一条路径，没有被吞掉的回退。

- 同一文件会被两个阶段改时，先排定顺序；不要为了并行把两个阶段混进一个提交。

## C3 返回写入路径证据

**目标**：回答“目录声明的每个结果，究竟是哪一个执行路径交出的”，而不是只要全仓库某处出现过同名引号文字
就算通过。现有返回值页与运行器对账保留，但不再承担完整证据链。

**依赖**：动作目录、运行时返回校验、返回页对账已完成。C3 只整理测试证据，不改用户可见行为。

**工作**：

- 为每个动作家族建立“动作键 → 分派处理器 → 可写结果”的测试台账；共享辅助函数可以写多个候选键，但每个
  动作实际可达的集合必须来自目录。
- 将 `ReturnsPageTests` 的源码字面量检查替换为按动作键检查：声明的结果至少有一个可达写入，写入键必须在该
  动作声明内；动态宏调用使用被调用宏签名作为唯一例外。
- 加一个故意删除某条声明写入的反向 fixture，确认失败信息同时给出动作键和结果键。

**验收**：`dotnet test WhaleGenie.Tests --filter FullyQualifiedName~ActionReturn` 能逐项定位；新增或改名返回键时，
目录、返回值页、运行器与手册任一处漏改都会各自报出动作键与结果键；不靠白名单掩盖普通动作。

## C4 提取缺口的结构化观测

**目标**：目录、展示元数据和设计期表单之间的缺口可定位、可回归，用户看到的是步骤上的问题，开发者看到的是
动作键、参数键或返回键，而不是启动时的一句泛化异常。

**依赖**：C3 固定返回值写入路径；现有 `ActionDisplay.json` 只保留展示事实。

**工作**：

- 把动作目录与展示目录的合并结果整理成一份结构化契约报告；缺动作、缺参数、缺返回、重复键和孤立展示项分别
  带定位信息。
- 设计期把能确定的问题落到具体步骤；未知动作、未知字段、未知返回值与非法目标名使用稳定文案键。
- 补一条故意缺展示元数据的 fixture，验证报告不会退化成静默回退或只报总数。

**验收**：加载坏目录时报告列出全部缺口而不是抛第一个异常；正常目录报告为空；`ActionContractTests`、
`MacroCheckTests` 与 `LocalizationTests` 全绿；设计期错误在对应步骤上可见。

## M3 调用契约的边界

传参的**语义**是自洽的（`arg.<名字>`、`.given` 显式空、`returns` 的 key/name、`MacroValues.Fits` 一套判据），
运行时也已经补上「传了没声明的形参」与「值与传空值并存」的拒绝。形状该不该长这样是 M5 的事，这一阶段不碰
形状，只收**剩下的边界**：同一个句柄、同一个结果名、以及宏之间的调用在多条宏一起跑时归谁。

**依赖**：`Run.UndeclaredArgument` / `Run.GivenWithValue` 已落地；设计期检查已存在。

**工作**：

- `waitAny` 纳入「等过了」的结算，`waitAll` 只清它等的那几个句柄（现在无条件全清，漏报）。
- 两个 `startMacro` 共用一个句柄名、两个调用取回到同一个结果名：设计期报出（运行时前者会覆盖、后者后者胜出）。
- 三个等待动作对句柄的处置统一：等待因类型不符失败后句柄仍留在表里，可以再 `runStatus`、再等；写进手册。
- 同步子宏里起的后台运行：句柄随局部表消失但运行还在。要么设计期报出，要么把这些子运行挂到调用方的句柄表。
- 子运行抛出非 `StepFailure` 的异常时折成 `Run.Failed`（详情带原异常类型），不让 `AggregateException` 绕过失败键。
- 重名宏不再静默丢弃：可调用名重复时 `ProjectMacroLibrary` 报出，调用处得到 `Run.BadDeclaration` 而不是
  `Run.MacroNotFound`。

**验收**：每条一个用例（`MacroRunnerTests` / `MacroCheckTests` / 新增调用编辑往返用例）；手册「调用别的宏」
一节与失败键表同步；`dotnet test` 全绿。

## M4 宏接口的表达力

接口页现在能写名字、类型、默认值、必填与说明，但写不出**顺序**与**记录里面有什么**，从现有步骤提为子宏时
还会把类型丢光。这一阶段补这三处表达力，并统一「必填」的默认口径。

**依赖**：M3 的调用边界先定下来，否则改顺序与字段表时还要再动一遍调用处。

**工作**：

- 宏接口页加「上移 / 下移」，形参与结果各自一列；顺序就是调用表单与运行调试「形参」段的顺序。
- `Record` 形参与结果带字段表（`fields: [{name, type}]`，沿用 `ActionReturnField` 的形状）：变量墙与 `$`
  建议能给出 `$rec.field`，设计期按字段表检查取用，不再只判「是不是一条记录」。
- 「提为子宏」按被读写的值推断类型与必填，不再一律写 `Text` + 必填。
- 新建形参的 `Required` 默认与文件缺省口径统一（现在界面 false、模型与文件 true）。

**验收**：带字段表的记录形参经保存/读回不变；提为子宏后类型与必填保留；`MacroCallTests` 与
`FieldNameTests` 覆盖 `fields` 形状；手册「宏接口」一节补顺序与记录字段。

## M2 MCP 收尾：补丁与清单的最后两块

「说得清」「改一处不必重传」「事后查得到」都做完了：动作能分页、能批量描述、参数带枚举与条件必填、拒绝带稳定
代号、校验问题带 `code`、apply 会拦阻断错误；补丁能改一个参数、一张表的行、插删移一步；目录是 MCP resources，
可以被客户端缓存；每次改动与每次动手都写进 `logs/mcp-<日期>.log`。量法见 [mcp-usability.md](mcp-usability.md)。

**依赖**：以上都已完成。这一轮只剩两小块。

**工作**：

- 补丁补全的最后一块：记录（`rect` / `place` / 窗口规则）还不能补——一个值里几个字段，写一半是几种可能的
  意思，要一个整体替换的 `setRecord`，而不是按字段改。
- `list_macros` 带上每个宏的形参与结果名，省一次 `get_macro`：客户端选宏时先要看它收什么。

**验收**：

- 补丁能整体换一条 `rect`，`McpSelfCheck` 的 `patch.*` 加一条，`patch.saving` 与 `patch.rowBytes` 不升。
- `list_macros` 的每一项带 `arguments` 与 `results` 的名字，`McpServerTests` 加一条。

## 可与阶段并行的零散项

当前没有独立零散项。参数契约与正确性/结构收口的阶段都已落地；新零散项先挂到能验收的新阶段，
挂不上就写进「待评估」，不要在这里再开一份账。

## 仍然有效的取舍

这些决定继续约束后续阶段；要推翻时按最后一列的重开条件重新评估。

| 取舍 | 现在的决定 | 理由与重开条件 |
| --- | --- | --- |
| 游戏向排在办公向前面 | 改为同等 | 两者都是一等公民；排序只看依赖与表达能力 |
| 变量名单按方向分 | 写名字的框只列这个动作真正会写的名字；有 `scope` 的列本宏与共享，没有的只列本宏；读值框列全部四组 | 写名字与读值是两件事；不能让用户选了共享名字却只得到局部影子 |
| 输入门只认 `input.` / `gamepad.` 前缀 | 改为目录声明，并沿宏调用图看可达步骤 | 点击图片、点击文字、点击检测、UIA 回退点击都发真实鼠标；子宏的输入也要算进来 |
| 比文字只有五档、永远忽略大小写 | 保留五档，加两个开关 | 校验码、口令、逐行正则需要表达；默认不变 |
| 宏内并行 | 仍不做并行块 | 一个宏仍是一条顺序流程；并发用多个宏与后台运行 |
| 浏览器多实例 | 仍不做 | 成本在档案、上下文与登录态；门与提示已经把共享当前页说清 |
| HTTP / 数据库 / 邮件 | 仍不做通用动作 | 手册给出用脚本发请求的路径；真实办公流程反复卡住时再按阶段评估 |
| `.wgmacro` 旧格式兼容 | 不做 | 开发阶段没有外部旧宏；P1–P2 改字段形状时各升过一次包格式版本并拒绝旧包 |
| 记录取值 | 仍只保留 `field()` 作为字段访问；位置/矩形字段自己收记录 | 一套词法比省几个字符重要；P2 起字段直接吃记录，`field()` 只用于取其中一项 |
| 表达式缓存 | 不做 | 实测解析与求值是看屏幕成本的零头；缓存会多一层状态 |
| 坐标与单位 | 像素坐标允许负数；时长从 0 起；空值含义由目录声明 | 多显示器与窗口相对坐标本来就有负值；46 小时是时间上限，不是坐标上限 |
| 循环变量 | 与 `sys.loopIndex` 一样只属于最内层循环 | 嵌套循环同名变量互相覆盖是静默错误；要留下值就在循环里赋给别的名字 |
| 结果变量 | 只属于这一次尝试；每次尝试开始清空 | 失败、重试、循环里读到上一次的答案是更难查的错 |
| 记录作身份 | 窗口记录按 `title` / `process` / `class` 用；UIA 运行时句柄不写成值 | 句柄不可序列化；能稳定表达的身份先做 |
| 子宏的互斥发输入 | 子宏用自己的设置，父宏不覆盖 | 宏的声明应当跟着宏走；父宏只影响它自己的步骤 |
| 公共宏更新 | 拖入时复制并固定来源版本，已有副本不跟随 | 项目必须能脱离本机宏库运行；要换新版就再拖一次建立新副本 |

## 明确不做

- **防检测**：不查内存、不改包、不做驱动级隐藏（VIIPER 是输入通道，不是隐藏）。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿解析，也不对接企业系统；数据文件只做 CSV、JSON 与纯文本。
- **第二套流程机制**：用户可见的流程控制只有块，加上 `break` / `continue` / `return` / `stop`；
  `try` 的过滤与重抛是既有块的能力，不是新机制。
- **记住上次填过的值**：关掉再打开或换了动作都回默认值；再填一遍用复制步骤。
- **从块内失败那一步继续**：重试就是整块重来；要断点续跑是另一项能力。
- **浏览器多实例**：同一时刻只有一份浏览器；并发靠门与提示。
- **宏内并行块**：一个宏仍是一条顺序流程；并发用多个宏与后台运行。
- **字段别名与双读**：旧名在同一版删掉，不写迁移分支。
- **默认改成区分大小写**：两个开关默认关。
- **`x(记录)` / `y(记录)` / `point(记录)`**：记录当位置用由 `Point` / `Rect` 字段解决，不再加
  第二种访问器。
- **DPI 缩放与单位换算**：屏幕像素就是像素；不做物理单位。
- **UIA 运行时句柄记录**：句柄不可序列化；需要“找到再操作”时先走窗口记录与鼠标记录，UIA 的稳定
  选择器另议。
- **完整静态类型系统**：只做目录声明得到的类型对账，不做类型推导。

## 阶段验收规则

1. 一个阶段一串提交，每个提交只做一件事；机械搬运与行为改动分开。
2. 前置阶段没完成，不开工依赖它的阶段；同一文件会被两个阶段改时，先排定顺序。
3. 改代码的阶段收尾跑 `dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`；只改文档的
   阶段跑 `git diff --check`、链接检查与对应的文档对账测试（见 [dev.md](dev.md)）。
4. 新增或改动动作时，目录、引擎、设计期检查、文案、页面归属、返回值页、失败键、测试与手册同一版改完；
   旧形状在同一版删掉。改字段形状、单位、空值或记录字段时，同版补对账用例；改文件形状时升包格式版本
   并拒绝旧包。
5. 真实桌面的项按 `AGENTS.md` 规范 5 手动过一遍，结论写进提交信息；无头能覆盖的不得留到手动。
6. 阶段完成就删掉本文件里对应的小节；范围变了就重写目标、依赖与完成条件，不把旧验收留在原地。
