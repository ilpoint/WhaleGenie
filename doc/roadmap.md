# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 接下来做什么，给改这个仓库的人（含 agent）看。它与仓库根目录的 `AGENTS.md` 分工：
`AGENTS.md` 讲定位、开发规范与设计约定（不常动的东西），这份文件只讲下一步动什么。用程序的人看
[manual.md](manual.md)，工程细节看 [dev.md](dev.md)。

- **只写还没做的**：一个阶段做完就把那一段删掉。做过的改动在 git 里，这里不留"已完成"清单——留着的话，
  这份文件会慢慢长成一本账，谁也不知道哪一条还算数。
- **一个阶段就是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，还会让读的人以为它在排期。
- 阶段里提到的东西如果还没在代码里，都写着"（将新增）"；没写的就是已经有的。

## 排序原则与衡量标准

- **先地基，后便利**：决定别的东西怎么写的（比如返回值的形状）排在前面；只是让人少点几步的排在后面。
- **游戏向排在办公向前面**。
- **判断标准只有一条**：用户能不能把这件事表达出来。
- **一个阶段的验收必须做得出来**：写清测试在哪、手动项是什么。说不清怎么验的，就不算一个阶段。

## 工程规矩

阶段里逐条照着做：

1. 一个阶段一串提交，每个提交只做一件事。
2. 阶段收尾三项全绿：`dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`（命令与出处见
   [dev.md](dev.md)）。
3. **改完就删旧的**：被新形状取代的参数、返回值、开关、文案键、测试与文档段落，都在同一阶段里删掉；不留
   双读、不留"旧文件也还能读"的分支。
4. 新增目录字段、返回值与文案时，中文与英文两侧的键一起加；`ActionPageTests` 的 Tuning 名单、
   `ReturnsPageTests`、`LocalizationTests` 跟着补。
5. 新增依赖必须是官方库、只 Windows，并写进 [dev.md](dev.md) 的依赖表与 `THIRD-PARTY-NOTICES.md`。
6. 真实桌面的项（移动鼠标、抓屏取色、注入按键、UIA 与页面拾取、录制、窗口布局）按 `AGENTS.md` 规范 5
   手动过一遍，结论写进提交信息。
7. 这一阶段动到的动作，说明文字按书面语顺手改（见 `AGENTS.md` 规范 2）。
8. 阶段做完，把这一段从这份文件里删掉。

## 阶段表

### 位置与矩形改用一条记录：各自一个开关

**现状**　上一批把"一条记录当位置/当矩形用"铺到了拖拽的两端、鼠标六个动作的 X 与 Y、看一个像素的两格、
以及要读要截的那四格与移动窗口的四格上，读法是"**随便哪一格**填一条记录就由它说了算"。写宏的人看到的
是：两格或四格里哪一格都能放记录，另一格写没写决定这一步报不报错；而拖拽的两端干脆整格是文本（写
`x,y` 或一条记录），连数字框都不是。这不方便看，也不方便写——一格该填什么，得先知道那条"随便哪一格"
的规矩。

**改成什么**　每个位置与每块矩形各有一个**开关**，说清这一步的位置从哪来：

1. **鼠标六个动作与看一个像素的两步**（`input.mouseMove` / `mouseClick` / `mouseDoubleClick` /
   `mouseDown` / `mouseUp` / `mouseScroll`、`vision.getPixel` / `vision.waitColor`）：新增 `useRecord`
   （开关，默认关）与 `record`（记录格，能写算式、带 `ƒ`）。勾着记录时 X 与 Y 不画；鼠标动作原有的
   「就在指针当前所在位置」开关照旧，勾上它时记录那两格也不画。读数顺序照今天的规矩：指针 → 记录 →
   数字，两个开关都开着时以指针为准。
2. **要读、要截的那一块与移动窗口**（`vision.capture` / `ocr.recognize` / `window.move`）：同样一对
   `useRecord` + `record`，说的是那一块矩形；数字格留空的含义照旧（读屏幕的宽高量到边缘，移动窗口
   至少 1 像素）。
3. **拖拽的两端**（`input.mouseDrag`）：`start` / `end` 两格文本**删掉**，恢复成四个数字
   （`startX` / `startY` / `endX` / `endY`，可写算式），每端另有一对 `startFromRecord` / `startRecord`、
   `endFromRecord` / `endRecord`。「框选区域」照样一次填满四格（起点左上角、终点右下角）。
4. 表单用既有的「跟着哪个字段」机制显示：勾了开关才画记录格，关着才画数字格；数字格留空的手写文件
   按数字读（取值名单里带着空）。一个字段要同时跟着两个开关（鼠标那两格：指针关着、记录没勾），
   机制里补一条"第二个跟随字段"。
5. 「框选区域」与 Alt+X 的「取指针位置」写完数字后，把它们写的那一处记录开关关掉：刚在屏幕上点出来
   的数就是这一步的位置，不该再被一条记录盖住。
6. 引擎里"任意一格收记录"那套逻辑与 `Run.BadPointTwice` / `Run.BadRegionTwice` 两个失败键删掉；
   `Run.BadPoint` / `Run.BadRegion` / `Run.BadPointEmpty` 的说明改成"交给它的那条记录里没有 x、y
   （或 left、top、width、height）"。记录里的数是屏幕像素、坐标基准只挪写出来的数字，这条不变。

**怎么验收**　引擎用例：每一个动到的地方各一条"勾了开关、记录说了算"（鼠标移、点击、滚轮、看像素、
截图、读文字、移动窗口、拖拽两端），一条"开关关着时数字照旧，含坐标基准"，一条"记录里没有那个位置/那块
矩形时报 `Run.BadPoint` / `Run.BadRegion`"，一条"拖拽的记录格空着时报 `Run.BadPointEmpty`"；拖拽原来
那批用例改成四个数字。表单用例：勾开关后数字格消失、记录格出现，记录格写 `$命中` 能存能读回，框选与
取指针位置之后记录开关是关的，拖拽框选一次填满四格。手上一组：真机上把一条命中填进鼠标点击的记录格、
截图那一格、移动窗口那一格，各自落在刚找到的东西上。

## 明确不做

这些是已经决定过的事，写在这里免得反复讨论；这一段永久保留。要重开某一条，就照「工程规矩」把它写成一个阶段
——现状与验收都摆出来，不在这里逐条讨论：

- **防检测**：不查内存、不改包、不做驱动级隐藏（VIIPER 那条虚拟键鼠是输入通道，不是隐藏，见 `AGENTS.md`
  的「驱动级输入（VIIPER）」）。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿这些文件本身的解析，也不对接企业系统（HTTP 接口 / 数据库 /
  邮件）；数据文件只做 CSV、JSON 与纯文本。窗口里或屏幕上看得见的表格照旧用「读取表格」那一步读。
- **第二套流程机制**：用户可见的流程控制只有块，加上循环体内的 `break` / `continue` 与「停止整个宏」。
- **记住上次填过的值**：填过的值只在这次打开、动作没换的时候留着，关掉再打开或换了动作都回到默认值；再填一遍
  用复制步骤就够了。
- **不为旧 `.wgmacro` 留兼容读法**：形状换了就换，见 `AGENTS.md` 规范 7。
- **记录只有一种说法**：取一个值只有一条路——`field(记录, "名字")`，不加 `$hit.score` 这类词法，也不让同一个
  值既是记录又是标量；一条记录里没读的字段留空，不另开一种取值。这一条管"值怎么取"，不管"字段收什么"：区域
  与搜索区域那四个数既收一条记录，也照旧收 `左,上,宽,高` 文本。生成记录的函数（`record(...)`）不做，等真
  有动作需要读用户造的记录再开。
- **不按字段取值的函数**：`x(记录)`、`y(记录)`、`point(记录)` 这类不做。`field()` 一条路已经够用，再加一套
  等于同一件事有两种写法；真要让"记录当位置用"，那是字段收什么的问题，由字段自己收不收一条记录去解决
  （拖拽的「起点」「终点」、鼠标动作与看一个像素的 X、Y 都已经这么办）。要加函数就得同时补 `doc/manual.md`
  的「表达式函数一览」（`FunctionTableTests` 拿它跟函数表对账），这也是加一个函数比改一个字段贵的理由。
