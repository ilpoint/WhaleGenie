# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 接下来做什么，给改这个仓库的人（含 agent）看。它与仓库根目录的 `AGENTS.md` 分工：
`AGENTS.md` 讲定位、开发规范与设计约定（不常动的东西），这份文件只讲下一步动什么。用程序的人看
[manual.md](manual.md)，工程细节看 [dev.md](dev.md)。

- **只写还没做的**：一个阶段做完就把那一段删掉。做过的改动在 git 里，这里不留"已完成"清单——留着的话，
  这份文件会慢慢长成一本账，谁也不知道哪一条还算数。
- **一个阶段就是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，还会让读的人以为它在排期。
- 阶段里提到的东西如果还没在代码里，都写着"（将新增）"；没写的就是已经有的。

## 排序原则与衡量标准

- **先地基，后便利**：决定别的东西怎么写的（比如返回值的形状）排在前面；只是让人少点几步的排在后面。
- **游戏向排在办公向前面**。
- **判断标准只有一条**：用户能不能把这件事表达出来。
- **一个阶段的验收必须做得出来**：写清测试在哪、手动项是什么。说不清怎么验的，就不算一个阶段。

## 工程规矩

阶段里逐条照着做：

1. 一个阶段一串提交，每个提交只做一件事。
2. 阶段收尾三项全绿：`dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`（命令与出处见
   [dev.md](dev.md)）。
3. **改完就删旧的**：被新形状取代的参数、返回值、开关、文案键、测试与文档段落，都在同一阶段里删掉；不留
   双读、不留"旧文件也还能读"的分支。
4. 新增目录字段、返回值与文案时，中文与英文两侧的键一起加；`ActionPageTests` 的 Tuning 名单、
   `ReturnsPageTests`、`LocalizationTests` 跟着补。
5. 新增依赖必须是官方库、只 Windows，并写进 [dev.md](dev.md) 的依赖表与 `THIRD-PARTY-NOTICES.md`。
6. 真实桌面的项（移动鼠标、抓屏取色、注入按键、UIA 与页面拾取、录制、窗口布局）按 `AGENTS.md` 规范 5
   手动过一遍，结论写进提交信息。
7. 这一阶段动到的动作，说明文字按书面语顺手改（见 `AGENTS.md` 规范 2）。
8. 阶段做完，把这一段从这份文件里删掉。

## 阶段表

### 浏览器：把表达不出来的动作补齐

**现状**　上一段把"页面上认哪个元素"做扎实了（选择器退路、第几个命中、拾取器出候选、超时按步骤走、登录档案）。
浏览器能做的动作仍然只有十四个，且都停在"点一下、填一段、读一段"上：页面里**读**只读得回一段文字，一次读一列、
读一张网页表格、读地址与标题都做不到；**判断与等待**只有"等某个元素到某个状态"；**交互**缺双击与右键（点击只
有左键单击）、缺逐键输入、缺滚动、缺回答页面弹出的对话框、缺下载文件；页面里**跑一段 JS** 也没有。这些是"用户
表达不出来"的那一类：页面上要读的东西拿不回来，宏就只能在旁边干看。

**改成什么**　一次收齐，按族分提交，凡是设备已经做得到的能力都开成动作：

1. **读取**：`browser.readAll`（读一列：`target`、`matchIndex`、`what`（文本 / 值 / 属性）、`attribute`、
   `maxItems` 默认 100、范围 1..10000，交出 `items` 列表）；`browser.readTable`（读网页表格：`target` 默认
   `table`、`matchIndex`、`maxRows` 默认 100、范围 1..10000，交出 `table`——一行一条记录、键是表头，没有表头
   就用 A、B、C，与 `uia.readTable` 同形状）；`browser.readPage`（没有字段，交出 `url` 与 `title`）；
   `browser.readText` 加 `what`（文本 / 值 / 属性）与 `attribute`（返回值不变）。
2. **判断与等待**：`condition.browserExists` / `condition.browserNotExists`（`target`、`matchIndex`、
   `state`：看得见 / 看不见 / 在页面上 / 不在页面上）；`browser.waitForUrl`（`match`，比文字那五档）；
   `browser.waitForLoad`（`state`：文档就绪 / 加载完成 / 网络空闲）。
3. **交互**：`browser.click` 加 `how`（左键单击 / 左键双击 / 右键单击）与 `force`（高级页，默认关）；
   `browser.fill` 加 `how`（直接填写 / 逐键输入）与 `intervalMs`（逐键间隔，默认 0）；新增 `browser.scroll`
   （`target` 可留空、`how`：滚到元素 / 往下滚一屏 / 到页面底部 / 到页面顶部）、`browser.dialog`（`how`：接受 /
   取消，`text` 是 prompt 要输入的文字、可留空，交出 `message`，到超时没弹报 `Run.Timeout`）、
   `browser.download`（`target` 可留空＝等下一个下载、`folder` 默认宏文件所在夹，交出 `path` 与 `name`）。
4. **页面里跑 JS**：`browser.evaluate`（`script` 是多行函数体，`return` 交回，`result` 按 JSON 转成文本）。
5. **设备一侧**：context 打开下载（`AcceptDownloads`）；页面脚本另起一份 `BrowserPageScript`（读表格、滚屏、
   对话框、下载前的等待都放在设备里，界面与引擎里不出现第三方名字）；新失败键两侧文案一起加。
6. 收尾时把 `AGENTS.md`「现有能力」的数字与概览改成新的（现在是 148 个可执行动作 + 21 个条件）。

**怎么验收**　真浏览器用例（`RealBrowserFact`，headless Edge，临时页面）：读一列读回三项、读表格能按表头取一列、
读页面给出地址与标题；浏览器条件在元素出现前后各判一次；等网址与等加载各等到一次；双击与右键各自触发页面记下的
那一种事件、逐键输入发得出每个键、滚动把元素带进视野、对话框按文本回答、下载落到指定的文件夹；页面里跑 JS 算一个
式子并把结果按 JSON 交回。引擎用例：每个新动作的字段与返回值各一条（`DeviceActionTests` 的双设备层）。界面用例：
新字段落在该落的页（`ActionPageTests`）、返回值一项一行（`ReturnsPageTests`）、中英两侧文案齐全
（`LocalizationTests`）。手动：在真页面上读一张带表头的表格、点开一次右键菜单、下载一个文件并确认它落在宏文件
旁边。收尾三项全绿（`dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`）。

## 明确不做

这些是已经决定过的事，写在这里免得反复讨论；这一段永久保留。要重开某一条，就照「工程规矩」把它写成一个阶段
——现状与验收都摆出来，不在这里逐条讨论：

- **防检测**：不查内存、不改包、不做驱动级隐藏（VIIPER 那条虚拟键鼠是输入通道，不是隐藏，见 `AGENTS.md`
  的「驱动级输入（VIIPER）」）。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿这些文件本身的解析，也不对接企业系统（HTTP 接口 / 数据库 /
  邮件）；数据文件只做 CSV、JSON 与纯文本。窗口里或屏幕上看得见的表格照旧用「读取表格」那一步读。
- **第二套流程机制**：用户可见的流程控制只有块，加上循环体内的 `break` / `continue` 与「停止整个宏」。
- **记住上次填过的值**：填过的值只在这次打开、动作没换的时候留着，关掉再打开或换了动作都回到默认值；再填一遍
  用复制步骤就够了。
- **不为旧 `.wgmacro` 留兼容读法**：形状换了就换，见 `AGENTS.md` 规范 7。
- **记录只有一种说法**：取一个值只有一条路——`field(记录, "名字")`，不加 `$hit.score` 这类词法，也不让同一个
  值既是记录又是标量；一条记录里没读的字段留空，不另开一种取值。这一条管"值怎么取"，不管"字段收什么"：区域
  与搜索区域那四个数既收一条记录，也照旧收 `左,上,宽,高` 文本。生成记录的函数（`record(...)`）不做，等真
  有动作需要读用户造的记录再开。
- **不按字段取值的函数**：`x(记录)`、`y(记录)`、`point(记录)` 这类不做。`field()` 一条路已经够用，再加一套
  等于同一件事有两种写法；真要让"记录当位置用"，那是字段收什么的问题，由字段自己收不收一条记录去解决
  （拖拽的「起点」「终点」、鼠标动作与看一个像素的 X、Y 都已经这么办）。要加函数就得同时补 `doc/manual.md`
  的「表达式函数一览」（`FunctionTableTests` 拿它跟函数表对账），这也是加一个函数比改一个字段贵的理由。
