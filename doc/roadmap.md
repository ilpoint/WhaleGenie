# WhaleGenie 开发路线图

[简体中文](roadmap.md)

## 这份文件是什么

这份文件写 WhaleGenie 还没做的事，给改这个仓库的人（含 agent）看。长期定位、规范与设计约定在仓库根目录的
`AGENTS.md`；工程命令、依赖、测试分层与发布看 [dev.md](dev.md)；用户怎么用看 [manual.md](manual.md)。

- **只写还没做的**：一个阶段做完就从这里删掉。做过的改动在 git 里，不在本文件留“已完成”账。
- **一个阶段是一次可以发布的改动**：阶段内一串提交，每个提交只做一件事。
- **不写工期**：估出来的日子不算承诺，也会让读的人以为它在排期。
- **阶段必须可验收**：写清依赖、测试落点、手动项与完成条件；说不清怎么验的，不算一个阶段。

## 衡量标准与排序

判断标准有三条，按这个顺序看：

1. **用户能不能把这件事表达出来**：少一层绕路、少一个手写字段、少一次猜。
2. **已经说出来的行为是否与实现一致**：字段提示、手册、运行调试与引擎说的是不是同一件事。
3. **多条宏同时跑时是否仍然正确**：共享变量、输入门、浏览器当前页不能靠“碰巧不撞”。

排序原则：

- **先契约，后行为，再便利**：决定别的东西怎么写的（目录、读法、失败键、返回形状）排在前面；只是让人少点
  几步的排在后面。
- **先正确，后效率**：会静默出错的地方先修；只是更快的放到结构整理或后续阶段。
- **游戏向与办公向同等**：两者都是一等公民，不按场景偏好插队；同类里先做能解除后续依赖的那一项。
- **一个阶段只解决一类问题**：机械搬运、行为改变与文档重写不混在同一个提交里。

## 分层总表

| 层 | 先解决什么 | 阶段 | 这一层交出什么 |
| --- | --- | --- | --- |
| F 正确性与并发收口 | 停止后资源能释放，共享集合不丢项 | F1 停止清理、F2 共享集合原子性 | 停止语义可依赖；并发追加与计数不再靠运气 |
| G 后台运行表达 | 等谁、等几个、怎么取消 | F3 后台运行生命周期 | 句柄可读、可取消、可等齐，同步调用有超时 |
| H 流程与门边界 | 循环结束原因、浏览器门不死锁 | F4 循环结果与浏览器门 | 循环可分支；跨运行浏览器冲突变成明确失败 |
| I 引擎结构 | 分派与读值不再埋在单文件里 | F5 Dispatch 与读值整理 | 改一个动作只需进对应家族 |

**推荐顺序**：F1 → F2 → F3 → F4 → F5。F1 与 F2 都改并发正确性，先做；F3 依赖 F1 的停止语义；
F4 依赖 F3 的后台运行；F5 最后做纯搬运，避免与行为改动混在一起。

**当前阶段**：F1 停止与收尾清理。

## F 正确性与并发收口

### F1 停止与收尾清理

**目标**：外部停止或父运行取消时，正在执行的 `control.try` 仍执行一次收尾步骤，资源能按宏作者的写法释放。

**改动范围**

- 根运行被取消时，`RunTry` 的 `finally` 按内到外执行一次；整次停止共享一份 5 秒清理预算，超过预算即结束。
- 清理失败写 `Log.CleanupFailed`，不覆盖原来的 `Stopped` 状态；清理里启动的等待或后台运行不获得新的预算。
- 步骤自身的超时仍走现有失败/收尾路径；只有整个运行被停止或父运行取消才进入这条清理路径。
- 手册与 `AGENTS.md` 改掉“外部停止不执行收尾”的例外说明。

**依赖**：C1、C2 已完成。

**测试**：停止后收尾写入标记；收尾含 10 秒等待时整次停止在约 5 秒内结束；嵌套收尾按内到外；普通失败仍只执行一次收尾。

**手动**：真实桌面运行带 `try/finally` 的宏，停止后确认清理动作执行。

**完成条件**：停止清理有界、只执行一次、原停止状态与失败键不变，文档与测试一致。

**不做**：不让清理步骤重启被停止的等待或后台运行；不为“从停止处继续”增加状态。

### F2 共享集合原子性

**目标**：多条宏同时修改同一个全局列表时不丢项；全局计数能直接读到新值。

**改动范围**

- `VariableBag` 增加 `TryUpdate`，把“读当前值、改、写回”放在同一把锁里。
- `control.listAdd` / `listInsert` / `listSet` / `listRemoveAt` / `listClear` 对全局列表使用它；局部列表行为不变。
- `control.incrementGlobal` 增加 `value` 返回值，等于增加后的计数。

**依赖**：C1 已完成。

**测试**：两条运行各追加 200 项，最终列表包含 400 项；并发插入/删除不抛异常、不丢项；`incrementGlobal` 返回值等于新计数；缺失列表和越界仍报原有失败键。

**手动**：两个触发器同时向一个全局列表追加，运行调试里核对总数。

**完成条件**：全局列表操作按操作级原子，普通写入仍是 last-writer-wins；`incrementGlobal` 可参与后续条件。

**不做**：不引入跨多个全局变量的通用事务。

## G 后台运行表达

### F3 后台运行生命周期与等待结果可见性

**目标**：句柄能说清“是哪个宏、会交回哪些结果”，并能取消或一次等待多个后台运行；同步调用也有可设置的超时。

**改动范围**

- `runMacro` 的句柄值改为记录 `{ id, macro, results }`；`waitMacro` 读取该记录，结果映射仍采用调用处勾选的行。
- `control.runMacro` 标记为可等待，超时来源为步骤设置；同步调用设置超时后能取消子宏，后台调用不受这一步超时影响。
- 新增 `control.cancelMacro`：按句柄取消并等待，默认超时 5000 毫秒，返回 `stopped`。
- 新增 `control.waitAll`：等待句柄列表，逐个应用结果映射，默认超时 60000 毫秒，返回 `count`。
- 新增 `Run.ChildStillRunning`，并补手册失败键表。

**依赖**：F1。

**测试**：句柄记录字段可读；同步调用超时返回 `Run.Timeout`；取消后子运行停止；`waitAll` 等齐并交回各调用的结果；等待超时后仍可再次等待。

**手动**：运行调试里同时看父宏、两个后台运行及取消/等待结果。

**完成条件**：用户不必靠猜句柄含义或逐个轮询全局变量来完成“开几个、等齐、取消一个”。

**不做**：不加宏内并行块；旧文本句柄不做兼容，句柄是运行时值，不写进 `.wgmacro`。

## H 流程与门边界

### F4 循环结束原因与浏览器门边界

**目标**：所有循环都能说清是正常结束还是被 `break` 提前结束；浏览器门不会因为父宏等待后台子宏而死锁。

**改动范围**

- `repeat` / `for` / `forEach` 增加 `ended`：正常结束分别为 `count` / `range` / `items`，提前离开为 `break`；`while` 的 `ended` 增加 `break`。
- 持有 `BrowserGate` 的父运行启动包含 `browser.*` 的后台子运行时立即报 `Run.BrowserRunWhileHeld`，并在设计期标出这类调用；同步调用不受影响。

**依赖**：F3。

**测试**：四种循环的正常与 `break` 结果；持有浏览器门时启动后台浏览器运行被拒绝；不含浏览器的后台运行仍可启动；同步浏览器调用仍可用。

**手动**：浏览器对话框内启动后台宏，确认给出明确错误而不是卡住。

**完成条件**：循环结束原因可分支；浏览器门相关死锁变成可诊断的失败。

**不做**：不做浏览器多实例；不让后台子运行继承浏览器的并发使用权。

## I 引擎结构

### F5 Dispatch 与读值整理

**目标**：`Dispatch` 不再是一个巨型 switch；跨家族读值代码不再放在 `MacroRunner.Script.cs`。

**改动范围**

- `Dispatch` 只按动作目录的 `Category` 分派到 `DispatchControl` / `DispatchFile` / `DispatchData` / `DispatchClipboard` / `DispatchProcess` / `DispatchSystem` / `DispatchWindow` / `DispatchInput` / `DispatchVision` / `DispatchOcr` / `DispatchUia` / `DispatchBrowser` / `DispatchScript` 等家族方法；具体动作开关移入对应家族文件。
- 把 `ReadValue` / `ReadText` / `Read` / `Interpolate` / `Number` / `Vary` 移到 `MacroRunner.Reading.cs`；后台运行的嵌套类型集中到 `MacroRunner.Children.cs`。
- 这是纯搬运：不改字段、失败键、运行时序与文案。

**依赖**：F1–F4 的行为改动完成。

**测试**：全套引擎、界面与画面获取用例；`ReturnsPageTests` 继续扫描所有 `MacroRunner*.cs`；搬前搬后结果一致。

**手动**：搬运后抽查运行调试与添加动作窗口。

**完成条件**：`Dispatch` 只识别分类，不再识别具体动作；读值入口集中在一个文件；各家族实现与分派在同一文件。

**不做**：不顺手改动作行为；不为表达式加编译缓存。

## 可与阶段并行的零散项

当前没有独立零散项。F1–F5 会改同一批运行时与目录字段，按顺序做；新零散项先挂到能验收的阶段，
挂不上就写进「待评估」，不要在这里再开一份账。

## 仍然有效的取舍

这些决定继续约束后续阶段；要推翻时按最后一列的重开条件重新评估。

| 取舍 | 现在的决定 | 理由与重开条件 |
| --- | --- | --- |
| 游戏向排在办公向前面 | 改为同等 | 两者都是一等公民；排序只看依赖与表达能力 |
| 变量名单按方向分 | 写名字的框只列可写名字；读值框列全部四组 | 写名字与读值是两件事，读值框要能选 `$sys.*` 与 `$step.*` |
| 输入门只认 `input.` / `gamepad.` 前缀 | 改为目录声明 | 点击图片、点击文字、点击检测与 UIA 回退点击都发真实鼠标 |
| 比文字只有五档、永远忽略大小写 | 保留五档，加两个开关 | 校验码、口令、逐行正则需要表达；默认不变 |
| 宏内并行 | 仍不做并行块 | C2 的不等待 + join 已落地；并行块是另一套调度与结果语义 |
| 浏览器多实例 | 仍不做 | 成本在档案、上下文与登录态；C1 的门与提示已经把共享当前页说清 |
| HTTP / 数据库 / 邮件 | 仍不做通用动作 | 手册给出用脚本发请求的路径；真实办公流程反复卡住时再按阶段评估 |
| `.wgmacro` 旧格式兼容 | 不做 | `v0.0.1`–`v0.0.5` 只在虚拟机上测试，没有外部旧宏；旧键不双读、不迁移 |
| 记录取值 | 仍只保留 `field()` | 一套词法比省几个字符重要；字段自己收记录已解决位置与矩形 |
| 表达式缓存 | 不做 | 实测解析与求值是看屏幕成本的零头；缓存会多一层状态 |

## 明确不做

- **防检测**：不查内存、不改包、不做驱动级隐藏（VIIPER 是输入通道，不是隐藏）。
- **多尺度模板匹配**：分辨率不同就另存一套参考图。
- **办公文档解析**：不做 PDF / Word / 工作簿解析，也不对接企业系统；数据文件只做 CSV、JSON 与纯文本。
- **第二套流程机制**：用户可见的流程控制只有块，加上 `break` / `continue` / `return` / `stop`；`try` 的过滤与
  重抛是既有块的能力，不是新机制。
- **记住上次填过的值**：关掉再打开或换了动作都回默认值；再填一遍用复制步骤。
- **从块内失败那一步继续**：重试就是整块重来；要断点续跑是另一项能力。
- **浏览器多实例**：同一时刻只有一份浏览器；并发靠 C1 的门与提示。
- **宏内并行块**：一个宏仍是一条顺序流程；并发用多个宏，C2 已补“不等待 + join”。
- **字段别名与双读**：旧名在同一版删掉，不写迁移分支。
- **默认改成区分大小写**：两个开关默认关，现有宏的行为不变。
- **`x(记录)` / `y(记录)` / `point(记录)`**：记录当位置用由字段自己收记录解决，不再加第二种写法。

## 阶段验收规则

1. 一个阶段一串提交，每个提交只做一件事；机械搬运与行为改动分开。
2. 前置阶段没完成，不开工依赖它的阶段；同一文件会被两个阶段改时，先排定顺序。
3. 改代码的阶段收尾跑 `dotnet build` / `dotnet test` / `dotnet format --verify-no-changes`；只改文档的阶段跑
   `git diff --check`、链接检查与对应的文档对账测试（见 [dev.md](dev.md)）。
4. 新增或改动动作时，目录、引擎、设计期检查、文案、页面归属、返回值页、失败键、测试与手册同一版改完；
   旧形状在同一版删掉。
5. 真实桌面的项按 `AGENTS.md` 规范 5 手动过一遍，结论写进提交信息；无头能覆盖的不得留到手动。
6. 阶段完成就删掉本文件里对应的小节；范围变了就重写目标、依赖与完成条件，不把旧验收留在原地。
