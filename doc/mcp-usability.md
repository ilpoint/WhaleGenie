# MCP 可用性自检

本文件记录 WhaleGenie MCP 服务的可用性指标、协议能力、已知限制和自检方法。指标来自
`WhaleGenie.exe --mcp-doctor --report <文件>`，由官方 MCP 客户端按固定场景执行并采集，
不是手工评价。构建、测试与发布流程见 [dev.md](dev.md)，当前进程拓扑与组合根见
[architecture.md](architecture.md)。

动作目录以 `WhaleGenie.Core/Execution/ActionSemantics.json` 为准。2026-11-01 的检测结果如下，
后续修改协议或工具时应重新生成报告并比较指标。

### 动作矩阵

`WhaleGenie.Core.Tests/Bench` 将目录中的每个动作按声明合成一步，在替身设备层上运行，核对：

- 结局是否符合声明；
- 返回值是否写入且形状正确；
- “发送输入”“查看屏幕”等副作用是否与设备调用一致；
- 是否存在无法提供值的参数。

当前 169 个动作全部通过。三项等待动作（`vision.waitImage`、`vision.waitDetect`、
`window.waitFor`）使用“第三次才出现”的夹具，验证等待确实发生，而非首次即命中。

```powershell
$env:ACTION_MATRIX_REPORT = "TestResults/action-matrix.md"
dotnet test WhaleGenie.Core.Tests -c Release --filter "FullyQualifiedName~ActionBench"
Remove-Item Env:ACTION_MATRIX_REPORT
```

报告是生成物。修改前后各保留一份，数字变化应能由代码或目录变化解释。

## 衡量标准

“可用”被拆成以下可测量问题：

| 问题 | 指标 |
| --- | --- |
| 完成一件典型任务需要多少次调用 | 调用次数 |
| 同一任务传输多少数据 | 请求与响应字节数 |
| 闭集参数是否声明为枚举 | 枚举参数数 / 闭集参数数 |
| 本可作为对象或数组的值是否被塞进字符串 | 字符串内 JSON 数 |
| 错误能否定位到具体宏、步骤或参数 | 可定位错误数 / 故意错误数 |
| 列表截断时是否主动说明 | 自报截断的列表工具数 / 列表工具数 |

这些指标必须在同一场景、同一命令下比较。新增指标时先确认它能被稳定采集，再写入本文件。

## 连接、权限与生命周期

MCP 使用 stdio，不监听端口：

- 客户端启动 `whalegenie --mcp` 子进程并交换 JSON-RPC。
- 若已有窗口进程，子进程通过命名管道把两股流转发给窗口，工具操作屏幕上的项目。
- 若没有窗口，子进程直接服务；`--open` 与 `--new` 可指定项目，未指定时尝试上次项目，
  否则使用空项目。
- 客户端关闭管道后会话结束，进程随之退出。

权限只有 `settings.json` 一个来源，服务每次调用前读取：

| 操作 | 默认 | 权限 |
| --- | --- | --- |
| 读取项目、动作、资源和日志 | 允许 | 无 |
| 写入草稿、校验、预览 | 允许 | 无 |
| 应用草稿、保存项目、写图片 | 拒绝 | 允许直接控制 |
| 键鼠、窗口操作、读取剪贴板 | 拒绝 | 允许直接控制 |
| 运行宏 | 拒绝 | 允许 AI 运行宏 |

授权是进程级开关，不是按客户端或按调用授权。状态文件不可读或只写入一部分时按未授权处理。

状态改变、机器操作或导出完整图像的调用写入 `logs/mcp-YYYY-MM-DD.log`；文本输入只记录长度。
失败日志与 MCP 审计按文件名前缀区分，不能按“最新 .log”猜测类型。

## 写入模型

宏编辑遵循“草稿 → 校验 → 预览 → 应用 → 保存”：

1. `open_project` 为项目建立深拷贝草稿，并记录打开时的 `Revision`。
2. 工具只修改草稿；项目未被改动。
3. `validate` 返回 `blocking` 与 `hints`。`apply` 只阻止 `blocking`，`force` 可显式越过。
4. `preview_apply` 列出将新增、删除和修改的宏、步骤和参数。
5. `apply` 要求项目 `Revision` 未变化，成功后草稿不能再次应用。
6. `save_project` 才写入宏包，并保留备份。

一次会话最多保留 8 张草稿。达到上限时先丢弃最旧的已应用草稿，并在 `open_project` 的
`dropped` 中报告；若没有可丢弃的草稿，则返回 `TooManyDrafts`，不删除未落地的修改。

补丁按步骤操作：

| 操作 | 用途 | 定位 |
| --- | --- | --- |
| `set` | 修改一个参数 | `stepId`、`param`、`value` |
| `setRow` | 修改表格一行 | `stepId`、`param`、`match`、`values` |
| `addRow` | 增加表格一行 | `stepId`、`param`、`values` |
| `removeRow` | 删除表格一行 | `stepId`、`param`、`match` |
| `insert` | 插入步骤 | `parent`、`index`、`step` |
| `remove` | 删除步骤 | `stepId` |
| `move` | 移动步骤 | `stepId`、`parent`、`index` |
| `meta` | 修改步骤的启用、超时、重试、延迟与失败策略 | `stepId` 与要改的字段 |
| `macro` | 修改宏的名称、说明、启用状态、触发与播放设置 | 宏字段 |
| `declare` | 新增、修改或删除宏的形参与结果 | `action`、`name` 与声明字段 |

一行由自身内容定位，不按位置定位；命中零行或多行都拒绝。`parent` 是步骤在宏中的列表路径，
空字符串表示顶层。修改子宏内的步骤或元数据时，操作用 `macro` 指定大纲中的标签：
`sub:名字`，嵌套时写作 `sub:a/sub:b`。

写入结果返回 `outline`，列出每一步的 `id`、`type` 和 `path`，不默认回显整段宏。
需要整宏时显式请求 `includeMacro`。步骤标识在写入时分配；发现重复时为后到步骤重新发号，
并在结果中报告 `renamed`。

## 工具、资源与错误

### 工具

- 动作查询支持单项、批量与分类、隐藏项过滤；批量查询的未知键进入 `missing`，不使整批失败。
- `get_action` 提供参数读法、形状、单位、空值、条件必填、行列表列、返回值与记录字段。
- `get_macro_signature` 提供被调用宏的形参、结果、参数列和 `callTemplate`。
- 写入工具收对象或数组，不再要求把 JSON 放进字符串。
- `put_image` 接收 base64 或本机文件路径，将图片写入项目资源目录并返回步骤可引用的名称；
  `get_image` 只读取项目目录或日志目录中的图片。
- 草稿、项目、运行和机器操作按权限分组；新增工具必须复制既有权限与审计规则。

### 资源

| 资源 | 内容 |
| --- | --- |
| `whalegenie://actions` | 动作目录 |
| `whalegenie://actions/{key}` | 单个动作 |
| `whalegenie://action-matrix` | 动作矩阵摘要 |
| `whalegenie://project` | 项目修订号、宏摘要、全局变量和触发器 |
| `whalegenie://macros/{name}` | 宏修订号、步骤大纲、声明和触发器 |

资源页带 `revision` 作为缓存键。服务不声明资源订阅：stdio 会话没有可依赖的推送时，客户端通过
修订号判断是否重读。宏资源不携带每一步的参数，参数通过 `get_step` 或 `get_macro` 读取。

### 错误

拒绝统一返回：

```json
{"error":{"code":"稳定代号","message":"本地化说明","hint":"下一步建议","retryable":true,"details":{}}}
```

`code` 不随界面语言变化，客户端按 `code` 分支，不比较 `message`。参数形状错误在调用真实工具前
由容错层返回 `BadJson`，并指出参数名、收到的形状和期望形状；工具的 `inputSchema` 本身不放宽。

### 提示词与服务说明

服务提供“写宏”和“调试”两条提示词，并在服务说明中按草稿、读取、写入、目录、运行、查看和机器
操作列出工具。`docs.tool_names` 会扫描服务说明与提示词中的 `whalegenie_*` 名称，逐个核对
`tools/list`，避免文档指向不存在的工具。

## 已知限制

- **记录字段表依赖宏声明**：`fields` 只反映接口页中已写下的字段；未声明时为空，客户端无法核对
  `field(...)` 的字段名。
- **点位与矩形记录只能整值使用**：`set` 对窗口规则可接收整条对象；点位和矩形在文件中是一个值，
  应写记录变量或 `field($记录, "字段名")`，不能传对象。
- **运行日志不是资源**：每次运行内容不同，没有稳定修订号；通过工具按运行编号读取。
- **授权不按调用细分**：开关打开后，同一进程内的客户端共享权限；审计只能事后追踪。
- **图片读取范围有限**：`get_image` 只读取项目目录和日志目录，不提供任意本机文件读取。
- **非对象参数可能由 SDK 先拒绝**：容错层处理已进入工具的 `arguments`；在 schema 层就被拒绝的
  请求，其措辞由 SDK 决定。
- **不提供多客户端资源订阅**：每个 stdio 客户端是独立会话；窗口转发模式共享项目，但资源失效仍由
  客户端通过修订号判断。

## 自检方法

### 1. 固定场景

每次运行使用同一脚本：读取状态、打开草稿、查询动作、写入宏、校验、应用、保存、修改参数、
读取项目与宏资源、测试权限拒绝路径、清理草稿。场景变化时同时更新基线说明。

### 2. 自检只采集，不代替测试

`McpSelfCheck` 使用真实 MCP 客户端记录结果，不抛断言。字段缺失时记录错误并继续，以便同一工具
既能测量旧版本基线，也能测量修改后的结果。行为正确性由 `WhaleGenie.Tests` 中的 MCP 用例负责。

### 3. 使用真实传输

自检同时覆盖无窗口进程和带权限的窗口转发路径。测试使用内存管道验证语义，自检使用真实 stdio 与
子进程验证启动、关闭、权限读取和进程退出。

### 4. 输出可比较的报告

```powershell
dotnet run --project WhaleGenie -c Release -- --mcp-doctor --report TestResults/mcp-after.md
```

报告包含检查项、指标、资源和逐次调用。修改前后各保留一份，并记录报告中的动作数量和工具数量。
`--mcp-doctor` 退出码：0 全部通过，1 有失败，2 参数错误，3 无法建立通信，4 子进程无法启动。

### 5. 先修测量，再比较结果

若基线失败来自自检脚本或样本宏本身，应先修正测量或样本，不改变判定标准。否则修改前后的数字不再
描述同一件事。

### 6. 保持真实产物可测

`--mcp` 与 `--mcp-doctor` 必须能直接运行发布构建。仅在单元测试中成立的行为不视为协议可用。
临时工程、命名管道和子进程在结束后必须清理；清理按已知前缀和标识匹配，不使用无边界通配删除。
