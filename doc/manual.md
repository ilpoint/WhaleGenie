# WhaleGenie 使用说明

[简体中文](manual.md)

这份说明写给用这个程序的人，界面用中文，说清程序怎么用：宏包是什么形状，拾取器与落点怎么用，每一步能交回
什么，运行与调试怎么看，画面从哪来、怎么取，以及程序自己的文件放在哪儿。要改这个仓库，看 [dev.md](dev.md)；
一次"看屏幕"要花多少，看 [performance.md](performance.md)。

## 宏包（.wgmacro）

`.wgmacro` 是一个 zip 容器：

| 内容 | 说明 |
| --- | --- |
| `Manifest.json` | 版本、宏的列表、全局变量 |
| `README.md` | 打开包时能看到的一份说明，列出里面的宏 |
| `assets/` | 宏用到的图片，引用写作 `assets/<文件名>` |
| `<宏名>.json` | 每个宏的步骤树 |

读写都在 `WhaleGenie/Storage/MacroPackage.cs`：打开时把 `assets/` 解到磁盘并在步骤里改写成绝对路径，
保存时再把用到的图片收进包里。

## 拾取器

编辑动作时，需要"屏幕上的某个东西"的参数都有对应的拾取按钮，不用手写坐标、路径或标题：

| 参数 | 按钮 | 做什么 |
| --- | --- | --- |
| 目标图片（`vision.findImage` / `waitImage` / `clickImage`、`condition.imageExists` / `imageNotExists`） | 加一张 / 浏览… / 截屏… / 删除 | **一列图，一行一张**，从上往下试，第一张认出来的就是这一步用的那张（同一个按钮换了字、图标另一个尺寸，写一行就行）；每行可以从磁盘选图，也可以在屏幕上拖一个矩形当场存成 PNG，行首显示缩略图。要的不是第一张时，用「高级设置」里的「认哪一张」 |
| 单个图片（`clipboard.writeImage`） | 浏览… / 截屏… / 清除 | 选磁盘上已有的图片，或在屏幕上拖一个矩形当场存成 PNG；字段下面显示缩略图。图片也可以写成前面步骤存下的图片变量，框里打进几个字符就会把那些名字列出来 |
| 窗口（`window.*`、`vision.captureWindow`、`uia.*` 与两个元素条件、`condition.windowExists`、看屏幕的步骤与鼠标动作的基准窗口、后台输入的目标窗口、窗口触发器） | 拾取窗口… | 列出当前打开的窗口（标题、程序、大小、是否最小化/最大化），可按标题或程序筛选，回车或双击选中；「匹配内容」框下面还会列出**这一步现在会认到的窗口**（按「匹配内容」与「匹配方式」当场算，随改动自动重读，旁边有「刷新」），写宏时不必先跑一遍才知道认的是哪个窗口（列出来的每个窗口都在屏幕上框出来，最多五个，最小化的除外，窗口被拖到别处框就跟着走）。**认哪个窗口全程序只有一套问法**：「匹配内容」是要找的那段文字（步骤里可以写 `$变量`，只做替换、不写算式；触发器那一格是纯文本），「匹配方式」说这段文字和窗口的什么比、怎么比：标题包含（默认）、标题开头、标题正则、进程名、窗口类名。标题随打开的文档或界面语言会变时，改用进程名或窗口类名就认得住；选「标题正则」时字段名不变，正则写坏了当场在列表里报出来。`uia.*` 的元素动作、看屏幕的步骤（找图、找色、找文字、截图…）与鼠标动作把「坐标基准」选成窗口或客户区时的基准窗口、输入动作（`input.*`）把「输入方式」选成后台消息时的「目标窗口」，以及窗口触发器，用的都是这同一对（后几处在「高级设置」里，框下面也有同一份窗口列表；选前台或驱动级时这一步根本不读那个窗口，两格也就不问）。列出窗口（`window.list`）同样用它俩：留空**列出所有窗口**（别的窗口动作留空是"最前面那个"），它另有一格「每个窗口都读程序名与类名（慢）」（在「高级设置」里，默认关）：关着时每条记录只读标题、句柄与矩形，程序名与类名两格留空 |
| 选择器（`uia.*`、`condition.uiaExists`） | 拾取元素… | 鼠标移到控件上，蓝色边框圈出它，点击即写入选择器；它所在的窗口会顺手填进窗口过滤——填进去的是标题，所以「匹配方式」同时回到「标题包含」，拾取器读到的就是标题 |
| 颜色 | 放大镜 | 跟随鼠标的取色器，方向键可逐像素微调 |
| 屏幕区域（要读/要截的那一块、搜索区域、拖拽的起点终点） | 框选区域 | 在屏幕上拖一个矩形，一次填满整组参数；拖完还能接着调——在框里拖动移动它，拖四角或四边的方块改大小，确认之前这个框一直在。要读或要截的那一块就是四个数字字段（左上角 X、左上角 Y、向右的宽、向下的高），都在「基础设置」里，各自也可以写表达式；**四个数都留空就是整块屏幕**（少填一个，就从给出来的那条边一直量到屏幕边缘），截图与识别的参数表因此没有默认值，新建一步不会自己框住屏幕一角；搜索区域一行一处，行里同样是这四个数字，另有一格可以改由一个变量说明看哪里（截图动作留下的图片变量就在那张图里找，装着 `x,y,宽,高` 的变量按它写的位置看） |
| 按键（`input.keyPress` / `keyDown` / `keyUp`） | 虚拟键盘 | 弹出画着键盘的一页，点哪个键就填入哪个键名（左右修饰键分开：左Ctrl 与 右Ctrl 是两个名字，和触发器绑定的一致）；F13–F24、媒体键、音量键、浏览器与程序键都在页面下方。字段本身也仍然可以手写，或从全部键名里筛 |
| 手柄控件（`gamepad.*`） | 虚拟手柄 | 弹出画着手柄的一页：按键点在键上，摇杆和扳机点在哪一根上就填哪一侧 |
| 变量（任何可以填变量的字段） | 变量 | 弹出变量墙：按本宏 / 共享 / 鲸灵自带 / 步骤结局筛，点一个就插到光标处——要的是变量名本身的字段（变量名、列表变量、计数变量）插名字，别处连 `$` 一起插。悬浮在按钮上能看见它是什么、装什么、是哪一步留下的。**字段上直接弹出的名单只列你自己的变量与共享变量**，形式跟着这个字段的用法走（写名字的给名字，读值的给 `$名字`）；鲸灵自带的与步骤结局在那面墙的「系统」「步骤结局」页里，手写照样读得出来 |

看屏幕的动作（找图、找色、找文字、截图）旁边多一个「试找一下」：**只识别，不点击、不按键、
不写变量**，跑完弹出"识别结果"窗口 —— 截图作底，识别范围、全部候选、选中的那个、动作真正
要落的地方用四种颜色分开，框上标分数，文字识别在框上标出读到的字；右侧每一条命中都可以
勾选显隐、悬浮联动、点一下拉到窗口中间。找不到时不弹空窗，而是把最高分和它需要的门槛一起
说明白。窗口右上角有「全屏」（F11 一样，Esc 退回），双击画面在像素原本大小与适应窗口之间
切换；找图列了几张参考图时，顶部写着"参考图 2/3"并显示认出来的那张。
「保存图片…」能把带框那张按原本大小存成 PNG，「保存原图…」存的是没有标记的那一张
（拿它剪新的参考图），两张都是原本大小。运行调试时每一步最后看到的画面也会
挂到它的步骤行上做缩略图（没有识别的步骤不显示），点开就是同一个窗口，跑完还能回看。运行时正在读哪个窗口也在屏幕上框出来，读到哪一步框就落在那个窗口上（这一步里把窗口拖到别处，框也跟过去），下一步开始或跑完就收。

找图（`vision.findImage` / `waitImage` / `clickImage`）的**识别算法**是一枚下拉，四选一，
默认归一化相关：**归一化相关**先抵消画面整体明暗再比对；**相关**不抵消明暗，参考图很小时
更稳；**逐像素**要求两处几乎一样，纯色图标或对话框截图用它；**特征比对**把两边明显的特征点
配对，画面缩放或有小改动也认得出，慢一些且只返回一个命中。选了特征比对，表单上就只剩它用得
上的那几项（最少特征对数、忽略的颜色）—— 用不上的字段不会留在那里让人以为它起作用。
**参考图里会变的那一块可以不参与比对**：填上那个颜色（忽略的颜色），按钮上的数字、会走动的
进度条就不再影响识别。

列了几张参考图时，**认哪一张**（`imageSet`，在「高级设置」里）说清这一步要的是哪一张：
默认**认出的第一张**，就是同一个按钮有两套画法时的用法；**最像的那一张**把每一张都比一遍，
取分数最高的一张，用来在两张相像的图标里挑更像的一张；**每一张都要**要求这几张同时都在，
缺一张就当没找到，用于「整套都在才算到了这一步」的画面。交回命中时以列在第一张的那张为准，
「第几个命中」也在这张里数。

**多点找色**（`vision.findColors`，条件里叫「颜色组合存在」`condition.colorsExist`）找的不是一个
颜色，而是**一个颜色加上它周围几个位置上该有的颜色**：一个红点只能说明"这里有个红的东西"，
红点旁边还有什么才说明是哪一个红的东西，两个长得像的按钮就是这么分开的。基准色是中间那个，
「周围要对的颜色」一行一个、写成相对基准色的偏移与颜色（`12,-4,#FF0000`，偏移可以是负数），
每一个都要在写的位置上，整个图案还要落在搜索区域里面。交回的位置是基准色那一像素，
「试找一下」与识别结果窗口都能看到它把哪些点对过、各自要的是什么颜色。

**查找颜色**（`vision.findColor`）看的是颜色在哪一点上，另有一个**至少占比**（`minCoverage`，
0–100，默认 0 即不看占比）看的是**这块区域里有多少是那个颜色**——血条涨到一半、按钮亮起来、
仪表过了刻度用后者，而不是找一个像素在哪儿。占比按整个搜索区域算，多行区域合起来算一个；
勾上返回值里的「占比 %」就能把它读出来。算占比要把整块区域走一遍，没问占比的步骤不会因此变慢。

截屏存下来的图片放在宏包旁边的 `<宏名>.assets` 文件夹里，保存宏包时自动收进 `assets/`；
项目还没保存过时先放在 `%LOCALAPPDATA%\WhaleGenie\images`。路径的解析与截图落盘都在
`WhaleGenie/Storage/ImageAssets.cs`。

「表达式」（字段旁的"表达式"按钮）里也是同一面墙：运算符是按钮，变量也是按钮，点一下插到
光标处，不必先记住名字再手打。凡是引擎按值读取的字段旁都有这一个按钮，文本、颜色与数字一样；
区域的四个数字、搜索区域每一行的四个数字也各有一个。数字框里写进表达式就换成表达式框，清空它、
或写回一个普通数字，就又回到数字框。

**哪些框能写算式，看标签前面那个小 `ƒ`**：带这个标记的字段整段值都是一次算出来的（数字、颜色、
文本都算），没有标记的字段里 `$名字` 只做就地替换，其余部分照原样使用。字段下面那行小字也写着
这一条，所以不必记住"这个框算不算式子"。

**数字框留空是什么意思，同样写在字段下面。** 区域那一族的四个数留空是从这条边一直量到屏幕边缘
（或量到基准窗口的那一边）；四个都留空就是整块屏幕。别的数字留空是"没填"：这一项不写进
宏文件，引擎按"什么都没说"处理——等待类动作的「查看间隔」就是靠这个"没说"去跟屏幕的刷新率。
区域那四个数从哪里量起，写在同一段下面的那行小字里（屏幕 / 基准窗口 / 客户区 / 元素锚点）。

选择器、按键和手柄控件旁边都有一个"测试"，用来在写宏的时候当场确认选的是不是想要的那个：

- **选择器**是把它在屏幕上高亮一下（`uia.*` 的边框、页面里元素的闪烁），**不点它**——验的是
  "选中了是不是它"，真点下去会把用户的东西弄乱。
- **按键和手柄控件**是真的发一次：按键按这一步自己的输入方式走（前台 / 后台消息 / 驱动级），
  手柄是按一下、拨一下或扣一下，随后自动松开。按之前对话框会让开，好让你在目标窗口或游戏里
  看一眼对不对；手柄要看见效果，游戏得在前台。

试的就是**这一步本身**（按关掉对话框后会存下来的那份设置跑），而且只跑这一步：引擎里
`MacroRunner.TryAsync` 走的是和运行宏同一套代码，跑完把还按着的东西松开。

## 落点与落手

点击类的字段决定的不只是"点哪儿"，还有"怎么落手"。这几个字段在写宏时常常一起考虑：

| 字段 | 在哪 | 什么时候填它 |
| --- | --- | --- |
| **就在指针当前所在位置**（`useCursor`，默认关） | 鼠标点击 / 鼠标双击 / 鼠标按下 / 鼠标松开 / 滚轮 | 位置由用户自己放好的鼠标决定时用它：勾上后这一步不写坐标，运行时在指针当时停留的地方完成。勾上后「X」「Y」不画、不写进宏文件，坐标基准与基准窗口留着但这一步不读它们；取消勾选时原来填过的值原样回来 |
| **落点随机范围**（`variance`，像素，默认 0） | 鼠标点击 / 鼠标双击 / 点击图片 / 点击文字 | 连着点同一处时，不希望每次落在同一个像素上。填了数就每次都在这范围内随机取一点；`0` 是正好落在写的位置。数字要小到整个范围仍在被点的东西里面 |
| **点完把指针移回原处**（`moveBack`，默认关） | 鼠标点击 / 鼠标双击 | 点完之后要把鼠标还回用户自己放的地方，不让它留在游戏画面上。后台模式下屏幕上的指针本来就没动，这个开关不起作用 |
| **到终点先停**（`settleMs`，毫秒，默认 0） | 鼠标拖拽 | 拖到终点后先按住不动一会儿再松开。要拖进格子的东西只有指针在格子上停过一下才会被放进去；`0` 是一到就松 |
| **落手前再确认**（`recheckMs`，毫秒，默认 0） | 点击图片 / 点击文字 | 命中之后要先等一会儿再看一眼，这次仍认得才点。用于按钮一闪而过、画面其实已经翻过去的情况；`0` 是一认出就点 |

「落手前再确认」的第二次查看只查一次、不再等：等一会儿再看的这一次就是要看它还在不在，画面已经
变过就算没找到。

## 返回值：这一步的结果交给谁

添加动作页的第四个页签是「返回值」，列的是**这一步运行时能算出来的东西**：找图给的是命中的
位置、大小、相似度，读文件给的是文本或行，截图给的是图片和它盖住的矩形，启动程序给的是进程号。
**勾上的结果各自成为一个变量**，名字按 `备注_返回值名` 拼（备注框里改一个词，名字跟着改；自己
在名字框里写过的名字就不再跟着动），能在「变量」墙里找到、能在「插入变量」里选到；这个名字已经
被别的步骤用了时，末尾自动补上这一步的步骤标识；手工把名字写成别人的会显示出来，旁边一个「换个
名字」加个编号避开。**没勾的结果不写**，既不出现在变量墙里，也不占内存 —— 读它会被设计期检查
标成"没定义"。一个都不勾是允许的：这一步不留结果，只留下 `step.<步骤标识>.outcome` 这个结局
变量。**要看这一步算出了什么，不必先勾上**：运行调试里每一步的行上会把这**一次真正算出的所有
结果**（勾没勾都在）连同耗时写出来，「没勾的结果」在那里读得到，也标出哪些是宏自己留着的。

每一步跑完还留下两条系统变量：**结局** `step.<步骤标识>.outcome` 是 `ok` / `failed` /
`skipped`，**失败原因** `step.<步骤标识>.error` 装的是鲸灵自己给这个失败起的名字（例如
`Run.NoDevice`），没失败或没跑到时是空的。宏因此能按原因分支：条件里比一比
`$step.<步骤标识>.error` 就知道是哪一种失败，不必靠日志里的文字。

找图、等图、点图、找色、点色、找颜色组合、找文字、点文字、认元素这些**找**的动作，交出的「命中」
（`match`）是一个**记录**：一条命中是"一件事的几项答案"，它们一起走，不用为每一项各勾一个变量。
记录里的字段按找的是什么略有不同：

| 字段 | 是什么 |
| --- | --- |
| `x`、`y` | 命中的中心，单位是屏幕像素：点图、点文字落的就是这里，也是"下一步移过去"的意思 |
| `left`、`top` | 命中矩形的左上角，和「搜索区域」里那四个数同一个口径 |
| `width`、`height` | 命中矩形的宽和高 |
| `score` | 这一次的把握：找图找色是相似度（0–1，1 表示完全一样），找文字是识别模型给的读数分 |
| `box` | 整块矩形，写成 `左,上,宽,高`：填进搜索区域那一行的变量格，下一步就在同一处找 |
| `text` | 读到的那句话（只有找文字、点文字、认元素有） |

**取记录里的一项用 `field($变量, "字段名")`**，写错字段名不只是取不到值：这一步会报错，并把这条
记录**有哪些字段**列在错误里。整个记录写进文本时会写成一个 JSON 对象（`{"x":30,"y":40,...}`），
所以 `toJson` 与读 JSON 的那几个函数照样能用；`count($变量)` 给出这条记录有几个字段。

**中心点与左上角在同一个记录里各占一个字段，因为这两件事本来就不一样**：`x`、`y` 是动作要点的
那个点，`left`、`top` 是矩形的左上角。要让下一步在刚找到的地方再看一次，把 `box` 填进搜索区域
那一行的变量格，或者**直接把整个记录交给那一行**：区域里写 `$变量` 时，「left」「top」「width」
「height」四个字段就是那块矩形。找图、找色、找文字与认元素（`uia.find`）的命中、`window.info` 交的
窗口、`window.list` 里的每一条、截图交的 `place` 都走这条路：整条记录填进那一行就行，取其中一格用
`field($记录, "left")`。

找图、找色、找文字这类会有多处的动作，返回值里还有一项**「全部命中」**（`every`）：勾上就有了
一列记录，顺序就是「命中排序」里的顺序，「第几个命中」数的也是这一列；`count()` 数一数、
`get()` 取出其中一条、`forEach` 逐个走一遍都能直接用。每一项的样子和上面那张表一样，所以
"这条文字写在哪儿、写的是什么"是同一项里的两个字段，不用拿两张表对号。不勾就只有选中的那一处。

**点图与点文字也把命中的位置交出来**，和找图、找文字一样：点完之后想知道"刚才点的是哪儿"、
或者要把那个位置交给下一步时，不必再写一次查找。

**窗口信息（`window.info`）交的是一条记录**，一条记录把"这个窗口在哪儿、它是什么"一起说清：`title`、
`process`（程序名，不带 `.exe`，就是「匹配方式」选进程名时要比的那一段）、`class`（窗口类名）、
`handle`（句柄）、`minimized` / `maximized`、`left` / `top` / `width` / `height` 与 `box`（整块矩形，
写成 `左,上,宽,高`），再加上 `clientBox`（内容区，去掉边框与标题栏的那块，也就是坐标基准选
「窗口客户区」时数坐标的起点）。标题会变的窗口用类名或句柄认得出来，两个标题相同的窗口用句柄分开。

**窗口的矩形说的是它被看见的那个矩形**，不是 Windows 用来拉伸它的那个：普通窗口上左右下各多出七像素
看不见的边框，最大化的窗口还比屏幕大一圈。窗口相对坐标、这里的矩形、屏幕上框出来的位置、以及窗口画面的
起点是同一件事的四个说法，所以都按看见的算；`window.move` 收的也是这个矩形，把刚读到的那组数填回去，
窗口就回到原处。

**列出窗口（`window.list`）给的是一列记录**，一个窗口一条，字段是 `title`（标题）、`process`
（程序名，不带 `.exe`，就是「匹配方式」选进程名时要比的那一段）、`class`（窗口类名）、`handle`
（句柄）、`minimized` / `maximized`、`left` / `top` / `width` / `height` 与 `box`（位置与大小，
写成 `左,上,宽,高`）——与 `window.info` 交的那条记录同一个形状，少一个 `clientBox`。标题相同的两个
窗口是两个窗口，各占一条。
「它有哪些窗口」与"这些窗口分别是什么"是同一列里的同一条，不用拿几张表对号。这一步一个结果都
不勾时不去查程序名与类名 —— 那两个要问一次系统才知道，不勾就不花这份时间；勾了之后还要勾上
「每个窗口都读程序名与类名（慢）」它们才有值（默认关，关着时这两格留空，只按标题认窗口的宏不必付
这份时间）。挑出要列哪些窗口用的也是「匹配内容」与「匹配方式」这一对，留空就是列出所有窗口。

**截屏（`vision.capture`）与截取窗口（`vision.captureWindow`）把画面在哪儿也交出来**：返回值里勾上
「位置」（`place`）就有了这块画面的记录，`left` / `top` 是它开始的位置，`width` / `height` 是它的大小
（画面在屏幕边上被截短时写的就是实际拿到的那一份），`box` 是整块矩形。下一步要在这块画面上再看一次，
把整条记录填进搜索区域那一行就行。

**读表格（`uia.readTable`）交的就是一列记录**：一行一条，键是表格列标题那一行写的列名，取一个单元格
按名字取——`field(get($表格, 0), "金额")`——不用数它排第几。表格没有列标题时，列名就是 `A`、`B`、
`C`；列名为空、或者与前面某一列重名的列，也用它的列号当名字——一个名字底下不能放两列。勾上「按表格
读」的文字识别（`ocr.recognize`）交的同样是每行一条记录，屏幕上读来的东西没有列标题，键一律是格子的
列号 `A`、`B`、`C`。这与读 CSV 是同一种形状（见「分隔符文件」）。

**认到的元素（`uia.read`）交的也是一条记录**：`enabled` 与 `visible`（现在能不能用、是不是显示着）、
`value`（元素自己持有的内容——输入框里的文字、按钮上的标题；本身不持有内容的元素为空）、`name`、
`automationId`、`controlType`，再加上 `left` / `top` / `width` / `height` 与 `box`。取其中一项用
`field($元素, "value")`：想"等这个按钮能用再点"就写一条条件读它，不必靠猜。
要**按下**一个控件而不动鼠标，用「按下元素」（`uia.invoke`）：它走控件自己的动作，鼠标停在原处、
窗口也不会被抬到前面，所以后台窗口里的按钮按得动；控件不提供这种方式时会报出来，不会退回去点鼠标
——真要挪过去点一下，用「点击元素」。

**占比 %**（`coverage`，只有查找颜色有）问的是"这块区域里有多少是那个颜色"：0–100 保留一位小数，
找没找到都会写，所以占比不够时能读出差多少；「至少占比」拿它当判定线，低于这条线就算没找到。
查找颜色只看一次：要一直等到占比够了才往下走，用条件**「颜色占比达到」**
（`condition.colorCoverage`，`至少占比 %` 0–100、默认 0 即"区域里有这个颜色就行"）配
`control.waitUntil`；只等某一个像素变成某个颜色，用「等待颜色」。

## 子宏：一段流程用第二次

一个宏可以说明自己**收什么、交回什么**，别的宏就能像调用一段现成的流程那样用它；这段流程在文件里只
有一份，改一处两处都跟着变。

「执行其他宏」（`control.runMacro`）这一步的表单**按被调用宏的声明生成**：先选宏，「基础设置」里就
出现它声明的每一个**形参**，一格一个，值按其他字段的读法读（`$n + 1` 传的是数字，`$列表` 传的是列表
本身）；有默认值的形参可以留空，留空就用那个默认值，声明为必填的留不得。这一步要取回哪些**结果**在
「返回值」页上勾，勾上的每一项在本宏里各自成为一个变量，名字由那一行决定。

填错的名字不会被放过去：传了一个被调用宏没有声明的形参、或者要取回一个它没声明交回的名字，写宏时
就在步骤上标出来；这样的步骤如果还是进了宏文件（手写进去，或者被调用的宏后来改了声明），运行到它
会当场停下并说清是哪一个名字。

被调用的宏用自己的一套变量：它读得到传进去的形参、共享变量与鲸灵自带的变量，读不到调用者的本宏变量；
它留下的东西只有声明过、并且这一步勾了的结果才回得来。写在里面的 `break` / `continue` 只作用于它自己
的循环，调用者的循环不受影响。

声明由「提为子宏」一次做出来：在动作列表里选中同一层里的若干步骤，按面板上的**提为子宏**，编辑器就建
一个以当前宏的名字命名的新宏（重名自动编号）、把这段步骤搬进去、在原来的位置留下一条指向它的
「执行其他宏」。这段步骤**读到的**本宏变量成为新宏的形参，调用处已经按原名填好；这段步骤**写下的**
变量成为新宏的结果，调用处把它们逐个取回同名的变量，所以宏剩下的部分照旧读到原来的名字，什么都不用改。
新宏跟着这个宏一起进项目：保存之后它才出现在列表里，也才成为别的宏调用得到的宏。共享变量与鲸灵自带的
变量两边都读得到，因此不会变成形参。

## 运行与调试

宏卡片的右键菜单里有一项**「运行调试」**：它打开运行与调试窗口，把那个宏的步骤装进去并开始跑。窗口一次
只开一个，再对另一个宏点这一项就是停下正在跑的那个、换成它的步骤重新开始，"为什么停了"写在日志的第一
行。主窗口标题栏的「运行调试」按钮打开的是同一个窗口，只是不带步骤：没有可跑的东西时运行控制不画，
页面上写着从卡片右键开始调试。

窗口分「调试」与「变量」两页。**调试**：步骤列表、每一步最后看到的画面缩略图（点开就是识别结果窗口）、
每一步跑出来的东西（见下），以及日志。**变量**：本宏 / 全局 / 系统三个页签，全局变量在这里新建、改名、
改默认值与说明、删除（宏只能改它的值），系统变量的当前值实时读出来且只读，"在用"那一页列出整个宏列表用到
了哪些变量。运行与「试找一下」还会把正在读的那个窗口在屏幕上框出来，读到哪一步框就落在哪个窗口上。

**断点与暂停**：点步骤左边的圆点就是下断点，再点一下取消。跑到带断点的步骤前会停下来等「继续」；断点还
可以带一个**条件**（右键圆点 →「设置断点条件…」，条件写在弹出的表单里，和 `if`、`waitUntil` 用的是同一
套条件）：条件成立才停，不成立就直接跑过去——循环里的某一步只有跑到第几轮才会停下来时用它。条件算不出结果
时（例如它读的变量那一刻还没有值）会照停，并在日志里写清是为什么。停在断点上时右键那个圆点还能**「跳过我
这一次」**：这一步不执行、也来不及有副作用，运行直接接着下一步走，行上写的是"未执行"。
条件那一行没有圆点：条件是被它所属的那一步问的，不是自己跑的一步，要停在问之前，把断点下在那一步上。

**每一步跑出来什么**：运行调试里每一步的行会把这一次的结果写出来 —— 怎么结束的（完成 / 失败 / 未执行）、
花了多少毫秒、失败的话为什么失败，以及**这一步真正算出的每一个结果**：勾了结果的行用宏里的变量名，没勾的
行用鲸灵自己的名字（例如 `encoded`、`match`），两者都读得到值，所以想看一眼某个返回值不必先回去勾上再跑
一遍。勾选只决定"要不要成为变量"，不决定"看不看得见"。

**宏自己问人**：「询问使用者」与「询问文字」这两步会让宏停下来等人：前者问一句话、交回真假，后者要一行
文字、交回文本。编辑器里跑的时候，问题出现在步骤列表下面那一条上；触发器发起的运行没有运行调试窗口，问题
由主窗口弹出来问。答到一半被「停止」按下，按"没有回答"收场——「询问使用者」交回假、「询问文字」交回空，
这一步仍然算完成，宏自己按交回来的东西决定下一步。问多久会一直等下去：宏停在那里，屏幕上就是那个问题。
交给引擎但不接界面的运行（例如自动化测试直接调引擎）也按"没有回答"走，不会挂住。

**这一步自己判失败**：「判为失败」（`control.fail`）把这一步记成失败，交给这一步设置里的重试与失败
策略，和你按下「停止整个宏」是两回事——判失败说的是"这一步没做成"，宏里写着的失败策略照常起作用。
原因可以不填；填了会写进日志，也写进 `step.<id>.error`，后面的步骤读得到，所以"哪一步不对"能顺着
往下传。反过来，「说明」（`control.note`）只是写在宏中间给人看的一行字：运行时不做事、不写日志，
里面的 `$名字` 也不替换，宏长起来以后靠它分段。

**两条宏一起跑**：两个宏同时发键鼠时，按键会写进对方中间——收到输入的那个窗口看到的是两条宏的按键交错在
一起。宏的触发页有一格「与别的宏互斥发输入」：勾上的宏共用一条输入门，只有发键鼠的步骤取门，一步一步轮流
发；读屏幕和识别的步骤不取门，两个宏可以同时看同一个窗口。默认不勾，一个宏单独跑时没有要等的人。勾了的宏
在运行调试里看得见现在是谁在发输入。

**开着的宏在等什么**：运行调试里有一段「等触发的宏」，凡是用定时去看的那几种触发器（颜色、程序、窗口、
计时）各占一行：等的是什么、现在成不成立、上次判定是什么时候、下次什么时候去看它。宏没有在该跑的时候跑起
来，答案几乎都在这一段里，不必靠猜。窗口这一类另有一句「窗口有变化时机器会先说一声」：机器听见窗口出现、
消失或改名就立刻看一遍，所以只亮一下就关掉的窗口也认得到；那 500 毫秒一轮是机器不肯说时的退路。
窗口触发器认窗口用的是和别处同一对「匹配内容」与「匹配方式」，标题会变就用进程名或正则认；宏的触发页里
「匹配内容」下面同样列着这一步现在会认到的窗口，改一格就重读一遍。

## 画面从哪来、怎么取

看屏幕的步骤（截图 / 截取窗口 / 找图 / 等待图片 / 点击图片 / 取色 / 等待颜色 / 查找颜色 /
多点找色 / 等画面静止 / 文字识别 / 找文字 / 点击文字，以及这一族的八个条件）都能说清画面**从哪来、怎么取**，
也能说清它**多久读一次屏幕**。还有一件不属于某一步：**从哪来、怎么取**由程序设置里那两行说了算——

| 设置里的「读窗口」 | 取到什么 |
| --- | --- |
| 自动（默认） | 先走 Graphics Capture，不行再让窗口自己画，最后退回屏幕像素 |
| 窗口（PrintWindow） | 让窗口自己画一遍，多数窗口都行；取到整窗，含标题栏与边框 |
| Graphics Capture | 取窗口自己显示的内容，被别的窗口压住也取得到；只有内容区、不含标题栏，需要 Windows 10 2004 或更高版本 |

| 设置里的「读屏幕」 | 取到什么 |
| --- | --- |
| 自动（默认） | 先问显卡要它正在往显示器送的那张画面（桌面复制，整屏约 2 毫秒），做不到时按 GDI 复制 |
| 桌面复制（DXGI） | 显卡交出的整块画面，独占全屏的游戏只有它取得到；显示器开着 HDR 或转着用时不行 |
| 桌面（GDI） | 从屏幕里复制，不要求显卡，抓一小块最省，总能取到点什么 |
| Graphics Capture | 按读窗口的那套机器读显示器，需要 Windows 10 2004 或更高版本 |

**来源由坐标基准决定**：坐标基准选屏幕就是桌面，读屏幕那一档；选窗口就是那个窗口（截取窗口用
它自己认出的那个），读窗口那一档。点了哪一档就只走那一档，这一档失败就报出来
（`Run.NoGraphicsCapture` / `Run.CaptureFailed` / `Run.EmptyRegion`），不换别的路——只有"自动"会
一路退下去。用得上这几条的前提是游戏**没被最小化**：最小化之后窗口自己不再画，窗口那两档都报
`Run.EmptyRegion`。改完设置从下一步看画面起生效。

**「整屏」指的是整块桌面**，不是主显示器：所有显示器合起来的那一块矩形就是宏坐标所在的那个范围，把显示器
摆在主屏左边或上边，它的左上角就是负数。区域那四个数留空量到的边缘、截图不带矩形时的整屏、系统变量
`sys.screenWidth` / `sys.screenHeight`，量的都是这块矩形；三块拾取器（取色、元素、区域）的覆盖层也盖住
整块桌面，副屏上的坐标同样拾得到。**每块显示器在哪**用「列出显示器」（`screen.list`，系统分类）读：交回
一条记录列表 `displays`，一块显示器一条，键是 `left` / `top` / `width` / `height` / `right` / `bottom` /
`primary` / `box`，取其中一块的一项写 `field(get($显示器, 0), "left")`，全部走一遍用 `forEach`。

**Graphics Capture 的会话按窗口、按屏幕各留一份**，不在每次读的时候重新开关。开一个会话要建显示设备与
帧池（第一次 0.4 秒上下），读一次就开关一次比留着慢三倍；而且 Windows 会在正被读的窗口或屏幕
四周画一圈捕获提示边框，会话开着就在、关掉就没——**每次读都开关会话，那圈边框就会一闪一闪**。
读不动（库认不出这个窗口）的窗口记下来，后面不再每次去试。

Windows 11 上那圈系统边框会被代码关掉（`IsBorderRequired`）；**Windows 10 19045 及更早没有这个接口，
关不掉**——会话一开，那圈黄框就一直在（本机 Windows 10 上实测：屏幕最上面两行是 199,174,7 的黄，没有
会话时一个黄像素都没有）。系统那圈框只说"有东西在读"，说不了"读的是哪一个"：读的是哪个窗口，看我们自己
画的蓝框——添加动作窗口列出来的窗口、运行调试读到哪个窗口，框就落在哪里。

会话与文字识别模型都来自**程序持有的那一份设备层**：窗口、触发器的运行、试找与调试运行共用它，谁都不在
半路释放，程序退出时才一起放掉——所以同一个窗口第二次读不再重开会话，第二步读文字不再加载一遍模型。设置里
的**「启动时在后台预加载文字识别」**（默认关）就是把模型加载提到启动时做，免得第一步读文字的步骤替它等；
关着时模型在第一次读文字时加载，之后一直留在内存里。

另外两个字段也在「高级设置」里，用来省下连着看同一处的开销：

- **接受多久以内的画面**（`frameMaxAgeMs`，0–60000 毫秒，默认 0）：大于 0 时，同一次运行里同一
  个来源（同一个窗口，或桌面）刚抓过、又包得住这次矩形的画面直接裁下来用；第一次读的是整个窗口
  或整块屏幕，省下的是它后面那几次读屏。0 表示每次都重新读。
- **查看间隔**（`intervalMs`，0–60000 毫秒）：等待类步骤（等待图片 / 等画面静止 / 点击图片 /
  等待颜色 / 点击文字）拿它当轮询间隔，留空就是**屏幕刷新一次的时间**（60 赫兹 16 毫秒、
  240 赫兹 5 毫秒），也就是每隔一次刷新看一回——再快也只是把同一张画面读第二遍；填 0 表示
  上一次看完了立刻再看。只看一次的步骤与条件拿它当同一步骤两次查看之间的下限，默认 0，
  也就是轮到它就立刻看。7 毫秒约等于每秒 144 次。

等待类步骤（等待图片 / 点击图片 / 等待颜色 / 等画面静止 / 点击文字 / 等待直到）等多久只写在
步骤设置里的**「超时」**一处：到了这个时长，这一步被取消并判失败，交给重试与失败策略，重试时
从头开始等；新建这些动作的步骤时它默认 5000 毫秒（等待直到是 10000 毫秒），清空即不限时，等到
运行被停为止。这一步等的是什么就说什么（没等到哪张图 / 哪个颜色 / 哪行字 / 哪个条件），不只是一句
"超时"。查找颜色与找文字只看一次，没有等待，等某个画面条件成立用 `control.waitUntil`，等一个像素
变色用「等待颜色」。

一次"查看"是一次取景加一次比对。在 2560×1440 的开发机上实测：整屏走桌面复制约 2 毫秒（每秒约 500 次），
同样整屏走 GDI 约 25 毫秒（每秒约 40 次）、100×100 的小区域约 4 毫秒（每秒约 240 次）、窗口 Graphics Capture 约
10 毫秒（每秒约 100 次）；参考图越大、区域越大，比对那一段越贵。

「试找一下」和运行调试回看的那个窗口，顶部会写上画面取自哪里、用哪种方式取的（桌面 / 窗口，
GDI / PrintWindow / Graphics Capture / 桌面复制（DXGI）），找不着时先看这一行就知道是不是读错了窗口。

桌面复制是整屏最快的一条路（整屏约 2 毫秒，画面没有重新画过时几乎不要钱），代价是每个进程第一次用它要
先建一次显卡设备，约 0.25 秒，一次运行只付一次；它取到的画面里没有鼠标指针，与 GDI 复制屏幕一致。

**读到什么**　读文字的三步（文字识别 / 找文字 / 点击文字）共用一格**「读取内容」**（在「基础设置」
里），说读到的每一段留下什么：**全部文字**照原样留下；**只读数字**、**只留字母**、**只留中文**、
**只留字母与中文**这几档只留下要的那类字符——首尾的空格去掉、中间连续的空格并成一个，一个要的字符
也不剩下的段落就当没读到，全角字母与全角数字按半角算；**按正则提取**时旁边多一格**「提取的正则」**
（在「高级设置」里），把这段正则套在每一段上：匹配不上的段落不算，匹配上的段落只留下括号里的第一组
（正则里没有括号时留下整个匹配），例如 `单号：(\d+)` 会把「单号：88231」只留下 88231，留空表示不
做提取、读到的文字原样留下。这几档让同一步既能把一屏标签读成金额、也能读成货号，还能只留下中文；
随包那一份模型本来就中英文都读，所以「只留中文」是在读出来的结果里挑中文，不是换一份模型。表格模式
读到的同样是这几档过滤之后的段落。

## 分隔符文件（CSV）

`file.readCsv` / `file.writeCsv` 读写的是一行一行的文本：分隔符可以点名，也可以让它自己从文件里
认出来（`auto`），引号、单元格里的换行、行尾、空行这些细节归 `CsvHelper` 管。

读到的每一行是一条记录：键就是表头那一行写的列名，所以取一个单元格按名字取——`field(行, "金额")`——
不用数它排第几；文件的第一行不是表头时，列名就是 `A`、`B` 这样的列号。按内容挑行用 `matchColumn` /
`matchValue`，只留几列用 `columns`。写的时候选"追加"再勾上
「按列名放进同名的列」（`align`），每个值就落进文件第一行里同名的那一列——别人的程序多一列、
少一列，都不会把后面的内容挤错位；文件里没有那个名字时会报出来点名。空单元格默认写成两个分隔符
之间留空，非要看见格子的程序可以用「空单元格写成」让它写成两个引号（`emptyCells`）。

## 图片与校验和

「保存图片」（`vision.saveImage`）把一张图片写成文件：图片可以是前面某一步截下来的图像变量
（`$shot`），也可以是一个已经在磁盘上的图片文件；写出来的**一律是 PNG**，同名文件会被替换。
不指定路径时按相对路径从宏文件夹算起（见下），所以一个宏把截图存在自己旁边、换个地方打开也照旧找得到。

「计算摘要」（`data.hash`）算的可以是**一段文本**，也可以是**一个文件**：选文件后填路径，读的是文件的
原始字节，和别的程序算出来的值对得上（MD5 / SHA-1 / SHA-256 / SHA-512）。文件是一块一块读的，多大的
文件都不会把内存占满——校验安装包、下载文件、备份包时用它。

## 表达式函数一览

下表是表达式里可以直接用的全部内置函数，与表达式编辑器里列出的那一份相同（编辑器按同一套分组列出，
点一条就把它的名字和左括号插到光标处，剩下的参数自己填）。写法里 `[, ]` 之间的参数可以不写，`...`
表示可以接着往下写更多个。函数名不分大小写。

### 文本

| 写法 | 说明 |
| --- | --- |
| `upper(text)` | 把值写成大写字母。 |
| `lower(text)` | 把值写成小写字母。 |
| `trim(text)` | 去掉两端的空格。 |
| `length(value)` | 一个值有多少个字符，或一个列表有多少项。 |
| `substring(text, start [, length])` | 取一部分文字，起点从 0 数起，不写长度就取到末尾。 |
| `replace(text, old, new)` | 把每一处旧文字换成新文字。 |
| `replaceRegex(text, pattern, replacement)` | 按正则替换，替换里用 `$1`、`$2` 引用括号里抓到的那几段；正则前面写 `(?i)` 表示不区分大小写。 |
| `split(text, separator)` | 按分隔符切成一个列表。 |
| `join(list, separator)` | 把列表的每一项接成一段文字。 |
| `contains(value, needle)` | 文字或列表里有没有这一段。 |
| `startsWith(text, prefix)` | 文字是不是以这一段开头。 |
| `endsWith(text, suffix)` | 文字是不是以这一段结尾。 |
| `indexOf(value, needle)` | 这一段在第几个字符上，找不到是 -1。 |
| `repeat(text, times)` | 把同一段文字重复若干遍。 |
| `concat(value, ...)` | 把每一个参数接成一段文字。 |
| `format(template, ...)` | 把模板里的 `{0}`、`{1}` 换成后面的参数。 |
| `match(text, pattern)` | 正则有没有匹配到这段文字。 |
| `extract(text, pattern)` | 正则匹配到的第一段文字。 |

| --- | --- |

| `sum(list)` | 把一个列表里的数加起来。 |
| `random([min, max])` | 一个随机数；写了范围就是该范围内的整数。 |

## 程序自己的文件放哪儿

`settings.json`（设置窗口里的选择）和 `logs`（运行失败时的截图）都写在 `WhaleGenie.exe` 所在的
目录：整个文件夹拷走就等于把设置一起带走，两个副本放在一起也不会互相干扰。装在只让管理员
写的地方（比如 `Program Files`）时这两样写不进去，程序照常运行，只是设置不落盘、失败不留图。

宏和宏包不跟着程序走：默认在「文档」目录下的 `WhaleGenie` 里（`%USERPROFILE%\Documents\WhaleGenie`），
它在哪由打开的宏包决定。
