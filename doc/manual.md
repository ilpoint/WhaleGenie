# WhaleGenie 使用说明

[简体中文](manual.md)

这份说明写给用这个程序的人，界面用中文，说清程序怎么用：宏包是什么形状，拾取器与落点怎么用，每一步能交回
什么，运行与调试怎么看，画面从哪来、怎么取，以及程序自己的文件放在哪儿。要改这个仓库，看 [dev.md](dev.md)；
一次"看屏幕"要花多少，看 [performance.md](performance.md)。

**第一次打开、手上什么都没有的时候**：主列表空着，下面那枚「新建宏」就是入口。帮助菜单的「快速上手」打开
的是随程序装好的这份手册（包里的 `doc/manual.md`），找不到那一份时才打开仓库里的页面。

## 宏包（.wgmacro）

`.wgmacro` 是一个 zip 容器：

| 内容 | 说明 |
| --- | --- |
| `Manifest.json` | 版本、宏的列表、全局变量 |
| `README.md` | 打开包时能看到的一份说明，列出里面的宏 |
| `assets/` | 宏用到的图片，引用写作 `assets/<文件名>` |
| `<宏名>.json` | 每个宏的步骤树 |

读写都在 `WhaleGenie/Storage/MacroPackage.cs`：打开时把 `assets/` 解到磁盘并在步骤里改写成绝对路径，
保存时再把用到的图片收进包里。

## 拾取器

编辑动作时，需要"屏幕上的某个东西"的参数都有对应的拾取按钮，不用手写坐标、路径或标题：

| 参数 | 按钮 | 做什么 |
| --- | --- | --- |
| 目标图片（`vision.findImage` / `waitImage` / `clickImage`、`condition.imageExists` / `imageNotExists`） | 加一张 / 浏览… / 截屏… / 删除 | **一列图，一行一张**，从上往下试，第一张认出来的就是这一步用的那张（同一个按钮换了字、图标另一个尺寸，写一行就行）；每行可以从磁盘选图，也可以在屏幕上拖一个矩形当场存成 PNG，行首显示缩略图。要的不是第一张时，用「高级设置」里的「认哪一张」 |
| 单个图片（`clipboard.writeImage`） | 浏览… / 截屏… / 清除 | 选磁盘上已有的图片，或在屏幕上拖一个矩形当场存成 PNG；字段下面显示缩略图。图片也可以写成前面步骤存下的图片变量，框里打进几个字符就会把那些名字列出来 |
| 窗口（`window.*`、`vision.captureWindow`、`uia.*` 与两个元素条件、`condition.windowExists`、看屏幕的步骤与鼠标动作的基准窗口、后台输入的目标窗口、窗口触发器） | 拾取窗口… | 列出当前打开的窗口（标题、程序、大小、是否最小化/最大化），可按标题或程序筛选，回车或双击选中；「匹配内容」框下面还会列出**这一步现在会认到的窗口**（按「匹配内容」与「匹配方式」当场算，随改动自动重读，旁边有「刷新」），写宏时不必先跑一遍才知道认的是哪个窗口（列出来的每个窗口都在屏幕上框出来，最多五个，最小化的除外，窗口被拖到别处框就跟着走）。**认哪个窗口全程序只有一套问法**：「匹配内容」是要找的那段文字（步骤里可以写 `$变量`，只做替换、不写算式；触发器那一格是纯文本），「匹配方式」说这段文字和窗口的什么比、怎么比：标题上有五档——包含（默认）、开头、结尾、等于、正则，进程名与窗口类名各两档——包含、等于（与别处比文字用的是同一批词，见「怎么比文字」）。标题随打开的文档或界面语言会变时，改用进程名或窗口类名就认得住；选「标题正则」时字段名不变，正则写坏了当场在列表里报出来。`uia.*` 的元素动作、看屏幕的步骤（找图、找色、找文字、截图…）与鼠标动作把「坐标基准」选成窗口或客户区时的基准窗口、输入动作（`input.*`）把「输入方式」选成后台消息时的「目标窗口」，以及窗口触发器，用的都是这同一对（后几处在「高级设置」里，框下面也有同一份窗口列表；选前台或驱动级时这一步根本不读那个窗口，两格也就不问）。列出窗口（`window.list`）同样用它俩：留空**列出所有窗口**（别的窗口动作留空是"最前面那个"），它另有一格「每个窗口都读程序名与类名（慢）」（在「高级设置」里，默认关）：关着时每条记录只读标题、句柄与矩形，程序名与类名两格留空 |
| 选择器（`uia.*`、`condition.uiaExists`） | 拾取元素… | 鼠标移到控件上，蓝色边框圈出它，点击即写入选择器；它所在的窗口会顺手填进窗口过滤——填进去的是标题，所以「匹配方式」同时回到「标题包含」，拾取器读到的就是标题。**打开时鲸灵自己的窗口全部收起来**（含正在写宏的编辑器与问话的那个对话框），拾完按原状回来 |
| 页面里的元素（`browser.*` 的元素动作） | 在页面里拾取… | 在宏已经打开的那份浏览器上拾取；还没有打开时，按这一步的「网址」与「档案」开一份出来。点一下要用的元素：**最稳的那条说法**写进字段，其余的说法列在按钮旁边，点一下追成字段的下一行（见「浏览器」）。按 Esc 放弃 |
| 颜色 | 放大镜 | 跟随鼠标的取色器，方向键可逐像素微调；**打开时鲸灵自己的窗口同样全部收起来**，取完按原状回来。取到的那一点**同时写进这一步的 X、Y**（这一步有位置字段时），瞄准哪个像素就取哪个像素的颜色，取完不必再对一次位置 |
| 屏幕区域（要读/要截的那一块、搜索区域、拖拽的起点终点） | 框选区域 | 在屏幕上拖一个矩形，一次填满整组参数；拖完还能接着调——在框里拖动移动它，拖四角或四边的方块改大小，确认之前这个框一直在。**框选期间鲸灵自己的窗口全部收起来**（含正在写宏的编辑器与问话的那个对话框），框完按原状回来；「截屏…」也在窗口还收着的时候拍，拍之前先等桌面重画一遍，所以图片里不会出现它们。**要框的那块画面看得清**：窗口打不开一个洞，所以打开的一刻先把桌面拍成一张底图铺在里面，底图定格在那一刻——刚打开时屏幕上什么都还是原样（指针也是平时的样子），一拖出框才把框外压暗、框内照原样，拖动与改大小都在这张底图上对准。要读或要截的那一块就是四个数字字段（左上角 X、左上角 Y、向右的宽、向下的高），都在「基础设置」里，各自也可以写表达式；**四个数都留空就是整块屏幕**（少填一个，就从给出来的那条边一直量到屏幕边缘），截图与识别的参数表因此没有默认值，新建一步不会自己框住屏幕一角；**要读要截的那一块另有一个开关「矩形取自一条记录」**（`useRecord`，默认关）：勾上它，这四个数不画、也不参与，改由「记录」那一格给出一整块矩形——上一步的命中、一个窗口、之前截下的画面都带着 `left`、`top`、`width`、`height`，下一步就在刚找到的那一块上读或截（见「返回值」的记录一节）；**框选之后那个开关会被关掉**，刚在屏幕上拖出来的数就是你这一块。搜索区域一行一处，行里同样是这四个数字，另有一格可以改由一个变量说明看哪里（截图动作留下的图片变量就在那张图里找，装着 `x,y,宽,高` 的变量按它写的位置看，一条带矩形的记录也按它说的那一块看）。**拖拽的起点与终点各是两格数字**（起点 X、起点 Y、终点 X、终点 Y），每一端另有一对开关与记录格（「起点取自一条记录」/「终点取自一条记录」）：勾上就由那一格里的记录说出这一点（上一步的命中、一个窗口、一个元素都行，取的是那块矩形的中心），框选一次四格一起填：起点是矩形的左上角，终点是右下角。**写出来的数字从「坐标基准」量起，一条记录按屏幕像素读**（见「返回值」的记录一节） |
| 按键（`input.keyPress` / `keyDown` / `keyUp`） | 虚拟键盘 | 弹出画着键盘的一页，点哪个键就填入哪个键名（左右修饰键分开：左Ctrl 与 右Ctrl 是两个名字，和触发器绑定的一致）；F13–F24、媒体键、音量键、浏览器与程序键都在页面下方。字段本身也仍然可以手写，或从全部键名里筛 |
| 手柄控件（`gamepad.*`） | 虚拟手柄 | 弹出画着手柄的一页：按键点在键上，摇杆和扳机点在哪一根上就填哪一侧 |
| 变量（任何可以填变量的字段） | 变量 / 用表达式取值 | 弹出变量墙：按局部变量 / 全局变量 / 鲸灵自带 / 步骤结局筛（另有「全部」一条），点一个就插到光标处——要的是变量名本身的字段（变量名、列表变量、计数变量）插名字，别处连 `$` 一起插。悬浮在按钮上能看见它是什么、装什么、是哪一步留下的。**字段上直接弹出的名单只列局部变量与全局变量**，形式跟着这个字段的用法走（写名字的给名字，读值的给 `$名字`）；鲸灵自带的与步骤结局在那面墙的「系统」「步骤结局」页里，手写照样读得出来。整段值被当作一个值读的字段（路径、能写算式的文本）在墙上还多一个「用表达式取值」：不插名字，改打开表达式编辑器，算出来的值直接写回这个字段；写变量名的字段与认窗口的字段没有这个按钮——那里写算式会变成名字或变成要匹配的文字；区域那一行的变量格也没有，那里写的是矩形文字、图片变量名或一条装着矩形的记录，算式不会当作值读。**取记录的那几格是一个值**：鼠标动作、看像素、截图、识别文字与移动窗口的「记录」，还有拖拽的「起点记录」「终点记录」，整格当作一条记录读，所以墙上多一个「用表达式取值」——要用算式算出那条记录就点它 |

看屏幕的动作（找图、找色、找文字、截图）旁边多一个「试找一下」：**只识别，不点击、不按键、
不写变量**，跑完弹出"识别结果"窗口 —— 截图作底，识别范围、全部候选、选中的那个、动作真正
要落的地方用四种颜色分开；右侧每一条命中都写出它落在哪儿、读到的是什么字、离这一步的门槛
还差多少（这一步没写门槛就不写这一句），都可以勾选显隐、悬浮联动、点一下拉到窗口中间。
**落在哪儿写的是矩形中心在前**（`(x, y)`，就是命中记录里那对 `x`、`y`，也是鼠标动作与拖拽两端从一条记录里取到的那个点），跟着是左上角与宽高：照界面上写的数填，不必自己把
宽高折半加上去。
找不到时不弹空窗，而是把最高分和它需要的门槛一起说明白。窗口一打开就按真实的画面区把整张图
铺满，窗口大小改了也跟着重算（自己缩放过之后就不再跟着）。右上角有「全屏」（F11 一样，
Esc 退回），双击画面在像素原本大小与适应窗口之间切换；找图列了几张参考图时，顶部写着
"参考图 2/3"并显示认出来的那张。

读到的文字有两条能带走的出路：右侧每一行写出它读到的那一行，另外「读到的文字」那一栏把这次
读到的字一行一条列在一个只读框里（可以自己选中复制），旁边那枚「复制」把它放进剪贴板。
图上的字默认不画 —— 框里就是刚读到的那几行字，标签压上去正好挡住要对着看的地方；要拿带字的
截图给人看时勾上「把文字写在框上」，字画在框的上沿外侧，上沿放不下就落到下沿外侧。从添加
动作窗口开的那一份还多一枚「再看一次」：只重新识别、不做动作，门槛改好按一下就在同一扇窗里
看新结果；运行调试打开的那一份不给它，那幅画面属于那一次运行。

「保存图片…」能把带框那张按原本大小存成 PNG，「保存原图…」存的是没有标记的那一张
（拿它剪新的参考图），两张都是原本大小。运行调试时每一步最后看到的画面也会
挂到它的步骤行上做缩略图（没有识别的步骤不显示），点开就是同一个窗口，跑完还能回看。运行时正在读哪个窗口也在屏幕上框出来，读到哪一步框就落在那个窗口上（这一步里把窗口拖到别处，框也跟过去），下一步开始或跑完就收。

找图（`vision.findImage` / `waitImage` / `clickImage`）的**识别算法**是一枚下拉，四选一，
默认归一化相关：**归一化相关**先抵消画面整体明暗再比对；**相关**不抵消明暗，参考图很小时
更稳；**逐像素**要求两处几乎一样，纯色图标或对话框截图用它；**特征比对**把两边明显的特征点
配对，画面缩放或有小改动也认得出，慢一些且只返回一个命中。选了特征比对，表单上就只剩它用得
上的那几项（最少特征对数、忽略的颜色）—— 用不上的字段不会留在那里让人以为它起作用。
**参考图里会变的那一块可以不参与比对**：填上那个颜色（忽略的颜色），按钮上的数字、会走动的
进度条就不再影响识别。

列了几张参考图时，**认哪一张**（`imageSet`，在「高级设置」里）说清这一步要的是哪一张：
默认**认出的第一张**，就是同一个按钮有两套画法时的用法；**最像的那一张**把每一张都比一遍，
取分数最高的一张，用来在两张相像的图标里挑更像的一张；**每一张都要**要求这几张同时都在，
缺一张就当没找到，用于「整套都在才算到了这一步」的画面。交回命中时以列在第一张的那张为准，
「第几个命中」也在这张里数。

**多点找色**（`vision.findColors`，条件里叫「颜色组合存在」`condition.colorsExist`）找的不是一个
颜色，而是**一个颜色加上它周围几个位置上该有的颜色**：一个红点只能说明"这里有个红的东西"，
红点旁边还有什么才说明是哪一个红的东西，两个长得像的按钮就是这么分开的。基准色是中间那个，
「周围要对的颜色」一行一个、写成相对基准色的偏移与颜色（`12,-4,#FF0000`，偏移可以是负数），
每一个都要在写的位置上，整个图案还要落在搜索区域里面。交回的位置是基准色那一像素，
「试找一下」与识别结果窗口都能看到它把哪些点对过、各自要的是什么颜色。

**查找颜色**（`vision.findColor`）看的是颜色在哪一点上，另有一个**至少占比**（`minCoverage`，
0–100，默认 0 即不看占比）看的是**这块区域里有多少是那个颜色**——血条涨到一半、按钮亮起来、
仪表过了刻度用后者，而不是找一个像素在哪儿。占比按整个搜索区域算，多行区域合起来算一个；
勾上返回值里的「占比 %」就能把它读出来。算占比要把整块区域走一遍，没问占比的步骤不会因此变慢。

截屏存下来的图片放在宏包旁边的 `<宏名>.assets` 文件夹里，保存宏包时自动收进 `assets/`；
项目还没保存过时先放在 `%LOCALAPPDATA%\WhaleGenie\images`。路径的解析与截图落盘都在
`WhaleGenie/Storage/ImageAssets.cs`。

「表达式」（字段旁的"表达式"按钮）打开一个对话框：左边是拼公式的地方，右边是拼公式要用的东西，
按「运算符 / 插入一个值 / 插入变量 / 函数」四段分区排着，段与段之间用一条横线隔开。凡是引擎按值
读取的字段旁都有这一个按钮，文本、颜色与数字一样；区域的四个数字、搜索区域每一行的四个数字也各
有一个。数字框里写进表达式就换成表达式框，清空它、或写回一个普通数字，就又回到数字框。

左上「结构」「手写」两页看到的是同一条公式。**结构**页把它摊成一棵每段一行的树：点一个位置把它选中，
再点右边的变量、函数或运算符——运算符把选中的那段包成一次运算（选中 `$a` 点 `+`，这一段就变成
`$a` 加一个空位，接着要填的就是空位），函数把选中的那段当作第一个参数（选中 `$a` 点 `upper`，得到
`upper($a)`），变量与常量把空位填上、或把整段换掉。变量墙上的按钮与函数按钮都能**拖**到某个位置上，
拖到空位就是填进去，拖到已有的一段就是换掉它；树上已有的一支也能拖到别的位置上。空位本身是一个小框，
点进去直接敲数字或文字——能读成数字的按数字读，其余按文字读，「文字」按钮让 `5` 这样看着像数字的也
按文字读。**括号不在这里手写**：哪里要括号由树的形状决定，生成出来的公式显示在下面一行。还有空位
没填时「确认」是灰的，旁边写着还差几处；整条公式一处都没填时，确认就是把这个值留空。

公式底下还有一行「👉 翻译结果」，把这条公式用中文说一遍：`field(get($sys.clipboard, 0), "月份")`
在这一行里是"取【剪贴板】里的【第1项】的【月份】字段"。这一行说的是一段一段拼起来的那棵树本身，
所以空位在这里念作"待填"，函数与参数都按文案表里的中文名说（与函数一览那一列是同一份），系统变量
按变量墙上的中文名说。看不懂下面的公式时，就看这一行核对自己的意思对不对。界面是英文时函数只显示
代码名，这一行不显示。

函数那一段上面是一条**分类 dock**（与「插入变量」那条同一套样式），一份是「全部」，其余按函数
一览的分组：文本 / 数字 / 列表 / 日期 / 记录 / 值与选择。按下其中一条，下面只列这一组的函数，不再
另写分组标题——**一个函数是哪一组的，看卡片颜色**：每一组一个色相，卡片用这一色的淡底、同色描边
与同色字。卡片上只写名字（`截取文本 (substring)`）；**鼠标停在卡片上会弹出气泡**，里面是那个函数
的写法（`截取文本(原文本, 起始位置 [, 截取长度])`）与一句说明，再往下每个参数一行，写着这个参数
叫什么、要放什么进去。dock 下面那个框按中文名、代码名或两种写法筛选；两边都没筛出东西时，框下面
写一行说明。

**手写**页就是原来的样子：运算符、变量与函数各是一个按钮，点一下插到光标处，公式直接在框里改，括号
自己写。两页说的是同一条公式：结构页拼好的公式切到「手写」就是那段文字，在手写页改完切回「结构」按
文字重新摆成树；手写页的文字读不通时，结构页只说明这件事，不显示树。

**哪些框能写算式，看标签前面那个小 `ƒ`**：带这个标记的字段整段值都是一次算出来的（数字、颜色、
文本都算），没有标记的字段里 `$名字` 只做就地替换，其余部分照原样使用。字段下面那行小字也写着
这一条，所以不必记住"这个框算不算式子"。

**数字框留空是什么意思，同样写在字段下面。** 区域那一族的四个数留空是从这条边一直量到屏幕边缘
（或量到基准窗口的那一边）；四个都留空就是整块屏幕。别的数字留空是"没填"：这一项不写进
宏文件，引擎按"什么都没说"处理——等待类动作的「查看间隔」就是靠这个"没说"去跟屏幕的刷新率。
区域那四个数从哪里量起，写在同一段下面的那行小字里（屏幕 / 基准窗口 / 客户区 / 元素锚点）。
写进数字框的算式是**跑起来的时候**算的：算不出来（名字不存在、内容形状对不上、除以 0）这一步判失败
并说明原因，不会悄悄按 0 接着走；写宏的时候只标当场就能确定的问题（算式没写完、名字或函数不存在），
像 `field($hit, "x")` 这种要从记录里取值、跑过才知道答案的写法，下面那行只提示"要跑起来才知道"。

选择器、按键和手柄控件旁边都有一个"测试"，用来在写宏的时候当场确认选的是不是想要的那个：

- **选择器**是把它在屏幕上高亮一下（`uia.*` 的边框、页面里元素的闪烁），**不点它**——验的是
  "选中了是不是它"，真点下去会把用户的东西弄乱。
- **按键和手柄控件**是真的发一次：按键按这一步自己的输入方式走（前台 / 后台消息 / 驱动级），
  手柄是按一下、拨一下或扣一下，随后自动松开。按之前对话框会让开，好让你在目标窗口或游戏里
  看一眼对不对；手柄要看见效果，游戏得在前台。

试的就是**这一步本身**（按关掉对话框后会存下来的那份设置跑），而且只跑这一步：引擎里
`MacroRunner.TryAsync` 走的是和运行宏同一套代码，跑完把还按着的东西松开。

## 怎么比文字

凡是"拿一段文字去比另一段"，程序里用的都是同一批词，五档：

| 档 | 宏文件里写的 | 什么时候算比中 |
| --- | --- | --- |
| 包含（默认） | `contains` | 要查找的那段出现在被比的文字里 |
| 以…开头 | `startsWith` | 被比的文字从要查找的那段开始 |
| 以…结尾 | `endsWith` | 被比的文字到要查找的那段结束 |
| 等于 | `equals` | 两段一样；比之前两端多出来的空格都去掉 |
| 正则匹配 | `regex` | 要查找的那段当正则表达式用 |

五档都**忽略大小写**；「等于」先去空格，是因为屏幕上读到的字常带着边上那点空隙，而照着手打一遍
不会有。这一格留空是"没说"，按「包含」走。手写的宏文件里写了这五个词以外的字，这一步**失败**并
报出原因（`Run.BadMatchMode`），不会在背后换成另一种比法。

用同一批词的地方：找文字、点击文字、两个文字条件（文字存在 / 文字不存在）的**「匹配方式」**；
**窗口那格「匹配方式」**是同一批字的九种拼法 —— 标题五档齐备，「进程名」「窗口类名」各两档
（包含 / 等于），所以"进程名正好是 notepad"写得出，`notepad` 也不会再命中 `notepad++`；
「多分支」（`control.switch`）与「读取 CSV」（`file.readCsv`）的文本档引用的也是这批字，它们另有
「不等于」与大于 / 小于那几档，那是数字的事。表达式里的 `contains` / `startsWith` / `endsWith` /
`match` 是函数调用、不是档位，词也照着这一批对齐。

## 落点与落手

点击类的字段决定的不只是"点哪儿"，还有"怎么落手"。这几个字段在写宏时常常一起考虑：

| 字段 | 在哪 | 什么时候填它 |
| --- | --- | --- |
| **就在指针当前所在位置**（`useCursor`，默认关） | 鼠标点击 / 鼠标双击 / 鼠标按下 / 鼠标松开 / 滚轮 | 位置由用户自己放好的鼠标决定时用它：勾上后这一步不写坐标，运行时在指针当时停留的地方完成。勾上后「X」「Y」不画、不写进宏文件，坐标基准与基准窗口留着但这一步不读它们；取消勾选时原来填过的值原样回来 |
| **落点随机范围**（`variance`，像素，默认 0） | 鼠标点击 / 鼠标双击 / 点击图片 / 点击文字 | 连着点同一处时，不希望每次落在同一个像素上。填了数就每次都在这范围内随机取一点；`0` 是正好落在写的位置。数字要小到整个范围仍在被点的东西里面 |
| **点完把指针移回原处**（`moveBack`，默认关） | 鼠标点击 / 鼠标双击 | 点完之后要把鼠标还回用户自己放的地方，不让它留在游戏画面上。后台模式下屏幕上的指针本来就没动，这个开关不起作用 |
| **到终点先停**（`settleMs`，毫秒，默认 0） | 鼠标拖拽 | 拖到终点后先按住不动一会儿再松开。要拖进格子的东西只有指针在格子上停过一下才会被放进去；`0` 是一到就松 |
| **落手前再确认**（`recheckMs`，毫秒，默认 0） | 点击图片 / 点击文字 | 命中之后要先等一会儿再看一眼，这次仍认得才点。用于按钮一闪而过、画面其实已经翻过去的情况；`0` 是一认出就点 |

「落手前再确认」的第二次查看只查一次、不再等：等一会儿再看的这一次就是要看它还在不在，画面已经
变过就算没找到。

## 返回值：这一步的结果交给谁

添加动作页的第四个页签是「返回值」，列的是**这一步运行时能算出来的东西**：找图给的是命中的
位置、大小、相似度，读文件给的是文本或行，截图给的是图片和它盖住的矩形，启动程序给的是进程号。
**勾上的结果各自成为一个变量**，名字按 `备注_返回值名` 拼（备注框里改一个词，名字跟着改；自己
在名字框里写过的名字就不再跟着动），能在「变量」墙里找到、能在「插入变量」里选到；这个名字已经
被别的步骤用了时，末尾自动补上这一步的步骤标识；手工把名字写成别人的会显示出来，旁边一个「换个
名字」加个编号避开。**没勾的结果不写**，既不出现在变量墙里，也不占内存 —— 读它会被设计期检查
标成"没定义"。一个都不勾是允许的：这一步不留结果，只留下 `step.<步骤标识>.outcome` 这个结局
变量。**要看这一步算出了什么，不必先勾上**：运行调试里每一步的行上会把这**一次真正算出的所有
结果**（勾没勾都在）连同耗时写出来，「没勾的结果」在那里读得到，也标出哪些是宏自己留着的。

每一步跑完还留下两条系统变量：**结局** `step.<步骤标识>.outcome` 是 `ok` / `failed` /
`skipped`，**失败原因** `step.<步骤标识>.error` 装的是鲸灵自己给这个失败起的名字（例如
`Run.NoDevice`），没失败或没跑到时是空的。宏因此能按原因分支：条件里比一比
`$step.<步骤标识>.error` 就知道是哪一种失败，不必靠日志里的文字。

找图、等图、点图、找色、点色、找颜色组合、找文字、点文字、认元素这些**找**的动作，交出的「命中」
（`match`）是一个**记录**：一条命中是"一件事的几项答案"，它们一起走，不用为每一项各勾一个变量。
记录里的字段按找的是什么略有不同：

| 字段 | 是什么 |
| --- | --- |
| `x`、`y` | 命中的中心，单位是屏幕像素：点图、点文字落的就是这里，也是"下一步移过去"的意思 |
| `left`、`top` | 命中矩形的左上角，和「搜索区域」里那四个数同一个口径 |
| `width`、`height` | 命中矩形的宽和高 |
| `score` | 这一次的把握：找图找色是相似度（0–1，1 表示完全一样），找文字是识别模型给的读数分 |
| `box` | 整块矩形，写成 `左,上,宽,高`：填进搜索区域那一行的变量格，下一步就在同一处找 |
| `text` | 读到的那句话（只有找文字、点文字、认元素有） |

**取记录里的一项用 `field($变量, "字段名")`**，写错字段名不只是取不到值：这一步会报错，并把这条
记录**有哪些字段**列在错误里。整个记录写进文本时会写成一个 JSON 对象（`{"x":30,"y":40,...}`），
所以 `toJson` 与读 JSON 的那几个函数照样能用；`count($变量)` 给出这条记录有几个字段。

**中心点与左上角在同一个记录里各占一个字段，因为这两件事本来就不一样**：`x`、`y` 是动作要点的
那个点，`left`、`top` 是矩形的左上角。要让下一步在刚找到的地方再看一次，把 `box` 填进搜索区域
那一行的变量格，或者**直接把整个记录交给那一行**：区域里写 `$变量` 时，「left」「top」「width」
「height」四个字段就是那块矩形。找图、找色、找文字与认元素（`uia.find`）的命中、`window.info` 交的
窗口、`window.list` 里的每一条、截图交的 `place` 都走这条路：整条记录填进那一行就行，取其中一格用
`field($记录, "left")`。这些记录里凡是有矩形的，都同时带着 `x`、`y`：取的就是这块矩形的中心
（奇数宽高时按整数除法取整），所以"把鼠标移到窗口正中"写 `field($窗口, "x")`、
`field($窗口, "y")` 就够，不必自己拿 `left` 与 `width` 算一半。
**写成数字的位置与矩形各有一个开关，说这一步的位置从哪儿来**：勾上「位置取自一条记录」
（`useRecord`，默认关）并把整条记录填进「记录」那一格，鼠标动作（移动、点击、双击、按下、松开、
滚动）与看一个像素的两步（`vision.getPixel`、`vision.waitColor`）就落在这条记录说的那一点上——
记录带着 `x`、`y`，取的是那块矩形的中心，"把刚找到的东西点一下"就是这么写的；没勾开关时读的是
X 与 Y 两格数字，那一格记录不参与，手写文件里留着上一次的记录不会把这一步悄悄挪到别处。拖拽的
起点与终点各有自己的一对（`startFromRecord` / `startRecord`、`endFromRecord` / `endRecord`），
两端可以一头取记录、一头写数字。**要读、要截的那一块与「移动窗口」的四格同理**：勾上「矩形取自
一条记录」（「移动窗口」那一格叫「位置与大小取自一条记录」）后，整块矩形由「记录」那一格给出一条带
`left`、`top`、`width`、`height` 的记录，"把刚找到的那一块截下来""读一读它上面的字""把这个窗口
摆成那个窗口那样"都是这么写的。**勾着开关而记录格空着**，这一步说的是"上一步什么都没找到"
（`Run.BadPointEmpty`）；那条记录里没有 `x`、`y`（或没有 `left`、`top`、`width`、`height`）时报
`Run.BadPoint` / `Run.BadRegion`，并把读到的那条记录写出来。**鼠标动作的「就在指针当前所在位置」
压过「位置取自一条记录」**：两个开关都勾上时（手写文件里才写得出这种状态）以指针为准。
记录里的数本来就是屏幕上量出来的，所以**「坐标基准」只挪写出来的数字**：起点两格填 `10` 与 `20` 时它们
是窗口里的那一点，交给它一条命中时它是屏幕上那一点（同一条命中在哪个基准下说的都是屏幕上那一点）；搜索区域那一行
交给一条记录时看的也是记录自己那一块，与基准无关。想按基准挪，就写 `field($记录, "left")` 这样把数
取出来再填。

找图、找色、找文字这类会有多处的动作，返回值里还有一项**「全部命中」**（`every`）：勾上就有了
一列记录，顺序就是「命中排序」里的顺序，「第几个命中」数的也是这一列；`count()` 数一数、
`get()` 取出其中一条、`forEach` 逐个走一遍都能直接用。每一项的样子和上面那张表一样，所以
"这条文字写在哪儿、写的是什么"是同一项里的两个字段，不用拿两张表对号。不勾就只有选中的那一处。

**点图与点文字也把命中的位置交出来**，和找图、找文字一样：点完之后想知道"刚才点的是哪儿"、
或者要把那个位置交给下一步时，不必再写一次查找。

**窗口信息（`window.info`）交的是一条记录**，一条记录把"这个窗口在哪儿、它是什么"一起说清：`title`、
`process`（程序名，不带 `.exe`，就是「匹配方式」选进程名时要比的那一段）、`class`（窗口类名）、
`handle`（句柄）、`minimized` / `maximized`、`x` / `y`（窗口矩形的中心）、`left` / `top` / `width` /
`height` 与 `box`（整块矩形，
写成 `左,上,宽,高`），再加上 `clientBox`（内容区，去掉边框与标题栏的那块，也就是坐标基准选
「窗口客户区」时数坐标的起点）。标题会变的窗口用类名或句柄认得出来，两个标题相同的窗口用句柄分开。

**窗口的矩形说的是它被看见的那个矩形**，不是 Windows 用来拉伸它的那个：普通窗口上左右下各多出七像素
看不见的边框，最大化的窗口还比屏幕大一圈。窗口相对坐标、这里的矩形、屏幕上框出来的位置、以及窗口画面的
起点是同一件事的四个说法，所以都按看见的算；`window.move` 收的也是这个矩形，把刚读到的那组数填回去，
窗口就回到原处。

**列出窗口（`window.list`）给的是一列记录**，一个窗口一条，字段是 `title`（标题）、`process`
（程序名，不带 `.exe`，就是「匹配方式」选进程名时要比的那一段）、`class`（窗口类名）、`handle`
（句柄）、`minimized` / `maximized`、`x` / `y`（窗口矩形的中心）、`left` / `top` / `width` /
`height` 与 `box`（位置与大小，
写成 `左,上,宽,高`）——与 `window.info` 交的那条记录同一个形状，少一个 `clientBox`。标题相同的两个
窗口是两个窗口，各占一条。
「它有哪些窗口」与"这些窗口分别是什么"是同一列里的同一条，不用拿几张表对号。这一步一个结果都
不勾时不去查程序名与类名 —— 那两个要问一次系统才知道，不勾就不花这份时间；勾了之后还要勾上
「每个窗口都读程序名与类名（慢）」它们才有值（默认关，关着时这两格留空，只按标题认窗口的宏不必付
这份时间）。挑出要列哪些窗口用的也是「匹配内容」与「匹配方式」这一对，留空就是列出所有窗口。

**截屏（`vision.capture`）与截取窗口（`vision.captureWindow`）把画面在哪儿也交出来**：返回值里勾上
「位置」（`place`）就有了这块画面的记录，`x` / `y` 是它的中心，`left` / `top` 是它开始的位置，
`width` / `height` 是它的大小
（画面在屏幕边上被截短时写的就是实际拿到的那一份），`box` 是整块矩形。下一步要在这块画面上再看一次，
把整条记录填进搜索区域那一行就行。

**读表格（`uia.readTable`）交的就是一列记录**：一行一条，键是表格列标题那一行写的列名，取一个单元格
按名字取——`field(get($表格, 0), "金额")`——不用数它排第几。表格没有列标题时，列名就是 `A`、`B`、
`C`；列名为空、或者与前面某一列重名的列，也用它的列号当名字——一个名字底下不能放两列。勾上「按表格
读」的文字识别（`ocr.recognize`）交的同样是每行一条记录，屏幕上读来的东西没有列标题，键一律是格子的
列号 `A`、`B`、`C`。这与读 CSV 是同一种形状（见「分隔符文件」）。

**认到的元素（`uia.read`）交的也是一条记录**：`enabled` 与 `visible`（现在能不能用、是不是显示着）、
`value`（元素自己持有的内容——输入框里的文字、按钮上的标题；本身不持有内容的元素为空）、`name`、
`automationId`、`controlType`，再加上 `x` / `y`（元素矩形的中心）与 `left` / `top` / `width` /
`height`、`box`。取其中一项用
`field($元素, "value")`：想"等这个按钮能用再点"就写一条条件读它，不必靠猜。
要**按下**一个控件而不动鼠标，用「按下元素」（`uia.invoke`）：它走控件自己的动作，鼠标停在原处、
窗口也不会被抬到前面，所以后台窗口里的按钮按得动；控件不提供这种方式时会报出来，不会退回去点鼠标
——真要挪过去点一下，用「点击元素」。

**占比 %**（`coverage`，只有查找颜色有）问的是"这块区域里有多少是那个颜色"：0–100 保留一位小数，
找没找到都会写，所以占比不够时能读出差多少；「至少占比」拿它当判定线，低于这条线就算没找到。
查找颜色只看一次：要一直等到占比够了才往下走，用条件**「颜色占比达到」**
（`condition.colorCoverage`，`至少占比 %` 0–100、默认 0 即"区域里有这个颜色就行"）配
`control.waitUntil`；只等某一个像素变成某个颜色，用「等待颜色」。

## 脚本

「运行脚本」（`script.run`）把一段正文交给机器上的某个程序运行，宏里没做成动作的那点活儿用它补：写一行
命令、一段批处理、一段 PowerShell 或 AutoHotkey，或者交给机器上装的其他解释器。

这一段说的是机器上现成的程序怎么跑。下面三段说的是鲸灵自己跑的三种脚本——Python、C# 与 AutoHotkey——它们在
子进程里跑，运行期间能读写宏的变量、调用宏的步骤；前两种各有一个动作给它们下要用的包，所以脚本动作里
不再列包。

**脚本类型**说这一段交给谁。三种命令写法都先把正文写成批处理文件再交给 `cmd.exe`，差别只在窗口：
**CMD命令(完成保留窗口)** 的窗口在命令跑完后留着，好让人回头看一眼输出（这一步等到命令跑完就往下走，
不会等到窗口被关掉）；**CMD命令(完成后关闭窗口)** 的窗口在命令跑完时自己关掉；**CMD命令(隐藏命令行窗口)**
根本不显示窗口。**BAT批处理文件(.bat)** 与 **CMD批处理脚本(.cmd)** 与隐藏那种一样，只是后缀按名字来。
**PowerShell脚本(.ps1)** 用系统自带的 Windows PowerShell 运行，不读配置、不问任何问题；**AutoHotKey脚本
(.ahk)** 要机器上装了 AutoHotkey（注册表、PATH 与常见安装目录挨个找），找不到时这一步直接说清要装什么，
而不是报一句看不懂的命令行错误；**自定义脚本类型**把解释器命令行与脚本后缀交给用户自己写，用于机器上别的
程序，例如 dotnet-script（用 `.csx`）或 cscript（用 `.vbs`）。

**编码设置**说交给程序的那份脚本按什么编码写，默认「按这类脚本的习惯」：批处理与命令用本机代码页（中文
Windows 上是 GBK，cmd.exe 读文件正是按它），PowerShell 与 AutoHotkey 带 BOM，自定义程序用 UTF-8。像
cscript 这种按系统代码页读文件的程序，要显式选 GBK，否则中文会变成问号。

脚本有两种来源，由**脚本来源**说。**写在下面**（默认）把**脚本正文**按上面那个编码写成一份带对应后缀的
临时文件交给程序，用完删掉，`{{变量名}}` 就是在这里替换的。**一个脚本文件**则把**脚本文件**那一格说的
那份文件**就地**交给程序：不写副本、不替换 `{{变量名}}`、也不改编码，所以脚本读它旁边的文件、`#Include`
别的脚本、用 `$PSScriptRoot` 找自己所在的目录，都是它原来那个位置的意思。这一格是文件选择，相对路径按宏
目录算，路径里可以写 `$变量`；后缀不看，谁运行它仍由**脚本类型**说了算，文件不在时这一步当场说找不到。
唯一例外是「CMD命令(完成保留窗口)」：它靠脚本末尾一行记号知道命令跑完，而指定的文件不能改，所以它当场
写一个两行的批处理（`call "那份文件" 参数` 加那行记号）交给窗口 —— 窗口里看到的仍是脚本自己的输出。

**脚本正文**里写 `{{变量名}}` 的地方会在运行前换成那个变量的值，这是宏的值传进脚本的方式；脚本语言自己的
`$` 与 `%` 不参与，PowerShell 里的 `$env:TEMP` 仍是它自己的意思。宏里没有的名字原样留着，好在脚本里一眼
看见。**参数**接在脚本命令行后面，其中的 `{{变量名}}` 一样替换；**工作目录**留空表示宏所在的目录；**超时**
默认 60000 毫秒，到点结束脚本并判这一步失败，填 0 表示不限时。

返回值三项：**输出**是脚本打印的内容，**错误消息**是脚本在错误输出上写的或解释器自己报的错，**是否执行
成功**是退出码是否为 0。前两项只有不显示窗口的类型收得到 —— 在窗口里跑的命令把输出写在那扇窗上，想知道
它说了什么就用隐藏窗口或批处理类型。退出码不是 0 时这一步也判失败：想接着往下走，把这一步的失败策略设成
继续，或者让它问你一声；放行之后，「错误消息」与「是否执行成功」就摆在后面的步骤里可以读。

### Python 脚本与它要的包

「运行 Python 脚本」（`script.python`）把一段 Python 交给机器上的 Python 运行。它在**子进程**里跑，宏就
在它旁边：脚本写成什么样都带不崩鲸灵，死循环、栈溢出、`sys.exit` 只结束这个进程，超时到点由鲸灵结束它。
**脚本正文**默认是一段能直接运行的示例，每一行都写明它调的是哪一件事。**Python 命令**说这一步用哪个
Python，默认是搜索路径上的 `python`；要用某个虚拟环境的解释器就填它的路径（有空格时用引号括起来），它
自己的开关写在前面。**超时**默认 60000 毫秒，到点结束脚本并判这一步失败，填 0 表示不限时。

脚本里能用的名字两种语言是同一套。`WhaleGenie.GetProperty("名字")` 读一个宏变量，值按 JSON 过界，Python
这边拿到的就是原本的 `dict`、`list`、数字与真假；`WhaleGenie.SetProperty("名字", 值)` 写一个宏变量，后面
的步骤读得到；`WhaleGenie.StepExecute("标识")` 跑本宏里的某一步，写它的四字符步骤标识（与条件里选步骤是
同一套），交回这一步是否成功，被调的步骤按它自己的失败策略走；`WhaleGenie.Print(文字)` 往运行日志写一行，
脚本自己 `print` 的内容也逐行写进运行日志；`WhaleGenie.SetResult(值)` 交回这一步的**返回值**。标识在本宏里
找不到时这一步当场失败。返回值三项：**返回值**是 `SetResult` 交回的那个，没交过就是空的；**错误消息**是
错误输出上的内容，Python 报的错就写在这里，带着出错的行号；**是否执行成功**是脚本有没有跑完且没出错。脚本
出错时这一步也判失败，与上面「运行脚本」一样按失败策略放行。

「安装 PIP 包」（`script.pip`）按**包清单**看这些包在不在，缺的用 `python -m pip install` 一次装完。清单
一行一个包，写成 `包名` 或 `包名==版本`，以 `#` 开头的行跳过。这一步不写自己的超时字段：等多久由这一步
设置里的「超时」说，默认不限时；**这次装上的包**是它的主结果，要的包都已经在时为空。两个动作装的包都放在
鲸灵自己的 `packages` 目录里（见「程序自己的文件放哪儿」），不进这台机器的 Python：Python 脚本运行时
`packages\python` 永远在搜索路径上，所以脚本里直接 `import` 就行，既不必在动作里再列一遍包，也不会动到
用户自己装的 Python。

### C# 脚本与它要的包

「运行 C# 脚本」（`script.csharp`）先把这段 C# 当场编成一份 dll，再交给**鲸灵自己的程序**另起一个进程运行，
所以它比 Python 那种还要稳：脚本里写 `Environment.Exit`、写出栈溢出、写出死循环，都只是那个进程自己的事，
宏照常拿到结果或者按超时把它结束掉。**脚本正文**默认是一段能直接运行的示例：`__InjectedServices.DynamicObject`
就是宏（示例里给它起了个名字叫 `WhaleGenie`），`GetProperty("名字")` 读一个宏变量，`SetProperty("名字", 值)`
写一个，`StepExecute("标识")` 跑本宏里的某一步，`SetResult(值)` 交回这一步的**返回值**，
`Console.WriteLine` 写的内容逐行进运行日志。**参数**会传给入口点（写 `static void Main(string[] args)` 就收得到），
**工作目录**与超时的说法和 Python 那种一样。返回值三项：**返回值**、**错误消息**、**是否执行成功**；
编译不过时这一步判失败，错误消息就是编译器自己的话，带着出错的文件、行、列与错误号（`script.cs(5,9): error CS0103: …`）；
脚本里没有可运行的入口（没有一个带 static Main 的类）时另说一句。脚本运行中抛了异常，抛出的异常与出错的行
也在错误消息里。

「下载 NuGet 包」（`script.nuget`）按**包清单**看这些包在不在，缺的从 nuget.org 上连同它们自己依赖的包一起
下下来。清单一行一个包，写成 `包名` 或 `包名` 后隔一个空格跟 `版本号`，只写包名取最新的稳定版，以 `#` 开头
的行跳过。包下在鲸灵自己的 `packages\nuget` 里，按包名与版本各占一格，同一个包只留一份（要了新的版本就把
旧的删掉），每个 C# 脚本都按这里的 dll 编译。这一步与「安装 PIP 包」一样不写自己的超时字段，等多久由这一步
设置里的「超时」说，默认不限时；**下载的包**是它的主结果，每项是包名与取到的版本，要的包都已经在时为空。

### AutoHotkey 脚本

「运行 AHK 脚本」（`script.ahk`）把一段 AutoHotkey 交给机器上的 **AutoHotkey v2** 运行。它和 Python、C# 两种
一样在子进程里跑，宏就在它旁边，用的也是同一套名字：`GetProperty("名字")` 读一个宏变量，`SetProperty("名字", 值)`
写一个，`StepExecute("标识")` 跑本宏里的某一步并交回 1 或 0（标识在本宏里找不到时这一步当场失败，被调的步骤按
它自己的失败策略走），`Print(文字)` 往运行日志写一行，`SetResult(值)` 交回这一步的**返回值**。AutoHotkey 只有
文字与数字两种值：宏里的列表与记录在这一边是它们的 JSON 文字，数字交回去时仍是数字，真假是 1 与 0。**脚本正文**
默认是一段能直接运行的示例，里面只有往运行日志写字的那一行没有注释掉，其余的调用都写成注释，写脚本时照着改
就行。**AutoHotkey 命令**留空表示用这台机器上的 AutoHotkey，它按注册表、搜索路径、常见安装目录的顺序找；找不到
时这一步直接说清要装 v2，找到的是 v1 也直说，因为这一档的脚本 v1 读不了。**参数**接在脚本命令行后面，脚本在
`A_Args` 里读到；**工作目录**与**超时**的说法与 Python 那种一样。返回值三项：**返回值**、**错误消息**、
**是否执行成功**。

这一段脚本里出的错写成运行日志里的一行文字（AutoHotkey 报的错，带着出错的那一行），而不是弹一个要人点确定的
窗口：宏是在后台跑的，没人坐在那扇窗口前点它。要常驻的热键类脚本用上面「运行脚本」里那一档 AutoHotkey，它只把
脚本交给 AutoHotkey，没有这五个函数。

## 子宏：一段流程用第二次

一个宏可以说明自己**收什么、交回什么**，别的宏就能像调用一段现成的流程那样用它；这段流程在文件里只
有一份，改一处两处都跟着变。

「执行其他宏」（`control.runMacro`）这一步的表单**按被调用宏的声明生成**：先选宏，「基础设置」里就
出现它声明的每一个**形参**，一格一个，值按其他字段的读法读（`$n + 1` 传的是数字，`$列表` 传的是列表
本身）；有默认值的形参可以留空，留空就用那个默认值，声明为必填的留不得。这一步要取回哪些**结果**在
「返回值」页上勾，勾上的每一项在本宏里各自成为一个变量，名字由那一行决定。

填错的名字不会被放过去：传了一个被调用宏没有声明的形参、或者要取回一个它没声明交回的名字，写宏时
就在步骤上标出来；这样的步骤如果还是进了宏文件（手写进去，或者被调用的宏后来改了声明），运行到它
会当场停下并说清是哪一个名字。

被调用的宏用自己的一套变量：它读得到传进去的形参、共享变量与鲸灵自带的变量，读不到调用者的本宏变量；
它留下的东西只有声明过、并且这一步勾了的结果才回得来。写在里面的 `break` / `continue` 只作用于它自己
的循环，调用者的循环不受影响。

声明由「提为子宏」一次做出来：在动作列表里选中同一层里的若干步骤，按面板上的**提为子宏**，编辑器就建
一个以当前宏的名字命名的新宏（重名自动编号）、把这段步骤搬进去、在原来的位置留下一条指向它的
「执行其他宏」。这段步骤**读到的**本宏变量成为新宏的形参，调用处已经按原名填好；这段步骤**写下的**
变量成为新宏的结果，调用处把它们逐个取回同名的变量，所以宏剩下的部分照旧读到原来的名字，什么都不用改。
新宏跟着这个宏一起进项目：保存之后它才出现在列表里，也才成为别的宏调用得到的宏。共享变量与鲸灵自带的
变量两边都读得到，因此不会变成形参。

## 运行与调试

宏卡片右上角有一枚**「运行调试」**（右键菜单里也有同一项）：它打开运行与调试窗口，把那个宏的步骤装进
去、**停在第一步之前**——什么时候跑由窗口里的「运行」/「单步」说。窗口一次只开一个，再对另一个宏点它
（或右键另一个宏）就是停下正在跑的那个、换成它的步骤重新装载；上一个为什么停了写在这次运行日志的第一
行。编辑器里左侧「保存」下面有一枚**「运行调试」**：把编辑器手里的步骤装进窗口并停在那儿，不用先保存；
还没有写步骤时它按不动；再按一次只换成一扇装着当前步骤的窗口，不会越按越多。主窗口标题栏的「运行调试」
按钮打开的是同一个窗口，只是不带步骤：没有装宏的时候运行控制不画，页面上给一个**「装哪个宏」**下拉和
**「载入这个宏」**，选一个按下去就把它装上、停着——与卡片走的是同一条路。

窗口分「调试」与「变量」两页。**调试**：步骤列表、每一步最后看到的画面缩略图（点开就是识别结果窗口）、
每一步跑出来的东西（见下），以及日志。**变量**：本宏 / 全局 / 系统三个页签，全局变量在这里新建、改名、
改默认值与说明、删除（宏只能改它的值），系统变量的当前值实时读出来且只读，"在用"那一页列出整个宏列表用到
了哪些变量。运行与「试找一下」还会把正在读的那个窗口在屏幕上框出来，读到哪一步框就落在哪个窗口上。

**看得见的都能带走**：每一步算出的结果、日志、变量值都写在可以选中的控件里，选中就能复制；日志那一栏
与每一条变量旁边另各有一枚**「复制」**——日志那一枚放走的是整份日志（时刻带文字一行一条），变量那几枚
放走的是它自己那一行的值，按了哪一行带走的就哪一行。

**运行失败会自己留下一份日志**：一次运行以失败收场时，这一整段运行日志会写成一份文字文件，放在程序所在
目录的 `logs` 里，文件名形如 `failure-订单导出-20251016-210311.log`：开头一行写着这是哪个宏、什么时候失
败的，往下是这一整段日志的每一行——每行先是时刻、再是文字，行首的空格表示它落在第几层块里，文字与运行调
试窗口里看到的一样（触发器起的运行没有那一扇窗口，这一份就是它唯一的记录）。编码是 UTF-8 带 BOM，双击就
能打开；运行调试窗口里的日志最后会多一条「已把运行日志存到 …」，把文件的全路径写在那里。宏顺利跑完、或者
是你自己按下的「停止」，都不写文件。

鲸灵自带的变量（`sys.` 开头）**每次读到的是当时的值**，不是运行开始时记下的那一份：循环里读两次
`$sys.mouseX` 是两个位置，等一分钟再读 `$sys.time` 是新的时间，`$sys.clipboard` 读的是这一刻的剪贴板。
其中 `sys.macroName` 是正在跑的宏的名字（调用了别的宏，那个宏里读到的是它自己的名字），
`sys.macroFolder` 是写相对路径时算起的那个文件夹，`sys.activeWindow` 与 `sys.activeProcess` 是此刻在最
前面的窗口的标题与程序名。上面那个变量页显示的也是同一个值：它读的就是宏会读到的东西。

**断点与暂停**：点步骤左边的圆点就是下断点，再点一下取消，点完那一点立刻变红。**断点的三件事都在那一步
的右键菜单里**：下断点 / 取消断点（标题跟着当前状态变）、设置断点条件…、清除条件（有条件的行才有）；右键
圆点与右键那一行是同一份菜单——圆点只有 16 像素宽，菜单挂在它上面大多数人找不到。跑到带断点的步骤前会
停下来等「继续」；断点还可以带一个**条件**（「设置断点条件…」，条件写在弹出的表单里，和 `if`、`waitUntil`
用的是同一套条件）：条件成立才停，不成立就直接跑过去——循环里的某一步只有跑到第几轮才会停下来时用它。
条件算不出结果时（例如它读的变量那一刻还没有值）会照停，并在日志里写清是为什么。「清除条件」只去掉条件，
断点还留着，回到每次到这儿都停。停在断点上时，工具栏上那枚**「跳过这一步（这一次）」**按下去就是：这一步
不执行、也来不及有副作用，运行直接接着下一步走，行上写的是"未执行"；没停住时它按不动。
条件那一行没有圆点：条件是被它所属的那一步问的，不是自己跑的一步，要停在问之前，把断点下在那一步上。

**窗口里的按键与按钮**：工具栏上是「运行 / 单步 / 继续 / 停止」四枚；停在断点上时旁边多一枚**「跳过这一
步（这一次）」**，它只在停住时按得动。键盘上 **F5** 管运行与继续（停着就是接着跑，没跑就
从头跑）、**F10** 是单步、**Shift+F5** 是停止，每枚按钮的悬浮提示里写着它对应哪个键。单步说的是"做下一
步、做完再停住"：第一次按下停在第一步之前，之后每按一次做一步。

**每一步跑出来什么**：运行调试里每一步的行会把这一次的结果写出来 —— 怎么结束的（完成 / 失败 / 未执行）、
花了多少毫秒、失败的话为什么失败，以及**这一步真正算出的每一个结果**：勾了结果的行用宏里的变量名，没勾的
行用鲸灵自己的名字（例如 `encoded`、`match`），两者都读得到值，所以想看一眼某个返回值不必先回去勾上再跑
一遍。勾选只决定"要不要成为变量"，不决定"看不看得见"。

**宏自己问人**：「询问使用者」与「询问文字」这两步会让宏停下来等人：前者问一句话、交回真假，后者要一行
文字、交回文本。编辑器里跑的时候，问题出现在步骤列表下面那一条上；触发器发起的运行没有运行调试窗口，问题
由主窗口弹出来问。答到一半被「停止」按下，按"没有回答"收场——「询问使用者」交回假、「询问文字」交回空，
这一步仍然算完成，宏自己按交回来的东西决定下一步。问多久会一直等下去：宏停在那里，屏幕上就是那个问题。
交给引擎但不接界面的运行（例如自动化测试直接调引擎）也按"没有回答"走，不会挂住。

**这一步自己判失败**：「判为失败」（`control.fail`）把这一步记成失败，交给这一步设置里的重试与失败
策略，和你按下「停止整个宏」是两回事——判失败说的是"这一步没做成"，宏里写着的失败策略照常起作用。
原因可以不填；填了会写进日志，也写进 `step.<id>.error`，后面的步骤读得到，所以"哪一步不对"能顺着
往下传。反过来，「说明」（`control.note`）只是写在宏中间给人看的一行字：运行时不做事、不写日志，
里面的 `$名字` 也不替换，宏长起来以后靠它分段。

**两条宏一起跑**：两个宏同时发键鼠时，按键会写进对方中间——收到输入的那个窗口看到的是两条宏的按键交错在
一起。宏的触发页有一格「与别的宏互斥发输入」：勾上的宏共用一条输入门，只有发键鼠的步骤取门，一步一步轮流
发；读屏幕和识别的步骤不取门，两个宏可以同时看同一个窗口。默认不勾，一个宏单独跑时没有要等的人。勾了的宏
在运行调试里看得见现在是谁在发输入。

**按键触发可以是组合键**：触发页里点「设置按键」以后，按一个键就是那个键；按住 Ctrl、Shift、Alt、Win 中的一个
或几个，再按最后一个键，绑定的就是一个组合键（例如 `Ctrl+Shift+S`）。运行时前面的修饰键都按着、最后那个键
按下的那一刻才算数；组合里的 Ctrl 左右不分，单独一个修饰键仍然分左右（`左Ctrl` 与 `右Ctrl` 是两个绑定）。
鼠标按键与滚轮各自是一个绑定，不跟修饰键配成组合。

**手柄按键也能当绑定**：触发页点「设置按键」以后，按一下手柄上的键就是那个绑定，名字写成 `Pad A`、
`Pad LB` 这样（与鼠标按键写成 `Mouse Left` 是同一个做法，动作参数里仍旧写 `a`、`lb`）。手柄不像键盘那样
会主动说按了什么，鲸灵是每隔 30 毫秒读一次：按下的那一刻起一次，松开算松开，所以「按住才跑」「再按一次
停」「松开才跑」这三档与绑键盘时一样。左扳机与右扳机是量出来的，越过三成行程就算按下；手柄上的 Guide
键 Windows 留给自己，绑不了。手柄按键各自是一个绑定，不跟修饰键配成组合（和鼠标按键一样）。

**手柄没插上会怎样**：读不到手柄就是「什么都没按着」——绑着手柄的宏永远不会被它触发，而正按着的时候拔掉
等于松手，用它启动的「按住才跑」的宏随之停下。手柄插回来按一下，照旧起一次。

**开着的宏在等什么**：运行调试里有一段「等触发的宏」，凡是用定时去看的那几种触发器（颜色、程序、窗口、
计时）各占一行：等的是什么、现在成不成立、上次判定是什么时候、下次什么时候去看它。宏没有在该跑的时候跑起
来，答案几乎都在这一段里，不必靠猜。窗口这一类另有一句「窗口有变化时机器会先说一声」：机器听见窗口出现、
消失或改名就立刻看一遍，所以只亮一下就关掉的窗口也认得到；那 500 毫秒一轮是机器不肯说时的退路。
窗口触发器认窗口用的是和别处同一对「匹配内容」与「匹配方式」，标题会变就用进程名或正则认；宏的触发页里
「匹配内容」下面同样列着这一步现在会认到的窗口，改一格就重读一遍。

## 画面从哪来、怎么取

看屏幕的步骤（截图 / 截取窗口 / 找图 / 等待图片 / 点击图片 / 取色 / 等待颜色 / 查找颜色 /
多点找色 / 等画面静止 / 文字识别 / 找文字 / 点击文字，以及这一族的八个条件）都能说清画面**从哪来、怎么取**，
也能说清它**多久读一次屏幕**。还有一件不属于某一步：**从哪来、怎么取**由程序设置里那两行说了算——

| 设置里的「读窗口」 | 取到什么 |
| --- | --- |
| 自动（默认） | 先走 Graphics Capture，不行再让窗口自己画，最后退回屏幕像素 |
| 窗口（PrintWindow） | 让窗口自己画一遍，多数窗口都行；取到整窗，含标题栏与边框 |
| Graphics Capture | 取窗口自己显示的内容，被别的窗口压住也取得到；只有内容区、不含标题栏，需要 Windows 10 2004 或更高版本 |

| 设置里的「读屏幕」 | 取到什么 |
| --- | --- |
| 自动（默认） | 先问显卡要它正在往显示器送的那张画面（桌面复制，整屏约 2 毫秒），做不到时按 GDI 复制 |
| 桌面复制（DXGI） | 显卡交出的整块画面，独占全屏的游戏只有它取得到；显示器开着 HDR 或转着用时不行 |
| 桌面（GDI） | 从屏幕里复制，不要求显卡，抓一小块最省，总能取到点什么 |
| Graphics Capture | 按读窗口的那套机器读显示器，需要 Windows 10 2004 或更高版本 |

**来源由坐标基准决定**：坐标基准选屏幕就是桌面，读屏幕那一档；选窗口就是那个窗口（截取窗口用
它自己认出的那个），读窗口那一档。点了哪一档就只走那一档，这一档失败就报出来
（`Run.NoGraphicsCapture` / `Run.CaptureFailed` / `Run.EmptyRegion`），不换别的路——只有"自动"会
一路退下去。用得上这几条的前提是游戏**没被最小化**：最小化之后窗口自己不再画，窗口那两档都报
`Run.EmptyRegion`。改完设置从下一步看画面起生效。

**「整屏」指的是整块桌面**，不是主显示器：所有显示器合起来的那一块矩形就是宏坐标所在的那个范围，把显示器
摆在主屏左边或上边，它的左上角就是负数。区域那四个数留空量到的边缘、截图不带矩形时的整屏、系统变量
`sys.screenWidth` / `sys.screenHeight`，量的都是这块矩形；三块拾取器（取色、元素、区域）的覆盖层也盖住
整块桌面，副屏上的坐标同样拾得到。**每块显示器在哪**用「列出显示器」（`screen.list`，系统分类）读：交回
一条记录列表 `displays`，一块显示器一条，键是 `left` / `top` / `width` / `height` / `right` / `bottom` /
`primary` / `box`，另有 `x` / `y` 是这块显示器的中心；取其中一块的一项写
`field(get($显示器, 0), "left")`，全部走一遍用 `forEach`。

**Graphics Capture 的会话按窗口、按屏幕各留一份**，不在每次读的时候重新开关。开一个会话要建显示设备与
帧池（第一次 0.4 秒上下），读一次就开关一次比留着慢三倍；而且 Windows 会在正被读的窗口或屏幕
四周画一圈捕获提示边框，会话开着就在、关掉就没——**每次读都开关会话，那圈边框就会一闪一闪**。
读不动（库认不出这个窗口）的窗口记下来，后面不再每次去试。

Windows 11 上那圈系统边框会被代码关掉（`IsBorderRequired`）；**Windows 10 19045 及更早没有这个接口，
关不掉**——会话一开，那圈黄框就一直在（本机 Windows 10 上实测：屏幕最上面两行是 199,174,7 的黄，没有
会话时一个黄像素都没有）。系统那圈框只说"有东西在读"，说不了"读的是哪一个"：读的是哪个窗口，看我们自己
画的蓝框——添加动作窗口列出来的窗口、运行调试读到哪个窗口，框就落在哪里。

会话与文字识别模型都来自**程序持有的那一份设备层**：窗口、触发器的运行、试找与调试运行共用它，谁都不在
半路释放，程序退出时才一起放掉——所以同一个窗口第二次读不再重开会话，第二步读文字不再加载一遍模型。设置里
的**「启动时在后台预加载文字识别」**（默认关）就是把模型加载提到启动时做，免得第一步读文字的步骤替它等；
关着时模型在第一次读文字时加载，之后一直留在内存里。

另外两个字段也在「高级设置」里，用来省下连着看同一处的开销：

- **接受多久以内的画面**（`frameMaxAgeMs`，0–60000 毫秒，默认 0）：大于 0 时，同一次运行里同一
  个来源（同一个窗口，或桌面）刚抓过、又包得住这次矩形的画面直接裁下来用；第一次读的是整个窗口
  或整块屏幕，省下的是它后面那几次读屏。0 表示每次都重新读。
- **查看间隔**（`intervalMs`，0–60000 毫秒）：等待类步骤（等待图片 / 等画面静止 / 点击图片 /
  等待颜色 / 点击文字）拿它当轮询间隔，留空就是**屏幕刷新一次的时间**（60 赫兹 16 毫秒、
  240 赫兹 5 毫秒），也就是每隔一次刷新看一回——再快也只是把同一张画面读第二遍；填 0 表示
  上一次看完了立刻再看。只看一次的步骤与条件拿它当同一步骤两次查看之间的下限，默认 0，
  也就是轮到它就立刻看。7 毫秒约等于每秒 144 次。

等待类步骤（等待图片 / 点击图片 / 等待颜色 / 等画面静止 / 点击文字 / 等待直到）等多久只写在
步骤设置里的**「超时」**一处：到了这个时长，这一步被取消并判失败，交给重试与失败策略，重试时
从头开始等；新建这些动作的步骤时它默认 5000 毫秒（等待直到是 10000 毫秒），清空即不限时，等到
运行被停为止。这一步等的是什么就说什么（没等到哪张图 / 哪个颜色 / 哪行字 / 哪个条件），不只是一句
"超时"。查找颜色与找文字只看一次，没有等待，等某个画面条件成立用 `control.waitUntil`，等一个像素
变色用「等待颜色」。

一次"查看"是一次取景加一次比对。在 2560×1440 的开发机上实测：整屏走桌面复制约 2 毫秒（每秒约 500 次），
同样整屏走 GDI 约 25 毫秒（每秒约 40 次）、100×100 的小区域约 4 毫秒（每秒约 240 次）、窗口 Graphics Capture 约
10 毫秒（每秒约 100 次）；参考图越大、区域越大，比对那一段越贵。

「试找一下」和运行调试回看的那个窗口，顶部会写上画面取自哪里、用哪种方式取的（桌面 / 窗口，
GDI / PrintWindow / Graphics Capture / 桌面复制（DXGI）），找不着时先看这一行就知道是不是读错了窗口。

桌面复制是整屏最快的一条路（整屏约 2 毫秒，画面没有重新画过时几乎不要钱），代价是每个进程第一次用它要
先建一次显卡设备，约 0.25 秒，一次运行只付一次；它取到的画面里没有鼠标指针，与 GDI 复制屏幕一致。

**读到什么**　读文字的三步（文字识别 / 找文字 / 点击文字）共用一格**「读取内容」**（在「基础设置」
里），说读到的每一段留下什么：**全部文字**照原样留下；**只读数字**、**只留字母**、**只留中文**、
**只留字母与中文**这几档只留下要的那类字符——首尾的空格去掉、中间连续的空格并成一个，一个要的字符
也不剩下的段落就当没读到，全角字母与全角数字按半角算；**按正则提取**时旁边多一格**「提取的正则」**
（在「高级设置」里），把这段正则套在每一段上：匹配不上的段落不算，匹配上的段落只留下括号里的第一组
（正则里没有括号时留下整个匹配），例如 `单号：(\d+)` 会把「单号：88231」只留下 88231，留空表示不
做提取、读到的文字原样留下。这几档让同一步既能把一屏标签读成金额、也能读成货号，还能只留下中文；
随包那一份模型本来就中英文都读，所以「只留中文」是在读出来的结果里挑中文，不是换一份模型。表格模式
读到的同样是这几档过滤之后的段落。

## 浏览器

浏览器动作（`browser.*`）驱动的是一份**真浏览器**的会话：默认是 Windows 自带的 Edge，选 Chromium、Firefox、
WebKit 则要按提示行里的命令先下载一份。会话开了就一直是同一份——**拾取器用的也是这一份**——要关掉它得写一步
「关闭浏览器」，宏跑完不会替你关。所以「打开浏览器」通常写在宏的开头，一次运行接着一次运行用的还是同一份
浏览器。

**在哪一页上干活**　一个窗口里有多个标签页，宏认的是**当前页**：打开浏览器（`browser.open`）时定下第一页，
「转到网址」（`browser.goTo`）让当前页去另一个地址，「切换标签页」（`browser.switchTab`）说清后面的步骤改在
哪一页上——最新打开的那个、按序号、或标题（网址）里包含某段文字，「关闭标签页」（`browser.closeTab`）关掉
当前页并落到旁边那页。「最新打开的那个」会等几秒，等不到报错。在页面上点出来的新标签页**不会自己变成当前
页**：接下来的步骤还在旧页上，所以要紧接着写一步「切换标签页」。在页面里拾取时点在哪个标签页上，当前页就
落到哪一页。

**说清是哪个元素**　页面上认哪个元素全程序只有一个问法：`target` 那一格（标签是「选择器」）写选择器，写法与
网页自己的 CSS 选择器相同，另外能按文字找——`text=登录` 认的是显示这段文字的元素。这格是多行的，读法如下：

- **一行一条，从上往下依次试**，第一条能认出元素的就是这一步用的；多写一条是页面改版之后这一步仍然找得到
  元素的办法。
- **换下一条只在这一条认不出元素的时候生效**：认到了却点不动（被挡住、还没长出来）时不换，失败说的是挡住
  它的东西。
- 行里写 `$名字` 只做替换，不写算式。
- 一个选择器可能同时对上多个元素，这时「第几个命中」说这一步要的是它们中的第几个，按在页面上出现的顺序从 1
  数起，默认 1。页面上没有这么多时按没找到处理，失败里会分开说「页面上一个也没有」还是「没有这么多」。
  目标可以留空的两步（「页面按键」把按键发给页面本身、「读取文本」读整个页面）用不上这一格。

**四种按页面上的字认的写法**　除了选择器，还能直接用页面上写着的那段字认元素，写法是在文字前面加一个词：
`label=用户名` 认的是旁边写着"用户名"的输入框（它在标记里挂在哪个 `<label>` 下、由哪一句话指着，都归程序
去追），`placeholder=邮箱` 认的是灰字提示着"邮箱"的那个框，`alt=鲸灵首页` 认图片的说明，`title=保存工具`
认鼠标停上去会弹出的那句话。四者都按**包含**比，忽略大小写与首尾空白：`label=用户` 一样认得"用户名"。字段
照样可以手写，拾取器把这几条也列在候选里。

**元素在框架里**　网页里的框架（`<iframe>`）装着另一个页面，元素在它里面时，先写进这个框架的选择器，再写
`>>`，最后写里面那个元素：`frame=#pay >> label=卡号`。框架一层套一层时从外往里一层层写。在框架里拾到的
元素，字段里带的就是这一段，不必自己补。

**拾取与候选**　「在页面里拾取…」把这一步的「网址」开在浏览器的这一步所用的「档案」上（见下），点一下要用
的元素。拾取器把**最稳的那条说法**写进字段，其余的说法列在按钮旁边，每条写着它是哪一种说法、在页面上匹配几
处：点一下就把那条**追成字段的下一行**，跑起来时它就成了第一条的退路。想只留某一条，把字段清空再点它。
几种说法从稳到不稳依次是：测试属性（`data-testid` 这一类，站点留给自己的测试用的，最跟得上改版）、角色与
名字、表单标签、显示的文字、占位文字、图片说明、提示文字、id、表单名字、aria 名字、标签路径（从页面上层
一路数下来，上面几种都用不上时用它兜底）。

「测试」按同一套规矩框出元素，并说明框的是**字段第几行**、这一条在页面上匹配**几处**；一条也没匹配到时也会
说明，不必先跑一遍才知道选择器写歪了。

**一步能碰的东西**　页面上能做的不止点一下和填一段：

- **点击**（`browser.click`）可以选左键单击、左键双击、右键单击。右键单击弹出的是页面自己的菜单，菜单里的
  东西只有它能打开。「硬点」（高级设置里）在元素被挡住、被禁用或还在移动时也点下去，默认关：页面挡住不让点
  的按钮，多半是点下去也达不到想要的结果。
- **填写**（`browser.fill`）可以一次填好，也可以逐键输入。边打边给出候选的搜索框、离开每个格子就检查的表单
  要用逐键输入；「按键间隔」是逐键输入时两个键之间停多久，默认 0。逐键输入会先把框里原来的内容选中再打，
  与人在框里重打一遍一样。
- **读取**：`browser.readText` 读一个元素，可以读它显示的文字、它带着的值（密码框显示的是点、带着的是密码，
  下拉框显示的是选项文字、带着的是它后面的值），或者标记里的某一个属性（链接的 `href`、图片的 `src`）。
  `browser.readAll` 把选择器认到的**每个**元素各读一条，交成一个列表，可以只读其中的一部分；`browser.readTable`
  把网页上的表格读成一行一条记录，键就是列标题那一行写的列名（页面把列名写在 `thead` 或第一行的 `th` 里才算
  列标题，否则列名是 `A`、`B`、`C`，与「读取表格」那一步读窗口里的表格同一个形状）；`browser.readPage` 交出
  当前页面的网址与标题。
- **等待**：`browser.waitFor` 等元素，`browser.waitForUrl` 等网址（比文字的几档与别处相同，默认「包含」），
  `browser.waitForLoad` 等加载（文档就绪 / 加载完成 / 网络空闲）。点击之后要去的是另一个页面时，等网址比等
  元素稳：元素在点击到达的那一页上，太早去找会找到正要离开的那一页上的同名元素。
- **判断**：`condition.browserExists` / `browserNotExists` 问页面上有没有这样一个元素、它现在是看得见还是
  看不见。它是**看一眼**，不等待，所以放进「等待到」块里用才有等的效果。
- **滚动**（`browser.scroll`）：可以滚到某个元素、往下滚一屏、到页面底部、回到页面顶部。一次一点加内容的
  页面要靠滚动才会把下面的东西取回来，滚到元素也是让"快滚到才加载"的图片加载出来的办法。
- **上传与下载**：`browser.upload` 把文件交给文件选择框（浏览器不许脚本直接指定路径，这是唯一的绕法）；
  `browser.download` 保存页面交出的文件，选择器留空就等页面自己开始的下载，保存位置默认是宏文件所在的
  文件夹，交出文件的路径与名字。
- **对话框**（`browser.dialog`）是一个**带子步骤的块**：把会弹出对话框的那些步骤（点那个会提问的按钮）写在
  盒子里，回答的答案在盒子外面先备好。写成盒子是因为**对话框没人回答时页面就停在那里**：触发它的那一步要等到
  被回答之后才会返回，所以"先点、再回答"两步是写不出来的。盒子里没有弹出对话框会报错；一个盒子里只有第一个
  按这里说的回答，之后弹出的按浏览器默认处理（自己关掉）。
- **在页面里跑脚本**（`browser.evaluate`）：写一段页面会调用的函数，用 `return` 交回结果，结果按 JSON 写成
  文本（文字带引号、数字还是数字、记录与列表保持原样）。上面那些动作都没覆盖到的事情由它兜底，代价是这个宏
  依赖页面自己的实现。

**登录档案**　「打开浏览器」有一格「档案」（在「高级设置」里）：

- **留空**（默认）每次都是全新的浏览器，记不住任何登录，也不碰你自己的浏览器与它的登录。
- **写一个名字**，用这个名字打开的就是同一份浏览器：Cookie 与登录状态都留在里面，所以"登录一次，以后每次
  都还在"写成一步登录加一个档案名就够了。

档案是程序旁边的 `browsers\<浏览器>\<名字>` 里的一格（程序目录写不进去时落在 `%LOCALAPPDATA%\WhaleGenie\browsers`，
与 `packages` 同一条规矩，见「程序自己的文件放哪儿」）。程序不会替你清理档案，要清掉就删那个文件夹。**同一时
刻只有一份浏览器**，所以这一步写的档案名与正开着的那份不同时，会先关掉前一份再打开新的。「在页面里拾取…」
用的也是这一步的档案，拾到的就是宏将来要驱动的那份会话。

**等多久**　浏览器的动作不写自己的等待字段：要等多久由这一步设置里的**「超时」**说——碰元素的动作（点击、
填写、读取、下拉选择、勾选、悬停、页面按键、滚动、上传、在页面里跑脚本）默认 10000 毫秒；会停在原地等的
动作（转到网址、等待元素、等待网址、等待加载、下载文件）15000 毫秒；步骤没写超时时，设备自己按 30000 毫秒
兜底。等的那几步状态一到就结束、不会停满，状态没来报的是这一步超时，而不是浏览器出错。

## 分隔符文件（CSV）

`file.readCsv` / `file.writeCsv` 读写的是一行一行的文本：分隔符可以点名，也可以让它自己从文件里
认出来（`auto`），引号、单元格里的换行、行尾、空行这些细节归 `CsvHelper` 管。

读到的每一行是一条记录：键就是表头那一行写的列名，所以取一个单元格按名字取——`field(行, "金额")`——
不用数它排第几；文件的第一行不是表头时，列名就是 `A`、`B` 这样的列号。按内容挑行用 `matchColumn` /
`matchValue`，只留几列用 `columns`。写的时候选"追加"再勾上
「按列名放进同名的列」（`align`），每个值就落进文件第一行里同名的那一列——别人的程序多一列、
少一列，都不会把后面的内容挤错位；文件里没有那个名字时会报出来点名。空单元格默认写成两个分隔符
之间留空，非要看见格子的程序可以用「空单元格写成」让它写成两个引号（`emptyCells`）。

## 图片与校验和

**截图顺手存盘**：「截取屏幕」（`vision.capture`）与「截取窗口」（`vision.captureWindow`）各有一格
「存到文件」：填了就趁这一步把这张图写成文件，留空（默认）只把图片交给变量。写出来的一律是 PNG，
同名文件会被替换；相对路径从宏文件夹算起（见下），所以一个宏把截图存在自己旁边、换个地方打开也照旧
找得到——想把结果图交给变量又留在磁盘上，一步就够，不必再单独存一次。要单独把一张已有的图片写到
别处，用「复制文件」。

「计算摘要」（`data.hash`）算的可以是**一段文本**，也可以是**一个文件**：选文件后填路径，读的是文件的
原始字节，和别的程序算出来的值对得上（MD5 / SHA-1 / SHA-256 / SHA-512）。文件是一块一块读的，多大的
文件都不会把内存占满——校验安装包、下载文件、备份包时用它。

## 程序自己的文件放哪儿

`settings.json`（设置窗口里的选择）和 `logs`（运行失败时的文字日志）都写在 `WhaleGenie.exe` 所在的
目录：整个文件夹拷走就等于把设置一起带走，两个副本放在一起也不会互相干扰。装在只让管理员
写的地方（比如 `Program Files`）时这两样写不进去，程序照常运行，只是设置不落盘、失败不留日志。

脚本要的包放在同一个目录下的 `packages` 里：`packages\python` 是 Python 包，`packages\nuget` 是 C# 脚本
用的 NuGet 包。它们与设置一样跟着程序目录走，装不进去时改用 `%LOCALAPPDATA%\WhaleGenie\packages`。

浏览器动作的**登录档案**也放在这里：`browsers\<浏览器>\<档案名>` 是「打开浏览器」那一格「档案」说的地方，
一份档案一个文件夹，删掉文件夹就等于让它重新登录一次（见「浏览器」）。

宏和宏包不跟着程序走：默认在「文档」目录下的 `WhaleGenie` 里（`%USERPROFILE%\Documents\WhaleGenie`），
它在哪由打开的宏包决定。
