## 2. 三条线（**范围必须分开报**）

| 线 | 值 | 范围 |
|---|---:|---|
| 本地样式 | **99**（13 文件） | `Views/*.axaml` |
| `App*` | **0** | `Views/*.axaml` + `App.axaml` |
| `App*`（字符串键） | **1** | `*.cs`，**数据键**（`palette.TryGetValue`），**不动** |
| 回退值 `Brush(key, fallback)` | **0** | `Views/*.cs` 全仓绝迹 |
| 裸值 · 债务 | **0** | axaml 0 + C# 0 |

**裸值债务归零。归零的方式有两种**：

- **落令牌 146 处**——**由减法得出，非逐批累加**：
  `axaml 132 → 28` 得 **104**；`C# 61 → 19` 得 **42**（基线 `0766f7f^`）。
- **判定为字面 42 处**（**永远不动**）：axaml 26（录音 19 / 拾取器 5 / 二维码白底 2）
  \+ C# 16（拾取器 13 / `LookWindow` 自绘 3）。
- **已裁例外 2 处**（**下次可能动**）：`MainWindow` 置顶蓝的常态/悬停。

> **为什么用减法**：加法只数"这轮动过的"，减法数"基线里所有后来不见了的"。
> 两个数都对，但回答的问题不同——**读者关心"这批债清掉了多少"，不是"这轮摸过什么"**。
> 加法这轮还被证伪过一次：`#BFE3BF` 报了没做（账上划掉了、代码里还在）。
> **可复算比精确更重要**：一个能重算的约数，胜过一个不能重算的精确数。

## 5. 缺变体清单（每条写"缺的是什么"，不是"和库不一样"）

**本清单是快照，不是现状。** 拿它去落地之前，**逐条确认"它说的那个东西还在"**——不在了就标掉，别照落。
判据：**清单写的是"当时它在哪"，不是"现在它在哪"。** 已见两例：芯片行那两个字面值已全仓 0 命中；
`Button.Rail` 这里写着"缺变体"，其实库里早有、只是视图还在用旧类名。

## 7. 五条扫描：覆盖面 + 已知盲区

| 扫描 | 覆盖 | 已知盲区 |
|---|---|---|
| 用了没定义 | `Views/*.axaml` | `/template/` 跳过；纯代码窗另有一条 |
| 定义了没人用 | `Views/*.axaml` | 消费者数三处（XAML/`.cs`/测试）；**跨窗的样式会被判成"有消费者"——`RemoveButton` 就这么漏到被修** |
| 类名组合配不配 | `Views/*.axaml` | 动态拼出的类名数不出；**大小写能报**（`On` vs `.on`） |
| `.cs` 里的类有没有样式 | `Views/*.cs` | 只查 `Add`/`Set`/初始化器三种写法；**测试把手要算消费者**（否则误删） |
| 裸值 | `Views/*.cs` 的 `Color.From*`/`Parse` | `Colors.*` 命名色与 xaml hex 不在这条里；**注释里写的值会被算进去，实测让 C# 计数偏高约 10%（19 里占 2）** |

**"带数量的盲区，比带描述的盲区更会被重视"**——所以上面那条盲区补了量化。

## 9. 作废过的结论（**走过的弯路也留下**）

| 作废的 | 原因 |
|---|---|
| "这些窗到底了"（曾报过十几个） | 旧口径**只数本地样式与 `App*`、没算裸值** |
| 同上，第二次 | 分类"**主题色样**"**根本不存在**——主题预览早已数据驱动（`ThemePalette`），axaml 里没有字面色样；按它剔掉的一批里有 4 处是真债务 |
| "裸值债务 33" | 上面那个不存在的分类剔过一批，33 是一版错的账。真值是从最初 **71 处**清到 0 |
| "落令牌 ≈45 处" | **加法累加**，必然漏记与重复计。改用**减法**得 **146** |
| "尝试记录 9 处是序数着色" | 去代码里查：**是按角色**（谁接手输入 / 谁接手浏览器 / 注释 / 问你 / 速度徽标 / 时间戳），不是按第几次 |
| `#8FB3D9` "沿用 `FormulaMark` 的裁定" | **主客颠倒**：不是标识符借了 `FormulaMark` 的颜色，是 `FormulaMark` 借了标识符的 |
| "`On` 改成小写就好" | 那个窗**没有 axaml**，声明不了本地样式——改小写一样配不到，**该删** |
| "`MenuCell` / `MenuIconChoice` 没样式就该删" | 它们是**测试的把手**（`Classes.Contains`）。**"没有样式"不等于"没人用"** |

**这些比当前值有价值**：它们告诉下一个人哪些弯路已经走过。

## 10. 这一轮的方法收获（`doc/dev.md` 第 1–20 条）

统计口径改了七次（口径 → 范围 → 写法 → 数据类 → 位置 → 报做未做 → 减法），
抓出十种静默失效，拆了五次"一色多用"。**最有价值的产出不是那些归零，是 `dev.md` 里那 20 条**——
它们让下一轮不必再走一遍这些弯路。

其中与本轮直接相关的几条：

- **处数要数，档数要问**；
- **"有据"不构成"答对"**——它证明查过，不证明查对了题；
- **判据要先验证它描述的对象存在**，否则它是一张通行证；
- **减法优于加法**：加法要记住每一批，减法只要总数与排除项；
- **注意力是回忆，窗口数是数得出来的**（写交付说明时按影响面排，不按"我觉得用户会注意到"）；
- **"没变"也要写**；**越早做的东西越容易被当成"本来就这样"**。
