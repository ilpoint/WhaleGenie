# 界面优化路线图

这份路线图回答一个具体问题：动作库里的 174 个动作，哪些已经按新样板改过，哪些还停在旧版式，
下一步按什么顺序改、每一类改什么。样板由比色族（找色 / 多点找色 / 点击颜色 / 比色）与
「基础设置 / 执行与容错」两页定下，后面所有动作都往同一套上靠。

**版式与能力分开记**：版式、分块、文案、页签在下面各节；**缺的参数与动作**在
「待补的动作与参数」一节，其中还有一张「已核对、确实不缺的」清单，提缺口之前先看它。

## 已经定下来的样板

- **分块**：一页里的字段按问题分组，每组一行**图标 + 标题**（`Group` + 块图标）。同块字段必须相邻，
  目录加载时校验。块图标由 `AppIcons.Block(组名)` 给：范围是裁切框、找什么是放大镜、怎样算找到是
  对勾、怎么点是鼠标、节奏是秒表、调参是滑杆；新加的组没有图标时退回显示序号。
- **必填与默认**：必填项一打开就有可用值；空值只表示"没说过"，不表示 0。
- **块号跟问题走**：一个问题可以分在两页上（「找什么」的基础页放参考图与置信度，高级页放识别方式与调参），
  两页上的标题与序号是同一个。表单一页一页地排，但问题只有一个。
- **拾取器**：能点的东西都给一个拾取按钮（坐标、区域、颜色、窗口、元素、文件），拾取窗口带放大镜。
- **行表**：一行一条的列表用统一的行表（表头 + 分隔线 + 定宽列），不把几段文字堆在一起。
- **结果**：返回值排成「留下 / 结果 / 结构 / 变量名」四列表，结构列给出示例，悬停给全字段。
- **失败**：执行与容错页统一问超时、前后延迟、重试、失败策略；危险动作额外确认。

## 本轮落地

- **每格的读法改由图标说**：`ƒ` / `$` 两个自造字形换成 Lucide 的 `SquareFunction` 与 `Variable`
  （13px，`TextSecondary`）；「此字段可填写表达式」「此字段按文本读取」两句从框下面的提示里整段去掉，
  由这两个标记的悬停承担。一页十来个字段时，同一句话不再复述十来遍，`Hints()` 只剩这一格自己的话。
- **块头由序号改图标**：`ParameterRowViewModel.GroupIcon` / `HasGroupIcon`，图标 14px；`Border.BlockNumber`
  去掉圆圈边框（图标自身有轮廓，再套一圈是两道边），没有图标的块仍显示序号。
- **空草稿不再变成"发现上次未保存的内容"**：`RecoveryEditor.IsWorthKeeping`（有步骤、有描述、有绑定键，
  或名字已经不是 `MacroNames.IsDefault` 那种"宏 N"）才写进快照；`RecoveryContents.IsEmpty` 用同一个判断，
  `Load()` 读到空快照顺手删掉。新建一个宏就关程序，下次启动不再问一句答了也回不到东西的问句。
- **变量与列表动作归入「数据与变量」**：`control.setVariable`、`control.incrementGlobal`、
  `control.listAdd/Insert/RemoveAt/Set/Clear` 从 `Control` 移到 `Data`。它们不决定下一步去哪，
  不该和分支、循环混在一栏；现在它们出现在「基础动作」的「数据与变量」组里，与编码、摘要同组。
- **「设置变量」保留原名**：它在语义上是赋值（Assign），不是"运算"；算式只是值的一种写法，
  已写进描述。行业里同一种动作叫 Set variable / Assign，改成「变量运算」反而让人以为它专门做计算。
- **动作卡片双击插入**：动作库卡片支持双击，等价于拖到当前落点；拖动要求真实拖放会话，
  键盘与自动化做不来。`ActionPaletteView.CardActivated` → `MacroEditorWindow.OnCardActivated`，
  复用同一个动作表单与 `AddStepHere` 的落点规则；`_actionEditorOpen` 防止双击叠出两个模态窗。
- **桌面元素也能说「还要像什么样」**：`uia.*` 的 12 个找元素的动作多了与网页同一张 `narrow` 行表。
  能问的事按族给：桌面元素只有 UI Automation 答得干脆的三件（看得见 / 能用 / 名字含或不含一段字），
  网页仍是原来六件；选项由目录的 `NarrowOn` 声明，同一个编辑器照着摆，网页那两颗「从页面选取」
  「看看效果」在桌面元素这一族不画。引擎侧 `UiQuery.Conditions` + `FlaUiDevice.Matches` 逐条比，
  不写条件时与从前完全一样。

- **动作名按族分开**：`uia.*` 的名字一律点明「界面」，`browser.*` 一律点明「网页」。原来两族各
  有一张「点击元素」，并排摆着只能靠猜；`勾选框` 与 `勾选`、`选择列表项` 与 `下拉选择`、
  `设置元素文本` 与 `填写` 也是同一件事的两种叫法，看不出谁在网页上、谁在桌面上。现在叫
  「点击界面元素 / 点击网页元素」「勾选界面复选框 / 勾选网页复选框」「填写网页输入」这样。
  动作库的搜索补了一层兜底：整句对不上时按两个字一段拆开，每一段都要出现，所以照老说法问
  「点击元素」仍旧同时找得到那两张。目录测试不允许两个动作同名，中文与英文各查一遍。

- **这一轮的四处修补**（都是用了之后才看出来的）：
  1. 「获取窗口」页底那颗「取当前窗口（F1）」从来没取到过东西：按下去的那一刻前台就是鲸灵自己。
     现在换成「取窗口」（准星图标）：按下后鲸灵自己的窗口全部让开，指针移到哪扇窗口它就被框出来
     （框就是窗口本身，中间挖空，点击落到目标上），点一下取走，Esc 取消；F1 是同一个动作。
     窗口由 `IWindowDevice.At` 回答，Windows 侧走 `WindowFromPoint` + `GetAncestor`，没有标题的
     窗口也能指；鲸灵自己的窗口按平台句柄与程序名排除。
  2. 坐标拾取器打开后发滞：每 16ms 一次 UIA 查询（跨进程）与全屏重绘。现在 33ms 一帧，UIA 答案
     按「指针挪了 2 像素以内就沿用、最密 80ms」缓存，读数文本没变就不重排；十字线与放大镜照旧跟手。
  3. 键、组合键、手柄字段旁的「测试」按钮删掉：与表单下方的运行按钮做的是同一件事。运行按钮
     继续把这一步真的发出去，切窗口、松手柄的逻辑不变。
  4. 截图与识别文字的「那一块」四个数（左上角 X/Y、宽、高）压成一行：复用搜索区域那一行的
     `NumberCellTight`（短名 + 框 + ƒ，长说明在提示里），一行说完，页面短了一半。

- **确认键统一成 F1，拾取器不再依赖"拿得到前台"**（这一轮之后）：
  - 「取窗口」悬浮时框住目标，**F1 确认**、Esc 取消。左键**完全放行**：拾取期间人还要点别的窗口、
    点任务栏启动一个应用，把要取的那扇摆到前面来；点击既不取走也不拦，取走只由 F1 决定。
  - 「取窗口」让位期间，对话框自己的 Esc 不再关掉对话框（焦点可能还留在它的框里），
    否则取消之后就回不到那一页了。
  - 区域拾取器的 F1/Esc 改为从 `IInputHook` 读：拾取器压在最上面，但 Windows 不保证把前台交给它，
    交不出去时按键落到了别的窗口上，看起来就是"按了没反应"——这正是识别文字框不出来时遇到的那件事。
  - 坐标拾取器回到 60 帧：放大镜与读数每帧跟着指针走；指针没动时整帧什么都不做，UIA（跨进程）
    按「挪了 2 像素以内沿用、最密 80ms 一次」缓存。先前把帧率降到 30 帧换来的"不卡"其实变成了"迟钝"。

- **识别文字的范围改回列表**（开发阶段，不留兼容）：`ocr.recognize` 的 `x/y/width/height/rect` 删掉，
  换成与找色、找字同一个 `region`（Rows）参数：区域1、区域2、行末删除、或变量、加一条区域。
  运行时 `ReadSpans` 逐处读、按顺序接起来；试看只摆第一处的图。截图动作仍是"一个矩形四个数压一行"，
  因为截图就是截一块，没有"再截一处"的意思。

- **动作表单的信息密度**（正在进行）：动作编辑器里最长的那块版面不是字段，是字段下面那段说明。
  一页十来格，每格一段话，读的人会跳过，版面却被撑满。
  - 已完成：字段说明从常驻段落收进**标签右侧的 info 图标**（点开是浮层，卡片底色 + 边框 + 阴影，
    不再是与表单同色的"一块黑"）；块标题也有 info（`Add.Group.<key>.hint` 一句话说这一块问什么）；
    动作描述收进动作名右侧的 info；窗口字段那句"认哪扇窗口"、颜色点那两条规则同样收进图标。
    识别文字这一页因此从两屏缩到一屏。
  - 已削第一刀：六段共用说明（输入方式、识别方式、窗口规则、搜索区域、读取内容、正则提取）
    与区域四数、窗口字段的说明压到一到两句，"识别方式选窗口时…"不再在四个格子里各说一遍；
    其余动作的 Hint 同样按"一到两句、书面、只留这一格必须知道的"逐条改。
  - 再下一步：`BasisNote` 收进 area 块的 info；参数单位与范围统一写成格内后缀；英文 Hint 同步。

- **变量中心两个按钮**：`局部变量`（新窗口：看来源、类型、谁在读，可改名）与 `全局变量`
  （原有管理窗）。局部变量由步骤写出来，所以那一窗不提供"新建/删除"，只做改名与查看。
- **窗口只绑一次（本轮）**：54 个动作都带窗口字段，原来每一步各存一段完整规则，同窗口做二十件事
  就要捕获二十次，而捕获那一路还要按 F1 对准窗口点一下。现在：
  1. 窗口字段只有一颗「选择窗口」，下拉里六种走法：前台窗口（不指定）、**沿用上一次用的窗口**、
     本宏已经用过的窗口（去重、带用了几处）、此刻打开着的窗口（点一条即取，不必按 F1）、
     捕获窗口（F1）、变量里的窗口。选填的匹配方式仍由捕获对话框编辑。
  2. `WindowRule` 多一个 `follow` 标记，字段里存的是**指向**而不是副本：运行时取这一轮里上一个
     自己指定了窗口的步骤那句话（`MacroRunner._lastWindowRule`），一次都还没有过时用前台窗口。
     上面那一步换了窗口，这一串跟着换。AHK 的 Last Found Window 是同一套语义。
  3. 新建的一步如果落点之上已经有人指定过窗口，默认就是「沿用上一次」（`WindowRuleChoices.NearestAbove`
     决定"之上"是哪一条），所以第 2 到第 N 步零操作；上面一个都没有时不替人做主，空着仍是前台窗口。
  4. 空着的摘要从「还没有获取窗口。」改成「前台窗口。」：空不等于没设，它是一个明确的意思。
  5. 「获取窗口」这一页也重做了：左边是此刻开着的窗口（可筛选、可刷新、鲸灵自己不在里面），
     点一条就选中；右边是「怎么认出它」（匹配方式、匹配内容、三个比较开关）与「现在会认到」
     （实时列出按这条规则认得哪些窗口），两栏齐底；底下是状态、F1、取消、使用这个窗口。
     原来那一页只有"按 F1 抓"一条路，抓到之前还摆着「句柄：0」这种没有意思的行。

- **条件分支与多分支的两页**（本轮，细节见 [step-list-and-conditions.md](step-list-and-conditions.md)）：
  1. 两块各有了一个块头，`Control` 族的「已分块」从 0 变成 2：`control.if` 的条件归入「条件」，
     `control.switch` 的值与比对方式归入「比对什么」。块头说完之后，条件那一格自己的标签不画，
     同一个词不在一页上连写两遍。
  2. 条件为空时表里直接有一行空比较，两个框各有一句占位词；原来这里是一句「还没有条件。」
     加一颗按钮，三个白框没有任何字。
  3. 红字只在写了一半时出现。新建就红「还缺：条件」说的是人没做错的事，现在一格没填是中性的一句
     「写一行比较就能添加这一步」。
  4. 「条件树」从三个入口收成一个（右上那颗切换），嵌套提示也从两处收成一处。
  5. 多分支的表单不再装作没有分支：值下面一行写「3 个分支 · 其他情况 2 步」，并给一颗「添加分支」。
     分支仍是步骤，值在列表那一行上写；表单只回答"有几支、再加一支"。
  6. 列表里：条件分支那一行的摘要从 `control.if · 条件 = $found == true` 改成 `$found == true`；
     分节名收短为「满足时 / 否则」，所有分节统一写成「标题 · 3 个步骤」；分支还没填值时那枚值片
     用警示色，不再是一句灰字。
  7. 动作库左下角那句提示补上双击：「双击动作卡片就插到当前落点；也可以把动作拖进步骤列表」。
     块页面里那句"子步骤在列表里拖入和排序"同样补上双击。
- **条件能问的事多了（本轮）**：比较词从 8 个运算符扩到 16 个，分数字 / 文本 / 列表 / 真假四族——
  文本多了「包含 / 不包含 / 开头是 / 结尾是 / 匹配正则 / 为空 / 不为空」，列表多了「条目数为」；
  行表顶上多了「全都不成立」（写 `not (a or b)`，`not (a and b)` 不认，因为那是另一个问题）。
  词表只有一份（`ViewModels/Comparison.cs`），条件行、多分支的比对方式与 `compare()` / `where()`
  的下拉都从它取；多分支补上了唯一缺的「不包含」，并统一了「开头是 / 结尾是 / 匹配正则」三个说法。
  引擎没动：这些词本来就写在普通表达式里（`contains($a, x)`、`length($a) == 0`、`count($l) == 3`），
  改的是写法与读回——读回不认时，`contains(...)` 会被当成"左边一整串"的成立，行表也就显示不出它。
  两格旁后来改成**一枚贴在框里的「取值」小片**（`AutoCompleteBox.InnerRightContent`）：按钮跟着格子走，
  不必先猜它填的是哪一格。第一版做成了框内 20 像素的淡色图标，没人看得出是按钮——这一条留着当反例：
  不带字的入口等于没有入口；而入口不跟着格子走，带字也得先猜。
- **两个窗口合成一个（本轮，并改了一次方向）**：先是做成 760×560 的页签窗（变量 / 值 / 函数各一页），
  用户当场否掉——写公式时材料必须同屏，页签把两样藏起来，切一次丢一次位置。现在改回旧表达式窗口的
  一页三盘（1040×700）：符号、变量、函数同时可见，公式行在上，右上说明选中的材料。`namesOnly` 只画
  变量盘。三盘用**彩色描边的胶囊**，度量和动作里的片同一套（`Secondary Chip Dense`），只换颜色；
  符号按族、变量按来源、函数按分组，色板复用 `FunctionGroupBrushConverter`。三栏之间两条 `GridSplitter`
  并各有最窄宽度；分类只留文字；值用旧页面的数字 / 文字 / 真 / 假 / 空。离开只有「确认」与 Esc。
  旧窗口的空画布、两页签不同步、底部被切掉，这三处在这版里都没有了。
- **结构改成插槽（本轮）**：原来左栏是一棵只读的积木树（一行一块 + 每层引导线），形状读不出来；
  现在结构独占上方全宽一条，函数是带括号的容器，参数就是盒子里面的位置，嵌套由递归模板画出来；
  每块带原文起止。带子里有一根常驻的细竖线，点一块的左半边或右半边把光标放到它前面或后面，
  接缝也能点；三盘材料、函数卡与常驻小输入框都写在光标处，不替换已有的块。函数末尾永远有一个
  幽灵槽（虚线 `＋`，不写进公式），填了就自动再长一个，写满 `MaxArguments` 才收起；删到最后一个
  幽灵槽自然回来，没有手动加空位的按钮。必填缺值是红虚线、可选是灰虚线，一个实参都没有时写
  「参数为空」。符号带下面常驻一行小输入框，`数字` 与 `文本` 只切换它写什么，按回车插入而不关窗。
  名字在公式框里是一个整体，退格与删除一次取走一个。细节见
  [step-list-and-conditions.md](step-list-and-conditions.md)。
- **光标能用方向键走，表头多了清空，分类按钮会标记（本轮）**：竖线原来只能用鼠标点，键盘用户只能一直
  指着；现在左右在接缝之间跨过一整块，上下按行找最近一处，走动时带子自动滚过去。接缝是块的两端而不是
  字符位置——线只画在接缝上，逐字符走看起来像没动。表头第三枚图标一次清空整条公式，它和撤销恢复共用
  一份历史，清空也就成了一步可以撤掉的编辑。变量盘与函数盘那一排分类按钮原来点过之后没有任何痕迹，
  下面列的是哪一组看不出来，现在当前那一类描着强调色，悬停也不褪。三处判定都留在 `ValuePickerViewModel`
  与窗口里，没有新增常量表。细节见 [../manual.md](../manual.md) 的取值窗口一节。
- **一个问题的两半用同一个号（本轮）**：表单每页各自从 ① 数起，于是 28 个动作的同一块在两页上各有一份
  同名标题、各挂一个 ①，读起来像两个问题。现在序号按整个动作排一次：基础页的 ②「找什么」与高级页的
  ②「找什么」是同一件事接着读，它后面的「④ 识别调参」也不再从 ① 起。
- **程序族问「哪一个程序」（本轮）**：`waitFor`、`waitExit`、`exists`、`info`、`kill` 的目标原来是
  三种写法（`processName`、`processTarget`、`id`），现在换成与 54 个动作同一格 `window`：菜单、F1 捕获、
  用过的窗口、变量里的窗口全都照旧，标签写「程序」。认法按 `how` 分流——进程名直接问进程表（后台服务、
  控制台程序靠这一档），句柄只认那个实例，标题与窗口类先找窗口再问它是哪个程序。这一格不能空着：
  窗口空着是「前台窗口」，程序空着是没答。`process.start` 交回的记录多一格 `how = processEquals`，
  所以 `$program` 能直接填进任何程序或窗口的格子。
- **危险动作先问一句（本轮）**：编辑器里那句「这一步会注销、睡眠或关闭这台机器」判的是一个早已改名的字段（`what`，现在叫 `powerAction`），所以从来没触发过；运行整个宏时则根本没有这条路。现在由目录声明：动作级 `Irreversible`（删文件、删文件夹），参数级 `IrreversibleWhen`（关机的五种取值，锁屏、关显示器、取消关机不算）。判定只有一处 `ActionSemanticsCatalog.CannotBeUndone`，编辑器的试跑与整次运行问的是同一处。拒绝是一个失败，失败键 `Run.NotConfirmed`，交给这一步自己的「失败时」；一次运行里同一步只问一次，循环重复二十遍也一样。`IRunHost` 多一个 `ConfirmIrreversible`，没有人在场的宿主（触发器没接回调、MCP 调用）一律答否。确认框多一枚危险标记：按钮与平常那次长得一样，读的人往往只看到按钮。
- **系统族与窗口族的读法（本轮）**：`window.move` 的「哪个窗口」补上块头（新组键 `subject`，
  图标 `AppWindow`），与「放到哪儿」并列；原来这一页只有第二件事有块，第一件事看起来像没归位
  的杂项。系统族逐个核对后**不加块**：`system.volume` / `system.brightness` 的「设为指定值」与
  「调大 / 调小」互斥，同一时刻只看得见一格，套块头等于给一行字加个标题；`system.power`、
  `system.sound`、`system.ime` 的两三格也是互斥或各带标签；其余各只问一件事。百分比那一格
  （置信度、容差、音量）的滑条压到 24 像素高：模板给的那一圈空原来把一格撑成两格。
- **英文说明收成一两句（本轮）**：视觉、识别、界面、浏览器四族的 392 处字段说明原来中位 250 字符、
  最长近千，摆在字段边上读不完，一页十来格时版面的重心从字段挪到了说明上。现在与中文同义、
  一到两句、最多 160 字符，`LocalizationTests.A_hint_is_read_beside_its_field_not_as_a_chapter`
  守着这四族。单位、范围、默认值仍写在句子里的原处；动作特有的细节回到动作描述与手册。
  一个族问同一件事的说明（窗口规则、结果勾选、网页选择器、第几个命中、识别调参）只写一份，
  铺到所有用它的动作上，不按动作各写一遍。其余族按族跟进。
- **流程族的表单与行摘要（本轮）**：四个循环、`waitUntil`、`runMacro` 按块重排——「重复几次」「什么时候停」
  「过什么」「每轮叫什么」「从哪儿数到哪儿」各一块，加一块「节奏」；间隔、步长、倒序从高级设置迁回
  基础设置，这四个动作因此少一个页签。间隔原先只有三个循环有，「当…时循环」这一轮补上同一个字段，
  四个循环的节奏才是一件事，而不是三种说法。`control.try` 用一行「尝试 3 步 · 捕获 1 步 · 收尾 0 步」
  说清三段构成，并写明三段都没接住的失败交给本步的「失败后」；它不加块，因为三个列表是步骤而不是字段。
  步骤行不再写技术键与字段名：`重复 10 次，每次间隔 500 毫秒`、`1 到 5，每次加 1，记作 $i`、
  `$list 的每一项，倒序`、`3 到 10`，结果收成「留下 1 项结果」。顺带修掉「等待直到」条件提示里写错的
  默认值：它取的是步骤超时，默认 10 分钟，而提示写的是 10 秒。
- **表格有它自己的形状（本轮）**：`uia.readTable`、`browser.readTable`、`ocr.recognize` 的表格与
  `file.readCsv` 的 rows 交的都是「一行一条记录、键是表头读到的列名」，但目录只能说到 `List`，结构列
  于是写成 `["文字", …]`。现在目录多一个事实 `Table`（只能在 `List` 上，且不能与字段同时声明），结构列
  写 `[{列名: "文字"}, …]`，悬停说明取一格用 `field(get($变量, 0), "列名")`。列名仍然不写死：它是运行时
  从表头读到的，写死会让每次读表都 `BadResultType`。MCP 的返回值投影也带 `table`。
- **剪贴板里那张图先看一眼（本轮）**：`clipboard.readImage` 没有可填的字段，它问的就是「此刻剪贴板上
  是什么」，所以表单在结果表上方直接摆出那张图与尺寸，旁边一颗「刷新」；空剪贴板与被别的程序占着各说
  各的。运行时这一步也交一张画面（新 `LookKind.Clipboard`），运行调试的行上有缩略图，点开是整图，看图
  窗口对没有标记的画面收起右边那一栏。
- **脚本正文是一块代码框（本轮）**：新增字段种类 `Code`，`browser.evaluate` 与四个脚本正文改用它：等宽、
  下沉底色、240 高、长行不折（缩进是脚本的一部分）。`Tall` 这个标志随之删掉，同一件事不留两个名字；
  三个脚本动作的 `scriptArguments` 收进高级页，正文成了基础页的主体。
- **文件族的三件事各归一处（本轮）**：路径统一成 `source` / `save`（复制与移动的 `from` / `to` 改掉），
  「撞上同名怎么办」统一进 `clash`（`writeMode` 从「怎么写」里挪出来），块名跟着说通文件与文件夹
  （从哪儿来、存到哪儿、已经有了这一份），两种写入的选项文案与标签也统一。两条守门用例把这三条钉住。
- **MCP 说得出一件事：这一步做了回不去（本轮）**：`McpActionDetails.irreversible` 与参数级
  `irreversibleWhen` 一起给，客户端复现得出运行期那一次询问（动作本身不可逆，或某格里选了那几个值）；
  工具说明、资源说明与服务器说明都写清「没人在场时按 `Run.NotConfirmed` 失败」。

- **补完最后五条缺口（本轮）**：五条各有各的读法，共同点是都只加「这一步真正要答的那一格」。
  1. **zip 带不带顶层文件夹**：`file.zip` 多一格「带上这一层文件夹」，与「文件夹」同块，默认不带上，
     解压得到的仍是文件夹里面的内容。顺带修掉一处说了没做到：那一格旁的「压缩包」一直写着「已存在时会
     替换」，而打包器是以「目标不能已存在」打开的，宏第二次运行就撞 `Run.FileFailed`。
  2. **找图的透明色**：「忽略的颜色」改名「透明色」，三动作各补一格「容差 %」（0–100，默认 0）。
     改名不是换词：同一个底层机制原来只说了「会变的部分」这一种用法，用户想不到拿它处理图标底色。
     容差用找色族同一套判据（`ColourReach`），所以「5%」在两处是一个意思。
     两处实测结论写进了代码注释与用例：带掩码时默认的归一化相关给的是坏结果（同一张图、同一个掩码，
     逐像素与相关都答 1.000 并在原处，归一化相关答 0.196、位置还是负的），掩码下改走相关；
     颜色读不出来原来被当成黑色掩掉，现在报 `Run.BadPoint`。三条用例真的跑 OpenCV——替身设备只记得住
     请求，说不出像素有没有被掩掉。
  3. **元素锚点**：十二个带选择器的界面动作各多一块「元素锚点」（挨着谁、在哪一边、至少隔开多少），
     收在高级设置里，与「第几个命中」并列。锚点选择器与主选择器走同一个解析器、同一条窗口规则；
     方位只看一条轴，所以同一行里上下差一点仍算「在右边」；任一矩形为空就不成立——提供方说不出元素
     在哪儿时按找不到处理，而不是退回随便挑一个。过滤排在排序与取第 N 个之前：先截断再过滤，
     被锚点排除的元素也占了号，宏拿到的是另一个元素，而且没人会告诉它。
  4. **注册表三个动作**：读、写、删各问一件事，用「在哪儿」与「放什么进去」两块。根只有当前用户与
     这台机器；带根名、带 `..`、两端带反斜杠的路径一律拒绝，否则上一格选的根就成了摆设。
     写机器级与删值都要运行期确认一次，没人在场按 `Run.NotConfirmed` 失败。读不到值不是失败，
     交回空串——「没有」也是一个答案。
  5. **环境变量写入**：`system.setEnvironment`，写用户级或机器级，写完广播 `WM_SETTINGCHANGE`，交回
     写后读到的内容。机器级要确认；已经在运行的程序读不到新值，手册里写明。广播失败不算这一步失败：
     变量已经落盘，新开的进程照样读得到。
- **注册表的块只给两块**：系统族其余动作每格只问一件事，或两件互斥的事，套块头等于给一行字加标题。
  注册表的写是唯一真有两件事的（写去哪儿、写什么），所以「在哪儿」与「放什么进去」各一块。

## 对比过的同类软件

动手前查了大漠与按键精灵的参数，结论如下。

| | 大漠 `FindPic` | 按键 `FindPic` | 按键 OpenCV `FindImgBest` | 我们 `vision.findImage` |
|---|---|---|---|---|
| 区域 | `x1,y1,x2,y2`（左上 + 右下） | 同左 | 同左 | `left,top,width,height`（矩形记录） |
| 多图 | `a.bmp\|b.bmp\|c.bmp` | 同左 | `a\|b\|c` | `images` 行 + `imageSet`（第一张 / 最像 / 每张） |
| 相似度 | `sim` 0.1–1.0 | `similar` 0.5–1 | `sim` 0–1 | `confidence` 0–100（百分比） |
| 偏色 | `delta_color` 每通道两位十六进制，两位 = 灰度 | 同左 | 无 | `ignoreColor` + 颜色容差（OCR 侧有 `colorTolerance`） |
| 方向 | `dir` 0–8（含中心往外、竖优先） | `方向` | 无 | `orderBy`（四向 + 面积/分数/随机，按动作给） |
| 多尺度 | 无 | 无 | `minScale/maxScale/stepCount` | 无 |
| 透明图 | 四角同色当透明色 | 同左，另支持 PNG 透明点 | 无 | 未见 |

三条取舍：

- **区域保留 `left,top,width,height`**。大漠的「左上 + 右下」在脚本里要换算成宽高，而我们的矩形记录本来就是这四个字段，返回值里也是同一组，不必为了对齐而改。
- **相似度用百分比**（`confidence` 90）而不是 0.9：和颜色族的「容差 %」同一种读法，界面里也不用解释小数。
- **不照搬 `dir` 0–8**：中心往外和竖优先在颜色族试过又删掉了，留四向 + 面积/分数/随机，按动作给可用的那几种。

对比下来，找图的参数并不缺，缺的是**一眼看懂的分块**（本批补上）。透明色后来也补了：`ignoreColor` 改名为
「透明色」并配一格容差，掩掉参考图里那块纯色底（见「本轮落地」）。多尺度查找不做，理由写在「明确不补」里。

## 对比过的元素族软件

元素族（`uia.*` 12 个、`browser.*` 20 个）动手前对的不是大漠，是这几家做同一件事的东西：

| | UiPath（桌面元素） | Playwright / Selenium（网页） | 我们 |
|---|---|---|---|
| 目标 | 一个选取器 + **最多 3 个锚点** | locator：css / xpath / text / role | `uiaSelector` 文本；网页是 `pageSelector` 多行（逐行退让） |
| 属性匹配 | 精确 / **通配符 `*` `?`** / 正则 / 模糊，逐属性选 | 文本可用正则或子串 | 精确（不分大小写）；**本轮加了通配符 `*` `?`** |
| 额外条件 | 锚点做"旁边那个元素" | `hasText`、`:visible`、过滤器链 | `narrow` 行：还要像什么样，逐行同时成立 |
| 第几个 | 选取器可带 index | `.nth()` / strict mode | `matchIndex` |
| 等它出现 | `WaitForElement`（元素族内） | auto-wait + `waitFor` | `uia.waitElement` / `browser.waitFor`（状态选择） |
| 找不到怎么办 | 由 Try/Catch 与超时决定 | 超时抛错 | 由「执行与容错」的失败策略决定 |
| 视觉兜底 | Computer Vision / 图像选取器 | 截图比对（外挂） | 视觉族（`findImage`）另做，两者不混 |

三条取舍：

- **补了通配符，没补正则与逐属性模糊**。UiPath 那三项里，通配符覆盖了绝大多数实际场景（"保存 (2)"、
  "未命名 - 记事本"），而且不新增字段：写在值里就行（`Button[name='保存*']`）。逐属性选匹配方式要在
  选择器里长出一层结构，编辑器与包格式都要动，收益不如把 `narrow` 那一套搬到 UIA 上——记在后续项里。
- **锚点没做**：`narrow` 的行已经能说"还要满足什么"，缺的是"相对某个元素的位置"。真要做，得先有元素
  拾取器，否则写不出来。
- **网页那边的参数已经够用**：多行选择器退让、`narrow` 过滤、`force`、按状态等待，对照 Playwright 只差
  严格的 strict 模式（多个命中直接报错），而我们有 `matchIndex`，默认取第一个，比报错更适合宏。

**结论**：元素族不缺参数，缺的是**同一种读法**。所以这一批只做分块，另外补上通配符（引擎 + 提示文案）。

## 对比过的文件与数据动作

数据 8 个、文件 20 个、剪贴板 10 个。这一批对的是 AutoHotkey v2、系统自带的命令行外壳、Python 与 UiPath：

| | AHK v2 | 命令行外壳 / Python | UiPath | 我们（改前） |
|---|---|---|---|---|
| 编码 | `FileEncoding`（可指定） | `-Encoding` / `encoding=` | 读写文本都有 | 读、写文本有；**追加日志没有** |
| 追加 | `FileAppend` | `-Append` / `mode='a'` | Append Line | `writeMode=append`、`appendLog` |
| 换行 | 自己写 `` `n `` | `newline=` | 自带 | `newline`（none/end/start） |
| 列文件夹 | `Loop Files, Dir, D` | `Get-ChildItem -Directory` | For Each Folder | **只能列文件** |

| 筛选 | 模式 | `-Filter`、`Where-Object` | Filter | 模式、大小窗、时间窗 |

发现两处真的缺：

- **追加日志不能选编码**：引擎早就按 `encoding` 读了（`EncodingOf`），只是目录里没声明这一项，界面就没有。
  GBK 的日志文件追加 UTF-8 字节会变成乱码。已补上编码字段（四个选项与写文本一致）。
- **列文件夹列不出来**：`file.listFiles` 只收文件，宏没法知道"这个目录下有哪些子文件夹"。上面几家的
  文件列举都能选目录。已补 `kind`（文件 / 文件夹 / 两样都要，默认文件），`IFileSystem.List` 多一个
  `ListKind`，递归时文件夹也按同名规则筛。

其余参数是够的：编码四种、写模式、换行、CSV 的一整套（分隔符、引号、对齐、空单元格）、读 CSV 的列与行
筛选、列文件的排序与时间/大小窗口，对照上表都不缺。zip 里是否带顶层文件夹也补了：一个「带上这一层
文件夹」开关，默认不带上，与从前一致。

**顺带修掉一个会要命的错**：上一批把 `control.setVariable` / `incrementGlobal` / 五个 `list*` 从
`Control` 改到 `Data`，动作库分栏对了，但引擎按分类分派——`DispatchData` 里没有这些 case，运行到它们
会报 `Run.Unsupported`。现在 `DispatchData` 开头把 `control.*` 交回 `DispatchControl`：分类只管分栏，
不决定哪段代码回答它。

## 对比过的脚本与系统动作

脚本 6 个、系统 9 个（本轮变成 10 个）。这一批对的是 Power Automate Desktop、AutoHotkey v2 与
Keyboard Maestro：

| | Power Automate Desktop | AutoHotkey v2 | 我们（改前） |
|---|---|---|---|
| 跑脚本 | Run PowerShell / Python / VBScript / JavaScript / .NET / DOS | `Run` | `script.run`（cmd/bat/ps1/ahk/自有解释器）加 python、C#、AHK 三个专用动作 |
| 装依赖 | 无（自己调 pip） | 无 | `script.pip`、`script.nuget` |
| 交回结果 | 输出到变量 | 输出、`ExitApp` 的代码 | 输出、错误、成功与否，**没有退出码** |
| 系统声音 | Play sound：系统声**或 wav 文件** | `SoundPlay`、`SoundBeep` | 只有五声系统提示音 |
| 显示桌面 | Show desktop：最小化 / 还原全部 | `WinMinimizeAll`、`WinMinimizeAllUndo` | **没有** |
| 机器事实 | 屏幕分辨率、默认打印机 | `A_TimeIdle`、`A_IsAdmin`、`DriveSpaceFree` | 22 项，用户名到开机秒数 |
| 环境变量 | Get / Set / Delete | `EnvGet`、`EnvSet` | 只读 |
| 注册表 | Open / Read / Write / Create / Delete 六个动作 | `RegRead`、`RegWrite`、`RegDelete` | 无 |

**补了四处真的缺的：**

- **脚本交回退出码**：`command.run` 早就有 `exitCode`，脚本一族只给「成功与否」。引擎本来就算着这个数
  （`ScriptResult.ExitCode`），只是没交出去。脚本用不同代码说不同意思是常事（3 可以是「今天没有要做的
  事」），失败规则放行之后没法分支，等于把这层意思丢了。五个脚本动作都补上。
- **提示音能放自己的文件**：系统那五声说不出一句「你的活儿好了」。PAD 与 AHK 都能放 wav，我们只能五选一。
  补 `soundSource`（系统提示音 / wav 文件）与 `soundFile`（路径，按与别处相同的规则解析相对路径）。
  Windows 自己只放得了 wav，这一点写在提示里。
- **显示桌面**：`system.showDesktop`，收起来或者放回来，就是任务栏最右端那个按钮的两半。实现落在已有的
  窗口设备上（列窗口，逐个最小化 / 还原），不新增系统调用，也因此在测试里跑得起来。
- **五个机器事实**：`idleSeconds`（键盘鼠标多久没动，对应 `A_TimeIdle`）、`isElevated`（是不是拿着管理员
  权限，对应 `A_IsAdmin`）、`freeRamMb`、`totalRamMb`、`freeDiskMb`。前两个是宏最常问的两件事：人走了
  没有，以及我能不能写这里。

**后补的两项，前提照原样落地：**

- **注册表读写**：三个动作（读、写、删）。前提是路径校验与「默认只碰 HKCU」，现在都做到了：根只给
  当前用户与这台机器，带根名、带 `..`、两端带反斜杠的路径一律拒绝；写机器级要运行期确认一次。
- **环境变量写入**：`system.setEnvironment` 写用户级或机器级，写完广播 `WM_SETTINGCHANGE`；机器级要确认，
  没有权限时失败里说清是哪个变量、写给谁。已经开始运行的程序读不到新值，手册里写明。

屏幕分辨率与默认打印机不做：前者改的是整台机器的显示方式，后者要配合「打印一份文档」才自洽。

### 已核对、确实不缺的（别再当成缺口提）

| 项 | 在哪儿 | 现状 |
|---|---|---|
| 每步超时 | 执行与容错「最多花多久 · 超时」 | `StepTimeoutMs`，单位毫秒，0 表示不限；从第一次尝试起算，所有尝试共用，包含重试之间的等待；块上的超时覆盖整段。**每个动作都有**，不是缺项 |
| 重试与失败策略 | 同一页 | 重试次数、间隔、间隔怎么变（固定 / 线性 / 指数）、失败四选一（停止 / 继续 / 下一轮 / 问我） |

| 列文件夹 | `file.listFiles.kind` | 文件 / 文件夹 / 两样都要 |
| 脚本交回结果 | `script.*` 五个动作 | 输出、错误、退出码都有 |
| 提示音放自己的文件 | `system.sound` | `soundSource` + `soundFile`（仅 wav，系统如此） |
| 显示桌面 | `system.showDesktop` | 收起来 / 放回来 |
| 机器事实 | `system.info` | 27 项，含空闲秒数、是否管理员、空闲内存 |
| 剪贴板等待的轮询 | `clipboard.waitChange` | 30ms 固定轮询，等多久由步骤超时兜住。**不给间隔参数**：多一格只是一个没人会去改的旋钮，而这一格会让「等待变化」看起来比它实际的复杂度高 |

### 明确不补的（理由写在这里，免得反复提）

- **多尺度模板匹配**：分辨率变了就换参考图，不做自动多尺度（`roadmap.md` 的非目标）。
- **`dir` 0–8 那套方向**：中心往外、竖优先在颜色族试过又删了，留四向 + 面积 / 分数 / 随机。
- **网页 strict 模式**：多个命中直接报错不适合宏；有 `matchIndex`，默认取第一个。
- **PNG 的 alpha 与四角同色**：透明色只认「指定的一个颜色 + 容差」。表单里有吸管，取一次底色就是
  同一件事；按 alpha 要把参考图的解码从 `ImreadModes.Color` 改掉，那会动到所有参考图。
- **多锚点**：UiPath 给三个，我们给一个。「在『确定』右边」一个就够了，两个锚点的表单与查询结构
  要再长一层，等真有说不清的地方再加。
- **注册表的其它根**：只给当前用户与这台机器。HKCR、HKU 那几处改的是「每个程序都照它办」，
  不是宏该随便碰的地方。
- **条件里直接问窗口与进程**：要么先加一步（`window.exists` / `process.exists`）再比它写出来的变量，
  要么给表达式开"宿主函数"的口子。后者的代价是 Core 的表达式表要接设备、录制与 MCP 都要跟着变，而
  `while` / `等待直到` 是 30 毫秒一轮的，每轮去跨进程查一次窗口足以拖死程序。这一批只给左值：
  `$sys.activeWindow`、`$sys.activeProcess` 随时可读，配文本族的比较词就够写"当前窗口标题包含记事本"。
- **屏幕分辨率与默认打印机**：前者改整台机器的显示方式，后者要配合“打印一份文档”才自洽。

## 各族的块顺序

分块不是随手加的：每一族都按「一个人问这件事的顺序」排。加新动作时照这张表走，不要另起一套。

| 族 | 从哪问到哪 |
|---|---|
| 视觉 / 识别 | 范围 → 找什么 → 按内容挑 → 怎样算成功 → 怎么点 → 识别调参 |
| 输入（键鼠、手柄） | 发给谁 → 按什么 / 点哪儿 → 怎么点 → 节奏 |
| 界面 / 浏览器 | 在哪个窗口 → 找哪个元素 → 元素限定 → 改成什么样 / 读哪一部分 → 第几个 |
| 数据 / 文件 / 剪贴板 | 哪个变量 → 从哪儿读 → 存到哪儿 → 挑哪些 → 怎么读 / 怎么写 → 怎么排 |
| 脚本 | 跑什么 → 交给谁跑 → 传什么给它 |
| 窗口 / 程序 | 哪个窗口 → 挪到哪儿 / 等它 → 交给它什么 |
| 流程 | 问什么（条件）/ 比什么（值 + 比对方式）/ 跑几轮 → 每轮叫什么 → 节奏 → 各分支跑什么 |

只有一件事要问的动作不分块：一个块头加在一格上，只是多一行字。

- [x] **幽灵槽接拖拽**：拖到幽灵槽就是追加进参数表（`concat($a) join($b)` 把后一个拖上去得
      `concat($a, join($b))`）；拖到两块之间的空隙则是追加到这一段末尾。手动加空参数的圆形 `＋` 已去掉，
      幽灵槽够用。
- [x] **`list` 这类枚举函数的按行排版**：实参超过 3 个或一行估算超过紧凑宽度时自动一行一个参数，
      前面写参数名、第几个、必填还是可选，可选参数另起一行缩进，左侧 1px 细线标层级；短公式仍排一行。
      **参数里套着别的函数不再单独触发展开**，收尾的 `)` 与幽灵槽同排，块内间距一并压缩。实机发现
      递归展开会把结构带撑到 540 像素，改成一次只展开一层，嵌套调用保持紧凑。
- [x] **参数语义与就地纠错**：参数名、序号、必填可选取自引擎同一张函数表；读不通时把未知函数与参数
      个数错误标到对应调用块、缺必填参数标到虚框上，红边是覆盖层不撑动布局；确认变灰时在按钮旁写明原因。
- [x] **常驻插入光标**：结构带里一根 2px 强调色竖线，硬闪；点块左/右半边与接缝定位，三盘材料、
      函数卡与常驻小输入框都写到它那里。光标用字符偏移表示，文本重建后按新长度夹取，函数卡插完把光标
      留在括号内；拖拽时让位给落点线，松手后恢复。`StartCaret` 从调用方的 `TextBox.CaretIndex` 接线。
- [x] **叉改真按钮**：删除叉原来画在不可点的覆盖层里、由带子按矩形判定，叉探到块顶之外的那 14 像素
      在首行落进滚动区的内边距，看得见的叉点不中，点得中的是下方压在块顶的薄条。现在它是覆盖层里的
      一枚按钮，画在哪儿就点得到哪儿，悬停变红也才真的生效；`_removeRect` 与「按下在叉上」的状态一并
      删掉，指针从块移到叉上靠几何而不是 `IsPointerOver` 分辨，免得叉在靠近时闪一下。光标同时加宽到
      2px 并硬闪，两根线靠闪不闪分开。
- [x] **结构过大与布局**：结构带与三盘之间加一条可拖的横向 `GridSplitter`，去掉 280 上限；撤销恢复
      移到表头最左；逐行触发收紧、块与容器内间距压缩，`get(list(1, 2), 2)` 不再撑成一块大面板。

## 每一批都要过的检查

- 一页里不超过 3 块；每块第一行是问题，不是标签。
- 能用拾取器的不要求手打数字。
- 有结果的动作，结果表里每一项都能在结构列看懂它是什么。
- 会让机器或数据不可逆的动作（删除、覆盖、关机、发键）有确认或有可撤销的路径。
- 文案：不许出现破折号；同一个概念在字段、提示、手册里用同一个词。
- 名字：两个动作不许同名；`uia.*` 与 `browser.*` 的名字各自说清在哪一族（界面 / 网页），
  看不出族的名字（「勾选」「填写」「悬停」）就是没写完。
