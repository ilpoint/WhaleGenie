# 界面优化路线图

这份路线图回答一个具体问题：动作库里的 171 个动作，哪些已经按新样板改过，哪些还停在旧版式，
下一步按什么顺序改、每一类改什么。样板由比色族（找色 / 多点找色 / 点击颜色 / 比色）与
「基础设置 / 执行与容错」两页定下，后面所有动作都往同一套上靠。

## 已经定下来的样板

- **分块**：一页里的字段按问题分组，每组一行**图标 + 标题**（`Group` + 块图标）。同块字段必须相邻，
  目录加载时校验。块图标由 `AppIcons.Block(组名)` 给：范围是裁切框、找什么是放大镜、怎样算找到是
  对勾、怎么点是鼠标、节奏是秒表、调参是滑杆；新加的组没有图标时退回显示序号。
- **必填与默认**：必填项一打开就有可用值；空值只表示"没说过"，不表示 0。
- **拾取器**：能点的东西都给一个拾取按钮（坐标、区域、颜色、窗口、元素、文件），拾取窗口带放大镜。
- **行表**：一行一条的列表用统一的行表（表头 + 分隔线 + 定宽列），不把几段文字堆在一起。
- **结果**：返回值排成「留下 / 结果 / 结构 / 变量名」四列表，结构列给出示例，悬停给全字段。
- **失败**：执行与容错页统一问超时、前后延迟、重试、失败策略；危险动作额外确认。

## 本轮落地

- **每格的读法改由图标说**：`ƒ` / `$` 两个自造字形换成 Lucide 的 `SquareFunction` 与 `Variable`
  （13px，`TextSecondary`）；「此字段可填写表达式」「此字段按文本读取」两句从框下面的提示里整段去掉，
  由这两个标记的悬停承担。一页十来个字段时，同一句话不再复述十来遍，`Hints()` 只剩这一格自己的话。
- **块头由序号改图标**：`ParameterRowViewModel.GroupIcon` / `HasGroupIcon`，图标 14px；`Border.BlockNumber`
  去掉圆圈边框（图标自身有轮廓，再套一圈是两道边），没有图标的块仍显示序号。
- **空草稿不再变成"发现上次未保存的内容"**：`RecoveryEditor.IsWorthKeeping`（有步骤、有描述、有绑定键，
  或名字已经不是 `MacroNames.IsDefault` 那种"宏 N"）才写进快照；`RecoveryContents.IsEmpty` 用同一个判断，
  `Load()` 读到空快照顺手删掉。新建一个宏就关程序，下次启动不再问一句答了也回不到东西的问句。
- **变量与列表动作归入「数据与变量」**：`control.setVariable`、`control.incrementGlobal`、
  `control.listAdd/Insert/RemoveAt/Set/Clear` 从 `Control` 移到 `Data`。它们不决定下一步去哪，
  不该和分支、循环混在一栏；现在它们出现在「基础动作」的「数据与变量」组里，与编码、摘要同组。
- **「设置变量」保留原名**：它在语义上是赋值（Assign），不是"运算"；算式只是值的一种写法，
  已写进描述。行业里同一种动作叫 Set variable / Assign，改成「变量运算」反而让人以为它专门做计算。
- **动作卡片双击插入**：动作库卡片支持双击，等价于拖到当前落点；拖动要求真实拖放会话，
  键盘与自动化做不来。`ActionPaletteView.CardActivated` → `MacroEditorWindow.OnCardActivated`，
  复用同一个动作表单与 `AddStepHere` 的落点规则；`_actionEditorOpen` 防止双击叠出两个模态窗。
- **变量中心两个按钮**：`局部变量`（新窗口：看来源、类型、谁在读，可改名）与 `全局变量`
  （原有管理窗）。局部变量由步骤写出来，所以那一窗不提供"新建/删除"，只做改名与查看。

## 对比过的同类软件

动手前查了大漠与按键精灵的参数，结论如下。

| | 大漠 `FindPic` | 按键 `FindPic` | 按键 OpenCV `FindImgBest` | 我们 `vision.findImage` |
|---|---|---|---|---|
| 区域 | `x1,y1,x2,y2`（左上 + 右下） | 同左 | 同左 | `left,top,width,height`（矩形记录） |
| 多图 | `a.bmp\|b.bmp\|c.bmp` | 同左 | `a\|b\|c` | `images` 行 + `imageSet`（第一张 / 最像 / 每张） |
| 相似度 | `sim` 0.1–1.0 | `similar` 0.5–1 | `sim` 0–1 | `confidence` 0–100（百分比） |
| 偏色 | `delta_color` 每通道两位十六进制，两位 = 灰度 | 同左 | 无 | `ignoreColor` + 颜色容差（OCR 侧有 `colorTolerance`） |
| 方向 | `dir` 0–8（含中心往外、竖优先） | `方向` | 无 | `orderBy`（四向 + 面积/分数/随机，按动作给） |
| 多尺度 | 无 | 无 | `minScale/maxScale/stepCount` | 无 |
| 透明图 | 四角同色当透明色 | 同左，另支持 PNG 透明点 | 无 | 未见 |

三条取舍：

- **区域保留 `left,top,width,height`**。大漠的「左上 + 右下」在脚本里要换算成宽高，而我们的矩形记录本来就是这四个字段，返回值里也是同一组，不必为了对齐而改。
- **相似度用百分比**（`confidence` 90）而不是 0.9：和颜色族的「容差 %」同一种读法，界面里也不用解释小数。
- **不照搬 `dir` 0–8**：中心往外和竖优先在颜色族试过又删掉了，留四向 + 面积/分数/随机，按动作给可用的那几种。

对比下来，找图的参数并不缺，缺的是**一眼看懂的分块**（本批补上）。多尺度查找与透明图是真正的差距，记在下面的后续项里，不在这一批动。

## 对比过的元素族软件

元素族（`uia.*` 12 个、`browser.*` 20 个）动手前对的不是大漠，是这几家做同一件事的东西：

| | UiPath（桌面元素） | Playwright / Selenium（网页） | 我们 |
|---|---|---|---|
| 目标 | 一个选取器 + **最多 3 个锚点** | locator：css / xpath / text / role | `uiaSelector` 文本；网页是 `pageSelector` 多行（逐行退让） |
| 属性匹配 | 精确 / **通配符 `*` `?`** / 正则 / 模糊，逐属性选 | 文本可用正则或子串 | 精确（不分大小写）；**本轮加了通配符 `*` `?`** |
| 额外条件 | 锚点做"旁边那个元素" | `hasText`、`:visible`、过滤器链 | `narrow` 行：还要像什么样，逐行同时成立 |
| 第几个 | 选取器可带 index | `.nth()` / strict mode | `matchIndex` |
| 等它出现 | `WaitForElement`（元素族内） | auto-wait + `waitFor` | `uia.waitElement` / `browser.waitFor`（状态选择） |
| 找不到怎么办 | 由 Try/Catch 与超时决定 | 超时抛错 | 由「执行与容错」的失败策略决定 |
| 视觉兜底 | Computer Vision / 图像选取器 | 截图比对（外挂） | 视觉族（`findImage`）另做，两者不混 |

三条取舍：

- **补了通配符，没补正则与逐属性模糊**。UiPath 那三项里，通配符覆盖了绝大多数实际场景（"保存 (2)"、
  "未命名 - 记事本"），而且不新增字段：写在值里就行（`Button[name='保存*']`）。逐属性选匹配方式要在
  选择器里长出一层结构，编辑器与包格式都要动，收益不如把 `narrow` 那一套搬到 UIA 上——记在后续项里。
- **锚点没做**：`narrow` 的行已经能说"还要满足什么"，缺的是"相对某个元素的位置"。真要做，得先有元素
  拾取器，否则写不出来。
- **网页那边的参数已经够用**：多行选择器退让、`narrow` 过滤、`force`、按状态等待，对照 Playwright 只差
  严格的 strict 模式（多个命中直接报错），而我们有 `matchIndex`，默认取第一个，比报错更适合宏。

**结论**：元素族不缺参数，缺的是**同一种读法**。所以这一批只做分块，另外补上通配符（引擎 + 提示文案）。

## 分批

0. **视觉族三个样板已分块**（本轮）：`vision.findImage` / `ocr.findText` / `uia.find` 加了
   `Group` 并按块重排：`area`（在哪个范围里找）→ `target`（找什么）→ 找图另有 `found`（怎样算找到）→
   `tuning`（识别调参），OCR 中间多一块 `content`（按内容挑）。块标题新增 `Add.Group.target` /
   `Add.Group.content`。另外 `findImage` 的 `orderBy` 与 `matchIndex` 归入 `found`，`frameMaxAgeMs` /
   `intervalMs` 归入 `tuning`，与颜色族同一套读法。

1. **视觉族收口已完成**（本轮）：15 个 `vision.*` 与 3 个 `ocr.*` 全部按块重排，
   读法统一成「范围 → 找什么 → 怎么点 → 怎样算成功 → 识别调参」：

   | 动作 | 块 |
   |---|---|
   | `findColor` / `findColors` / `clickColor` | 范围 · 什么颜色 · 怎样算找到 · 怎么点 · 识别调参 |
   | `findImage` / `waitImage` / `clickImage` | 范围 · 找什么 · 怎样算找到 · 怎么点 · 识别调参 |
   | `detect` / `waitDetect` / `clickDetect` | 范围 · 找什么 · 怎样算找到 · 怎么点 · 识别调参 |
   | `findText` / `clickText` | 范围 · 找什么 · 按内容挑 · 怎样算找到 · 怎么点 · 识别调参 |
   | `capture` | 抓哪儿 · 存到哪个文件 · 识别调参 |
   | `captureWindow` | 抓哪儿 · 存到哪个文件 · 识别调参 |
   | `waitStable` | 范围 · 怎样算稳定 · 识别调参 |
   | `recognize` | 范围 · 识别什么 · 识别前处理 · 识别调参 |
   | `getPixel` / `waitColor` / `matchColor` | 看哪一个点 · 什么颜色 · 识别调参 |

   颜色族的 `orderBy` / `matchIndex` 从「识别调参」移到「怎样算找到」：它们决定的是"挑哪一个"，
   不是识别参数。新块标题 `Add.Group.capture` / `save` / `stable` / `read` / `before`（中英各一），
   并加了一条测试 `Every_block_a_field_stands_in_is_named_in_both_languages`：目录里出现的每个块
   都必须在两张文案表里有名字，漏一条就报。

   **还没做**：`capture` / `recognize` 的四个数字仍是 2×2（区域行已经是一行四格），要统一得让
   四个连续的数字字段也能落到一行里。
1b. **输入与窗口已分块**（本轮）：`input.*` 16 个、`gamepad.*` 3 个、`process.*` 2 个与 `window.move`
   按「发给谁 → 按什么 / 点哪儿 → 怎么点 → 节奏」重排；新块 `sender / keys / where / pacing / wheel /
   from / to / axis / program / options / place`。单问一件事的动作（`window.activate`、`process.info`、
   `gamepad.trigger` 这类）不分块：一块只有一个字段时，块头只是多出来的一行。
2. **输入与窗口**：`input.*`、`window.*`、`process.*` 共 38 个动作，共用"目标窗口 + 坐标/按键 + 节奏"。
   这一步同时把窗口选择器收敛成一个控件。
2b. **元素族已分块**（本轮）：`uia.*` 12 个与 `browser.*` 20 个按「在哪个窗口 → 找哪个元素 →
还得像什么 → 改成什么样 / 读哪一部分 → 第几个 → 取多少」重排；新块 `entry / state / taking /
narrowing / limit / address / tab`，图标补齐。只问一件事的动作（`uia.focusWindow`、`browser.goTo`、
`waitForLoad`、`evaluate`）不分块。
   同时给 `uiaSelector` 加了通配符：`Button[name='保存*']` 是名字以「保存」开头的按钮，`?` 是一个字符；
   不带通配符的选择器仍然按原来的精确比较，老宏不受影响（`TextCompare.Wildcard`、`UiQuery.Answers`）。
3. **元素族**：`uia.*` 与 `browser.*` 共 37 个，共用"元素（选择器 / 拾取）+ 动作 + 等待"。
4. **数据与文件**：`data.*`、`file.*`、`clipboard.*` 共 39 个，共用"来源 → 处理 → 落到哪"。
5. **脚本与系统**：`script.*`、`system.*` 共 15 个，代码框与危险确认。
6. **流程**：`control.*` 24 个，条件行表与 `try` 的失败策略。

## 每一批都要过的检查

- 一页里不超过 3 块；每块第一行是问题，不是标签。
- 能用拾取器的不要求手打数字。
- 有结果的动作，结果表里每一项都能在结构列看懂它是什么。
- 会让机器或数据不可逆的动作（删除、覆盖、关机、发键）有确认或有可撤销的路径。
- 文案：不许出现破折号；同一个概念在字段、提示、手册里用同一个词。
