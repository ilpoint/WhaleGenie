# 步骤列表与流程条件

两件事放在一份里，因为它们改的是同一块地方：列表一行装不下的是「条件」，而条件现在只能写成一格
表达式。先定列表的读法，条件才知道要长成什么样。

实现过程、走过的岔路与每次回退的细节以 git 为准，本文只留现在这个样子和不能随便改的原因。

## 一、步骤列表：一行一步，详情另说

### 为什么一行只有一步

早先一步占一张卡片，卡片上叠着四段字：名称与三枚徽标、说明（`Detail`）、备注、执行节奏
（`MetaSummary`）。行高下限 42，说明或备注一折就 70 以上；一屏二十来步里只看得见七八步。四段话
同字号同颜色，扫读时找不到「这一步在干什么」。流程块还额外多出「子步骤标题」「空列表提示」
「块收尾」三种行，块一多，列表里一半是脚手架而不是步骤。

### 一行长什么样

```
┌────────────────────────────────────────────────────────────┐
│ ▸ 🔗 点击界面元素  click1  后台    未命名 - 记事本 · Button…  │  30px
│ ▾ 🔁 重复 10 次                                        3 步  │
│     🔗 延迟   delay1             control.delay · 等待 1000 毫秒 │
│     ┌────────────────────────────────────────────────────┐ │
│     │ control.delay · 等待时长 = 1000 毫秒                 │ │  点中的这一行
│     │ 备注：等界面稳定后再点保存                            │ │  在原处展开
│     │ 失败后询问                                          │ │
│     └────────────────────────────────────────────────────┘ │
│     🔗 按键   key2               Ctrl+S                       │
└────────────────────────────────────────────────────────────┘
```

1. **一行 30px**：折叠箭头、图标、名称、徽标（id / 跳过 / 输入方式），然后一句摘要，最后是问题
   标记。名称与摘要在窄列里都截断，完整的话在展开之后与悬停里。
2. **点中的那一行在原处展开**：完整说明、备注、执行节奏接在它下面，别的行仍是一行——视线不离开
   那一行，列表也不跳。点另一行就换过去；多选时一个都不展开，免得让人以为只选中了一条。
3. **双击打开编辑**保持不动；右键菜单、多选、拖放落点也都不动。
4. **块的步数**：单列表的块写在块行右侧，多列表的块按节各写各的（写在体行上），折叠起来也看得见
   里面有几歩；不把「那么 2 步 + 否则 1 步」加成「3 步」。
5. **缩进与树线**：每层 26px、虚线、`TreeGuide`（深色 40% 白）。层级靠线读，不靠留白猜。

### 为什么是 TreeView

层级本来就在数据里，让控件去画它，比让每一行自己算缩进稳。四件原先要自己重做的事因此落在控件上：

- **拖放落点**算「哪个列表，第几位」：块行与体行整行都是「放进这一块、排在最末」（展开、折叠
  一样），普通步骤分上下半「之前 / 之后」，树上面的空白是宏开头、下面的空白是宏末尾。没有收尾行，
  也没有「上三分之一进块」这类分区。
- **多选**走树的 `SelectedItems` + 节点上的 `IsPicked`；编辑器仍然只认步骤，分节与收尾行选中时
  归到块本身。
- **块的标题与收尾**：每个块都有一行「体」（`循环体 / 满足时 / 否则`），它说清「从这一行往下都
  属于这个块」，也是拖进去的落点；块自己的行只写动作与参数。**收尾行取消**，块的结束由缩进线断在
  哪儿表示。
- **折叠状态**：节点自带 `IsExpanded`，绑在步骤自己的 `IsExpanded` 上；折叠只是「不画子节点」，
  **不再重建任何东西**。

`NavigationView` 不用：它是应用级左栏（菜单、页面切换），拿它装步骤等于把「页面」和「步骤」塞进
一个控件，选中、返回栈、面包屑都用不上。

### 行的形状

- 行是**平**的，不是一摞卡片：层级的读法交给树线。
- 层级还有第二条线索：块行字重更重、字号大一档；体行用浅底、小字，读起来是「这个块的目录」。
- 选中由行自己画（`.selected`），树自己那层底与行首的小竖条都让开，避免两套高亮叠在一起。
- 行上**没有按钮**：进块的唯一入口是「把动作拖到块的那一行」或「选中块再新建一步」，不再有加号，
  也没有「拖入子步骤」这类重复入口。
- **双击只认行本身**：双击左侧引导线所在的空白、或双击折叠方块，都不打开步骤编辑——方块有它自己
  的活要干（折叠），空白是行悬挂的空间而不是行。
- **行必须撑满行高**（`PART_HeaderPresenter` 的 `VerticalAlignment=Stretch`）：行有 30 的下限，
  文字只有 20 高时居中放，上下各留 5 像素；不撑满，线走到那儿就断一截。
- **横向滚动关掉了**（`HorizontalScrollBarVisibility=Disabled`）。开着的时候，一行里那句参数摘要
  会把列表的内容宽度撑过视口，树就横向滚起来——缩进、箭头、竖线全被推到左边看不见，屏幕上只剩
  一列左对齐的字。这是「每层看不出缩进」的真正原因，不是缩进值太小。

### 树线

- 线是**画**出来的（`GuideLinesView`）：一格一格的矩形拼不出跨行的虚线，每段各自从头数节奏，
  接起来就是毛边。
- **一根线属于它下面那一层的节点**：第 N 列的线由深度 N+1 的节点掌管，所以它一直画到那个节点的
  最后一个直接子节点为止。把「第 N 列要不要继续」数错一层，就是整列提前一行收尾
  （`StepGuideTests` 按列逐段校验）。
- **最外层也有干线**：第一级的行从最左边一条竖线上接出来（每条都有一根横枝）。没有它，第一级
  看起来只是一列文字。
- **只有「自己跑步骤」的那一行有折叠方块**：`循环体步骤` 是块的一部分，它上面不再放第二枚方块；
  块那一行的方块同时管整块的开合。
- **块折叠时，从方块垂下去的那一截线也要收掉**：折叠不重建行，所以下垂线要在 `IsExpanded` 变化时
  重算，否则会在合上的方块下面留一小截。
- **线不能画到自己那一列上**：一行只画它上面各层的列，加上自己下垂的那一截；越界就是伸到别的
  分支里去了。
- **空列表也要下垂线**：`尝试/捕获/收尾` 的三个列表刚加时都是空的，但每一个都有「尝试步骤 0 个
  步骤」这一行挂着；按「有步数」判断，列会晚一行才开始。
- **虚线 6 划 2 隔、2px 粗**：划与隔一样长时，三十像素一行只剩两三段，读起来是「断线」。
- 每段的虚线**按它在树里的位置错相位**：按绝对纵坐标取模，一列才是一条线；各段自行从 y=0 起算，
  行与行的接缝上会正好断在空隙里。
- 拐进一行的**横枝是实线**，且从竖线中心起笔：拐角是虚线与虚线相遇的地方，两条都带节奏就必然在
  某个相位上断开，而「断在拐角」正是最像 bug 的断法。
- **缩进步长 26**（主题默认 16）：16 的时候三层连着看还是一列。这个数写在 `StepRow.IndentWidth`，
  树模板（`StepIndentConverter`）与树线都从它算，改一处是一处。
- **树的模板自己给**：FluentAvalonia 的 `TreeViewItem` 把「层级 × 16」写死在模板里，外面改
  `TreeViewItemIndent` 资源改不动。层级要靠线读，缩进、展开钮、选中态就得在同一个 `ControlTheme`
  里，所以 `Themes/Controls.axaml` 里有一份自己的 `TreeViewItem`。
- 树线颜色 `TreeGuide` 是 **40% 白**：20% 在暗色卡片上几乎看不见，看成「没有线」。

## 二、流程条件：行表为主，表达式兜底

### 为什么不是一格文本

「条件」原来是一格文本，旁边一个「表达式」按钮。会写的人直接写，不会写的人面对 `$found` 不知道
从哪儿下手；读的人也要在脑子里把 `&& || !` 翻译一遍才看得出这一步在等什么。顺带一个小毛病：
`control.if` 新建时预填 `$found`，而这个变量常常还不存在，表单底下立刻红字「还缺：条件」——新建
就报错，说的还是用户没做错的事。

### 为什么是行表加条件树，而不是二选一

- **纯文本**什么都能写、零成本，但不会写的人用不了，也读不出结构。
- **条件行表**（左值 / 比较 / 右值，一行一条，顶上「全部 / 任一」）一眼看懂、变量可拾取，代价是
  嵌套条件（(A 或 B) 且 C）表达不了。
- **可视化条件树**表达力最强，实现与学习成本都高，小屏放不下。

落地取的是行表与条件树**同时保留、顶上切换**：两者看的是同一份模型（嵌套的分组 + 一行一条比较），
切换视图只是换模板，不是格式转换。行表适合「甲且乙且丙」这种平铺的、可以像填表一样一条条录入的；
树适合「甲且（乙或丙）」这种嵌套。行表读到一个嵌套时不禁用，只在旁边写一句「这条条件有嵌套，
按条件树编辑」。

```
条件                                    [全部成立 ▾]
┌──────────────┬────────────┬──────────────────────┐
│ $found       │ 等于 ▾     │ true                 │
│ $count       │ 大于 ▾     │ 3                    │
│ 窗口标题      │ 包含 ▾     │ 记事本                │
└──────────────┴────────────┴──────────────────────┘
+ 添加条件                                        [用表达式写]
```

- **左值**：变量或表达式（`$名字`、`ƒ` 打开取值窗口、也可以直接写字面量）。
- **比较**：按左值的类型给——数字不给「包含」，文字不给「大于」（除非写成数字表达式）。
- **右值**：「为空」「为真」这类不需要右值，那一格直接收起，不是留个空框让人猜。
- **顶上**：「全部成立 / 任一成立」。行表不做嵌套——真要嵌套就切条件树。
- **行末**：删除；底部「添加条件」；右下角「用表达式写」切换。

### 存储与引擎：一行都不用改

行表只负责**写**，写出来的仍是原来那一格表达式字符串（`$a > 3 && $b == "x"`）。**读**的时候尝试
拆回行：只认同一层的 `&&` / `||` 与简单比较；拆不开（有函数调用、括号嵌套）就落到表达式模式并把
原文摆出来。宏文件格式、引擎、运行时都不动；两套写法自然互转，也不会出现「行表存的格式引擎读不懂」
这种事。

### 流程族其它动作

- `control.while`、`control.waitUntil` 用**同一个条件控件**，只是下面挂的步骤与超时不同。
- `control.switch` 是「值 → 分支」的**行表**：树里一行一个分支，行首是一枚可点的值片
  （`值 1; 2`），后面跟步数，分支的步骤直接挂在下面。分支之间唯一的区别是值，值就写在行上。

  **分支是唯一没法从动作库拖进来的东西**（库里没有「分支」这张卡片），所以表尾有一行
  「＋ 添加分支」：按下就写一支空的，并**把这一支的值打开在原地**（占位「例如 1; 2; 3」），
  回车收下、Esc 还原。值片本身也能点，点开同样是这一行原地编辑——一个字段的东西不值得开整张
  动作表单，更不该要求人先猜到「双击能改」。多分支的行摘要只写「`$key` 等于」，不写两个字段名：
  分支已经摊在下面，行只需要说出这一块在比什么。

  **原地编辑不能是「降级」**：一行值仍是「写成文本、里面的 `$名字` 会被换掉」的字段，所以编辑时
  框旁有和步骤表单同一颗「变量」（`Focusable=False`，按下它不许把框关掉）：名字插在光标处，
  或在同一个取值窗口里改写成表达式。输入框在**重建行**和**取值窗口打开**时都不算「人走了」，
  否则刚按「添加分支」的那一行会在拿到焦点的瞬间自己关掉。
- `control.repeat` 的次数与间隔、`for` 的起止与步长、`forEach` 的列表与倒序现在各自成块，另有一块
  「节奏」放间隔；`while` 的条件、「什么时候停」与节奏也是三块。先前判断「一个块头加在一格上只多
  一行字」，而循环要填的从来不止一格，块头省下的是找字段的时间。
- 新建 `control.if` 时**条件留空**，占位写「例如 $found」，不再预填一个不存在的变量。

### 比较词：一张表，三处用

条件原来只有八个词，而且全是运算符：等于、不等于、大于、小于、不小于、不大于、成立、不成立。
引擎早就有 `contains` / `startsWith` / `endsWith` / `match` / `length` / `count`，`TextCompare` 还是
多分支与 `compare()` 共用的同一份语义——要补的只是**词表、写法与读回**：`Condition.ReadRow` 原来
只认运算符和 `not`，`contains($a, x)` 会被读成「左边一整串、比较词是成立」，行表也就显示不出
这类条件。现在它把函数写法读成对应的词，`length($a) == 0` 与 `count($l) == 3` 也各是一行，
左边不会变成「没人打过的一串表达式」。

现在有十六个词，分四族，每族一种写法：

| 族 | 词 | 写进宏 | 要右值 |
|---|---|---|---|
| 数字 | 等于 / 不等于 / 大于 / 小于 / 不小于 / 不大于 | `$a == 1` | 要 |
| 文本 | 包含 / 不包含 / 开头是 / 结尾是 / 匹配正则 | `contains($a, x)`、`not contains($a, x)` | 要 |
| | 为空 / 不为空 | `length($a) == 0`、`length($a) > 0` | 不要 |
| 列表 | 条目数为 | `count($list) == 3` | 要 |
| 真假 | 成立 / 不成立 | `$a`、`not $a` | 不要 |

三条取舍：

- **不单列「在列表里」**。`contains()` 本来就同时认一段文字和列表里的一项，反过来写
  （`contains($list, $a)`）读回时必然和「包含」分不清；同一个词覆盖两族，行表也就不会出现
  两行字一样、写法相反的东西。
- **为空 / 条目数为用 length / count 写**，不新增 isEmpty 之类：两个函数已经在，读回时把
  `length(x) == 0`、`count(x) == 3` 认成这两行，左边不会变成「没人打过的一串表达式」。
- **`not (a and b)` 不认成「全都不成立」**。只认 `not (a or b)`：否掉「全部成立」是另一个问题，
  硬当成「全都不成立」会读错意思；碰到 `not (a and b)` 仍是一条「不成立」的行，原文照存。

多分支的比对方式取自同一张表，取其中适用的十一种，补上了「不包含」，并把
`以…开头 / 以…结尾 / 正则匹配` 改成与条件同名的「开头是 / 结尾是 / 匹配正则」。它不给「为空」
「条目数为」：分支值本身就是右值，空值那件事由「其他情况」回答。

**一枚贴在框右端的「取值」小片**（`AutoCompleteBox.InnerRightContent`，Avalonia 12 原生就有）：
条件是一条表达式，而全站每个能写值的格子旁边都有「变量 / 表达式」这两样。按钮跟着格子走，
不必再猜它填的是哪一格；文字让出右端 48 像素（`HasChip`），小片带边、带字，不靠悬停才认得出。

### 取值窗口：五条不能推翻的取舍

窗口本身怎么用写在 [manual.md 的「取值窗口」一节](../manual.md#取值窗口)，这里只留几条设计上
不能随便推翻的决定：

- **一个窗口，三盘同页**：符号 / 变量 / 函数同时可见。页签适合浏览，不适合拼装——写一条
  `contains($a, x) and $b > 3` 要在三页之间来回切，切一次丢一次位置。「选名字」与「写公式」仍是
  同一个窗口，从只写名字的格子进来时（`namesOnly`）只画变量盘。
- **结构带是一串块，不是一棵语法树**（`SlotRecipe`）：语法树里「读不通」就是没有树，而半条式子
  恰恰是最需要看着改的时候。读法改成逐块扫描，认不出的字符也是一块，照样画出来、照样能删，
  没有「读不懂的一段」这种东西。
- **没有整条公式输入框**：带子仍是唯一的编辑面，每块都能点、能删、能拖，不必记住哪里该打逗号、
  括号配平到哪一层。符号带下面那行小输入框只写一个数字或一段文字，不是整条式子。
- **叉是独立覆盖层里的一枚真按钮**：不能靠「覆盖层画一个矩形 + 在带子上按坐标判定」——看得见的
  地方点不到，点得到的是压在块顶的那几像素。也不能用 `:pointerover` 判断「指针在哪一块上」：
  Avalonia 会把伪类传给命中元素的**所有祖先**，悬停一个名字会点亮套着它的每一层函数块。所以由
  窗口自己维护 `SlotNode.IsHovered`，命中变化时重算一次。
- **拖拽用指针事件自己做**，不发起平台拖放会话：拖的是同一个窗口里的东西，会话一开窗口就管不着它。

### 两块的表单：条件有一个块，多分支知道有分支

行表与分支表都在列表里，但**打开其中一块的表单时，看到的曾经是另一件事**：条件分支的页面只有
一行「ƒ 条件」，三个白框没有任何字；多分支的页面只有值和一个下拉，整页不知道分支存在。同族的
两块两套读法，`Control` 那 20 个动作也就一直停在「已分块 0」。

- **两块各有一个块头**：`control.if` 的 `condition` 归入「条件」（GitBranch 图标），
  `control.switch` 的 `switchValue` / `switchMode` 归入「比对什么」（GitCompareArrows）。
  块头说完之后，条件那一格自己的标签不画（`HidesLabel`）：同一个词连写两遍，
  一是块头一是标签，读的人会以为页面上有两个条件。
- **空的比较就是一行**：条件为空时表里直接摆一行空比较（左 `例如 $found`、右 `例如 3 或 true`），
  不是「还没有条件。」加一个按钮。这一行是空的，所以写进宏的仍是空文本，不是什么默认条件。
- **红字只在写了一半时出现**：一格都没填时底部是中性的一句「写一行比较就能添加这一步。」
  （`Add.NeedCondition`，判断在 `ConditionEditorViewModel.HasInput`）；填了左边、缺右边才是
  红字「还缺：条件」。
- **「条件树」只有一个入口**：右上那颗切换。行表下面那颗按钮删掉，嵌套提示也从两处收成一处。
- **多分支的表单知道有几支**：值的下面一行「3 个分支 · 其他情况 2 步」加一颗「添加分支」，
  按下就在这支块里写一支空的（`AddActionViewModel.AddBranch`），保存后出现在列表里。
  分支是步骤不是字段，所以那支仍要在列表中写值、拖子步骤；表单只负责「这一块有几支、再加一支」。
  新分支的名字由编辑器发（`NextStepId(ISet<string>)`），一次加两支也不会撞号。
- **分支还没填值是一处空缺**：值片「还没填值」用警示色（`Button.Secondary.Chip.Dense.empty`），
  灰字读起来像「已经填好了」。
- **分节名收短**：`满足时步骤 / 不满足时步骤` → `满足时 / 否则`；分节行统一写成
  「标题 · 3 个步骤」，与其他分节同一个断点。

**考虑过、没做的两条**（免得下次重新讨论）：

- **「其他情况」做成与分支行同族的值片**：它是这一块自己的 else 列表，和 `if` 的「满足时 / 否则」
  是同一类东西；做成值片会让人以为那里也能填值。它保持分节行，靠名字说清是兜底那一支。
- **值 + 比对方式并到一行**：「要比对的值」这一格带「表达式」「变量」两颗按钮，并排后文本框只剩
  一百来像素，读一句比读两行更费劲。两行照旧。
