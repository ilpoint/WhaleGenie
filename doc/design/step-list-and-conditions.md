# 步骤列表与流程条件

两件事放在一份里，因为它们改的是同一块地方：列表一行装不下的是「条件」，而条件现在只能写成一格
表达式。先定列表的读法，条件才知道要长成什么样。

## 一、步骤列表：一行一步，详情另说

### 现在的问题

一张卡片上叠着四段字：名称与三枚徽标、说明（`Detail`）、备注、执行节奏（`MetaSummary`）。行高
下限 42，说明或备注一折就是 70 以上；一屏二十来步里只看得见七八步。流程块还额外多出「子步骤标题」
「空列表提示」「块收尾」三种行，块一多，列表里一半是脚手架而不是步骤。

四段话不是重点不等：名、说明、备注、节奏同样的字号与颜色，扫读时找不到「这一步在干什么」。

### 改法

```
┌────────────────────────────────────────────────────────────┐
│ ▸ 🔗 点击界面元素  click1  后台    未命名 - 记事本 · Button…  │  30px
│ ▾ 🔁 重复 10 次                                        3 步  │
│     🔗 延迟   delay1             control.delay · 等待 1000 毫秒 │
│     ┌────────────────────────────────────────────────────┐ │
│     │ control.delay · 等待时长 = 1000 毫秒                 │ │  点中的这一行
│     │ 备注：等界面稳定后再点保存                            │ │  在原处展开
│     │ 失败后询问                                          │ │
│     └────────────────────────────────────────────────────┘ │
│     🔗 按键   key2               Ctrl+S                       │
└────────────────────────────────────────────────────────────┘
```

1. **一行 30px**：折叠箭头、图标、名称、徽标（id / 跳过 / 输入方式），然后一句摘要，最后是问题
   标记。名称与摘要在窄列里都截断，完整的话在展开之后与悬停里。
2. **点中的那一行在原处展开**：完整说明、备注、执行节奏接在它下面，别的行仍是一行——视线不离开
   那一行，列表也不跳。点另一行就换过去；多选时一个都不展开，免得让人以为只选中了一条。
3. **双击打开编辑**保持不动；右键菜单、多选、拖放落点也都不动。
4. **块的步数**（待做）：块那一行的右侧写「3 步」，折叠起来也看得见里面有几歩，不必展开数。
5. **缩进与树线**（已完成）：每层 26px、虚线、`TreeGuide`（深色 40% 白）。层级靠线读，不靠留白猜。

### 为什么最后换成了 TreeView

先用的是 `ListBox` + 「每行写一个缩进数字」的假树。假树能看，但层级的每一件事都要自己重做，而
`ListBox` 也不提供这些事的入口。换掉它的理由不是「树更好看」，是**层级本来就在数据里**，让控件
去画它，比让每一行自己算缩进稳。

四件原先要重做的东西，换树之后各自落在哪儿：

| 原来（ListBox） | 现在（TreeView） |
|---|---|
| 拖放落点带算「第几行」，`head` 行表示块首、`foot` 行表示块尾 | 落点算**（哪个列表，第几位）**：**块行与体行整行都是「放进这一块、排在最末」**（展开、折叠一样），普通步骤分上下半「之前 / 之后」，树上面的空白是宏开头、下面的空白是宏末尾。没有收尾行，也没有「上三分之一进块」这类分区 |
| 多选批量剪切粘贴 | 树的 `SelectedItems` + 节点上的 `IsPicked`；编辑器仍然只认步骤，分节与收尾行选中时归到块本身 |
| 块的标题与收尾行 | 每个块都有一行「体」（`循环体步骤 / 满足时步骤 / 不满足时步骤`）：它说清"从这一行往下都属于这个块"，也是拖进去的落点；块自己的行只写动作与参数。**收尾行取消**，块的结束由缩进线断在哪儿表示 |
| 折叠状态与重建行 | 树节点自带 `IsExpanded`，绑在步骤自己的 `IsExpanded` 上；折叠只是「不画子节点」，**不再重建任何东西** |

`NavigationView` 仍然不用：它是应用级左栏（菜单、页面切换），拿它装步骤等于把「页面」和「步骤」
塞进一个控件，选中、返回栈、面包屑都用不上。

### 这一版已经落地

- 行压成一行（30px），备注与节奏离开行。
- 点中一行时它**在该行内展开**（第一次做成了列表下方的一条详情，点一下视线要往下跳，改回来了）。
- 动作库的搜索不再分「基础动作 / 流程控制」两个页签：搜「延迟」不必先切到流程那一栏；清空搜索
  仍回到原来那一页，分类芯片仍管收窄。
- 换成一棵真的树：块自己的子步骤挂在它的「体」行下面，多列表的块每个列表一个体行；块的结尾不单画一行。
- **块的步数**写在体行上（每节各写各的），不把「那么 2 步 + 否则 1 步」加成「3 步」。
- 折叠归树控件：箭头由控件画，`TreeViewItem.IsExpanded` 双向绑到步骤上，收起不重建节点。
- 行是**平**的，不是一摞卡片：层级的读法交给树线——每层一根 2px 的虚线，走到那一行的中点向右
  拐进这一行（`├ / └`），某支没有兄弟时就只画到拐点；有子步骤的行还会从自己的方块下垂一段，
  让"从这个块往下属于它"接得上。线是**画**出来的（`GuideLinesView`）：一格一格的矩形拼不出跨行
  的虚线，每段各自从头数节奏，接起来就是毛边。
- **一根线属于它下面那一层的节点**：第 N 列的线由深度 N+1 的节点掌管，所以它一直画到那个节点的
  最后一个直接子节点为止。判断写成"第 N 列要不要继续"时数错一层，就是整列提前一行收尾——这正是
  条件分支下面那段断线的成因（已修，并由 `StepGuideTests` 按列逐段校验）。
- **最外层也有干线**：第一级的行从最左边一条竖线上接出来（每条都有一根横枝），`重复` 这类块前面
  也是这条线，折叠方块就长在线上——和参考软件一致。没有它，第一级看起来只是一列文字。
- **只有"自己跑步骤"的那一行有折叠方块**：`循环体步骤` 是块的一部分，它上面不再放第二枚方块；
  块那一行的方块同时管整块的开合。
- **块折叠时，从方块垂下去的那一截线也要收掉**：折叠不重建行，只是不画子节点，所以下垂线要在
  `IsExpanded` 变化时重算，否则会在合上的方块下面留一小截（`StepGuideTests` 有一条用例守这个）。
- **线不能画到自己那一列上**：一行只画它上面各层的列，加上自己下垂的那一截；`StepGuideTests`
  按"列号必须小于层号"逐行校验，越界就是伸到别的分支里去了。
- **空列表也要下垂线**：`尝试/捕获/收尾` 的三个列表刚加时都是空的，但每一个都有"尝试步骤 0 个步骤"
  这一行挂着，所以块到自己第一行之间那一截必须画——按"有步数"判断，列会晚一行才开始。
- **双击只认行本身**：双击左侧引导线所在的空白、或双击折叠方块，都不打开步骤编辑——方块有它自己的
  活要干（折叠），空白是行悬挂的空间而不是行。只有双击卡片本身（文字、徽标、图标）才打开。
- **行必须撑满行高**（`PART_HeaderPresenter` 的 `VerticalAlignment=Stretch`）：行有 30 的下限，
  文字只有 20 高时居中放，上下各留 5 像素，线走到那儿正好断一截。
- 层级还有第二条线索：块行字重更重、字号大一档；体行用浅底、小字，读起来是"这个块的目录"。
- **横向滚动关掉了**（`HorizontalScrollBarVisibility=Disabled`）。开着的时候，一行里那句参数摘要
  会把列表的内容宽度撑过视口，树就横向滚起来——缩进、箭头、竖线全被推到左边看不见，
  屏幕上只剩一列左对齐的字。这是"每层看不出缩进"的真正原因，不是缩进值太小。
- 选中由行自己画（`.selected`），树自己那层底与行首的小竖条都让开，避免两套高亮叠在一起。
- 行上**没有按钮**：进块的唯一入口是"把动作拖到块的那一行下半"或"选中块再新建一步"，
  不再有加号，也没有「拖入子步骤」这类重复入口。
- 行高测试：下限 30、卡片装得进这一行、**没点中的行再长的备注也不许撑成两行**、点中的那一行
  必须长高。
- **缩进步长 26**（主题默认 16）：16 的时候三层连着看还是一列，26 才看得出"这行属于上面那行"。
  这个数写在 `StepRow.IndentWidth`，树模板（`StepIndentConverter`）与树线都从它算，改一处是一处。
- **树的模板自己给**：FluentAvalonia 的 `TreeViewItem` 把"层级 × 16"写死在模板里，外面改
  `TreeViewItemIndent` 资源改不动（实测仍是 16）。既然层级要靠线读，缩进、展开钮、选中态就得
  在同一个 `ControlTheme` 里，所以 `Themes/Controls.axaml` 里有一份自己的 `TreeViewItem`。
- 树线颜色 `TreeGuide` 从 20% 白提到 **40% 白**：20% 在暗色卡片上几乎看不见，看成"没有线"。
- 虚线是 **6 划 2 隔**（2px 粗）：划与隔一样长时，三十像素一行只剩两三段，读起来是"断线"。
- 每段的虚线**按它在树里的位置错相位**：一行一个控件，各自从 y=0 起算节奏的话，行与行的接缝上
  会一段正好落在空隙里——四十行就是四十条各自从头数起的线。按绝对纵坐标取模，一列才是一条线。
- 拐进一行的**横枝是实线**，且从竖线中心起笔：拐角是虚线与虚线相遇的地方，两条都带节奏就必然
  在某个相位上断开，而"断在拐角"正是最像 bug 的断法。

## 二、流程条件：行表为主，表达式兜底

### 现在的问题

「条件」是一格文本，旁边一个「表达式」按钮。会写的人直接写，不会写的人面对 `$found` 不知道从
哪儿下手；读的人也要在脑子里把 `&& || !` 翻译一遍才看得出这一步在等什么。顺带一个小毛病：
`control.if` 新建时预填 `$found`，而这个变量常常还不存在，表单底下立刻红字「还缺：条件」——新建
就报错，说的还是用户没做错的事。

### 四个方案

| 方案 | 长什么样 | 好处 | 代价 |
|---|---|---|---|
| A 纯文本（现状） | 一格表达式 + 表达式编辑器 | 什么都能写，零成本 | 不会写的人用不了；读不出结构 |
| B 条件行表 | 左值 / 比较 / 右值，一行一条，顶上「全部 / 任一」 | 一眼看懂，变量可拾取 | 嵌套条件（(A 或 B) 且 C）表达不了 |
| C 可视化条件树 | 可嵌套的分组 | 表达力最强 | 实现与学习成本都高，小屏放不下 |
| D 行表 + 表达式兜底 | 默认行表；切到「表达式」写原文 | 两头都顾 | 两套写法要能互转 |

**落地时取 D 的一个变体：行表与条件树同时保留，顶上切换。** 两者看的是同一份模型（嵌套的分组 +
一行一条比较），切换视图只是换模板，不是格式转换：行表适合「甲且乙且丙」这种平铺的、可以像填表
一样一条条录入的；树适合「甲且（乙或丙）」这种嵌套。行表读到一个嵌套时不禁用，只在旁边写一句
「这条条件有嵌套，按条件树编辑」。

```
条件                                    [全部成立 ▾]
┌──────────────┬────────────┬──────────────────────┐
│ $found       │ 等于 ▾     │ true                 │
│ $count       │ 大于 ▾     │ 3                    │
│ 窗口标题      │ 包含 ▾     │ 记事本                │
└──────────────┴────────────┴──────────────────────┘
+ 添加条件                                        [用表达式写]
```

- **左值**：变量或表达式（`$名字`、`ƒ` 打开表达式编辑器、也可以直接写字面量）。
- **比较**：等于 / 不等于 / 大于 / 小于 / 不小于 / 不大于 / 包含 / 不包含 / 为空 / 不为空 /
  为真 / 为假。**按左值的类型给**：数字不给「包含」，文字不给「大于」（除非写成数字表达式）。
- **右值**：「为空」「为真」这类不需要右值，那一格直接收起，不是留个空框让人猜。
- **顶上**：「全部成立 / 任一成立」。不做嵌套——真要嵌套就切表达式。
- **行末**：删除；底部「添加条件」；右下角「用表达式写」切换。

### 存储与引擎：一行都不用改

行表只负责**写**，写出来的仍是原来那一格表达式字符串（`$a > 3 && $b == "x"`）。**读**的时候尝试
拆回行：只认同一层的 `&&` / `||` 与简单比较；拆不开（有函数调用、括号嵌套）就落到表达式模式并把
原文摆出来。这样宏文件格式、引擎、运行时全都不动，风险压到最低；两套写法自然互转，也不会出现
「行表存的格式引擎读不懂」这种事。

### 流程族其它动作

- `control.while`、`control.waitUntil` 用**同一个条件控件**，只是下面挂的步骤与超时不同。
- `control.switch` 是「值 → 分支」的**行表**（已完成）：树里一行一个分支，行首是一枚可点的值片
  （`值 1; 2`），后面跟步数，分支的步骤直接挂在下面。之前是「分支」总节 → 每个分支一个节点 →
  「分支步骤」节 → 步骤，四层只装一行内容，而分支之间唯一的区别——值——还藏在那行节点的摘要里。

  **分支是唯一没法从动作库拖进来的东西**（库里没有"分支"这张卡片），所以表尾有一行
  「＋ 添加分支」：按下就写一支空的，并**把这一支的值打开在原地**（占位「例如 1; 2; 3」），
  回车收下、Esc 还原。值片本身也能点，点开同样是这一行原地编辑——一个字段的东西不值得开
  整张动作表单，更不该要求人先猜到"双击能改"。多分支的行摘要只写「`$key` 等于」，不写两个
  字段名：分支已经摊在下面，行只需要说出这一块在比什么。

  **原地编辑不能是"降级"**：一行值仍是"写成文本、里面的 `$名字` 会被换掉"的字段，所以编辑时
  框旁有和步骤表单同一颗「变量」（`Focusable=False`，按下它不许把框关掉）：名字插在光标处，
  或在同一个挑选窗口里改写成表达式。输入框在**重建行**和**挑选窗口打开**时都不算"人走了"，
  否则刚按「添加分支」的那一行会在拿到焦点的瞬间自己关掉。
- `control.repeat` 的次数与间隔不分块，块头只会多一行字。
- 新建 `control.if` 时**条件留空**，占位写「例如 $found > 3」，不再预填一个不存在的变量。

### 分阶段

1. 步骤列表一行 + 详情条（已完成）。
2. 步骤列表换成 TreeView，四件事在树上重做（已完成）。
3. 条件行表 + 条件树，顶上切换，存的是同一格表达式（已完成：`control.if`、`control.while`、
   `control.waitUntil`）。
4. `switch` 分支表（已完成：树里一行一支，值写在行首并可原地改，表尾一行「＋ 添加分支」）。
5. 缩进与树线（已完成：26px 一档，虚线与拐角由 `GuideLinesView` 画）。
