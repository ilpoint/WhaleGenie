# 步骤列表与流程条件

两件事放在一份里，因为它们改的是同一块地方：列表一行装不下的是「条件」，而条件现在只能写成一格
表达式。先定列表的读法，条件才知道要长成什么样。

## 一、步骤列表：一行一步，详情另说

### 现在的问题

一张卡片上叠着四段字：名称与三枚徽标、说明（`Detail`）、备注、执行节奏（`MetaSummary`）。行高
下限 42，说明或备注一折就是 70 以上；一屏二十来步里只看得见七八步。流程块还额外多出「子步骤标题」
「空列表提示」「块收尾」三种行，块一多，列表里一半是脚手架而不是步骤。

四段话不是重点不等：名、说明、备注、节奏同样的字号与颜色，扫读时找不到「这一步在干什么」。

### 改法

```
┌────────────────────────────────────────────────────────────┐
│ ▸ 🔗 点击界面元素  click1  后台    未命名 - 记事本 · Button…  │  30px
│ ▾ 🔁 重复 10 次                                        3 步  │
│     🔗 延迟   delay1             control.delay · 等待 1000 毫秒 │
│     ┌────────────────────────────────────────────────────┐ │
│     │ control.delay · 等待时长 = 1000 毫秒                 │ │  点中的这一行
│     │ 备注：等界面稳定后再点保存                            │ │  在原处展开
│     │ 失败后询问                                          │ │
│     └────────────────────────────────────────────────────┘ │
│     🔗 按键   key2               Ctrl+S                       │
└────────────────────────────────────────────────────────────┘
```

1. **一行 30px**：折叠箭头、图标、名称、徽标（id / 跳过 / 输入方式），然后一句摘要，最后是问题
   标记。名称与摘要在窄列里都截断，完整的话在展开之后与悬停里。
2. **点中的那一行在原处展开**：完整说明、备注、执行节奏接在它下面，别的行仍是一行——视线不离开
   那一行，列表也不跳。点另一行就换过去；多选时一个都不展开，免得让人以为只选中了一条。
3. **双击打开编辑**保持不动；右键菜单、多选、拖放落点也都不动。
4. **块的步数**（待做）：块那一行的右侧写「3 步」，折叠起来也看得见里面有几歩，不必展开数。
5. **缩进与树线**（已完成）：每层 26px、虚线、`TreeGuide`（深色 40% 白）。层级靠线读，不靠留白猜。

### 为什么最后换成了 TreeView

先用的是 `ListBox` + 「每行写一个缩进数字」的假树。假树能看，但层级的每一件事都要自己重做，而
`ListBox` 也不提供这些事的入口。换掉它的理由不是「树更好看」，是**层级本来就在数据里**，让控件
去画它，比让每一行自己算缩进稳。

四件原先要重做的东西，换树之后各自落在哪儿：

| 原来（ListBox） | 现在（TreeView） |
|---|---|
| 拖放落点带算「第几行」，`head` 行表示块首、`foot` 行表示块尾 | 落点算**（哪个列表，第几位）**：**块行与体行整行都是「放进这一块、排在最末」**（展开、折叠一样），普通步骤分上下半「之前 / 之后」，树上面的空白是宏开头、下面的空白是宏末尾。没有收尾行，也没有「上三分之一进块」这类分区 |
| 多选批量剪切粘贴 | 树的 `SelectedItems` + 节点上的 `IsPicked`；编辑器仍然只认步骤，分节与收尾行选中时归到块本身 |
| 块的标题与收尾行 | 每个块都有一行「体」（`循环体 / 满足时 / 否则`）：它说清"从这一行往下都属于这个块"，也是拖进去的落点；块自己的行只写动作与参数。**收尾行取消**，块的结束由缩进线断在哪儿表示 |
| 折叠状态与重建行 | 树节点自带 `IsExpanded`，绑在步骤自己的 `IsExpanded` 上；折叠只是「不画子节点」，**不再重建任何东西** |

`NavigationView` 仍然不用：它是应用级左栏（菜单、页面切换），拿它装步骤等于把「页面」和「步骤」
塞进一个控件，选中、返回栈、面包屑都用不上。

### 这一版已经落地

- 行压成一行（30px），备注与节奏离开行。
- 点中一行时它**在该行内展开**（第一次做成了列表下方的一条详情，点一下视线要往下跳，改回来了）。
- 动作库的搜索不再分「基础动作 / 流程控制」两个页签：搜「延迟」不必先切到流程那一栏；清空搜索
  仍回到原来那一页，分类芯片仍管收窄。
- 换成一棵真的树：块自己的子步骤挂在它的「体」行下面，多列表的块每个列表一个体行；块的结尾不单画一行。
- **块的步数**写在体行上（每节各写各的），不把「那么 2 步 + 否则 1 步」加成「3 步」。
- 折叠归树控件：箭头由控件画，`TreeViewItem.IsExpanded` 双向绑到步骤上，收起不重建节点。
- 行是**平**的，不是一摞卡片：层级的读法交给树线——每层一根 2px 的虚线，走到那一行的中点向右
  拐进这一行（`├ / └`），某支没有兄弟时就只画到拐点；有子步骤的行还会从自己的方块下垂一段，
  让"从这个块往下属于它"接得上。线是**画**出来的（`GuideLinesView`）：一格一格的矩形拼不出跨行
  的虚线，每段各自从头数节奏，接起来就是毛边。
- **一根线属于它下面那一层的节点**：第 N 列的线由深度 N+1 的节点掌管，所以它一直画到那个节点的
  最后一个直接子节点为止。判断写成"第 N 列要不要继续"时数错一层，就是整列提前一行收尾——这正是
  条件分支下面那段断线的成因（已修，并由 `StepGuideTests` 按列逐段校验）。
- **最外层也有干线**：第一级的行从最左边一条竖线上接出来（每条都有一根横枝），`重复` 这类块前面
  也是这条线，折叠方块就长在线上——和参考软件一致。没有它，第一级看起来只是一列文字。
- **只有"自己跑步骤"的那一行有折叠方块**：`循环体步骤` 是块的一部分，它上面不再放第二枚方块；
  块那一行的方块同时管整块的开合。
- **块折叠时，从方块垂下去的那一截线也要收掉**：折叠不重建行，只是不画子节点，所以下垂线要在
  `IsExpanded` 变化时重算，否则会在合上的方块下面留一小截（`StepGuideTests` 有一条用例守这个）。
- **线不能画到自己那一列上**：一行只画它上面各层的列，加上自己下垂的那一截；`StepGuideTests`
  按"列号必须小于层号"逐行校验，越界就是伸到别的分支里去了。
- **空列表也要下垂线**：`尝试/捕获/收尾` 的三个列表刚加时都是空的，但每一个都有"尝试步骤 0 个步骤"
  这一行挂着，所以块到自己第一行之间那一截必须画——按"有步数"判断，列会晚一行才开始。
- **双击只认行本身**：双击左侧引导线所在的空白、或双击折叠方块，都不打开步骤编辑——方块有它自己的
  活要干（折叠），空白是行悬挂的空间而不是行。只有双击卡片本身（文字、徽标、图标）才打开。
- **行必须撑满行高**（`PART_HeaderPresenter` 的 `VerticalAlignment=Stretch`）：行有 30 的下限，
  文字只有 20 高时居中放，上下各留 5 像素，线走到那儿正好断一截。
- 层级还有第二条线索：块行字重更重、字号大一档；体行用浅底、小字，读起来是"这个块的目录"。
- **横向滚动关掉了**（`HorizontalScrollBarVisibility=Disabled`）。开着的时候，一行里那句参数摘要
  会把列表的内容宽度撑过视口，树就横向滚起来——缩进、箭头、竖线全被推到左边看不见，
  屏幕上只剩一列左对齐的字。这是"每层看不出缩进"的真正原因，不是缩进值太小。
- 选中由行自己画（`.selected`），树自己那层底与行首的小竖条都让开，避免两套高亮叠在一起。
- 行上**没有按钮**：进块的唯一入口是"把动作拖到块的那一行下半"或"选中块再新建一步"，
  不再有加号，也没有「拖入子步骤」这类重复入口。
- 行高测试：下限 30、卡片装得进这一行、**没点中的行再长的备注也不许撑成两行**、点中的那一行
  必须长高。
- **缩进步长 26**（主题默认 16）：16 的时候三层连着看还是一列，26 才看得出"这行属于上面那行"。
  这个数写在 `StepRow.IndentWidth`，树模板（`StepIndentConverter`）与树线都从它算，改一处是一处。
- **树的模板自己给**：FluentAvalonia 的 `TreeViewItem` 把"层级 × 16"写死在模板里，外面改
  `TreeViewItemIndent` 资源改不动（实测仍是 16）。既然层级要靠线读，缩进、展开钮、选中态就得
  在同一个 `ControlTheme` 里，所以 `Themes/Controls.axaml` 里有一份自己的 `TreeViewItem`。
- 树线颜色 `TreeGuide` 从 20% 白提到 **40% 白**：20% 在暗色卡片上几乎看不见，看成"没有线"。
- 虚线是 **6 划 2 隔**（2px 粗）：划与隔一样长时，三十像素一行只剩两三段，读起来是"断线"。
- 每段的虚线**按它在树里的位置错相位**：一行一个控件，各自从 y=0 起算节奏的话，行与行的接缝上
  会一段正好落在空隙里——四十行就是四十条各自从头数起的线。按绝对纵坐标取模，一列才是一条线。
- 拐进一行的**横枝是实线**，且从竖线中心起笔：拐角是虚线与虚线相遇的地方，两条都带节奏就必然
  在某个相位上断开，而"断在拐角"正是最像 bug 的断法。

## 二、流程条件：行表为主，表达式兜底

### 现在的问题

「条件」是一格文本，旁边一个「表达式」按钮。会写的人直接写，不会写的人面对 `$found` 不知道从
哪儿下手；读的人也要在脑子里把 `&& || !` 翻译一遍才看得出这一步在等什么。顺带一个小毛病：
`control.if` 新建时预填 `$found`，而这个变量常常还不存在，表单底下立刻红字「还缺：条件」——新建
就报错，说的还是用户没做错的事。

### 四个方案

| 方案 | 长什么样 | 好处 | 代价 |
|---|---|---|---|
| A 纯文本（现状） | 一格表达式 + 表达式编辑器 | 什么都能写，零成本 | 不会写的人用不了；读不出结构 |
| B 条件行表 | 左值 / 比较 / 右值，一行一条，顶上「全部 / 任一」 | 一眼看懂，变量可拾取 | 嵌套条件（(A 或 B) 且 C）表达不了 |
| C 可视化条件树 | 可嵌套的分组 | 表达力最强 | 实现与学习成本都高，小屏放不下 |
| D 行表 + 表达式兜底 | 默认行表；切到「表达式」写原文 | 两头都顾 | 两套写法要能互转 |

**落地时取 D 的一个变体：行表与条件树同时保留，顶上切换。** 两者看的是同一份模型（嵌套的分组 +
一行一条比较），切换视图只是换模板，不是格式转换：行表适合「甲且乙且丙」这种平铺的、可以像填表
一样一条条录入的；树适合「甲且（乙或丙）」这种嵌套。行表读到一个嵌套时不禁用，只在旁边写一句
「这条条件有嵌套，按条件树编辑」。

```
条件                                    [全部成立 ▾]
┌──────────────┬────────────┬──────────────────────┐
│ $found       │ 等于 ▾     │ true                 │
│ $count       │ 大于 ▾     │ 3                    │
│ 窗口标题      │ 包含 ▾     │ 记事本                │
└──────────────┴────────────┴──────────────────────┘
+ 添加条件                                        [用表达式写]
```

- **左值**：变量或表达式（`$名字`、`ƒ` 打开表达式编辑器、也可以直接写字面量）。
- **比较**：等于 / 不等于 / 大于 / 小于 / 不小于 / 不大于 / 包含 / 不包含 / 为空 / 不为空 /
  为真 / 为假。**按左值的类型给**：数字不给「包含」，文字不给「大于」（除非写成数字表达式）。
- **右值**：「为空」「为真」这类不需要右值，那一格直接收起，不是留个空框让人猜。
- **顶上**：「全部成立 / 任一成立」。不做嵌套——真要嵌套就切表达式。
- **行末**：删除；底部「添加条件」；右下角「用表达式写」切换。

### 存储与引擎：一行都不用改

行表只负责**写**，写出来的仍是原来那一格表达式字符串（`$a > 3 && $b == "x"`）。**读**的时候尝试
拆回行：只认同一层的 `&&` / `||` 与简单比较；拆不开（有函数调用、括号嵌套）就落到表达式模式并把
原文摆出来。这样宏文件格式、引擎、运行时全都不动，风险压到最低；两套写法自然互转，也不会出现
「行表存的格式引擎读不懂」这种事。

### 流程族其它动作

- `control.while`、`control.waitUntil` 用**同一个条件控件**，只是下面挂的步骤与超时不同。
- `control.switch` 是「值 → 分支」的**行表**（已完成）：树里一行一个分支，行首是一枚可点的值片
  （`值 1; 2`），后面跟步数，分支的步骤直接挂在下面。之前是「分支」总节 → 每个分支一个节点 →
  「分支步骤」节 → 步骤，四层只装一行内容，而分支之间唯一的区别——值——还藏在那行节点的摘要里。

  **分支是唯一没法从动作库拖进来的东西**（库里没有"分支"这张卡片），所以表尾有一行
  「＋ 添加分支」：按下就写一支空的，并**把这一支的值打开在原地**（占位「例如 1; 2; 3」），
  回车收下、Esc 还原。值片本身也能点，点开同样是这一行原地编辑——一个字段的东西不值得开
  整张动作表单，更不该要求人先猜到"双击能改"。多分支的行摘要只写「`$key` 等于」，不写两个
  字段名：分支已经摊在下面，行只需要说出这一块在比什么。

  **原地编辑不能是"降级"**：一行值仍是"写成文本、里面的 `$名字` 会被换掉"的字段，所以编辑时
  框旁有和步骤表单同一颗「变量」（`Focusable=False`，按下它不许把框关掉）：名字插在光标处，
  或在同一个挑选窗口里改写成表达式。输入框在**重建行**和**挑选窗口打开**时都不算"人走了"，
  否则刚按「添加分支」的那一行会在拿到焦点的瞬间自己关掉。
- `control.repeat` 的次数与间隔不分块，块头只会多一行字。
- 新建 `control.if` 时**条件留空**，占位写「例如 $found」，不再预填一个不存在的变量。

### 比较词：一张表，三处用

条件原来只有八个词，而且全是运算符：等于、不等于、大于、小于、不小于、不大于、成立、不成立。
引擎早就有 `contains` / `startsWith` / `endsWith` / `match` / `length` / `count`，`TextCompare` 还是
多分支与 `compare()` 共用的同一份语义——缺的只是**词表、写法与读回**：`Condition.ReadRow` 只认运算符和
`not`，`contains($a, x)` 今天会被读成「左边一整串、比较词是成立」，所以行表根本显示不出这类条件。

现在有十六个词，分四族，每族一种写法：

| 族 | 词 | 写进宏 | 要右值 |
|---|---|---|---|
| 数字 | 等于 / 不等于 / 大于 / 小于 / 不小于 / 不大于 | `$a == 1` | 要 |
| 文本 | 包含 / 不包含 / 开头是 / 结尾是 / 匹配正则 | `contains($a, x)`、`not contains($a, x)` | 要 |
| | 为空 / 不为空 | `length($a) == 0`、`length($a) > 0` | 不要 |
| 列表 | 条目数为 | `count($list) == 3` | 要 |
| 真假 | 成立 / 不成立 | `$a`、`not $a` | 不要 |

三条取舍：

- **不单列「在列表里」**。`contains()` 本来就同时认一段文字和列表里的一项，反过来写
  （`contains($list, $a)`）读回时必然和「包含」分不清；同一个词覆盖两族，行表也就不会出现
  两行字一样、写法相反的东西。
- **为空 / 条目数为用 length / count 写**，不新增 isEmpty 之类：两个函数已经在，读回时把
  `length(x) == 0`、`count(x) == 3` 认成这两行，左边不会变成"没人打过的一串表达式"。
- **`not (a and b)` 不认成「全都不成立」**。只认 `not (a or b)`：否掉"全部成立"是另一个问题，
  硬当成"全都不成立"会读错意思；碰到 `not (a and b)` 仍是一条「不成立」的行，原文照存。

多分支的比对方式取自同一张表，取其中适用的十一种，本轮补上唯一缺的「不包含」，并把
`以…开头 / 以…结尾 / 正则匹配` 改成与条件同名的「开头是 / 结尾是 / 匹配正则」。它不给「为空」
「条目数为」：分支值本身就是右值，空值那件事由「其他情况」回答。

**一个窗口，按钮在框里**：条件是一条表达式，而全站每个能写值的格子旁边都有"变量 / 表达式"这两样，
只有这两格没有过。第一版把它们做成框内 20 像素的淡色图标，**没人看得出那是按钮**——图标不像字那样
自报家门；第二版改成行末两枚带字的片，又冒出另一个问题：一行有两个格子，片在行末，得先猜它填的是
哪一格。

现在收成**一枚贴在框右端的「取值」小片**（`AutoCompleteBox.InnerRightContent`，Avalonia 12 原生就有），
按钮跟着格子走，不必再猜。文字让出右端 48 像素（`HasChip`），小片带边、带字，不靠悬停才认得出。

**一个窗口，三盘同页**（`ValuePickerWindow`，1140×720）：结构带在上，符号 / 变量 / 函数三盘在下，
右上一栏说选中的材料是什么。初版把三样做成页签，一次只看得见一类——写一条
`contains($a, x) and $b > 3` 要在三页之间来回切，切一次丢一次位置。页签适合浏览，不适合拼装；
拼装要材料同屏。名字是表达式的原子（`$found` 本身就是一条合法表达式），所以"选名字"和"写公式"
仍是同一个窗口，只是从只写名字的格子进来时（`namesOnly`）只画变量盘。

三盘里的东西都是**彩色描边的胶囊**，度量和动作里的片是同一套（`Secondary Chip Dense`：24 高、11.5 号字、
同一个圆角），只换描边与底色；符号按族分色（数字、比较、连接、括号），变量按来源分色（系统、全局、
参数、步骤结果、局部），函数按分组分色（文本、数字、列表、日期、记录）。色板只有一份，在
`FunctionGroupBrushConverter` 里，边框 / 底色 / 文字取 `line / fill / ink` 三个权重。胶囊贴着自己的
字长，一行放几枚，不占一整行。

结构带与下半区之间是一条**可拖的横向 `GridSplitter`**，变量盘与函数盘之间是一条纵向的，各自把高度或
宽度交给人定。分类标签只留文字：没有底、没有框，选中的那条加粗；左右留 8、下面留 4，不占一排格子。
「值」只留**真 / 假 / 空**，`数字` 与 `文本` 移到符号带下面那行**常驻的小输入框**上，只切换它写什么。

**结构带是一串块，不是一个树**（`SlotRecipe`）。整条式子是一段**序列**（`SlotSequence`），函数的
每条参数也是一段序列——序列里能放值（名字、数字、一段文字）、符号、括号，还能再放一个函数，
顺序就是拼上去的顺序。函数是唯一会往回收的东西：`SlotCall` 里一条一条参数序列，加末尾的幽灵槽。
之所以不再按引擎的语法画树：语法树里"读不通"就是没有树，而半条式子恰恰是最需要看着改的时候。
读法因此变成**逐块扫描**：认得名字、数字、字符串、符号、括号，认得"词后面跟 `(`"就是一次调用；
**认不出的字符也是一块**，照样画出来、照样能删。没有"读不懂的一段"这种东西了——引擎怎么读
由带子下面那行说，带子只负责把有的东西都摆出来。

**块要紧凑又点得中**：结构带里每一块统一 28 高、12.5 号等宽字、`8,3` 内边距、圆角 6。叉不画在块里，
而是贴在块外上角，所以块不必为它留位置，整条式子和嵌套容器都收得下来。括号一样有描边和底色。

**写下来的每一块都有一枚 ×**（Lucide 的 `circle-x`，16×16，实心底免得描边从圆环中间穿过去）：
实参、函数块、运算符、括号，一样一枚，贴在那一块的上角外侧。它**只在指针落到这一块上时才出现**，
其余时候整条式子干干净净。这件事不能用 `:pointerover` 做：Avalonia 会把这个伪类给命中的元素**以及它
所有的祖先**，悬停一个名字会把套着它的每一层函数块的叉都点亮；而且拖拽一开始 `Capture` 就会把整条
带子的 pointerover 清空。所以由窗口自己维护「指针在哪一块上」，命中变化时改 `SlotNode.IsHovered`，
模板绑 `ShowsRemove => CanRemove && IsHovered`。文本一改，`Recipe` 整棵树换新，于是按最后记录的指针
位置重新命中一次（`Recipe` 变更与 `ScrollChanged` 各一次），否则叉会"消失到下次抖鼠标"。

叉画在**独立覆盖层**里的一枚按钮上。`ControlFor()` 只认打了 `SlotPiece` 标记的
token 控件：调用块里的 `Panel`、`WrapPanel`、`ItemsControl` 与逐行模板的 `Grid` 都继承同一个
`SlotNode` 的 `DataContext`，早先取 pre-order 第一个匹配控件会拿到整个调用框或整段序列，把叉放到
大容器右上角，飞出结构带后连点击都收不到。叉放在块外上角而不是块内：点块的右半边要用来定位
插入光标，画在块里的叉会吞掉这一次点击。

**叉必须是一枚真按钮**，不是「覆盖层里画一个矩形 + 在带子上按坐标判定」。后者看着一样，点起来不是：
叉的 16×16 有 14 像素探到块的上边缘之外，首行块的叉就落进滚动区的上内边距里，而按下只有落在带子本体上
才收得到，于是**看得见的地方点不到，点得到的是它下方压在块顶的那几像素**。现在 `RemoveLayer` 只去掉
`IsHitTestVisible`（**不能设底**：Canvas 不画东西就不接指针，设了底整条带子都点不动），叉自己接
`Click`，按钮携带它所属的那一块，无需再比对坐标；那套 `_removeRect` 与「按下在叉上」的状态一并删掉，
顺带让样式里写着的悬停变红第一次真的生效。叉的位置只受覆盖层自身裁剪的约束，`ClipToBounds` 剪到哪儿就
夹到哪儿；夹到内容视口是错的，那会把首行的叉压回块上，正好复现「点块右半边却删掉了块」。

指针从块移到叉上时带子会收到 `PointerExited`（叉是兄弟层，不是子元素），所以那一下要按**几何**判断指针
是否还在叉上，否则叉会在指针到达的瞬间被藏掉、下一次移动又重新出现，变成每次靠近都闪一下。真机上
指针停在叉上时 `Band` 收不到 `PointerMoved`，位置由叉自己的 `PointerMoved` 记着，删完一块后叉才落得回
指针下那一块。
**空白气泡**也一起修掉：`HoverHint` 对无问题块返回 `null`，Avalonia 12 对空串照样弹有壳没字的
ToolTip；确认按钮改绑 `BlockReasonTip`，只在禁用时才有气泡。

删的是这一块连同它的逗号/接缝：按剩下的重写这一段，剪完两边都是空格就并一个，逗号该跟谁走走谁走。
删掉一条参数里的最后一块，幽灵槽自然回来：它从来没被写进文本。整条式子删空就是格子留空。

**括号是一枚一枚的**：`(`、`)`、`[`、`]` 各自是 `SlotBracket`，符号条上也是一次给一个字符。
`"` 不在符号条上了——一段文字要么由「文本」那枚就地输入，要么整块删掉，不该靠插一个引号拼出来。

**幽灵槽**：函数块末尾那个没写进公式的位置（虚线 `＋`），把光标点到它再写材料就再长一个，
写满 `MaxArguments` 就收起；不再有手动加空位的圆形按钮，幽灵槽够用。实参一个都没有时块里写
「参数为空」，缺参数时幽灵槽是红虚线、够了是灰虚线。

**每个参数都说清楚自己是干什么的**：参数名、第几个、必填还是可选都取自 `FunctionLibrary.Metadata`，与引擎
校验调用用的是同一张表，卡片气泡里写的也是这一份。参数超过 3 个或一行估算超过紧凑宽度时，容器自动
一行一个参数，可选参数另起一行缩进，左侧一条 1px 细线标层级；短式子仍排一行。参数里套着别的函数不再
单独触发展开，收尾的 `)` 与幽灵槽同排，块内间距一并压缩。一次只展开
一层：嵌套调用在父行里保持紧凑，否则结构带会被撑到看不见后半条式子。读不通时 `SlotDiagnostics` 把未知函数
与参数个数错误标到对应调用块、缺必填参数标到虚框上，红边是覆盖层不撑动布局；「确认」变灰时在按钮旁写明
原因。错误标记只从块序列与函数表推导，不改引擎的 `ExpressionException`，也不改宏文件里的纯字符串。

**拖**：按住一块拖到另一块上就搬到那里——落左半边是放到前面，右半边是放到后面，参数之间自动补逗号，
跨函数也行。括号也是普通一块，拖过去同样是搬动；点符号条上的 `(` 只写一个字符，不会给谁补一对。
自动包裹与选中替换这两条交互已整条删除。拖拽用指针事件自己做，不发起平台拖放会话：拖的是同一个
窗口里的东西，会话一开窗口就管不着它了。

**拖的时候看得见落点**：插入的位置画一根 2px 强调色竖线（文本光标的样子，高度取目标块的实际高度），
目标块描一圈淡边说明"落在这块的旁边"。两者都由 `PreviewMove()` 返回的同一份 `DropPreview` 派生：锚点、
前后侧、允许与否都在这份里，窗口画完把它缓存起来，松手直接复用，不再二次命中、也不再重算前后。原先
窗口拿指针命中的控件来画，`Resolve()` 却会把序列锚点改写成最后一块，于是画的是整段、做的是最后一块
之后；现在 `AnchorControl(preview.Anchor)` 才决定往哪儿画，序列锚点取最后一块的 token。把块拖回它
原来站的地方会算出「什么都不发生」，不画线也不动手。`PreviewDrop()` 与 `DropKind` 随包裹一起删掉，
不再有假的包裹环。竖线画在 `DragLayer`
（滚动区的兄弟层）里，用两次 `TranslatePoint` 求坐标，再与 `BandScroll` 的视口求交后裁剪；序列的
`WrapPanel` 有透明底，空白也接得住指针，拖到两块之间才会追加到这一段末尾。结构带里那根常驻的
2px 插入光标在拖拽开始时隐藏、松手后按新的文本重画，两根线不会同时占住同一个接缝。

**插入光标**：一根 2px 强调色竖线，硬闪，指出下一块材料落在哪里。与落点线一样宽，两根线靠「闪不闪」
分开，不靠粗细；闪烁写在 `Border.Caret` 的样式动画里（四帧把切换压进 1% 的时长，是断的不是渐变的），
不用计时器，窗口不必负责停它。光标用字符偏移 `Caret` 表示，
点一块的左半边放在它前面、右半边放在它后面，接缝取最近的边界；三盘材料、函数卡与常驻小输入框都
写在这个位置，函数卡插空调用后把光标留在括号内。文本重建只把光标按新长度夹取，`StartCaret` 从调用
方的 `TextBox.CaretIndex` 接线。

**两块挨在一起不能黏成一块**：拖、填空、光标插入、删除这四条路都在接缝上判一次「这两个字符会不会被读成
同一个 token」（数字与名字、两个引号、会并成 `>=` 的两个符号）。会，就补一个空格——`1 + 2` 把 `2` 拖
到 `1` 前得到 `2 1 +`，不是 `21 +`；`1-2` 删掉 `-` 得到 `1 2`，不是 `12`。`-` 配数字不用补，`-1` 还是
`-1`。接缝的位移不靠"删除前后长度相减"算：`Cut` 会顺手带走前面的逗号，那段区间要用前后文本比对
出来（`Difference` → `CutSpan`），再用 `SeamAfterCut` 映射，否则 `f(a, b, c)` 把 `b` 拖到 `a` 右边会
变成 `f(ab, , c)`。

**没有整条公式输入框**。窗口里只有带子、三盘和一句「读作 / 校验」。符号带下面常驻一行**只写数字或
文字的小输入框**：`数字` / `文本` 两枚按钮切换它写什么，点进去直接打字，按「插入」或回车写到结构带的
插入光标处（数字按不变文化读，读不成数「插入」是灰的；文字自动加引号并转义），插完清空并回焦。
它不是整条公式框，带子仍是唯一的编辑面：每块都能点、能删、能拖，不必再记住哪里该打逗号、括号配平到
哪一层。

**撤销与恢复**：结构带表头最左两枚图标（Lucide `undo-2` / `redo-2`），Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z
同样可用。历史只有一份：打字、点材料、按 ×、拖，改的都是那段文本，所以一处记全部；
按键走 tunnel 阶段，否则会被别的输入框先吃掉。

离开只有两条路：右下角的**确认**，和 Esc。常驻小输入框里的回车只插入材料、不关窗；搜索框、列表都不
绑 Enter——写到一半碰一下回车就关窗，是把正在做的事丢掉；窗口本身可以按标题栏拖动。
标题栏左上角是鲸鱼标志。

公式模式下点材料只把内容放进结构带，窗口留着继续拼一条式子，不因为格子原来是空的就关窗，也没有双击
或回车插入并关闭的快捷键。只有只写名字的格子进来时，点一个名字就是全部任务，点完直接交回名字。
离开始终只有「确认」和 Esc 两条路。


### 两块的表单：条件有一个块，多分支知道有分支

行表与分支表都在列表里，但**打开其中一块的表单时，看到的曾经是另一件事**：条件分支的页面只有
一行「ƒ 条件」，三个白框没有任何字；多分支的页面只有值和一个下拉，整页不知道分支存在。同族的
两块两套读法，`Control` 那 20 个动作也就一直停在「已分块 0」。

- **两块各有一个块头**：`control.if` 的 `condition` 归入「条件」（GitBranch 图标），
  `control.switch` 的 `switchValue` / `switchMode` 归入「比对什么」（GitCompareArrows）。
  块头说完之后，条件那一格自己的标签不画（`HidesLabel`）：同一个词连写两遍，
  一是块头一是标签，读的人会以为页面上有两个条件。
- **空的比较就是一行**：条件为空时表里直接摆一行空比较（左 `例如 $found`、右 `例如 3 或 true`），
  不再出现「还没有条件。」加一个按钮。这一行是空的，所以写进宏的仍是空文本，不是什么默认条件。
- **红字只在写了一半时出现**：一格都没填时底部是中性的一句「写一行比较就能添加这一步。」
  （`Add.NeedCondition`，判断在 `ConditionEditorViewModel.HasInput`）；填了左边、缺右边才是
  红字「还缺：条件」。原来新建就报红，说的还是人没做错的事。
- **「条件树」只有一个入口**：右上那颗切换。行表下面那颗按钮删掉，嵌套提示也从两处收成一处。
- **多分支的表单知道有几支**：值的下面一行「3 个分支 · 其他情况 2 步」加一颗「添加分支」，
  按下就在这支块里写一支空的（`AddActionViewModel.AddBranch`），保存后出现在列表里。
  分支是步骤不是字段，所以那支仍要在列表中写值、拖子步骤；表单只负责"这一块有几支、再加一支"。
  新分支的名字由编辑器发（`NextStepId(ISet<string>)`），一次加两支也不会撞号。
- **分支还没填值是一处空缺**：值片「还没填值」用警示色（`Button.Secondary.Chip.Dense.empty`），
  灰字读起来像"已经填好了"。
- **分节名收短**：`满足时步骤 / 不满足时步骤` → `满足时 / 否则`；分节行统一写成
  「标题 · 3 个步骤」，与其他分节同一个断点。

**考虑过、没做的两条**（免得下次重新讨论）：

- **「其他情况」做成与分支行同族的值片**：它是这一块自己的 else 列表，和 `if` 的「满足时 / 否则」
  是同一类东西；做成值片会让人以为那里也能填值。它保持分节行，靠名字说清是兜底那一支。
- **值 + 比对方式并到一行**：「要比对的值」这一格带「表达式」「变量」两颗按钮，并排后文本框只剩
  一百来像素，读一句比读两行更费劲。两行照旧。
